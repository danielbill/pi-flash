# UI 自动化测试框架（应用内自动化服务）

给 agent 用的应用内桌面自动化测试框架：**数据化界面（JSON 快照）+ 进程内操作
（方法直调 / 合成按键）**，让 agent 调试 UI 全程只发 bash 指令、读文本结果，
不与用户争抢真实屏幕/鼠标/键盘。操作手册（起实例、断言范式、CLI 陷阱）在
`.agents/skills/pi-flash-ui-test/SKILL.md`，本文只写设计。

模块代码：`crates/pi-link/src/automation.rs`（协议 + 实例发现，测试在此）、
`crates/pi-link/src/bin/pif-ui.rs`（CLI 驱动器）、`crates/app/src/automation/`
（服务端四件套 mod/handlers/snapshot/screenshot）。

## 0. 设计立足点

- 桌面端没有 DOM：gpui 每帧重画、无保留元素树，外界「看 UI」只能截屏；而
  agent 截屏 = 抢屏幕、模拟点击 = 抢鼠标，与用户互踩。
- `Chat`/`SessionRuntime` 字段全 `pub(crate)`，**UI 状态即数据**——快照直接读
  实体字段产 JSON，比像素树稳、比 a11y 树便宜（设置页
  `SettingsFormData::snapshot` 是现成先例）。
- app 是**方法调用驱动**的 shell（全仓只有 4 个 composer action）——「执行
  界面指令」直调 Chat 方法就是真实用户路径（`send_input` 就是回车键走的
  函数），不需要坐标点击。
- gpui 0.2.2 生产 API 有 `Window::dispatch_keystroke` / `dispatch_event`——
  合成按键走真实键位表→action 路径，快捷键行为可测。

原则：**数据优先于像素；方法直调优先于事件模拟**。坐标点击、通用元素树、
a11y 树全部不需要（gpui 升级时可 backport，见 §8）。

## 1. 截图：进程内渲染回读

`ui.screenshot` op / `pif-ui shot`。gpui 0.2.2 无窗口内容回读 API；vendored
gpui 内置 zed main 的 D3D11 staging 纹理回读（`Window::render_to_image`，
约 100 行，`vendor/gpui/src/window.rs` + windows 平台层），PNG 编码在
`app/src/automation/screenshot.rs`。进程内、不抢屏、窗口被遮挡/最小化也能截，
像素即 gpui scene 输出（合规于「禁止 OS 截图」铁律）。

帧语义边界：

- 截的是**最近一次绘制**的帧——`exec` 改状态后紧跟 shot 可能差一帧，使用
  模式是先 `wait` 后 shot（或隔一次 CLI 调用，泵在主线程逐条处理，帧间通常
  已刷新）。
- PNG 编码在主线程（2K 窗口约百 ms 冻结，测试场景可接受）。
- 拍不到 OS 级装饰（标题栏/阴影是 DWM 的，不在 gpui scene 里）；透明/模糊
  窗口的 alpha 通道未验证（pi-flash 主窗不透明）。

## 2. 架构与线程形制

```
agent(bash) → pif-ui CLI(pi-link bin)
  → TCP 127.0.0.1 NDJSON: {id, method, params} / {id, ok, result|error}
    → app/src/automation: TcpListener 线程 + 每连接读线程（握手后把请求行
      推 futures unbounded channel）+ 每连接写线程
      → cx.spawn 泵把请求逐条搬回主线程（同 session/runtime.rs attach_pump 形制）
        → snapshot 读 Chat/SessionRuntime 字段 / handlers 直调方法 /
          window.dispatch_keystroke 合成按键
```

- **开关**：`PI_FLASH_AUTOMATION=<port|auto|1>`，缺省关闭。绑定只落 127.0.0.1，
  token 握手防误连（时间+pid+栈地址熵两次 DefaultHasher，本地防误连用，非
  安全边界）。
- **实例发现**：`<配置目录>/automation/<pid>.json` {pid,port,token,started_at_ms}。
  多实例 CLI 选最新探活成功者；服务启动时探活清理死登记；CLI 发现时顺手清。
  `PI_FLASH_DIR` 隔离整套配置（并行实例互不干扰）。
- **判死只认 `ConnectionRefused`**（`port_is_definitely_dead`，CLI discover/
  list/clean 与 app 启动 prune 统一走它）：探活方缺 `SystemRoot` 时 Winsock
  自报错而实例活着，超时等其他失败一律保守保留。token 同时进启动日志行
  （`--addr/--token` 可直连救回误删登记的实例）。
- **韧性**：分发全程 catch_unwind——自动化触发的 panic 回 `internal` 错误
  响应，不许带崩 app；泵不因单次窗口更新失败而死。

## 3. 线协议（NDJSON，一行一记录）

连接时序：服务端先发 `hello{proto,app,pid,version}` → 客户端 `auth{token}` →
`auth_ok` 后进入请求循环。记录对齐 protocol.rs 手写风格：坏行忽略（读方
continue 不断连）、未知 type 落 `Unknown` 不静默丢（线协议漂移排查靠它）。

- 请求 `{"id","method","params"}`（params 缺省 `{}`）；响应
  `{"id","ok":true,"result"}` / `{"id","ok":false,"error":{code,message}}`。
- method 常量表 = **op 清单唯一事实源**（`pi_link::automation::method`，新增
  op 须带 params/断言面注释），CLI 与服务端共用防漂移；本文不重复抄清单。
- surface（`ui.snapshot` 的 params.surface）：`app | sessions | session |
  composer | files | git | settings | dialogs | term`，缺省 = 全部概要。
  term 面 = 每 tab 的 cwd/status/focused/cols/rows + 可见网格前 6 行文本
  （键入回显断言）。

## 4. 服务端四件套（crates/app/src/automation/）

- **mod.rs**：listener + 握手 + 读/写线程 + `cx.spawn` 泵 + catch_unwind 分发 +
  实例文件生命周期。
- **snapshot.rs**：9 个 surface 只读函数。纪律：**只读字段与既有 read API，
  绝不为快照改状态**；读 runtime 前先判 `runtimes.contains(active_key)`
  （`Chat::rt()` 内有 expect，异常路径回结构化错误，不靠 catch_unwind 兜）；
  消息尾部取 20 条（role + 文本预览 + 工具调用计数），长文本截断。
- **handlers.rs**：op → 直调 Chat 方法分发表。改状态 op 一律 `cx.notify()`
  收尾（GPUI 铁律：状态变 UI 动）。`input.keys` 必须 `window.defer` 后再
  `dispatch_keystroke`（entity_map 重入，见 docs/agents/gpui.md）。git
  stage/unstage 的错误回写 `chat.git_error`（与 UI 按钮同一状态出口），commit
  走 `git_commit_input` + `git_commit_staged`（不绕过 UI 校验路径）。
- **screenshot.rs**：`ui.screenshot` 的 PNG 编码与落盘（§1）。

## 5. CLI（pif-ui）

```
pif-ui list                          # 本机实例（探活标注，不删）
pif-ui clean                         # 清死登记（仅明确拒绝连接的）
pif-ui snapshot files --only open_tabs   # 看一个面，还能裁剪顶层键
pif-ui exec file.open --arg path=C:/x/a.md   # CLI 组 JSON，免三层转义
pif-ui exec session.send '{"text":"..."}'    # 手拼 JSON 仍可用
pif-ui keys "ctrl-s"                 # 走真实键位表（服务端 defer 派发）
pif-ui exec input.focus '{"target":"git_commit"}'   # 元素级聚焦
pif-ui shot                          # 截最近一帧 → automation/shots/，回 JSON
pif-ui shot D:/tmp/x.png             # 指定输出路径
pif-ui wait --path session.agent_running --eq false --timeout 60
pif-ui wait --path app.focused --eq git_commit     # 焦点类断言
pif-ui wait --path files.open_tabs[0].dirty --truthy
pif-ui wait --path session.messages.tail[0].text --contains "完成"
```

- 全局旗标只认**子命令之前**（`--pid/--addr/--token/--timeout`）。
- `wait` 成功只打印命中值（全量快照可到 MB 级，超时错误的最后快照也截断到
  1.5KB）；轮询在客户端做，服务端不背状态。断言三选一：`--eq`（相等）/
  `--contains`（JSON 字符串化后包含）/ `--truthy`（非空非假）；路径支持
  对象键与数组下标（`a.b[0].c` 与 `a.b.0.c` 等价）；`--surface` 限定轮询面。
- `exec --arg k=v`：值合法 JSON 则按 JSON、否则字符串——Windows 反斜杠路径
  的「bash×JSON×路径」三层转义地狱的出口；**路径建议正斜杠**。
  `--params-file f.json` 整个 params 从文件读。
- 输出忽略 EPIPE（接 `head` 不 panic）。

## 6. 使用范式

事务式断言：`exec` → `wait` → `snapshot` 读 JSON 断言，全程 bash + 文本。
文本输入一律直调 setter（`composer.set_text` / `session.send`）——**不做逐字
KeyDown 打字**：gpui-component 的文本进的是 IME/替换路径，`InputState::
on_key_down` 只管光标闪烁，逐字模拟不可靠。快捷键语义用 `input.keys`。

焦点类验证：`input.focus {"target": "composer|chat|git_commit|terminal|editor"}`
元素级聚焦（非坐标点击），配合 app 面的 `focused` 字段（composer/chat/
dialog/git_commit/ext_input/terminal:N/editor/other）即可脚本化断言「焦点该
在哪、有没有被抢」。`editor` = 当前打开文件的 CodeEditor（Ctrl+F 搜索条等
「焦点在编辑器才生效」的键位/弹层断言入口）。

终端键入验证：`terminal.open`（新开一个工作区终端 tab 并前置——不复用已有
终端）→ `input.keys`（真实键位表合成按键）→ `snapshot term` 断言网格回显。

## 7. 测试策略

- 协议编解码与实例发现单测在 pi-link（仓库铁律：协议/路径测试都在
  pi-link）：hello/auth 往返、垃圾行忽略、未知 type 保留、实例文件乱序/
  坏文件、判死只认 ConnectionRefused。
- CLI 对假 TCP 服务对测握手/认证失败/错误响应路径。
- 实机断言走隔离 `PI_FLASH_DIR` 实例（可与用户实例并存），范式见
  `.agents/skills/pi-flash-ui-test/SKILL.md`。

## 8. 边界与后续

- **a11y**：gpui 0.2.2 无 a11y 树，`inspector` feature 不是自动化出口；升级
  gpui 时可 backport 新版 AccessKit 元素树，顺带把「元素几何进 snapshot」
  （tab 宽度/区域 bounds）补上。
- MCP 包装：CLI 之上的薄层，按需再加；协议层不动。
