# UI 自动化测试框架（应用内自动化服务）

给 agent 用的应用内桌面自动化测试框架：**数据化界面（JSON 快照）+ 进程内操作
（方法直调 / 合成按键）**，让 agent 调试 UI 全程只发 bash 指令、读文本结果，
不与用户争抢真实屏幕/鼠标/键盘。2026-10-07 落地，bead pi-flash-2kq。

模块代码：`crates/pi-link/src/automation.rs`（协议 + 实例发现，测试在此）、
`crates/pi-link/src/bin/pif-ui.rs`（CLI 驱动器）、`crates/app/src/automation/`
（服务端三件套 mod/handlers/snapshot）。

## 0. 为什么要有这一层（现状问题）

- 桌面端没有 DOM：gpui 每帧重画、无保留元素树，外界「看 UI」只能截屏。
- agent 截屏 = 抢屏幕；模拟点击 = 抢鼠标；用户和 agent 互踩。
- 截屏还要视觉模型猜像素，断言脆弱；且窗口被遮挡/最小化即失效。

**定案（用户确认）**：无头截图 gpui 0.2.2 无窗口内容回读 API → **不做**，纯视觉
问题（颜色/布局错位）留给人工；驱动接口选 **CLI**（agent 天然跑 bash，MCP 留作
以后薄包装）；v1 能力 **全量**：快照 + 命令 + 合成键盘。

> **修订（pi-flash-0uq，2026-10-08）**：截图做了——但不走无头路线。把 zed main
> 的 D3D11 staging 纹理回读（`Window::render_to_image`，约 100 行）移植进
> vendored gpui，暴露 `ui.screenshot` op + `pif-ui shot`。进程内、不抢屏、
> 窗口被遮挡/最小化也能截，像素即 gpui scene 输出（合规于「禁止 OS 截图」）；
> 帧语义与边界见 §9。vendor 升级时需重放此补丁（同 IME/剪贴板补丁惯例）。

## 1. 核心洞察：这个 app 不需要像素树

- `Chat`/`SessionRuntime` 字段全 `pub(crate)`，**UI 状态即数据**——快照直接读
  实体字段产 JSON，比像素树稳、比 a11y 树便宜（设置页 `SettingsFormData::snapshot`
  是现成先例）。
- app 是**方法调用驱动**的 shell（全仓只有 4 个 composer action）——「执行界面
  指令」直调 Chat 方法就是真实用户路径（`send_input` 就是回车键走的函数），
  不需要坐标点击。
- gpui 0.2.2 生产 API 有 `Window::dispatch_keystroke` / `dispatch_event`——合成
  按键走真实键位表→action 路径，快捷键行为可测。

原则：**数据优先于像素；方法直调优先于事件模拟**。坐标点击、通用元素树、
a11y 树全部不需要（升级 gpui 时可 backport，见 §9）。

## 2. 架构与线程形制

```
agent(bash) → pif-ui CLI(pi-link bin)
  → TCP 127.0.0.1 NDJSON: {id, method, params} / {id, ok, result|error}
    → app/src/automation: TcpListener 线程 + 每连接读线程（握手后把请求行
      推 futures unbounded channel）+ 每连接写线程
      → cx.spawn 泵把请求逐条搬回主线程（同 session/runtime.rs attach_pump 形制）
        → snapshot 读 Chat/SessionRuntime 字段 / handlers 直调方法 /
          window.dispatch_keystroke 合成按键
```

- **开关**：`PI_FLASH_AUTOMATION=<port|auto|1>`，缺省关闭。绑定只落 127.0.0.1，
  token 握手防误连（时间+pid+栈地址熵两次 DefaultHasher，本地防误连用，非安全边界）。
- **实例发现**：`<配置目录>/automation/<pid>.json` {pid,port,token,started_at_ms}。
  多实例 CLI 选最新探活成功者；服务启动时探活清理死登记；CLI 发现时顺手清。
  `PI_FLASH_DIR` 隔离整套配置（并行实例互不干扰）。
- **韧性**：分发全程 catch_unwind——自动化触发的 panic 回 `internal` 错误响应，
  不许带崩 app；泵不因单次窗口更新失败而死。

## 3. 线协议（NDJSON，一行一记录）

连接时序：服务端先发 `hello{proto,app,pid,version}` → 客户端 `auth{token}` →
`auth_ok` 后进入请求循环。记录对齐 protocol.rs 手写风格：坏行忽略（读方
continue 不断连）、未知 type 落 `Unknown` 不静默丢（线协议漂移排查靠它）。

- 请求 `{"id","method","params"}`（params 缺省 `{}`）；响应
  `{"id","ok":true,"result"}` / `{"id","ok":false,"error":{code,message}}`。
- method 常量表 = **op 清单唯一事实源**（`pi_link::automation::method`），
  CLI 与服务端共用防漂移。
- v1 surface：`app | sessions | session | composer | files | git | settings |
  dialogs`（`ui.snapshot` 的 params.surface，缺省 = 全部概要）。
- v1 op（28 个）：app.info / ui.snapshot / app.quit / theme.set / lang.set /
  input.keys；session.new/open/switch/delete/send/steer/followup/abort；
  composer.set_text；panel.dock；content.view；file.open；files.toggle_dir；
  project.switch；git.stage/unstage/commit/push/refresh/set_tab；
  settings.open/close；dialog.close。
- 0uq 增补：`ui.screenshot`（params `{path?}` 缺省写
  `<配置目录>/automation/shots/`；返回 `{path,width,height,bytes}`）——vendor
  gpui 渲染回读，非 OS 抢屏，详见 §9。

## 4. 服务端三件套（crates/app/src/automation/）

- **mod.rs**：listener + 握手 + 读/写线程 + `cx.spawn` 泵 + catch_unwind 分发 +
  实例文件生命周期。
- **snapshot.rs**：8 个 surface 只读函数。纪律：**只读字段与既有 read API，
  绝不为快照改状态**；消息尾部取 20 条（role + 文本预览 + 工具调用计数），
  长文本截断。
- **handlers.rs**：op → 直调 Chat 方法分发表。改状态 op 一律 `cx.notify()`
  收尾（GPUI 铁律：状态变 UI 动）。git.stage/unstage 的错误回写
  `chat.git_error`（与 UI 按钮同一状态出口），commit 走 `git_commit_input` +
  `git_commit_staged`（不绕过 UI 校验路径）。

## 5. CLI（pif-ui）

```
pif-ui list                          # 本机实例（探活标注，不删）
pif-ui clean                         # 清死登记（仅明确拒绝连接的）
pif-ui snapshot files --only open_tabs   # 看一个面，还能裁剪顶层键
pif-ui exec file.open --arg path=C:/x/a.md   # CLI 组 JSON，免三层转义
pif-ui exec session.send '{"text":"..."}'    # 手拼 JSON 仍可用
pif-ui keys "ctrl-s"                 # 走真实键位表（服务端 defer 派发）
pif-ui exec input.focus '{"target":"git_commit"}'   # 元素级聚焦
pif-ui shot                          # 截最近一帧 → automation/shots/，回 JSON
pif-ui shot D:/tmp/x.png             # 指定输出路径
pif-ui wait --path session.agent_running --eq false --timeout 60
pif-ui wait --path app.focused --eq git_commit     # 焦点类断言
pif-ui wait --path files.open_tabs[0].dirty --truthy
pif-ui wait --path session.messages.tail[0].text --contains "完成"
```

- 全局旗标只认**子命令之前**（`--pid/--addr/--token/--timeout`）——`--timeout`
  曾被全局与 wait 双重声明截走（冒烟暴露的坑）。
- `wait` 成功只打印命中值（全量快照可到 MB 级，超时错误的最后快照也截断到
  1.5KB）；轮询在客户端做，服务端不背状态。断言三选一：`--eq`（相等）/
  `--contains`（JSON 字符串化后包含）/ `--truthy`（非空非假）；路径支持
  对象键与数组下标（`a.b[0].c` 与 `a.b.0.c` 等价）；`--surface` 限定轮询面。
- `exec --arg k=v`：值合法 JSON 则按 JSON、否则字符串——Windows 反斜杠路径
  的「bash×JSON×路径」三层转义地狱的出口；**路径建议正斜杠**。
  `--params-file f.json` 整个 params 从文件读。
- 输出忽略 EPIPE（接 `head` 不 panic）。

## 6. 使用范式（AGENTS.md「UI 自动化测试」节同源）

事务式断言：`exec` → `wait` → `snapshot` 读 JSON 断言，全程 bash + 文本。
文本输入一律直调 setter（`composer.set_text` / `session.send`）——**不做逐字
KeyDown 打字**：gpui-component 的文本进的是 IME/替换路径，`InputState::
on_key_down` 只管光标闪烁，逐字模拟不可靠。快捷键语义用 `keys.send`。

焦点类验证：`input.focus {"target": "composer|chat|git_commit|terminal"}`
元素级聚焦（非坐标点击），配合 app 面的 `focused` 字段（composer/chat/
dialog/git_commit/ext_input/terminal:N/other）即可脚本化断言「焦点该在哪、
有没有被抢」。

## 7. 测试策略

- 协议编解码单测在 pi-link（仓库铁律）：hello/auth/请求响应往返、垃圾行 None、
  未知 type 保留、实例文件乱序/坏文件——5 测。
- CLI 对假 TCP 服务（node 一分钟脚本）对测握手/认证失败/错误响应路径。
- 实机冒烟（隔离 `PI_FLASH_DIR` + 临时工作区，与用户实例并存）：list 发现→
  info→type→snapshot 回读→session.new→panel.dock→files.toggle_dir（b.txt
  depth 2）→file.open（content_view=file）→settings.open/close→keys（
  dispatched=false 如实上报）→错误路径 exit 1→wait 命中/超时→app.quit 干净
  退出、死登记自动清理。
- 回归：`cargo test` pi-link 119 + app 119 全绿。既有 2 个 `#[gpui::test]`
  无头测试路线（vlist/chat_list）不受影响、不扩大。

## 8. 已知坑（写给下一个改这里的人）

- 本 vendored gpui 的 `window.update` / `chat.update` **不做 Flatten**——
  catch_unwind 包出来是
  `Result<Result<Result<Result<Value,(code,msg)>, anyhow::Error>, anyhow::Error>, Box<dyn Any>>`
  四层（`let _: () = outcome;` 探针让编译器报型确认）；别照抄 Zed 上游的
  Flatten 签名直觉。
- gpui 0.2.2 无 a11y 树：`inspector` feature 不是自动化出口。窗口内容回读
  0uq 已补（vendor 补丁，见 §0 修订）；bump gpui 时记得重放。
- `Chat::rt()` 内有 `expect`——快照侧必须先判 `runtimes.contains(active_key)`
  再读，异常路径回结构化错误（catch_unwind 兜底但别依赖它）。
- `input.keys` 必须 `window.defer` 后再 `dispatch_keystroke`：keystroke 进
  真实 UI 事件链（输入框/弹层回调里 weak.update Chat），在 chat.update 内
  同步派发必触发 entity_map 重入断言（004 项目菜单弹窗 ESC 首次暴露）。
- **token 只存在登记文件里**——登记误删 = 实例永久失联。两道防线（v1.1）：
  判死只认 `ConnectionRefused`（`port_is_definitely_dead`，超时/Winsock
  起不来等一律保守保留；实测踩坑：探活方缺 `SystemRoot` 时 Winsock 报错而
  实例活着）；启动日志行带 `token=`，丢了登记还能 `--addr/--token` 直连救回。

## 9. 边界与后续

- **截图（0uq 已做）**：`ui.screenshot` 截的是**最近一次绘制**的帧——
  `exec` 改状态后紧跟 shot 可能差一帧，使用模式是先 `wait` 后 shot（或隔
  一次 CLI 调用，泵在主线程逐条处理，帧间通常已刷新）。PNG 编码在主线程
  （2K 窗口约百 ms 冻结，测试场景可接受）。透明/模糊窗口的 alpha 通道
  未验证（pi-flash 主窗不透明）。vendor readback 拍不到 OS 级装饰
  （标题栏/阴影是 DWM 的，不在 gpui scene 里）。
- **bead pi-flash-q9f**：settings.set/save（设置页表单直改+保存）、
  terminal.write（终端注入）、事件推送订阅（SessionEvent，免轮询）——协议已留位。
- **bead pi-flash-0kq**：升级 gpui 时 backport 新版 AccessKit a11y 树 +

## 10. v1.1 反馈轮修订（2026-10-07，首轮 agent 实战反馈六条全修）

1. **误删活登记**：判死收紧为只认 `ConnectionRefused`（`port_is_definitely_dead`，
   CLI discover/list/clean 与 app 启动 prune 统一走它）；token 进启动日志行，
   登记丢了可 `--addr/--token` 救。
2. **Windows 路径转义地狱**：`exec --arg k=v`（值合法 JSON 则 JSON、否则
   字符串，可重复覆盖）+ `--params-file`；文档明示路径用正斜杠。
3. **焦点原语缺失**：`input.focus {"target": ...}` 元素级聚焦（composer/
   chat/git_commit/terminal；`window.focus` 无同步回调可直调）+ app 面
   `focused` 字段（逐句柄 `is_focused` 比对，未登记者报 "other"）。
4. **wait 太弱**：路径支持数组下标 `[N]`；断言 `--eq/--contains/--truthy`
   三选一；`--surface` 限定轮询面；超时错误的最后快照截断 1.5KB。
5. **snapshot 太肥**：`snapshot <surface> --only k`（服务端 params.only
   过滤顶层键，可重复）。
6. **死登记窗口期**：`pif-ui clean` 手动清场（同一判死规则）；`list` 只标注
   不删；discover 跳过死候选而不是停下来报错。

实战确认好用的（保留）：事务范式（exec→wait→snapshot 纯文本断言）、method
常量单源、catch_unwind 不崩 app、agent 侧自加 op 的路径（defer 修复即其产物，
已并入主线）。
