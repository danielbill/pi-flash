软件分发模块：一条安装命令完成下载与更新。

模块代码：distribution

---

## 0. 目标与边界

用户一条命令完成**首次安装**，以后**更新也是同一条命令**：

```bash
npm install -g pi-flash@latest   # 没装 = 首次安装；装过 = 更新
pi-flash                          # 启动
npm uninstall -g pi-flash         # 卸载（载荷在包目录内，一并清除）
npx pi-flash@latest               # 不常驻安装直接跑
```

- **方案**：npm 薄壳包（`npm/` 目录）+ 载荷走 GitHub Releases 下载；版本三处（`crates/app/Cargo.toml` / git tag / `npm/package.json`）由 release.sh 单点同步
- **用户侧门槛**：机器有 Node ≥ 22.19（启动器启动时校验，见 §3.1）
- **平台**：仅 Windows（win32-x64）；**不发布 macOS 版本**
- **不做**：PowerShell/curl 安装脚本、winget（无 Node 用户的后续通道）；`cargo install`（vendored gpui + `[patch.crates-io]`，分钟级编译，排除）
- **应用内自动更新**：已落地（2026-10-11，`docs/模块设计/081-软件自动更新.md`）——
  exe 后台下载新载荷到 staging，薄壳启动时 swap（§3.1 第 2 步）；下载源/SHA-256
  语义与本章同构，戳比包版本新不降级（§3.1 第 3 步）

## 1. 设计取舍

为什么用"薄壳 + 下载"而非把载荷全塞进 npm 包：载荷裁剪后解压仍 ≈310 MB、压缩 ≈120 MB
（`pi-flash.exe` 70 MB + 内置 node 93 MB + `vendor/pi` 裁 esbuild 后），大包 publish 易超时、
npmmirror 同步慢、回滚时旧大包撑爆 packument。薄壳只有几 KB，安装/更新/卸载/回滚/缓存
全部复用 npm 语义，载荷走 GitHub Releases（Azure CDN）。

先例：electron（主包 1.17MB，postinstall 下 zip）、`@openai/codex`（主包 13KB + 平台载荷）、
`@biomejs/biome`（optionalDependencies 平台子包）、playwright/puppeteer（postinstall 下浏览器）。
**npm 只当"带版本管理的下载器"，exe 本体不认识 npm。**

## 2. 包结构（`npm/` 目录入库，随 release 发布）

```
npm/
├── package.json          # name: pi-flash, version: = Cargo 版本（release.sh 同步）
│                         # bin: { pi-flash: bin/pi-flash.js }
│                         # scripts: { postinstall: "node bin/fetch-payload.js" }
│                         # engines: { node: ">=22.19.0" }
├── bin/
│   ├── pi-flash.js       # 启动器（见 §3.1）
│   ├── fetch-payload.js  # 下载器 CLI 入口（postinstall 调用；见 §3.2）
│   └── lib.js            # 共享逻辑（探测/下载/校验/解压/落位）
├── test/
│   └── e2e.js            # 本地回环端到端自测（node npm/test/e2e.js，见 §5）
└── README.md
```

## 3. 运行机制

### 3.1 启动器 `bin/pi-flash.js`

1. Node 版本检查（低于 22.19 友好报错退出）
2. **应用内更新落位（081）**：`<pkg>/update-staged.json` 标记存在且 staging
   完整 → `payload.stage-<ver>` rename 成 `payload/`（旧实例占用则本次跳过，
   标记留给下次）；无标记即零成本直过
3. **自愈检查**：`payload/.payload-version` 与 `package.json.version` 语义比较
   （081 起戳比包版本**新** = 应用内更新先行，不重下；更旧/缺失 → 调同一份
   下载逻辑补齐，兜底 `--ignore-scripts`、镜像剥 postinstall、半途断网）
4. `spawn(payload/pi-flash.exe)`，转发信号、透传退出码
5. 更新时旧实例运行导致目录锁（EBUSY）→ 提示"请先退出正在运行的 pi-flash 再执行"

### 3.2 下载器 `bin/fetch-payload.js`

1. **平台探测**：`process.platform` + `process.arch` → 仅支持 `win32-x64`，其他平台明确报错
2. **下载源**：`https://github.com/danielbill/pi-flash/releases/download/v<ver>/pi-flash-<ver>-<platform>.zip`；
   环境变量 `PI_FLASH_MIRROR` 可整体覆盖（国内镜像/自建回退口）
3. **校验**：取用顺序 `<资产>.sha256`（资产级 sidecar，release.sh 生成，按资产名隔离）
   → `SHA256SUMS`（汇总兜底）。比对不过即删下载文件、退出非零
   （让 npm 报错，不装半截）；两个文件都找不到对应行也报错并给 release 页链接。
4. **原子落位**：解压到 `payload.tmp-<pid>` → rename 为 `payload/` → 最后写 `.payload-version`
   （崩溃自愈靠"无版本戳 = 重下"）
5. 下载失败自动重试（有限次 + 退避）；暂不支持 Range 断点续传

## 4. 发布流水线（`scripts/release.sh` + CI）

```bash
# ① 裁非宿主平台 esbuild（仅保留 win32-x64）
ESBUILD_DIR="dist/pi-flash/vendor/pi/node_modules/@earendil-works/pi-coding-agent/node_modules/@esbuild"
for d in "$ESBUILD_DIR"/*; do [[ "$(basename "$d")" == "win32-x64" ]] || rm -rf "$d"; done

# ② 生成 SHA256SUMS + 上传 Release 资产
(cd dist && sha256sum "$ZIP_NAME" > SHA256SUMS)
gh release create "v$VERSION" --verify-tag --title "v$VERSION" \
  --notes-file "$NOTES_FILE" "dist/$ZIP_NAME" "dist/SHA256SUMS"

# ③ npm 版本对齐 + 发布（三处版本单点同步，禁止手改两处）
npm version "$VERSION" --no-git-tag-version --prefix npm
```

- 资产命名 `pi-flash-<版本>-win32-x64.zip` + `<资产>.sha256`（平台入名，薄壳靠它解析）
- 顺序：烟测通过 → 裁剪 → 打资产 → npm publish；任一步失败即中止，不发半套
- 裁 esbuild 的正确性由发版门禁保证：pi-link 符合性测试 + 依赖 esbuild 的插件 bundling 真机路径

### 4.1 npm 发布：OIDC trusted publishing（publish-npm.yml）

长效 token 与 2FA 的矛盾用 OIDC 一步到位（npm 官方终态，2027-01 起 bypass token
直发被移除，OIDC 不受影响）：

- `.github/workflows/publish-npm.yml`：tag `v*` 触发，`id-token: write`，
  node 24 + npm ≥11.5.1，`npm/` 目录直接 publish（零依赖零构建）；
  自动附 provenance 供应链签名；文件名即信任配置的逐字凭据
- **首发例外（npm/cli#8544）**：npm 不支持 OIDC 发首版（配置入口在包 Settings 页，
  包不存在则无页面）→ **首发必须手动一次**：`cd npm && npm publish`（浏览器 2FA）
- Trusted Publisher 配置：npmjs → pi-flash → Trusted Publisher → GitHub Actions →
  `danielbill/pi-flash` + `publish-npm.yml` + **Allowed action 勾 `npm publish`**
  （新建 Trusted Publisher 默认只给 stage publish，须手动勾选）；**配置后 2 天内须有一次
  成功发布完成绑定**，否则过期删除重建——故选在下次正常发版前 2 天内配置
- 终态加固（OIDC 验证成功后）：npmjs → Package Settings → Publishing access →
  "Require two-factor authentication and disallow tokens"——长效 token 彻底禁用

## 5. 本地自测

```bash
node npm/test/e2e.js
```

本地回环端到端，19 项断言，覆盖薄壳可离线验证的全部行为：安装、启动透传、
三种自愈场景（缺 payload / 版本不符 / `--ignore-scripts`）、SHA256SUMS 兜底、
损坏下载拦截、更新、快路径。改动 `npm/` 后必须跑绿。

## 6. 已知限制与注意事项

| 事项 | 说明/处置 |
|---|---|
| Windows Node 装在 `Program Files`，`npm i -g` 要管理员权限 | 文档标注 + 提示 `npm config set prefix` 或提权；无 Node 用户走后续通道（安装脚本/winget） |
| `--ignore-scripts` / 镜像剥 postinstall | 启动器首启自愈（§3.1-2），双保险 |
| GitHub Releases 国内慢/失败 | 重试 + `PI_FLASH_MIRROR` 回退；必要时默认候选列表加镜像 |
| 载荷传输损坏/被篡改 | SHA256SUMS 不符即失败重下 |
| 更新时旧 exe 运行锁目录 | 捕获 EBUSY → 提示先退出实例 |
| SmartScreen/杀软报警 | 与安装方式正交；长期解 = 代码签名（单列技术债） |
