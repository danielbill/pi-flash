模块代码：sessionNavPanel 033

功能对齐 pi-web。

## 功能

- 每轮对话生成一次摘要：用户发言前 50 字 + Agent 首条有正文回复的首行前 50 字
- 给每轮摘要编号 01、02…顺排全部轮次
- 摘要卡片式顺序排列，点击卡片会话重定位到相应位置
- 导航竖条 gutter（`session/nav_panel/gutter.rs nav_gutter`，挂会话区右缘）：
  命中区宽 9px（段体左缘 5px 实体 + 右侧 4px 透明可点）；rail 屏高 75%，
  轮次均分切割整条（1 轮 = 整条弱主题色、N 轮切 N 段，flex_1 等分 + 2px 缝），
  10 轮后段高不再缩小（`TICK_MAX = 10`），>10 轮走百分比桶映射（轮 k 命中段
  k×10/N，点击段回桶首轮）；每次生成新段整体重新居中（屏高 − composer 高度
  ×50% 后居中）
- 段样式：弱 accent 填充（α0x3d）常驻；当前定位段与 hover = accent 实色
  填充（无边框方案，无尺寸跳动）
- 悬浮竖条向左弹出导航面板（topbar 之下 100% 高、宽 500px，下缘与 composer
  底线对齐）：顶部总结栏 + 轮次摘要卡片列表，内容过多时右缘显示滚动条
- 总结栏（高 36px，不随滚动）：【icon 数字】四组——消息icon 总数：用户icon
  x、助手icon y、工具icon z（lucide message-square-text / user-round /
  bot / wrench；N = x+y+z），无文案不走过 i18n；尺寸全对 UI组件规范令牌
  （icon MD16、图标↔数字 gap SP4、组间 gap SP5、数字 ui(11)，色 text_dim）；
  整包 1px accent 描边 + 5px 圆角，字体族跟随「面板」槽位设置

## 当前实现

布局（`nav_gutter`）：

- gutter 命中区 9px = 段实体 5px + 右 4px 透明可点（不贴窗口边；透明区与
  实体同权命中）；rail 屏高 75%（`relative(0.75)`），挂 `mb(0.5×composer高)`
  由 flex 连 margin 盒居中——视觉中心正好上移 composer/4，即「屏高 −
  composer 高度×50% 后居中」。composer 高度用 `chat.composer.composer_h`
  每帧实测（读到上一帧值，滞后一帧无感）
- 段生成：轮次均分切割，flex_1 等分 + 2px 缝；≤10 轮逐轮一段，>10 走百分
  比桶映射（10 段）：正向 `turn_of_tick(i) = floor(i·N/k)`（i·N/k 取整），
  逆向 `tick_of_turn(t) = floor(((t+1)·k − 1)/N)`（clamp k−1）——与正向边
  界自洽的包含式逆映射
- 段样式：弱主题色常驻（accent α0x3d 填充）+ 圆角 2；选中/hover = accent
  实色填充

选中语义：

- 选中段 = 真实定位轮次。无点击时按「视口顶之上最近轮」推导；贴底（含未
  滚动短会话）逻辑位是 None、`scroll_top_ix` 回退成总条目数 → 自然选中末
  段（对话常态在末轮）。**不能**用 pager.is_at_bottom 推导——那是滚轮回
  调维护的 Cell，程序化定位不经过它
- 点击卡片/段 → `pager.nav_goto(turn, item_ix)`：目标条目置顶 + 钉住被点
  轮次（Core::nav_pinned）。钉住原因：目标靠尾部时下方内容不足填满视口，
  gpui list 的贴底钳制会向上补条目并改写 logical_scroll_top，按位置推导
  会错选上一段；物理滚轮清除钉住，交还位置推导
- 程序化定位不触发任何 notify——点击处理器须 `window.refresh()` 当帧重绘
- 卡片 hover 只在 enter 置位、leave 不清（gpui 鼠标事件 bubble 阶段按绘制
  逆序派发，向下移动时上一张卡的 leave 在下一张卡 enter 之后触发会误清），
  统一由面板 on_hover(false) 清理

悬浮面板：

- 弹出触发区 = `nav-rail-hit`（rail 垂直带：屏高 75% + composer 偏移 ×
  gutter 全宽 9px 含右侧 4px 透明区）。on_hover 挂这层而非 gutter 全高
  （rail 上下方空白区会误触）也非 rail 本体（右侧 4px 成死区，鼠标得精准
  压中 5px 段体）
- 整包 wrap（absolute，right 9 与段左缘齐平，bottom = `footer_bar::BAR_H`
  与 composer 底线对齐）= 总结栏 36px 固定 + 卡片滚动区 flex_1；1px accent
  描边 + 5px 圆角挂 wrap（子元素方角由 overflow_hidden 裁进圆角）；悬停
  保持打开的 on_hover 挂整包 wrap（鼠标挪到总结栏不算离开，否则 250ms
  宽限一到面板就收）
- 卡片列表虚拟化：gpui `list()`，`nav_flyout_list`（ListState）存 Chat 的
  layout（跨开合保持滚动位，轮次数变化时 reset），每帧只建可视卡片 ~20 张；
  水平 padding（pl 6 / pr 14）挂外层容器（List 条目只认上下 padding），
  pt/pb 8 挂 list 本体；滚动区背景同左 dock（t.nav）
- 滚动条：`ui::list_handle::ListStateHandle` 把 ListState 的 scrollbar 协
  作接口（负 y 约定与 ScrollHandle 一致）适配成 gpui-component 的
  ScrollHandleOffsetable，组件滚动条（含拖拽）原样可用；仅实际溢出渲染，
  absolute 兄弟层锚在滚动区（top 44 = 总结栏 36 + list pt 8，right 3、宽 8）
- 段 → 面板联动：点段除消息定位外，面板 `scroll_to_reveal_item` 到该段区域
  起始卡（卡序号 = 轮序号）
- 卡片：编号列 25px 右对齐（mono、ui(10)、行高 1.7）+ 用户摘要
  面板字号 −1（ui(11)、不加粗、`line_clamp(3)` 按行数钳制，硬换行已在
  `plain_text_prefix` 拍平）+ A 行 agent 摘要 ui(10)（text_dim、单行
  ellipsis）——两行同构（25px 右对齐标号列 + gap 9），A 对齐编号、正文对
  齐用户正文；行点击 nav_goto 定位
- 第三行（子代理）：该轮有子代理时画 `[bot] ●●●●` 点阵（点数 = 该轮子代理
  数、7px 圆点色取会话运行结果青/红点、缩进 34 与 A 行正文起点对齐），
  数据 = NavData.turn_agents

数据（runtime `nav.rs`）：

- `NavData { turns, turn_agents, users, assistants, tool_calls }` 存
  SessionRuntime：`notify_list`（一切消息变化的必经点）置脏，`nav_summary()`
  惰性重建返回 Rc——摘要与统计「一轮一次」，渲染帧零重算
- 摘要：用户前 50 字 + agent 首条有正文回复首行前 50 字（定位器不是会话
  副本；agent 首行探测先取前 80 字再截首行）；`Msg::plain_text_prefix(N)`
  只拼前缀，避免全量 join 长回复
- 统计口径 N = 用户 + 助手 + 工具调用（ToolCall 块级计数，custom/bash 卡
  不计）。自洽口径，非 pi-web totalMessages——那条把 toolResult/system 条
  目也计入，本工程 toolResult 合并进 ToolCall 块、system 入库即跳过，两边
  数字本就对不上
- turn_agents 点阵读内存账本（事件流增量维护），不扫消息反推——扫消息看
  不见 codemode 嵌套派发
