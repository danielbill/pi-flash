功能：
- 每轮对话生成一次摘要： 用户发言前50字+Agent回复前50字
- 给每轮摘要编号 01 - 99
- 摘要卡片式顺序排列，用户点击卡片会话重定位到相应位置
- 导航栏垂直竖条【导航刻度条】，占据屏幕高度75%，宽12px，每次生成摘要时，居中生成一个2px高10px宽，左右padding 4px的【轮次刻度】，生成新刻度时，整体重新居中（屏幕高度 - inputpanel高度*50% 后居中），刻度之间间隔4px
- 鼠标悬浮在导航刻度条时，向左弹出导航面板，高topbar之下100%, 宽度400px，顺序罗列【轮次摘要卡片】，内容过多时有滚动条
- 轮次摘要卡片使用现有样式，但Agent回复，A要和轮次编号对齐，内容要和用户内容对齐

待讨论：
- 性能问题：导航栏做缓存池，先进先出，缓存5个导航，优先用户激活会话，而非后台更新会话，即用户频繁打开优先后台agent跑长程任务频繁updated的，由于用户不看反而不重要
- 上百轮对话要如何加载导航栏 ，是否要使用分页技术？（当前策略：刻度条 overflow_hidden 居中裁剪，>150 轮视觉溢出待定）

实现记录（v63 / v63-1）：
- 编号不截断：全部轮次 01、02…顺排（v54 旧版只显示最近 10 个已废弃）
- 刻度规格（v63-1 定稿）：2px 高 × 10px 宽，行 = 刻度 + 左右 padding 4（18×6 命中区），间隔 4px；当前定位轮 accent 12px（条全宽）
- 居中规则（v63-1）：屏高 75%，按「屏高 − inputpanel 高度×50%」居中——rail 挂 mb(0.5×composer高)，flex 连 margin 盒一起居中，视觉中心上移 composer/4；composer 高度用 ui::measure_height 每帧实测（读上一帧值，一帧滞后无感）
- 选中语义（v63-1 定稿）：刻度选中 = 真实定位轮次——贴底（含未滚动短会话）= 最后一轮（对话常态在末轮，末刻度常态选中），上翻 = 视口顶之上最近轮；点击卡片/刻度改写滚动位置后选中随之走
- 摘要取数：plain_text_prefix(N) 只拼前 N 字符，避免每帧全量 join 长回复
- 滚动条：gpui-component Scrollbar 挂滚动容器平级的 absolute 兄弟（容器内绝对定位子元素会随内容滚走），仅 max_offset>0 渲染
- 卡片 hover 只在 enter 置位、leave 不清：gpui 鼠标事件 bubble 阶段按绘制逆序派发，向下移动时上一张卡的 leave 在下一张卡 enter 之后触发会误清选中框（v63 修）

当前bug（v63-2 已修）：
- 被选中刻度不应该是卡片选中框对应刻度，选中框是随意滑动的，只有点击后才重新定位，而定位后的轮次才是选中的刻度，正常因为对话总在最后一轮，所以总算最后一个刻度被选中
  ——根因：刻度与卡片共用 sel = nav_hover_turn.or(active_turn)，悬浮卡片即改刻度。修法：解耦，刻度只看 active_turn（真实滚动位置 + 贴底=末轮），卡片选中框只看 nav_hover_turn
- 重新定位后刻度没有相应变化（v63-1 引入的两处坑）
  ——① active_turn 信了 pager.is_at_bottom：那是滚轮回调维护的 Cell，程序化 scroll_to_reveal_item 不经过它，点击导航后仍是 true → 刻度错停末轮。修：去掉该分支，纯 rposition（贴底时逻辑位是 None，scroll_top_ix 回退成总条目数，自然选中末轮）
  ——② 程序化定位不触发任何 notify，且 scroll_to_reveal_item 向下跳是「目标底边贴视口底」，视口顶落进上一轮内容，active 判定算到前一轮。修：pager 新增 nav_goto（目标置顶 + at_bottom 补正 false，jump_to_bottom 同款维护），三处点击改用它并 window.refresh() 当帧重渲染
