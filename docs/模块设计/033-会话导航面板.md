模块代码：sessionNavPanel 033

功能对齐 pi-web，UI 重新设计。

## 功能

- 每轮对话生成一次摘要：用户发言前 50 字 + Agent 回复前 50 字
- 给每轮摘要编号 01、02…顺排全部轮次
- 摘要卡片式顺序排列，点击卡片会话重定位到相应位置
- 导航栏垂直竖条：屏高 75%，宽 12px + 右侧 4px 呼吸位；轮次均分切割整条
  （1 轮 = 整条弱主题色、N 轮切 N 段），20 轮后段高不再缩小；每次生成新段
  整体重新居中（屏高 − inputpanel 高度×50% 后居中）
- 悬浮竖条向左弹出导航面板（topbar 之下 100%、宽 400px）：顶部总结栏 +
  轮次摘要卡片列表，内容过多时有滚动条
- 总结栏（高 32px，不随滚动）：【N条消息：用户x条 助手y条 工具调用z次】，
  N = x+y+z

## 当前实现

布局（session/mod.rs `nav_gutter`）：

- 竖条 gutter 16px = 段 12px + 右 4px 呼吸位；rail 屏高 75%，挂
  `mb(0.5×composer高)` 由 flex 连 margin 盒居中——视觉中心正好上移
  composer/4，即「屏高 − inputpanel 高度×50% 后居中」。composer 高度用
  `ui::measure_height` 每帧实测（读到上一帧值，滞后一帧无感）
- 段生成：轮次均分切割，flex_1 等分 + 2px 缝；≤20 轮逐轮一段，>20 走百分
  比桶映射（20 段）：正向 `turn_of_tick(i) = floor(i·N/k)`（i·N/k 取整），
  逆向 `tick_of_turn(t) = floor(((t+1)·k − 1)/N)`（clamp k−1）——与正向边
  界自洽的包含式逆映射，错一桶的两个变形（floor(t·k/N) 偏上、
  floor((t+1)·k/N) 偏下）都已排除
- 段样式：弱主题色常驻（accent α0x3d）+ 常驻 1px 边框槽位；选中 = accent
  边框（不整段覆盖），hover = accent 实色

选中语义：

- 选中段 = 真实定位轮次。无点击时按「视口顶之上最近轮」推导；贴底（含未
  滚动短会话）逻辑位是 None、`scroll_top_ix` 回退成总条目数 → 自然选中末
  段（对话常态在末轮）。**不能**用 pager.is_at_bottom 推导——那是滚轮回
  调维护的 Cell，程序化定位不经过它
- 点击卡片/段 → `pager.nav_goto(turn, item_ix)`：目标条目置顶 + 钉住被点
  轮次（Core::nav_pinned）。钉住原因：目标靠尾部时下方内容不足填满视口，
  gpui list 的贴底钳制会向上补条目并改写 logical_scroll_top，按位置推导
  会错选上一段；物理滚轮清除钉住，交还位置推导
- 程序化定位不触发任何 notify——点击处理器须 `window.refresh()` 当帧重绘
- 卡片 hover 只在 enter 置位、leave 不清（gpui 鼠标事件 bubble 阶段按绘制
  逆序派发，向下移动时上一张卡的 leave 在下一张卡 enter 之后触发会误清），
  统一由面板 on_hover(false) 清理

悬浮面板：

- 整包 wrap（absolute right 16 与段左缘齐平）= 总结栏 32px 固定 + 卡片滚
  动区 flex_1；悬停保持打开的 on_hover 挂整包 wrap（鼠标挪到总结栏不算离
  开，否则 250ms 宽限一到面板就收）
- 卡片列表虚拟化：gpui `list()`，ListState 存 Chat（跨开合保持滚动位，轮
  次数变化时 reset），每帧只建可视卡片 ~20 张；水平 padding 挂外层容器
  （List 条目只认上下 padding），pt/pb 挂 list 本体
- 滚动条：`ui::list_handle::ListStateHandle` 把 ListState 的 scrollbar 协
  作接口（负 y 约定与 ScrollHandle 一致）适配成 gpui-component 的
  ScrollHandleOffsetable，组件滚动条（含拖拽）原样可用；仅实际溢出渲染，
  锚在总结栏之下
- 段 → 面板联动：点段除消息定位外，面板 scroll_to_reveal_item 到该段区域
  起始卡（卡序号 = 轮序号）
- 卡片：编号（18px 右对齐）+ 用户摘要 11px SEMIBOLD（max 58px）+ A 行
  agent 摘要 10px——两行同构（18px 标号列 + gap 9），A 对齐编号、正文对
  齐用户正文；行点击 nav_goto 定位

数据（runtime.rs）：

- `NavData { turns, users, assistants, tool_calls }` 存 SessionRuntime：
  `notify_list`（一切消息变化的必经点）置脏，`nav_summary()` 惰性重建返回
  Rc——摘要与统计「一轮一次」，渲染帧零重算
- 摘要：用户前 50 字 + agent 首条有正文回复首行前 50 字（定位器不是会话
  副本）；`Msg::plain_text_prefix(N)` 只拼前缀，避免全量 join 长回复
- 统计口径 N = 用户 + 助手 + 工具调用（ToolCall 块级计数，custom 不计）。
  自洽口径，非 pi-web totalMessages——那条把 toolResult/system 条目也计入，
  本工程 toolResult 合并进 ToolCall 块、system 入库即跳过，两边数字本就对
  不上
