Pi-Flash中，用“扩展”指代 Pi的 “package”

代码模块： packageManager

对应界面：
1、settings - 扩展（原名：插件）
2、inputpanel  - 扩展按钮/菜单 （原 插件）

## settings - 扩展 

### 界面功能设计
- 列出所有已安装的扩展
- 可统一开启/关闭所有扩展
- 可单独开启/关闭/卸载扩展
- 支持 https://pi.dev/packages 推荐的安装命令安装新扩展， 如：`pi install npm:pi-web-access`
我们不省略 pi install 前缀，更方便用户从网页copy命令后直接黏贴执行。
安装结束后，刷新页面，更新已安装扩展列表。
注意，按安装只支持全局安装。

## inputpanel 的 扩展按钮
在管理面板中保存的设定要反映在inputpanel的扩展菜单上。
用户默认会选择一些扩展作为使用PI的基础扩展包持续生效，然后根据任务/会话选择一些扩展加入。
所以，扩展选取菜单打开时，已经开启的应该自动勾选置顶，按名称排序，去掉“npm:”前缀。

### 须支持每轮对话修改扩展配置
PI原生支持在会话中切换扩展配置，当用户切换为 chat-only、read-only等tool配置时，扩展提示词就会从系统提示词中移除。
所以，custom模式下，我们也应当支持，每轮对话开始前重新调整package list。


## 扩展说明占多少Token预览
多数用户不知道扩展包安装后可能占有大量的系统上下文空间，在扩展管理加载package信息后，在【startup-延迟加载】进程中，额外解析计算扩展说明大约消耗的token数。计算方法复用计算会话系统提示词的脚本。

注意：考虑到某些用户可能会装载几十上百个插件，此非关键过程挪入【延迟加载】

扩展说明占token在哪里预览
- settings - 扩展 - 详情，在状态行这下插入一行， 【说明大小】 xxx tokens ； 
- inputpanel - 扩展列表：列表加宽100px，右侧标注各扩展tokens（单位tokens不写），title行右侧对齐合计数【合计约：xxx 】
