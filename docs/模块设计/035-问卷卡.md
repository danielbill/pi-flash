# 问卷卡（ask_user_question 宿主渲染）

`ask_user_question` 工具的 GUI 宿主：CLI 侧装 `@juicesharp/rpiv-ask-user-question`
包，RPC 模式下它只会发 pi 的 `extension_ui_request`（select/input 两个原语），
多选被降级成"文本框手打 1,3"。问卷卡在渲染侧把降级请求拦截升维：**整卷 tab 卡、
真复选框、预览侧栏、键盘全程可操作**，包侧零改动。

模块代码：`dialogs/ask_card.rs`（状态机 + 卷/题模型 + 序列化）+
`dialogs/ask_card/`（`parse.rs` 解析、`actions.rs` 交互、`render.rs` 装配、
`widgets.rs` 渲染件）；路由入口 `dialogs/ext_ui/actions.rs::on_ext_ui` →
`ask_route_request`；浮层挂载 `session/mod.rs::main_column`（#chat-wrap 中栏）；
焦点仲裁 `shell/render/focus.rs`。

交互结构移植自 my-mastra-bot `AskCard.tsx`（tab 切题/答完标记/确认门控）。

## 协议链路

```
pi 调 ask_user_question(args.questions[])
  ↓ transcript 流
pi-flash 截获 Block::ToolCall{args}（name = ask_user_question）──→ 整卷解析
  ↓ 包开始逐题阻塞请求
extension_ui_request #N 到达 ──→ ask_route_request：title 命中题 N ──→ 挂起等用户
  ↓ 用户点「确认 [n/N]」
应答挂起请求 → 收卡（卡不销毁）→ 本卷后续请求按 title 静默自动应答
```

- **卷标识 = tool_call id**：transcript 里最近的 `ask_user_question` tool_call
  （`find_last_ask_call`，跳过 `args_partial`）的 id 是一卷的唯一标识。同一 id
  的请求都归这一卷；换 id = 开了新卷，旧卡作废（作废前旧卡挂起的请求先回
  `cancelled`，否则那条阻塞的扩展 handler 永久吊死）。
- **整卷先行**的依据：args 在 `toolcall_end` 即收全（`args_partial=false`），先于
  逐题请求可见；卡片打开即答全部题目，工具阻塞等待本来就是常态。
- **不假设「一题一请求、严格串行」**：扩展多选走 `input`、单选走 `select`，
  自定义答案还有一条 `input` 追问（rpc-fallback 的 "Type your answer:" 分支）
  ——同一题可能来两个请求。已作答的题来请求就按 title 定位后**静默应答**，
  未作答才挂起弹卡（同题重复请求以最新为准）；确认后卡收起但**不销毁**，专为
  接住本卷后续追问；换新 tool_call id 或取消时才作废。
- title 匹配（`title_matches`）：包的 title = `[header] question` + 折叠
  preview 块，用 `title.contains(question)` 判定请求↔题目对应（同文多题时优先
  未作答的那题）；不命中（其他扩展的 select/input）→ 放行走 legacy 弹窗，
  问卷卡不受影响。

## 回传契约（与包 rpc-fallback.ts 解析器严格对齐）

| 题型 | 用户作答 | extension_ui_response.value |
|---|---|---|
| 单选 select | 选中选项 i | `req.options[i]` **原行**（含 "N. label — desc" 前缀，包按行 indexOf） |
| 单选 select | 自定义文本 | 纯文本（包 `resolveSingleSelectReply` 判非选项行→custom，**免哨兵二次弹窗**） |
| 多选 input | 选项+自定义 | `"1,3; 文本"` |
| 多选 input | 仅选项 / 仅文本 | `"1,3"` / `"文本"` |
| 多选 input | 全不选 | `""`（包语义 = 刻意空提交） |

取消整卷（Esc / 取消钮 / 点外 / 停止键 `ext_cancel_all`）= 挂起请求经共用的
`ext_ui.rs::ext_send` 回 `cancelled` → 包整卷 DECLINE。

## 交互模型（AskCard 同款）

- **tab 自由切题**：标签 = 题目 header（缺省「问题 N」）；答完圆点转实心；
  挂起请求对应题描 accent 呼吸边提示"正在等这题"。
- **确认 [n/N] 门控**：全部答完才亮；单选答完 = 选中项或自定义文本非空；多选同
  （作答口径 `answered()` 把关）。
- **键盘**：`1-4` 直选当前题选项 · `Enter` 未答完跳下一未答题 / 答完全卷提交 ·
  `Esc`/`×`/点外 = 取消整卷。Tab 键已砍（与 Enter 表观重叠；Root 层
  `tab→Tab` 绑定会抢在 on_key_down 前吞键，见 docs/agents/gpui.md keymap 节）。
  自定义答案输入框聚焦时键入进框，框内 Enter 同样走跳题/提交（TextInput
  on_submit → defer → `ask_enter`，defer 防双租约 panic）；打字态下整卡键盘
  让位（数字只作正文、Enter 不双跳）。
- **自定义答案行**每题常驻：单选与选项互斥（点选项清文本与选中，点行/圆标清
  选项；圆标再点 = 取消选中，取消后文本保留）；多选并存（序列化时拼在分号后）。
  输入框现值经 on_change 逐键镜像进当前题（`ask_input_mirror`），切题时与题目
  存档互同步（`ask_switch_tab`）。

## 布局与焦点

- **对齐 inputpanel**（内容列宽 = `workspace::chat_content_width`，设置-界面
  「会话内容宽度」，默认 920px）：浮层挂 `main_column` 的 `#chat-wrap`
  （relative 中栏），与 composer 同一居中轴；挂整窗根会被左右侧栏挤偏（实测
  教训）。卡片 `max_w(relative(1.))` 窄窗随中栏收缩，两侧 24px 呼吸边距。
- **预览侧栏**：当前题任一选项带 preview 时出双栏（qcol 400px + 预览占余）；
  预览显示选中项（无选中取首个带 preview 项）。包把 preview 折叠进 title
  （`--- N. label preview ---`），pi-flash 只用 args 原始结构，无需反解 title。
- **焦点仲裁**（focus.rs）：卡片持 `dlg.dialog_focus`（Esc/数字键/Enter），
  用户点进自定义输入框后持有 `ask_input` 真句柄不被抢；两者皆失焦时回收给卡片。
  ⚠ 焦点句柄必须 `focus_handle_in(cx)` + `has_inner()` 门闸：`TextInput::focus_handle()`
  是 fallback 句柄（不在元素树），用它会被每帧仲裁与内件抢焦点、打不进字。

## 降级与边界

- args 不可解析 / transcript 里无可解析的 ask_user_question tool_call / 题目
  不匹配 → legacy 阻塞弹窗（`ext_ui.rs::render_ext_dialog`），其他扩展的
  select/input/confirm/editor 不受影响。
- 非阻塞原语（setStatus/setWidget/notify/setTitle）不进问卷路由，照旧走
  widgets/status 条。
- 会话切换不清 `aux.ask`（与 legacy `ext_dialog` 同策略）：串行请求模型下不会
  串台，异源请求因 title 不命中自然放行；换卷/取消/停止才作废（见协议链路）。

## 参数解析

`find_last_ask_call`：从 runtime messages 末尾向前找最近的
`ask_user_question` ToolCall（跳过 `args_partial`）；`parse_args` 用
serde_json::Value 手解（app 不直接依赖 serde derive）。防御性校验：题目
1..=10、选项 1..=12、question/label 非空，异常即整体放弃走 legacy。
