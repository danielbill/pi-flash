# 问卷卡（ask_user_question 宿主渲染）

`ask_user_question` 工具的 GUI 宿主：CLI 侧装 `@juicesharp/rpiv-ask-user-question`
包，RPC 模式下它只会发 pi 的 `extension_ui_request`（select/input 两个原语），
多选被降级成"文本框手打 1,3"。问卷卡在渲染侧把降级请求拦截升维：**整卷 tab 卡、
真复选框、预览侧栏、键盘全程可操作**，包侧零改动。

模块代码：`ask_card.rs`（状态机+解析+序列化+渲染）；路由入口 `ext_ui.rs::on_ext_ui`；
浮层挂载 `session/mod.rs::main_column`（#chat-wrap 中栏）；焦点仲裁 `shell/render.rs`。

交互结构移植自 my-mastra-bot `AskCard.tsx`（tab 切题/答完标记/确认门控）；
视觉评审稿 `tmp/ask-user-redesign.html`（MIST 主题逐值对译）。

## 协议链路

```
pi 调 ask_user_question(args.questions[])
  ↓ transcript 流
pi-flash 截获 Block::ToolCall{args} ──→ 整卷解析（ask_card::parse_from_transcript）
  ↓ 包开始逐题阻塞请求
extension_ui_request #N 到达 ──→ ask_route_request：title 命中 tab N ──→ 挂起等用户
  ↓ 用户点「确认 [n/N]」
应答挂起请求 → 收卡 → 后续请求静默自动应答 → 流完自清 aux.ask
```

- **整卷先行**的依据：args 在 `toolcall_end` 即收全（`args_partial=false`），先于
  逐题请求可见；卡片打开即答全部题目，工具阻塞等待本来就是常态。
- 包严格**串行**发请求（上一题应答前不发下一题），任意时刻至多一个挂起请求
  （`AskCard.pending`），这是"确认后自动流过剩余请求"成立的前提。
- title 匹配：包的 title = `[header] question` + 折叠 preview 块，用
  `title.contains(question)` 判定请求↔题目对应；不命中（其他扩展的 select/input）
  → 放行走 legacy 弹窗，问卷卡不受影响。

## 回传契约（与包 rpc-fallback.ts 解析器严格对齐）

| 题型 | 用户作答 | extension_ui_response.value |
|---|---|---|
| 单选 select | 选中选项 i | `req.options[i]` **原行**（含 "N. label — desc" 前缀，包按行 indexOf） |
| 单选 select | 自定义文本 | 纯文本（包 `resolveSingleSelectReply` 判非选项行→custom，**免哨兵二次弹窗**） |
| 多选 input | 选项+自定义 | `"1,3; 文本"` |
| 多选 input | 仅选项 / 仅文本 | `"1,3"` / `"文本"` |
| 多选 input | 全不选 | `""`（包语义 = 刻意空提交） |

取消整卷 = 挂起请求回 `cancelled` → 包整卷 DECLINE。微信远程桥同一请求的
`clear_pending` 由共用的 `ext_ui.rs::ext_send` 收口，不重复消费。

## 交互模型（AskCard 同款）

- **tab 自由切题**：标签 = 题目 header（缺省「问题 N」）；答完 `●→✓`（实心点）；
  挂起请求对应题描 accent 边提示"正在等这题"。
- **确认 [n/N] 门控**：全部答完才亮；单选答完 = 选中项或自定义文本非空；多选同。
- **键盘**：`1-4` 直选当前题选项 · `Tab` 下一题 · `Enter` 未答完跳下一未答题 /
  答完全卷提交 · `Esc`/`×`/点外 = 取消整卷。自定义答案输入框聚焦时键入进框，
  框内 Enter 同样走跳题/提交（TextInput on_submit → `ask_enter`）。
- **自定义答案行**每题常驻：单选与选项互斥（点选项清文本，点行清选项）；
  多选并存（序列化时拼在分号后）。切题时输入框现值与题目存档互同步。

## 布局与焦点

- **对齐 inputpanel**（内容列宽 = 设置-界面「会话内容宽度」，默认 920px）：浮层挂 `main_column` 的 `#chat-wrap`（relative 中栏），
  与 composer 同一居中轴；挂整窗根会被左右侧栏挤偏（实测教训）。卡片
  `max_w(relative(1.))` 窄窗随中栏收缩，两侧 24px 呼吸边距。
- **预览侧栏**：当前题任一选项带 preview 时出双栏（qcol 400px + 预览占余）；
  预览显示选中项（无选中取首个带 preview 项）。包把 preview 折叠进 title
  （`--- N. label preview ---`），pi-flash 只用 args 原始结构，无需反解 title。
- **焦点仲裁**（render.rs）：卡片持 `dlg.dialog_focus`（Esc/数字键/Enter），
  用户点进自定义输入框后持有 `ask_input` 真句柄不被抢；两者皆失焦时回收给卡片。
  ⚠ 焦点句柄必须 `focus_handle_in(cx)` + `has_inner()` 门闸：`TextInput::focus_handle()`
  是 fallback 句柄（不在元素树），用它会被每帧仲裁与内件抢焦点、打不进字。

## 降级与边界

- args 不可解析 / 无进行中问卷 / 题目不匹配 → legacy 阻塞弹窗（`ext_ui.rs::render_ext_dialog`），
  其他扩展的 select/input/confirm/editor 不受影响。
- 非阻塞原语（setStatus/setWidget/notify/setTitle）不进问卷路由，照旧走 widgets/status 条。
- 会话切换不清 `aux.ask`（与 legacy `ext_dialog` 同策略）：串行请求模型下不会串台，
  异源请求因 title 不命中自然放行。

## 参数解析

`parse_from_transcript`：从 runtime messages 末尾向前找最近的
`ask_user_question` ToolCall（跳过 `args_partial`），serde_json::Value 手解
（app 不直接依赖 serde derive）。防御性校验：题目 1..=10、选项 1..=12、
question/label 非空，异常即整体放弃走 legacy。
