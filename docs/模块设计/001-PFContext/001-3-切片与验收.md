## 2 验收指标

1. `grep -rn "subagent_capacity" crates/` → 只剩迁移读点 + 测试。
2. 冷启动 settings 读盘 **1 次**，`[perf] settings.load=<µs>` 进日志；二次读走
   snapshot，0 次 I/O。
3. 手改 `app-settings.json` → UI **2s 内**反映，无重启。
4. 手工加未知键 → 一次 UI 保存后仍在（逐字一致）。
5. 连续拖 capacity stepper 20 次 → **1 次**写盘（coalesce）。
6. 新增一个 setting 的 diff = 1 字段 + 1 控件，**0 新文件 / 0 新 env**。
7. 改 `ext-context.json` 的 `subagents.capacity` → 下一次 `agent` 委派即按新值，
   免重启。
8. 投影写入与扩展读取的时间差 < 100ms（同机，`generated_at` 对比）。

## 3 测试清单

**Rust（`crates/pf-context`）**

- precedence：L0 < L1 < L2 < L3；L4 env 只对路径生效。
- round-trip：未知键 / section 内未知字段写入前后逐字不变。
- 坏档：整份非法 → 保上一份好快照 + `problems`；单 section 非法 → 该段
  `Default`，其它段正常。
- 并发：读线程循环 `get()` 同时写线程 `set()`，无 panic、无撕裂快照。
- watcher：外部写入触发一次重载；自写不回环（预期哈希窗口）。
- 迁移：v1 平铺 → v2 整份升级，旧平铺键保留；再读回值不变。
- flush：退出路径落盘；写失败注入 → 内存保留 + 重试计数。
- 投影：exportable 白名单过滤、同内容跳过、敏感键硬闸。
- state：快照语义 + 并发读写；domain：迁移/事务回滚/并发写/架构断言
  （settings 键与 DB 表名零交集）。

**app（`crates/app`）**

- 桥：`pfctx-manager-op` 条目 → op 队列 FIFO + session 归属；其它自定义条目
  不串台（`on_event.rs::pfctx_bridge_tests`）。
- agent section：默认 on、落盘往返（`settings/tests.rs::s8_*`）。

**扩展（`node --test`）**

- pf-subagents：读段 / version 不匹配 / 文件缺失 / 半截 JSON 的返回值与
  `problem`；回退顺序 投影 → legacy → FALLBACK；坏投影不改变在跑上限。
- pfctx-manager：目录校验（键/类型/枚举/范围）、恒拒项、注册形态。

**端到端（`#[ignore]` 门控，需已配置模型）**

- `cargo test -p pi-link --test live_pfctx_manager_probe -- --ignored --nocapture`
  ：真 spawn pi → agent 真调用 `pfctx_manager` → 宿主契约条目
  （customType=`pfctx-manager-op`）上事件流。

驱动：`node test/001-PFContext/run.mjs`（A 工具面 + B 挂载链守卫）。

## 4 风险与处置

| 风险 | 处置 |
|---|---|
| watcher 自写回环 | 预期哈希窗口 + 同内容跳过；单测覆盖 |
| 写失败（磁盘满/占用） | 内存保留 + 退避重试 + 告警；不丢用户意图 |
| 双实例 | 文件 last-writer-wins；冲突且本机有未落盘改动时提示一次 |
| 过渡期双文件不一致 | 双写一版 legacy；扩展以投影为准，旧文件只作 fallback |
| 设置页与扩展钳制不一致 | clamp 只在 `Section::validate`；扩展仅防御性钳 |

回滚：v2 文档按 v1 平铺键读回（旧键保留一版即为此）；投影可整体删除，扩展自动
走 legacy 链。
