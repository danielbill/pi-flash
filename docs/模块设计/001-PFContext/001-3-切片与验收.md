## 2 验收指标（可执行）

1. `grep -rn "subagent_capacity" crates/` → 只剩迁移读点 + 测试。
2. 冷启动 settings 读盘 **1 次**，日志含 `[perf] settings.load=<µs>`；二次读走 snapshot，0 次 I/O。
3. 手改 `app-settings.json`（外部编辑器）→ UI **2s 内**反映；无重启。
4. 手工加未知键 → 一次 UI 保存后仍在（字节级一致）。
5. 连续拖 capacity stepper 20 次 → **1 次**写盘（coalesce），`[perf] settings.flush=<µs>`。
6. 新增一个 setting 的 diff = 1 字段 + 1 控件，**0 新文件 / 0 新 env**。
7. 改 `ext-context.json` 的 `subagents.capacity` → 下一次 `agent` 委派即按新值，免重启。
8. 投影写入与扩展读取的时间差 < 100ms（同机，日志对比 `generated_at`）。

## 3 测试清单

**Rust（`crates/pf-context`）**

- precedence：L0 < L1 < L2 < L3，且 L4 只对路径生效。
- round-trip：未知键/未知 section 写入前后字节级不变。
- 坏档：整份非法 → 保上一份好快照 + `problems`；单 section 非法 → 该段 `Default`，其它段正常。
- 并发：读线程循环 `get()` 同时写线程 `set()`，无 panic、无撕裂快照。
- watcher：外部写入触发一次重载；自写不回环（预期哈希窗口）。
- 迁移：v1 平铺 → v2，旧键保留；再读回值不变。
- flush：退出路径落盘；写失败注入 → 内存保留 + 重试计数。
- 投影：白名单过滤（未声明 `exportable` 的段不出现）、同内容跳过、半文件不写入。

**扩展（`node --test`，`extensions/pf-subagents`）**

- 读段成功 / `version` 不匹配 / 文件缺失 / 半截 JSON 四种输入的返回值与 `problem`。
- 回退顺序：投影 → legacy `agents/config.json` → FALLBACK。
- 坏投影不改变当前 `manager.capacity`。

## 4 风险与回滚

| 风险 | 处置 |
|---|---|
| watcher 自写回环 | 预期哈希窗口 + 同内容跳过；单测覆盖 |
| 写失败（磁盘满/占用） | 内存保留 + 退避重试 + 状态栏一次提示；不丢用户意图 |
| 双实例 | 文件 last-writer-wins；冲突且本机有未落盘改动时提示一次 |
| 过渡期双文件不一致 | S3 双写一版；扩展以投影为准，旧文件只作 fallback |
| 设置页与扩展钳制不一致 | clamp 只在 `Section::validate`；扩展仅防御性钳 |

回滚：S1/S2 的读取兼容层允许把 `version: 2` 文档按 v1 平铺键读回（旧键保留一版即为此）；投影可整体删除，扩展自动走 legacy 链。
