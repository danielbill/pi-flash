# 001-2 跨进程投影：ext-context.json

> 前置：[001-0 总体设计](001-0-PFContext总体设计.md)。设置文档形态见 [001-1](001-1-settings正式化.md)。

## 1 通道规则

扩展跑在 pi 子进程，只见文件与 env：env 只装**启动期不变的路径**，运行期会变的
策略值一律走本投影文件——一份索引文件，扩展不猜该读哪个 json。PF 是唯一写者，
扩展**禁止回写**。

## 2 形态

`<PF数据目录>/ext-context.json`

```json
{
  "version": 1,
  "generated_at": "2026-11-08T08:20:00Z",
  "subagents": { "capacity": 10, "max_depth": 1, "enabled": true },
  "market": {},
  "remote_control": {}
}
```

- 只含**扩展需要**的段；段名 = `Section::KEY`，字段 = 该 section 的 `exportable` 子集。
- `version`：投影格式版本，扩展据此决定回退行为（不匹配 = 视为不可用）。
- `generated_at`：扩展排查「读到的是旧档」的唯一依据；payload 哈希不变则整体
  跳过写，`generated_at` 只在内容真变时前进。
- 顶层不带 `settings` 包裹：扩展按段名直取。

## 3 写入

- 由 `SettingsStore` 在**段内容变化后**触发（open 初次后台线程 / flush 实写后 /
  外部重载成功后），debounce 50ms 合并连续改动。
- 原子写：同目录 tmp + rename。
- 内容与盘上一致则跳过（避免 watcher 自身回环）。
- 白名单：只有 `exportable` 的 section 出现；`generate` 时二次过滤，**不依赖
  section 自觉**。

## 4 扩展读取契约

- **时机**：`agent` 工具 `execute` 入口读一次（`syncModuleConfig`）。不在流式
  输出、渲染、每次工具调用的热路径上；不缓存 mtime。
- **回退链**（顺序固定）：
  1. 读投影成功且 `version` 匹配 → 用该段；
  2. 投影存在但坏档 / 版本不匹配 → **保持现值**（不覆盖正在跑的上限），记 `problem`；
  3. 投影缺失（首启 / 非 PF 宿主）→ 读 legacy `agents/config.json`；
  4. 再无 → 扩展内置 `FALLBACK_MODULE_CONFIG`（capacity 默认 8）。
- **坏档不静默改行为**：`loadModuleConfig` 返回带 `problem` 的结果，
  `syncModuleConfig` 只在无 problem 时 apply。
- 读取容忍半文件（原子 rename 下理论上不会发生，Windows 杀软/同步盘会），
  `JSON.parse` 失败即走回退链。

## 5 env 白名单

只剩**路径类 bootstrap**（进程启动前就要知道，且不该变）：

| env | 用途 |
|---|---|
| `PI_SUBAGENTS_PROFILES_DIR` | 子代理 profile 目录 |
| `PI_FLASH_DIR` | PF 数据目录（显式指定优先） |
| `PI_FLASH_PI_BIN` | 开发期覆盖内置 pi |

- **策略值（容量/深度/开关）一律不得走 env**。
- `PI_SUBAGENTS_CAPACITY` / `PI_SUBAGENTS_MAX_DEPTH` / `PI_FLASH_APP_SETTINGS`
  已从 spawn 环境移除（旧版扩展兼容期已过）。

## 6 安全与卫生

- 白名单导出，默认拒绝：section 不声明 `exportable` 就不出现在投影里。
- **永不出现在投影**：api key、oauth token、keyring 引用、`auth.json` 任何字段
  （051 / 042-1 边界）；导出前对键名递归扫描 `api/token/key/secret/oauth/password`
  片段，命中拒绝导出。
- 不含 PII：投影只放数字/布尔/枚举与用户显式设置的短字符串。
- 文件权限沿用 PF 数据目录默认；不加密（无秘密），不放可反推凭据的指纹。

## 7 观测与排障

- `hub.dump()` → `<PF数据目录>/context-dump.json`（并入现有同名概念）：
  每 section 的生效值、来源层（L0/L1/L2/L3/L4）、最近写入时间、最近重载时间、
  watcher 状态、`problems`。
- 扩展侧：`ModuleConfigReadResult.problem` 上报到会话事件日志，UI 在子代理面板
  显示一次黄色提示（不打断）。
- 排查口诀：值不对 → 先看 `context-dump.json` 的来源层，再看 `ext-context.json`
  的 `generated_at`，再看 `pfctx.log` 的 `[write]/[reload]/[agent]` 行。

## 8 `agents/config.json` 退役计划

| 版本 | 行为 |
|---|---|
| S3（已落地） | 投影上线；PF 仍写 `agents/config.json`（双写一版，给未升级扩展留活路）；扩展读段 + 回退链 + 坏投影保现值已实现 |
| S3+1 | 停写 `agents/config.json`，保留 `ensure_module_config` 只做「文件缺失时补一份」 |
| S4+1 | 读取兼容删除；文件仅在用户手编时被尊重（作为 legacy override），文档标注 deprecated |

退役判断标准：投影上线后一个版本周期内，扩展日志中 `problem` 与 legacy
fallback 命中为 0。
