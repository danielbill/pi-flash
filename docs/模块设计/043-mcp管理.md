## 程序设计

### 现行机制

- settings-mcp：只做全局（`~/.pi/agent/mcp.json`）；左侧 全局组（总开关 + 行开关，点行进编辑、再点已选行回新增）；右侧表单 = MCP名称 标签+保存（编辑态加移除）/ 全宽名称框 / MCP配置 标签 + 8行粘贴框 / 四行纯文本说明（单串左对齐）
- 录入：一个粘贴框四种形态自动识别（JSON / URL / 命令行 / `pi|claude|codex|gemini mcp add` 前缀剥除；命令前旗标 `-s/--scope` 等丢弃、`-e/--env KEY=VAL` 转 env，命令之后的参数原样保留），粘贴 JSON 里的 exposure 等字段原样保留；改名 = 删旧条目 + 增新
- inputpanel：MCP 勾选菜单在扩展钮右边，无条目隐藏，各档可用（MCP 全档装载，不设 full+ 守卫）；勾选当即写 mcp.json `enabled`，并标记 `pending_mcp_reload`（无论会话运行与否都标记）
- 生效时机：改动只落盘 + 标记重绑；空闲但活着的进程不会自己重读 mcp.json，下一轮空闲发送前 `rebind_pending` 重绑进程生效（`--session` 复接不丢消息），未 spawn 的会话 spawn 时读盘生效；保存 toast 已提示；列表数据盘上现读，不走启动缓存

### 设计事实

- pi RPC 协议零 MCP 语义：无状态事件、无管理命令；故障告警由 pi 主动发 notify → PF ext_notice toast（`dialogs/ext_ui/actions.rs`，已有通路，无需新增）
- needs-auth 登录：inputpanel `!pi mcp login <名字>` 即可（bash 无超时，login 自带 300s 上限，可中止；浏览器自动拉起，URL 也在 shell 卡里）；全局 `pi` 由 081 shim 注册到 PATH
- 状态列 / 会话内重连：可选排障便利，未做（已知限制）
