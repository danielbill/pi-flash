## 程序设计

### 已落地（2026-10）

- settings-mcp：只做全局（`~/.pi/agent/mcp.json`）；左侧 全局组（总开关 + 行开关，点行进编辑、再点已选行回新增）；右侧表单 = MCP名称 标签+保存（编辑态加移除）/ 全宽名称框 / MCP配置 标签 + 8行粘贴框 / 四行纯文本说明（单串左对齐）
- 录入：一个粘贴框四种形态自动识别（JSON / URL / 命令行 / `pi|claude|codex|gemini mcp add`），粘贴 JSON 里的 exposure 等字段原样保留；改名 = 删旧条目 + 增新
- inputpanel：MCP 勾选菜单在扩展钮右边，无条目隐藏，各档可用（MCP 全档装载，不设 full+ 守卫）；勾选即写 mcp.json，运行中标记下一轮发送前重绑生效（pending_mcp_reload）
- 生效时机：一切改动只对新会话生效（pi session_start 才读 mcp.json），保存 toast 已提示；列表数据盘上现读，不走启动缓存

### 设计事实

- pi RPC 协议零 MCP 语义：无状态事件、无管理命令；故障告警由 pi 主动发 notify → PF ext_notice toast（ext_ui_actions.rs，已有通路，无需新增）
- needs-auth 登录：inputpanel `!pi mcp login <名字>` 即可（bash 无超时，login 自带 300s 上限，可中止；浏览器自动拉起，URL 也在 shell 卡里）；前提 PATH 有全局 `pi`，没有时再做 UI 按钮
- 状态列 / 会话内重连：可选排障便利，不做
