MCP 服务的注册和管理。

模块代码：mcpManager（`crates/app/src/settings/mcp.rs` + `crates/pi-link/src/mcp.rs`）

对应界面：
1、settings - mcp
2、inputpanel  - mcp菜单

## 模块定位（心智模型）

MCP server = 独立的外挂工具箱：一个子进程（stdio）或 HTTP 服务，按 MCP 协议向 agent 供给一组工具（`mcp__<server>__<tool>`）。

本模块 = 一张**默认注入清单**（`~/.pi/agent/mcp.json`）的编辑器 + 连接生命周期前台。三个环节：

1. **登记**：用户带来启动方式（命令行 / URL / JSON），模块解析落盘。不安装任何东西——stdio 进程是 pi 会话启动拨号时才拉起的。
2. **连接**：pi 在 `session_start` 照清单连接，模块负责把连接结果（状态）显示出来、处理登录。
3. **供给**：连接成功的工具以什么姿态给模型，由 exposure 四档决定。

**不是**：工具市场（没有浏览/安装，server 地址永远由用户带来）、自动发现（唯一自动的是连接后拉取工具清单）、运行时插件管理（扩展是另一套，见 040/041）。

三层语义，排查「加了 MCP 没生效」按此顺序：

| 层 | 字段 | 含义 |
|---|---|---|
| 连不连 | `enabled` | false = 保留条目，下个会话不连接 |
| 给不给模型 | `exposure` | codemode（默认，模型写代码经 searchTools 调）/ deferred（经 tool_search）/ direct（直接声明）/ hidden（不可见） |
| 连接结果 | state | connected / needs-auth / failed / disabled |

## 协议基调（为什么这么做，已逐条验证）

pi 的 RPC 协议**零 MCP 语义**：33 个 `RpcCommand` 无一涉及 MCP，也无结构化状态事件（`vendor/pi/.../dist/modes/rpc/rpc-types.d.ts` 全文核对）。但有两层机制兜底：

- `prompt("/mcp …")` 会执行扩展命令且**不进对话上下文**（`agent-session.js:1490`，preflight 返回 `"handled"`；流式中也可执行）。注意：`steer`/`follow_up` 对扩展命令直接报错，只能走 `prompt`。
- 非 TUI 模式下 `/mcp` 的全部交互走 `extension_ui_request`（`rpc-mode.js:80-231`），PF 已完整解析并应答（`pi-link/protocol.rs:419`、`app/ext_ui.rs`）。

能力矩阵：

| 操作 | 走法 | 结论 |
|---|---|---|
| 查状态 | spawn `pi mcp list --json`（结构化，无会话也可用）；或借道 `prompt("/mcp")` 收 notify 纯文本 | ✅ 可做 |
| OAuth 登录 | spawn `pi mcp login <name>`（开浏览器 + loopback 回调，默认 300s） | ✅ 可做 |
| 重连/登出 | `prompt("/mcp reconnect\|logout <name>")` | ✅ 可做（纯 notify） |
| 改配置即时生效 | 配置只在 `session_start` 读一次，`reconnect` 也不重读 | ❌ 做不到，**新会话生效是产品行为** |

两条铁律：

1. `/mcp` 系 prompt 只能由 PF 内部发起，**绝不把用户输入的 `/` 开头文本直通 prompt**（会误触任意扩展命令）。
2. 对外部格式（CLI 输出、notify 文本）的解析必须宽容 + 可降级（解析失败就展示原文），上游无格式承诺。

## settings - mcp（一期，本次改造）

**只做全局配置**（`~/.pi/agent/mcp.json`），去掉项目配置。注意已知行为：pi 引擎仍会自行加载受信任项目的 `.pi/mcp.json` 并覆盖同名全局条目，UI 不展示、不编辑——接受。

布局：左侧注册列表 + 右侧【配置MCP】表单。

### 左侧：MCP 注册列表

参考对齐扩展列表：

- 顶部**总开关**：批量启停全部条目
- 每行：名称 + 单独开关（`enabled`）+ 移除；**点行 → 右侧载入该条目进入编辑**
- （二期）每行加状态徽标

### 右侧：【配置MCP】表单

第一行 title ：配置MCP    |    右侧【保存】按钮
第二行 单行input：MCP名称
第三行 inputarea：8行高；placeholder : "粘贴 JSON/url/命令行/pi mcp add..."（编辑模式回填该条目 JSON）
第四行 四种说明（纯文本，取消原先的点击互动）：

- 例1 JSON
- 例2 URL
- 例3 命令行
- 例4 pi命令

输入框下加一行**实时解析反馈**（边输入边解析）：识别形态徽标 + 解析摘要（名称/传输类型）；识别失败红字提示支持的四种形态，【保存】置灰。

exposure 四选一行（codemode/deferred/direct/hidden），与 JSON 的 `exposure` 字段联动，编辑时回填。

### 解析归一

四种形态共用一个输入框，自动识别，归一成同一内部结构（name + stdio{command,args,env,cwd} | http{url,headers,oauth}）：

1. 以 `{` 开头或含 `"mcpServers"` → JSON（取第一个条目）
2. 匹配 `^(pi|claude|codex|gemini)\s+mcp\s+add` → CLI 粘贴（剥前缀解析 flag）
3. 以 `http(s)://` 开头 → URL（http 传输）
4. 其余 → 按命令行拆（首 token 为 command，其余为 args，stdio）

env/headers 值支持 `${VAR}` 引用（秘密不落盘），预览只显变量名。

保存 = `pi_link::mcp::add/patch`（读-改-写，保留文件其余内容与缩进）；改名 = 删旧条目 + 增新条目。

**生效时机**：本页一切改动只对新会话生效——保存后状态条提示「对新会话生效」。

## inputpanel - mcp菜单（一期）

完全对照 inputpanel - 扩展菜单（plugin_picker）：

- 增加一个 icon 在扩展 icon 右边；**全局 mcp.json 无条目时不显示该 icon**
- 交互完全对照：勾选即生效、无确认按钮、单列已勾置顶、限高滚动
- 生效通路：勾选 → 写 mcp.json `enabled` → 走 pending 重绑（下一轮 send_input 前 respawn，新进程 `session_start` 重读清单）——与扩展同一条重绑通路
- 一处刻意不同：扩展按钮仅 full+ 档激活（其余档扩展不挂载）；**MCP 各档都装载**（builtin:mcp 全档启用，tools_recipe 各档均放行），故 mcp icon 不设档位守卫
- 差异注记：扩展清单是会话级（spawn 参数），MCP 清单是全局文件——本会话勾选对其他会话同样生效（接受，与「全局清单」定位一致）

## 状态与登录（二期）

- **状态列**：刷新按钮 spawn 内置 pi `mcp list --json`（输出 name/state/tools/exposure/enabled，文档化 CLI，无会话也可用），行内显示状态徽标；会话运行中另收 reportProblems 的 notify 作被动提醒（config error / needs-auth / failed）
- **OAuth 登录**：needs-auth 行显示【登录】→ spawn 内置 pi `mcp login <name>` → 从 stdout 解析授权 URL → 调系统浏览器打开 → 等待进程退出（exit 0 = 成功）；「浏览器无法回连时粘贴回调 URL」的 fallback 后续再做
- **重连**（可选）：运行中会话借道 `prompt("/mcp reconnect <name>")`

## 边界与非目标

- 不做项目级管理（一期定稿）
- 不做热更新/热生效——pi 协议无通路，「新会话生效」即产品行为
- 不做 SSE（pi 仅支持 streamable HTTP）
- 结构化 MCP 状态 RPC 等上游；上游出现后二期的借道实现可平替
