Pi 扩展市场：内置浏览安装 pi 社区 package 的页面。现行实现 = **Pi 原生扩展市场页**（pi.dev `Package Catalog` 目录页的桌面移植，代码模块 `crates/app/src/market/pi_native_market/`，代码注释里自称「040-2」）。

早期版本曾按 PF 自行设计的「单列卡片 + 工具栏」页面实现（`market/pi_ext_market.rs` 单文件页）；该页已退役连代码删除（`open_pi_ext_market` / prefetch / 首页磁盘快照随之清除）。本文件描述的是现行原生市场页。

## 功能说明
本页面为方便浏览安装 Pi 社区的 package 而设。照抄 pi.dev 官网目录页的版式与文案：四列「最近发布」条 + 双列大卡 + 页码条。与官方页面的差异：`[ install ]` 按钮 = **PF 内真安装**（走 040 设置页同一条 `pi install npm:<name>` CLI 管线）；已安装的包显示绿色 ✓ 不可点。已装扩展的管理（启停/卸载/更新）依旧在 settings - 扩展（040）。

入口：topbar 三横「菜单」按钮 → 「Pi扩展市场」。

## UI设计
设计稿：`docs/UI设计/仿-pi.dev-Packages-页面设计/pi-packages.html`（同目录 `DESIGN-HANDOFF.md` 为视觉契约：像素优先）。本页是「pi.dev 原生皮肤」：深色单档、配色/尺寸全部字面量（真值住在 `pi_native_market/design.rs`），不跟随 PF 八主题。

## 注意事项
安装使用全局单飞的 `pkg_op`（与设置页共用），安装逐个进行；进行中其它安装入口（设置页）同样禁用。

## 0. 边界与结论

- **不嵌网页、不依赖 pi.dev 的 API**：`https://pi.dev/api/packages` 返回
  `{"ok":false,"error":"API routes are reserved for future features."}`，
  `/packages.json` 404；站点只有服务端渲染 HTML。抓 HTML 不做主路径。
- **数据面 = npm registry 搜索 API**（站点自身的数据源）：
  `GET {base}/-/v1/search?text=keywords:pi-package[ 关键词]&size=50&from=N&popularity=1&quality=0&maintenance=0`，
  返回 name、description、version、date、`downloads.monthly`、publisher、links。
  base 默认 `https://registry.npmjs.org`，`PI_FLASH_NPM_REGISTRY` 可覆盖。
- **类型/资源清单 = 单包 latest 清单**：`GET {base}/<name>/latest` → `pi` 键
  （`extensions/skills/prompts/themes/subagents` → `MarketKind`）。
- **写路径 = 与 040 同一条 vendored pi CLI 管道**（`mc_install_package` →
  `pi install npm:<name>`，op 泵收尾刷新）；市场页不自己动 `node_modules`、
  不自己写 `settings.json`。
- **不改 Settings 模块**（铁律）：网络代理/镜像类配置一律不加，只认环境变量（§9）。
- **排序参数不存在**：npm 搜索忽略 `sort=`（实测与默认同序）；「最近发布」
  只能取一页上限 250 条（`SEARCH_SIZE_MAX`）本地按发布时间倒序截前 8 条，
  语义 = 「按相关度取到的这一批里最近发布的」，不是全库最新。

## 2. 数据结构（pi-link/src/market/pi_ext_market.rs）

```rust
pub enum MarketKind { Extension, Skill, Prompt, Theme, Subagent }
// key() = pi 清单键的单数形式（extension/skill/prompt/theme/subagent），
// 类型徽标/类型筛选按它对齐；i18n_key() = market.type.*（app 侧 tr()）

pub struct MarketEntry {
    pub name: String,            // npm 名（含 scope，显示原样）
    pub description: String,
    pub version: String,         // latest
    pub monthly_downloads: u64,
    pub updated: String,         // registry 的 ISO 字符串，原样展示
    pub kinds: Vec<MarketKind>,  // 由 pi 清单推出；空 = 清单未补全/缺 pi 键
    pub repo: Option<String>,    // 剥 git+ 前缀与 .git 后缀
    pub author: Option<String>,  // npm publisher.username
}

impl MarketEntry {
    pub fn is_extension(&self) -> bool;      // kinds 空（放行）或含 Extension
    pub fn install_command(&self) -> String; // "pi install npm:<name>"
    pub fn source(&self) -> String;          // "npm:<name>"（安装/卸载入参）
}

// URL 拼装（纯函数，单测覆盖）：scope 的 @ 保留、其余 percent-encode
pub fn search_url(query, from, size) -> String;
pub fn latest_url(name) -> String;
pub fn format_downloads(n) -> String;        // 1.8M / 792.8K / 3.4K / 999
pub fn days_since(iso, now_unix) -> Option<i64>;

// 解析（纯函数）：缺字段容错；无 pi 键 = 空 kinds；脏 JSON = Err
pub fn parse_search_page(body) -> Result<MarketPage, String>;   // {entries, total}
pub fn parse_latest_manifest(body) -> Result<Vec<MarketKind>, String>;

// 网络（阻塞，调用方在后台线程）
pub fn search(query, from, size) -> Result<MarketPage, String>;
pub const SEARCH_SIZE_MAX: usize = 250;      // npm 搜索 size 服务端钳制上限
pub fn search_recent(take) -> Result<Vec<MarketEntry>, String>;
pub fn fetch_kinds(name) -> Result<Vec<MarketKind>, String>;    // 失败 = Err（不写缓存）
pub fn fill_kinds(&mut entries, &mut kinds); // 并发 8，命中 kinds 表跳过；失败保留空 kinds

// 跨会话 kinds 缓存：<数据目录>/pi-native-kinds-cache.json
pub struct KindsCache;
impl KindsCache {
    pub fn load() -> HashMap<String, Vec<MarketKind>>;  // 坏文件/缺失 = 空表
    pub fn save(&HashMap<String, Vec<MarketKind>>);     // 原子写（tmp+rename），失败静默
}
// 缓存条目上限 KINDS_CACHE_MAX = 5000，超限整体清空重学（兜底，不设 LRU）
```

常量：`PAGE_SIZE = 50`（一页条数）、`FILL_CONCURRENCY = 8`（清单补全并发）。

**`is_extension` 是唯一过滤口径**：只隐藏清单明确不含 Extension 的包；
`kinds` 为空（清单请求失败/包没写 `pi` 键但走约定目录）→ **放行**并标类型
「package」，不因为网络抖动把整页清空。

## 3. 数据流与页内状态机

```
// crates/app/src/market/pi_native_market/mod.rs（挂 aux.market.native）
NativeState {
    input,            // 搜索框实体（首次打开懒创建）
    query,            // 服务端搜索词（回车 / SEARCH 按钮）
    filter,           // 页内实时过滤词（打字，0 网络）
    kind,             // NativeKind: All | Extension | Skill | Theme | Prompt
    sort,             // NativeSort: Downloads（服务端序）| Recent | Name（当前页内）
    entries,          // 当前页 ≤50 条
    recent,           // 「最近发布」8 条（仅第一页拉取）
    total, page,      // 服务端 total 与当前页（1 起）
    loading,          // 单飞闸：为真不再发新页请求
    error,            // 搜索失败信息（空态行显示「Failed to load. Try Reset.」）
    gen_ix,           // 请求代际：换词/翻页/重置 ++，回包不符即丢弃
    loaded_once,      // 首载闸
    pending,          // 安装中的包来源（npm:<name>）：按钮转圈 + 动作禁用
    filter_gen,       // 过滤去抖代际（每键 ++；到点的旧轮次不再重排）
    kinds_pending,    // kinds 后台补齐在途（空窗期空态显示「Loading type info…」）
    kinds,            // 会话级 kinds 表（首载从 KindsCache 灌入；补齐后回存磁盘）
    list, sb,         // 变高虚拟列表 + 滚动条状态
}
```

一次拉页（`native_fetch`，网络与清单补全全在后台线程）：

1. `gen_ix += 1`、`loading = true`、`kinds_pending = true`；后台
   `search(query, (page-1)*50, 50)`；仅第一页附带 `search_recent(8)`；
2. 搜索落地 `native_land`（gen 不符即丢）：写 entries/recent/total；
3. 后台 `fill_kinds`（会话 kinds 表为起点：命中即 0 网络；批内并发 8，
   约 3-6s）→ 整批到齐才刷新一次（本页卡片等高，逐批上屏会跳版）；
4. `KindsCache::save` 回存磁盘缓存，`native_kinds_land` 落 entries 并清
   `kinds_pending`。

触发点：页面首次打开、回车 / SEARCH（读框内文本回第一页）、RESET（清词 +
类型 + 排序回第一页）、类型下拉（**重查第一页**——pi.dev `?type=` 口径，随重查
自愈首装填充失败的坏态）、翻页条 / 上一页 / 下一页（翻页回顶）。

**打字只过滤当前页**（设计稿 JS 同款：0 网络、160ms 去抖重排）；`query == filter`
时不再二次过滤同词（npm 按 keywords 命中的条目不允许被描述判掉）。

**类型过滤是客户端过滤**（npm 无类型查询参数）：过滤集只覆盖当前页 50 条；
过滤生效时计数与页码改按过滤集本页真实值（total = shown、单页）。

翻页上限 **20 页**（`MAX_PAGES`，npm 分页深度保守值）；
`total_pages = ceil(total / 50).max(1).min(20)`。

## 3.5 缓存与性能策略

- **内存**：当前页 `Vec<MarketEntry>`（≤50 条，翻页即换）+ 会话级
  `HashMap<name, Vec<MarketKind>>` + 「最近发布」8 条；进程退出即丢。
- **磁盘只落一份 kinds 缓存**：`<PF数据目录>/pi-native-kinds-cache.json`
  （name → kinds，单条约 100B，上限 5000 条）。价值：原生市场每次重查要补
  50 个 `latest` 清单（约 15-20s），有缓存后命中即零网络，选类型立即出结果。
  **页面条目本身不落盘**（无首页快照），每次打开拉第一页。
- **渲染性能 = 分段变高虚拟列表**：整页塞进一个滚动容器会逼 GPUI 每帧重排
  全部 50 张卡（含 50 段 3 行长描述），实测每次重渲染约 100ms。改法 =
  `gpui::list` 虚拟化，把同一条边框拆成「最近发布 / 头+工具栏 / 卡行×N /
  页码条」多段各自画，项高只跟项数走（过滤/打字不丢滚动位）。
- **网络复用**：共享 ureq Agent（keep-alive + gzip：实测不复用连接 50 包
  6.0s、复用后 2.6s），15s 超时，body 截断 2MB。
- 明确不做：全量字典落盘 / LRU / 多 query 缓存、启动预取、in-flight 去重、
  图片缓存、累积多页。
- **与 082 无联动**：市场页不触发更新检测，不显示「有新版本」（已装 = ✓ 三态
  之外没有更新态）；更新入口在 settings - 扩展与 082 的两处 UI。

### 失败处理

| 情形 | 行为 |
|---|---|
| 搜索失败 | 空态行「Failed to load. Try Reset.」（无自动重试、无退避） |
| 单包清单失败 | 该条 kinds 留空（放行标 package）、不写缓存，下次自然重试 |
| `PI_OFFLINE=1` | 不发任何请求（http 层直接返回 offline 错误） |

## 9. 网络 / 代理 / 离线

- 搜索端点镜像不通：实测 `registry.npmmirror.com/-/v1/search` 返回
  `{"objects":[],"total":0}`（不支持搜索），**主路径必须 registry.npmjs.org**。
- 代理与镜像**不加设置项**（铁律：不动 Settings），只认环境变量：
  - `PI_FLASH_NPM_REGISTRY`（默认 `https://registry.npmjs.org`，拼 search/latest 的 base）
  - `PI_FLASH_HTTP_PROXY`（ureq `Proxy`，`http://` / `socks5h://`）
  - 与 `PI_OFFLINE=1` 联动：置位则不发任何请求（082 检测同判）。
- ureq Agent：`timeout = 15s`、`user-agent = pi-flash/<ver>`、
  `Accept: application/json`；响应体截断 2MB。
- 失败分级：搜索失败 → 空态错误文案（§3.5）；单包清单失败 → 只影响该行
  kinds，不报错。
