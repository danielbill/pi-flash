## 已定稿决策（2026-10-09）

1. **默认模型存 PF 自己的 `~/.pi-flash/app-settings.json`**——不写 pi 的 settings.json（系统 pi / pi-web 的地盘）。代价：pi 不知道 PF 默认模型，**新会话进程就绪后由 PF 主动 `set_model` 应用**（幂等，保证胶囊显示与实际模型一致）。
2. **新增 Provider 弹窗本期只做「自定义 + API KEY」两组**；「订阅服务」组（全是 OAuth 登录）不渲染。051 已定稿 OAuth 归 pi、PF 不发起登录；OAuth 发起留后续独立设计（beads pi-flash-1cb）。
3. **保存 apikey 后做真探查**（PF 超出 pi-web 的优化）：保存后向该 provider 列模型端点发一次轻量 GET 验证 key。考证：pi-web 并无独立探查请求，模型列表来自 SDK 静态注册表；但 051 的痛点是 key 错了要重启会话才发现，探查把失败提前到保存时刻。
4. **Provider 行 switch 的停用 ≠ 删凭据**：统一走 enabledModels 整商关闭/开启（可逆，凭据保留）；「断开连接」（删 key）只留在详情页。

## 设计事实（pi-web 代码与实测，对齐的根据）

- **模型目录与凭据无关**：内置商的模型列表是 SDK 静态注册表（+ `~/.pi/agent/models-store.json` 目录 overlay + models.json 自定义）。pi-web 实测：保存 key / 登录后该 provider 才「激活」、其模型才可勾选（未认证内置商详情区是登录空状态）；列表本身一直在。PF 的 `catalog_for` 已含全部内置商模型，对齐后表现为：保存 key → 探查 → 状态点变绿 + 该商模型可勾选（原本就显示，勾选即用）。
- **enabledModels 无 provider 字段**：provider 级启停完全由白名单表达。全启用 = settings.json 无 `enabledModels` 键；停用整商 = 白名单里去掉该商全部条目（从全启用态停用 = 写其余各商的经验证 glob `provider/*` / `provider/**`）；部分启用 = 显式条目。侧栏 `x/N` 徽章仅在白名单收窄时显示。
- **白名单语义陷阱**：patterns 解析为空 = 全部启用（pi 的回落规则）；关掉最后一个启用模型必须拒绝（`last-model` guard，pi-web 409 同款）；失配（stale）条目对所有编辑操作不可见、永不触碰。
- **pi-web 的 OAuth 登录** = SSE 事件流 + 浏览器授权 + 手工粘贴回调（`OAuthPastePanel`），成本高，本期不做（决策 2）。
- **051 联动**：key 存系统凭据库、`pf-auth.json` 只留变量名、spawn 注入官方 env 名；**换 key 注入的是子进程环境，重启会话才生效**——探查通过后的提示必须带上这点。
- **会话内切模型（inputpanel 点行）是会话级的**（RPC `set_model`，不落盘）；落盘的只有星标默认模型。pi-web 同款分工（星标才是 pi Ctrl+S 的等价物）。

## 核心功能盘点
注意，代码层尽量对齐pi-web，对齐后再进行界面优化

### 供应商管理
- 列出注册的供应商，区分PI内置和用户自定义（合并列表：内置与自定义混排显示名序）
- 新增自定义供应商【添加模型商】，弹窗对齐 pi-web 两组（决策 2）
- 启用/停用供应商：switch 整商开关，落 enabledModels，不动凭据（决策 4）
- 删除供应商：仅自定义商可删（详情页【移除】）；PI内置供应商不删除，只可断开连接（详情页，删凭据）

### 模型管理
- 列出"启用"模型（Provider 行下平铺，见 UI 定稿）
- 设置"默认"模型（五角星，唯一，存 app-settings）
- 自定义供应商：增加、删除模型（表单编辑，现状保留）
- 启用/禁用模型（详情区可用模型行开关，现状保留）
- 为超长模型列表提供筛选功能（OpenRouter 几百个模型：详情区 >8 出现；合并列表启用总数 ≥10 出现，与菜单同规则）

### 保存 apikey 后的探查通路（决策 3 展开）

- **端点表**：pi-link 固化 `内置商 id → (列模型 URL, 鉴权样式, key env 名)`，URL/样式对齐 pi-web `lib/model-discovery.ts` 的构造规则（openai 系补 `/models`、anthropic 加 `x-api-key` + `anthropic-version`、google 加 `x-goog-api-key`）；env 名与 051 的 `injectAs` 映射表同源，随 vendor pin 固化、pi-link 符合性测试看护。表里没有的商跳过探查（直接已配置态）
- **自定义商**：读 models.json 的 `baseUrl` + `api` 字段走同一 URL 构造规则；key 按 `$PF_KEY_*` 引用从凭据库解（明文/`!cmd` 引用原样不探查）
- **三态结果**：`通过（延迟 + 模型数）` / `key 被拒（401/403）` / `网络不可达（超时/DNS，附原因）`；20s 超时
- **结果只驱动 UI**：状态点与探查行文案，**不回滚保存、不改 models-store**——可能是网络问题，key 留着
- 通过后提示：「新会话生效；运行中会话需重启后可用」（051 §8）

### 新增 Provider 弹窗（对齐 pi-web AddProviderPicker 代码）

- **数据源 = SDK 全量注册表**（不是 available 集合）：pi-link `registry.rs` 起一次性 node 走 SDK 自己的 API（`ModelRuntime.create({ refreshOnCreate:false })` + `getProviders()/getModels()/listCredentials()`）dump JSON，落 `~/.pi-flash/registry-cache.json`，vendor VERSION 为缓存键。RPC `get_available_models` 是凭据过滤后的 available，只有少数商——这就是早期弹窗只列 5 个 provider 的根因。
- 版式：近满窗大面板（980×88%）+ 顶部全宽搜索（分隔线压底）+ 滚动卡片网格（卡 = 左名称+副标题、右 provider 图标，自定义卡右侧虚线加号框）
- 分组与组序（2026-10-10 定稿：API KEY → 订阅服务；**自定义组已移除**——PF 只提供内置 + 订阅，存量自定义商走左栏合并列表既有编辑器）：
  - **API KEY**：声明 `auth.apiKey.login` 且当前凭据非 `api_key`；副标题 `N models`（全量 registry 计数，与启用开关无关）→ 点击进详情区 API KEY 表单
  - **订阅服务**：声明 `auth.oauth` 且当前凭据非 `oauth`；副标题 `OAuth`；点击提示「暂未接入」（OAuth 登录缓行，051/beads pi-flash-1cb）。OAuth 显示名走覆盖表（openai-codex→ChatGPT Plus/Pro、github-copilot→GitHub Copilot）→ oauth.name → provider.name
- 组内保持 registry 原始顺序不排序（pi-web 同款）；PF 自定义账本的 provider 不进 API KEY 组（pi-web 排除 custom sources 同款）；搜索：API KEY 匹配显示名/id、订阅服务匹配显示名、自定义卡反向子串
- 已配置的商不进弹窗（pi-web `!configured` / `!loggedIn` 同款）；弹窗打开即后台拉注册表（缓存命中同步可用），未就绪时自定义卡照常可用
- 弹窗挂载在 settings 之后（后渲染者在上——原先被设置面板盖住，遮挡层吃掉全部点击）
