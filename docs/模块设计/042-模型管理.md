## PF 特有改动

1. **默认模型存 PF 自己的 `~/.pi-flash/app-settings.json`**（`default_provider`/`default_model` 两键，snake_case）：pi 的 settings.json 是系统 pi / pi-web 的地盘。应用链路：spawn 时以 `--model` 带给**全新草稿**（重绑/恢复的会话不动）。无 PF 星标时的兜底链：pi settings.json 默认模型（在启用范围内 ∧ 该商有凭据）→ 显示名序第一个。
2. **新增 Provider 弹窗三组：自定义 → API KEY → 订阅服务**：自定义卡 = OpenAI/Anthropic 兼容端点，点击直接进空白新建表单；OAuth 登录归 pi、PF 不发起（051 边界），订阅卡点击仅提示未接入。
3. **保存 apikey 后自动探查**（PF 超出 pi-web 的优化）：保存即向该商列模型端点发一次 GET 做连通检查，key 错误在保存时刻暴露（否则要重启会话才发现）；结果只驱动详情状态点，**不落任何目录**（内置商模型列表 = pi 自带注册表，models.json 零写入）。
4. **停用 ≠ 删凭据**：供应商/模型启停全部走 enabledModels 白名单（可逆，凭据保留）；删 key 只在详情页【移除】。

## 设计事实

- 模型目录与凭据无关：内置商模型列表来自 SDK 静态注册表（registry dump 缓存，+ models-store.json 目录 overlay + 自定义清单仓），保存 key 后模型「可勾选」，列表本身常在。
- enabledModels 无 provider 字段：整商启停 = 白名单增删该商条目（从全启用态停用 = 写其余各商的经验证 glob）；全启用 = 无 `enabledModels` 键；侧栏 `x/N` 徽标仅白名单收窄时显示。
- 白名单语义：patterns 解析为空 = 全启用（pi 回落规则）；停用最后一个启用模型必须拒绝（last-model guard）；失配（stale）条目对编辑不可见、永不触碰。
- 会话内切模型（菜单点行）是会话级的（RPC `set_model` 不落盘）；落盘的只有星标默认模型。
- 051 联动：key 存系统凭据库、auth.json 只放 `!pif-secret get <provider>` 标记条目；换 key **运行中会话需重启才生效**（pi 的命令结果按进程缓存）。

左栏 = 单一合并列表；右栏 = 详情。无页面级 banner / footer（改动即写盘；models.json 不可读的错误挂详情区错误条，保存禁用逻辑保留）。

│     GLM-5.3-Flash               ★    │ ← 该商启用模型平铺（★ = 默认，唯一）
│ ⛨ DeepSeek          1/2  [开关]      │ ← 有启用模型的
│     DeepSeek V4.1 Flash         ☆    │
│ ⛨ OpenAI            0/44 [开关]      │ ← 没模型的沉底
│ ───────────── 分隔线 ─────────────   │ ← 内置及插件在上，自定义在下
└─────────────────┬────────────────────┘

- 合并列表（单一 vlist 虚拟化，全表等高行）：
  - Provider 行 = 图标 + 显示名 + `x/N`（白名单收窄时）+ switch。switch = enabledModels 整商切换（内置/自定义一致）；未配置 key 的内置商恒关禁用，点行进详情配 key。
  - 模型行 = 缩进槽 + 显示名 + thinking pin 徽章 + 五角星，与菜单共用组件（`group_model_row`）；**点模型行打开模型详情弹窗**（内置模型走 modelOverrides 只读覆盖视图，自定义模型进编辑器；行内开关/五角星自己拦截不误触）。
  - 分组：内置及插件在上、自定义 Provider 在下（分隔线隔开）；组内排序三档：默认模型所在 Provider → 有启用模型的 → 没模型的；档内按 Provider 显示名字典序，组内模型按显示名字典序。
  - 过滤框：启用总数 ≥10 才显示（`MODEL_FILTER_MIN`，与菜单同规则，阈值以下文本不参与过滤）；只筛模型行，Provider 行常驻。
- 默认模型（五角星）：实心 = 当前默认（全局唯一）；点星写 app-settings 并同步设置页与菜单；再点 = 取消（无默认时按兜底链显示）。
- Provider 详情（内置商，自上而下）：
  - 标题行 = Provider 显示名（左）+【移除】【保存】（右，同宽 84）：【移除】确认「删除 X 的 API Key，并不再显示？」后删该商 api_key 凭据条目（含钥匙库条目），商家自然从合并列表出列（无隐藏清单）；重新保存该商 key（或从新增弹窗配置）即恢复显示。
  - API Key 段 = 标题 + 全宽输入框（右缘内置眼睛图标切换显隐）。已配置的把已存 key 解出预填进输入框（掩码 `***` 显示），不显示已配置状态与存储落点文案。
  - 可用模型段 = 「可用模型 N/总数」（左）+【获取模型】（右，隐藏，见下节）；失败原因挂详情错误条（详情页唯一信息栏，按钮下方右对齐）。
- 可用模型区：已启用 x/N + 只看free 开关（标题行、刷新钮左侧；开 = 列表只显示 id/名字含 `free` 的模型，筛选叠加隐藏的 free 关键字——AND 语义、不写进输入框）+ 全部开启/关闭 + 筛选（>8 出现）+ 行开关（last-model 守卫）+ vlist 虚拟化。

### 获取模型（决策 3）

- 内置商「获取模型/刷新」UI **隐藏不删**（`Chat::BUILTIN_FETCH_UI = false`）：内置商列表 = pi 自带注册表，无需 key 即罗列全部，代码路径保留、翻开开关即复现。
- 保存 key 后的自动探查（`mc_probe_start`）只做**连通检查**：端点 = registry dump 的 SDK baseUrl/api 经 `registry::models_list_target` 机械派生（无手写端点表、零厂商/模型名硬编码）；key 按 `auth_json::resolve_secret` 从凭据库解（用户明文取原值）。
- 20s 超时；三态：通过（只亮状态点）/ key 被拒（401/403，挂错误条）/ 网络不可达（附原因）。结果**不落任何目录**——probe 不回滚保存。
- 【获取模型】钮与自动探查同一条链路（`mc_fetch_models` = `mc_probe_start`）。
- 换 key 需重开会话生效（051）。

### 新增 Provider 弹窗

- 数据源 = SDK **全量注册表**（非凭据过滤后的 available）：`pi-link::registry` 起一次性 node 走 SDK API（`ModelRuntime.create({refreshOnCreate:false})` + `getProviders()/getModels()/listCredentials()`）dump，落 `~/.pi-flash/registry-cache.json`；vendor VERSION 不一致 / 非纯静态 dump / 计数为空 / 缺 baseUrl 或模型字段均视为失效重 dump。
- 版式：近满窗大面板 + 顶部全宽搜索（分隔线压底）+ 滚动卡片网格（卡宽 292 = 左名称+副标题、右 provider 图标，无图标走首字母兜底）。
- 组序：**自定义 → API KEY → 订阅服务**。自定义 = OpenAI/Anthropic 兼容端点卡，点击关闭弹窗进空白新建表单（重名 -N）；API KEY = 声明 `auth.apiKey.login` 且无 api_key 凭据、副标题 `N models`（registry 全量计数，与启用开关无关）→ 点击进详情 API KEY 表单；订阅服务 = 声明 `auth.oauth` 且无 oauth 凭据，副标题 OAuth 显示名（覆盖表：openai-codex→ChatGPT Plus/Pro、github-copilot→GitHub Copilot），点击提示未接入。
- 组内保持 registry 原始顺序；已配置的商不列（`!configured`/`!loggedIn` 同款）；models.json 已有同名条目的商不进 API KEY 组；搜索：API KEY 匹配显示名/id、订阅匹配 OAuth 显示名、自定义卡按端点字样显隐。
- 打开弹窗即后台拉注册表（`ensure_registry`，缓存命中同步可用），未就绪/失败显示状态行。
- 弹窗挂载在 settings 之后（后渲染者在上，否则遮挡层吃掉点击）。

## inputpanel - 模型菜单

- 锚定模型钮的 pill 菜单（与扩展/MCP 菜单同机制、统一定位算法）；顶部过滤输入按 `MODEL_FILTER_MIN` 阈值显隐，↑/↓/Enter 键盘导航。
- 卡片宽 380px（模型名 + 右缘星标不贴边）。
- 按 provider 分组，组头 = provider id 大写；行 = ✓槽位（当前会话模型）+ 显示名 + pin 徽章 + 五角星。
- **标星默认模型置顶**（五角星 = app-settings 默认，全局唯一）：默认模型所在 Provider 组置顶、组内默认模型置首；其余 Provider 保持目录出现序（组序不二次排序，避免把置顶商打回原位）。序由纯函数 `order_model_indices` 产出（单测看护），菜单行序 = 键盘选择序 = Enter 落点序（同一 vec 下标，↑/↓ 高亮与落点不漂移）。
- 内容超高时：列表滚动 + 右缘常显滚动条（`ui::psp_scrollbar::menu_scrollbar`）；列表高 = min(内容高, 10 行上限, 视口可用高)（卡片不顶出窗口上沿）；↑/↓ 选中行自动滚进可视区。
- 点行 = 会话级切换（`set_model`）；点星 = 设默认（写 app-settings，与设置页同一份、双向同步）。
- 数据走 Chat 共享目录（`catalog_for`），无进程草稿照常弹出。

## 程序设计

- `app/src/services/models_config.rs`：白名单全量语义（pattern 匹配 / glob 展开 / `:level` pin / stale 保留 / last-model 守卫 / 整商开关），单测看护。
- `pi-link/src/registry.rs`：全量注册表 dump + 缓存（vendor VERSION 键、staticOnly/字段失效守卫），分组/凭据过滤/OAuth 显示名覆盖表为纯函数，单测看护。
- `pi-link/src/probe.rs`：三模块探查（① api type 判定 ② 连通 ③ 拉目录 + 响应字段 best-effort 解析，单测看护字段映射）；`pi-link/src/catalog.rs`：磁盘目录装配（models.json + models-store.json）。
- `app/src/session/model_picker/`：菜单 + 两处共用组件（`group_entries` / `group_header_row` / `group_model_row` / `MODEL_FILTER_MIN`）+ 注册表后台拉取（`ensure_registry`/`RegistryState`）。
- `app/src/settings/models/`：设置页合并列表（内置/自定义分列 + 三档排序）/ 详情 / 探查行 / 星标（写 app-settings 并扇出全部 runtime）。
- `app/src/dialogs/provider_picker.rs`：`render_provider_picker`。
- 自动化面：`model.picker_open` op + 快照键 `model_rows`（语义：可见模型数）。
