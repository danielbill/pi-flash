# 90-9 插件生命周期设计（定案）

> 2026-10-30 定案。上位：`90-1-插件设计需求.md`（需求来源）、`090-1-插件的生命周期管理`（议题）。
> 相关：`90-9-插件生命周期设计.md`（load/unload/plugin-ctx）、`90-4`（清单/运行）、`90-5`（PF 钩子）、`90-6`（执行域实例）、`90-7`（wasm 测试）、`90-8`（开发闭环）。
>
> 一句话：**插件侧只有两个接口 `load` / `unload`；宿主侧一条销毁路径（停用）；一切可观测性落 `plugin.log`，不做自动惩罚。**

## 1. 结论速览

| # | 结论 |
|---|---|
| 1 | 插件导出面 = `load(plugin-ctx)` + `unload()`，两个都必需（`unload` 允许空实现） |
| 2 | 没有 `init`：插件的自我初始化发生在 `load` 内，由插件自己完成 |
| 3 | PF → 插件的上下文统一叫 `plugin-ctx`，**常量与变量装在同一个对象里**，每次调用都给完整一份 |
| 4 | 插件 → PF 的呈现申请仍是**清单声明**（不改成运行期交换） |
| 5 | 销毁路径收敛为一条：**停用**（卸载 = 停用 + 删；更新 = 停用 + 覆盖；退出 = 全体停用） |
| 6 | 宿主保留状态机与事件流水，落 `<插件目录>/plugin.log` |
| 7 | 本版**不做**加载超时强杀、不做自动隔离、不做错误码分类——先观测，用数据再定策略 |

## 2. 插件侧接口

| 接口 | 必需 | 语义 |
|---|---|---|
| `load(plugin-ctx)` | 是 | 被 PF 加载。建立自身状态、注册回调、交出运行期动作能力 |
| `unload()` | 是（默认空） | 被 PF 卸载前的最后一次调用：停用 / 卸载 / 更新覆盖 / PF 退出 |

- `unload` 无返回值、限时、超时强杀（best-effort，不做"等插件确认存盘"，否则关不掉的插件能卡住宿主）。
- 异常处理：`load` 抛错/超时 → 本次会话禁用该插件 + toast + `plugin.log` 记一条；**不影响宿主**。
- 词汇作废：`init` / `activate`（插件级）一律改称 `load`。执行域**实例级**的 `activate(svc)` / `onStop`（`90-6`）是另一层，名字不动。

## 3. `plugin-ctx`（PF → 插件）

每次调用都给完整一份，**永远是最新的，插件永远不保存它**。

```json
{
  "plugin":  { "id": "pf-wxbot", "version": "0.2.0", "dataDir": ".../plugins/pf-wxbot/data" },
  "pf":      { "version": "0.1.x", "locale": "zh-CN" },
  "session": { "key": "pf-wxbot-2610302104129" },
  "cwd":     "/path/to/project"
}
```

规则：

- **会话身份只从这里来**（收编 `90-5` 的「唯一会话身份 = 宿主下发」）。无会话时 `session` 为 `null`。
- 字段**只增不改**：新增字段不构成破坏性变更，旧插件忽略未知字段即可。
- 开关翻值等**输入事件**不是上下文，作为动作参数另传（如 `{"value":true}`）。
- 禁止把可变身份塞进"一次性 ctx 里存着用"——ctx 就是一次性的，状态变了下次调用自然变。

## 4. 插件 → PF（呈现申请）

保持 `90-2`/`90-4` 的**声明式清单**：区域（status_bar / topbar_menu / fn_bar / popups / panels）、图标、标题全部写在 `pf-plugin.toml`。

理由：市场扫描、加密包验签前上架、启动零代码执行都依赖"清单静态可读"。

运行期只保留**动作型**能力（不改区域/图标）：

- `act.openPopup` / `act.closePopup`
- 会话列表徽标（`session_row` 钩子返回值）
- 临时开关（启用位由宿主台账管）

## 5. 宿主状态机

```
Registered ──load──> Loading ──ok──> Active
                        │err            │停用
                        └──> Crashed    ▼
                                     Unloading ──> Disabled
                                     Unloading ──> Uninstalled（目录已删）
```

- 状态是**宿主事实**，插件不可见（插件可查的只有执行域实例态 `ctx.service.query`，`90-6`）。
- 每次转移写一条事件（见 §7）。

## 6. 销毁路径（唯一入口 = 停用）

| 场景 | 动作序列 |
|---|---|
| 停用（用户点开关） | 全体实例 `onStop` → `unload()` → 丢运行时 → 状态 `Disabled` |
| 卸载 | 停用 → 删插件目录（含 `plugin.log`、`.cache/`） |
| 更新 | 停用 → 覆盖新版本 → 下次装载走新包 |
| PF 退出 | 全体插件 `unload()`（总预算 1 秒）→ 停 pi 子进程 → 存窗口状态 |
| 会话切换 / 项目切换 | **不触发 `unload`**（会话级收尾归执行域 `onStop`） |

退出顺序固定为：`unload` → 停 pi → 存窗口状态。理由：带 `pi_extensions` 的插件需要在 pi 进程还活着时说完最后一句话。

## 7. `plugin.log`

位置：`<插件目录>/plugin.log`（**每插件一份**；卸载随目录删；详情页直接读）。

行式，人可读，含时间与耗时：

```
2026-10-30T21:04:12 load   ok    3120ms   (首次验签+编译)
2026-10-30T21:10:03 load   ok       8ms   (cwasm 缓存命中)
2026-10-30T21:44:51 unload ok       2ms
2026-10-31T09:12:07 load   ERR     45ms   proof rejected: kid missing
```

**成对判定（崩溃识别）**：`load` 与 `unload` 必须成对。启动时读最后一个未闭合的 `load` → 判定上次异常退出 → 追加一条 `[上次异常退出，未执行 unload]`。不需要任何哨兵文件。

**用户可见**：插件详情页展示最近一次 `load`/`unload` 耗时、失败次数、最近一条错误，并给出"禁用此插件"开关——由用户自行判断，宿主不替人做隔离。

## 8. pi 侧扩展（`contributes.pi_extensions`）

- 不归 PF 管生命周期：扩展随 pi 子进程生死，PF 只决定"下次 spawn 时挂什么"。
- 唯一耦合窗口 = PF 退出时那 1 秒 `unload`：插件可经执行域通道与 pi 侧告别；**不提供 ack**。
- 停用/更新后的摘除：走既有"写会话清单 + 空闲重启挂载"，`plugin.log` 记一条 `pi-extension 待生效`。
- 版本偏差（更新后 pi 侧仍跑旧码）：`plugin.log` 记录"下次 spawn 生效"，详情页可见，不静默。

## 9. 本版不做（明确推迟）

| 项 | 理由 |
|---|---|
| 加载超时强杀（1s 一类阈值） | 首次装载实测 3.2s（验签+编译），一刀切会误杀；等日志攒够真实分布再定 |
| 自动隔离 / 下次启动自动关闭问题插件 | 与「启动不播报」冲突，且需要解封入口；先给用户手动开关 |
| 错误码封闭枚举 | 先按事件 + 错误串记录，分类等有样本后再做 |

## 10. 落地口径

1. **契约**：`manifest_schema` 升 5（导出面 `load`/`unload` 为 ABI 变更）。
2. **wasm 面**：WIT 导出 `init` → `load`，新增 `unload`；`plugin-ctx` 作为参数串（JSON）下发。
3. **过渡兼容**：宿主优先调用 `load`，缺失时回退旧 `init`/`activate`，保证在役包（wxbot）不断。
4. **JS 载体**：随 wxbot 转 wasm 后整条退场（`js.rs`、`qjsc`、`rquickjs`、`90-4 §5`）；退场顺序见 `90-8`。
5. **门禁**：`load`/`unload` 的时序与 `plugin.log` 断言进 L2；面板/功能栏/弹窗走 L3（`pif-ui`）。

## 11. 验收口径

1. 停用插件 → `plugin.log` 出现成对 `load`/`unload`，耗时可见。
2. 强杀 PF → 下次启动该插件日志出现「上次异常退出」一条。
3. PF 退出顺序：`unload` 先于 pi 子进程退出（可在日志时间戳上验证）。
4. 会话切换不产生新的 `load`/`unload`。
5. 详情页能读到耗时与失败次数，开关能直接禁用。
