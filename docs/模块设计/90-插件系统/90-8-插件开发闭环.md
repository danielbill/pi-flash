# 90-8 插件开发闭环（唯一合法开发流程）

> 上位：`90-4`（载体优先级条）、`90-7`（wasm 测试链路）。
> 目的：把「改一行 → 知道好坏」的往返压到秒级，**让人肉验收只发生在最后一次**。

## 0. 一条铁律

**PF 官方插件唯一开发载体 = Rust→wasm。禁止先写 `main.js` 再移植。**

- 加密只能靠 wasm 编译产物（JS 载体无加密能力）。


## 2. 三层门禁（缺一层就不许提交）

| 层 | 覆盖 | 跑一次 | 归属 |
|---|---|---|---|
| **L1 编译 + 契约** | wasm 编译通过、清单过契约 check、WIT 面对齐 | 秒级 | 插件仓 `npm run dev` 内建 |
| **L2 逻辑** | 钩子返回值、动作序列、验签门、状态机 | 秒级 | 插件仓 `npm run test:wasm`（`90-7` 瘦协议 + PF 的 `plugin-test` runner） |
| **L3 接线** | 装包 → 台账 → 装载 → 面板出现 → 交互 → 事件回灌 → 停用/卸载 | 十秒级 | **pif-ui 自动化**（`.agents/skills/pi-flash-ui-test/SKILL.md`）驱动隔离实例 |

**提交前 L1+L2+L3 全绿**；任何一层红着提交 = 把往返时间转嫁给用户。

## 3. 一条命令的开发循环（脚手架目标）

```
npm run dev -- <slug>      # 编译 wasm → 现签 proof → 投 dev 数据目录 → 热重载
npm run test:wasm -- <slug>   # L2
npm run e2e -- <slug>         # L3（PIF 隔离实例，禁抢真实屏幕/鼠标/键盘）
```

- 部署链路已有：`scripts/link-dev.mjs --wasm --pkg <slug>`（清单由源清单生成、残留 `main.js` 自动清）
- 缺口：**生成器**（`npm run new -- <slug>`，插件仓 README 的 crate 模板 TODO）、
  **一条龙 dev 脚本**、**PF dev 热重载**（dev 数据目录 `plugins/` 变更即
  `reload_plugin_by_pkg`；`load_cached` 已按 sha256 缓存，换文件天然失效）。
  release 不启用 watch，零输出烟测门禁不变。

## 4. 验收口径

- **开发期**：Agent 只对三层门禁负责，不看界面截图验收。
- **验收期**：用户一次人肉终验（真机视觉 + 手感），不做往返式"改一点看一眼"。
- **L3 用例属于插件仓**：PF 仓内零插件身份（`90-7` 解耦红线不变）。

## 5. 新增能力的顺序（防止再次双实现）

1. 契约/WIT 先落（`schema/plugin-contract.json` + 插件的 `wit/pf-plugin.wit`）；
2. Rust 实现 + L2 用例；
3. 宿主接线 + L3 用例；
4. 清单/文档最后补。

**禁止顺序**：先写 JS 跑通 → 再移植 Rust → 再回头补 WIT。
