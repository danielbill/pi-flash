# 90-4 插件存储与运行（context 接口 v2）

> 当前契约版本 **v2.2**（`grid`、`panel-frame` 外壳）。配合 `90-3-插件UI组件规范.md` 与
> `schema/plugin-contract.json`（机器真源）。定四件事：**目录、清单、
> context 能力接口、加载时机**。
>
> 原则一句话：**位置与时机归宿主，内容与格式归插件。**
>
> 执行域：`ctx.service.*` 与 `activate(svc)` 见 `90-6-插件执行域-plugin-context.md`（机器真源 `schema/plugin-contract.json`，本文不重抄）。 宿主管目录、原子性、卸载清理；
> 插件管自己数据长什么样——**PF 从不解析插件数据**。
>
> **载体优先级**：PF 官方插件**唯一开发载体 = Rust→wasm**（§7 为主干）。
> JS 标准包（§5）冻结为存量兼容面：**新插件、新能力一律不得先落 JS**，开发闭环见
> `90-8-插件开发闭环.md`。

## 1. 插件目录（PF 统一）

```
<数据目录>/plugins/<id>/
  pf-plugin.toml     清单（PF 读，见 §2）
  main.js            逻辑入口（§5）
  assets/            图标等静态资源（可选）
  data/              插件私有数据目录（PF 首次加载时创建，插件读写，PF 不解析）
```

- `<数据目录>`：debug = `pi-flash-dev/`，release = `~/.pi-flash/`（`paths.rs` 既有）
- `<id>` = 目录名 = 清单 `id`（如 `example`）
- PF 保证：目录存在、`ctx.dir` 指向 `data/`、**卸载时整目录删除**
- **PF 不解析 `data/` 下任何文件**——存储是插件自治领域

## 2. pf-plugin.toml（PF 读的清单）

```toml
schema = 2                        # = 契约大版本（manifest_schema）；高于宿主支持 → 拒装
id = "example"
title = { zh = "示例面板", en = "Example Panel" }
version = "0.1.0"

# 申请进驻（PF 画，不给就什么都不出现）；v2.5 入口二选一：
# 状态栏 status_bar 或 topbar 菜单 topbar_menu，不得同时声明；
# v3 新增注册面：fn_bar（会话标签功能栏槽）+ popups（非模态弹窗），见下
[[contributes.status_bar]]
icon = "assets/icon.svg"          # 状态栏 tab 图标（相对本目录，单色 SVG）
title = { zh = "示例" }

# —— 或（二选一）——
# [[contributes.topbar_menu]]     # topbar「菜单」三横浮层里的条目（v2.5）
# title = { zh = "示例功能", en = "Example" }
# icon = "assets/wx.svg"          # 规则同 status_bar icon

[[contributes.file_menu]]         # 文件右键 → 插件 → 该项
id = "add-pin"
title = { zh = "加入收藏", en = "Add Pin" }
icon = "pin"                      # 宿主内置图标名（90-3 §3.4）

[[contributes.panels]]            # 点击状态栏 tab 打开的面板
id = "quick"
title = { zh = "示例" }
entry = "main.js"                 # 逻辑入口

# —— v3（90-3 §4A/§4B）——
# [[contributes.fn_bar]]          # 会话标签功能栏注册槽：每个会话标签一个示例 icon
# command = "bind"                # 点击回环命令（env 带当前 session.key）；chrome 由 main.js 导出 fn_bar(ctx, env) 给

# [[contributes.popups]]          # 非模态弹窗：内容由 main.js 导出 render_popup(ctx) 给
# id = "info"
# title = { zh = "示例弹窗", en = "Example Popup" }
# size = "MD"                     # SM/MD/LG 档位（MD≈500x500，映射归宿主）
# entry = "main.js"
```

校验（`check.mjs` 与宿主同读 `schema/plugin-contract.json`）：
- `schema` 必须 = 契约 `manifest_schema`（当前 = **3**）；更高 → 记日志跳过（不降级运行）
- `id` kebab-case 且 = 目录名
- `contributes.*` 全可选；至少一种可装载内容（panels/popups/fn_bar/status_bar/topbar_menu/file_menu 任一）
- `icon` 三来源：宿主内置名 / `assets:<名>` / `assets/` 相对路径
- `entry` 必须存在
- **禁用字段**：`layout` / `store` / `api` —— 出现即报错；
  `wasm` 字段仅内层包可用（§7），标准包出现即报错

## 3. context 能力接口（插件拿到的唯一东西）

装载后插件获得 `ctx`，**此外没有任何全局可调**（没有 fs / net / process）。

```js
// —— 提问（同步）——
ctx.isExecutive(path)            // → bool     宿主按后缀/平台判定（script_exec 同表）
ctx.fileIcon(path)               // → 不透明引用，直接放进 button.icon，只透传不解释

// —— 持久化（插件自管，宿主只保证目录与原子性）——
ctx.dir                          // → string   私有目录（data/）绝对路径
ctx.fs.read(name)                // → string   整读；缺失/坏文件 → ""（插件自己兜底）
ctx.fs.write(name, str)          // → void     原子写（临时文件 + rename），只限 ctx.dir 内
ctx.fs.list()                    // → string[] 目录下的文件名

// —— 动作（宿主执行）——
ctx.run(path)                    // 021 执行链，新终端 tab
ctx.edit(path)                   // 编辑器/查看器打开
ctx.revealInExplorer(path)       // 资源管理器定位
ctx.toast(msg)                   // 轻提示
ctx.act.openPopup(id)            // v3：打开清单 popups 条目（非模态，宿主管定位/随手关）
ctx.act.closePopup(id)           // v3：关闭

// —— 宿主证明（内层 wasm 插件专用，§7）——
ctx.hostProof(nonce)             // → { kid, proof, nonceTag }  官方构建证明；宿主只递数据不判定

// —— 注册（activate 里调，unload 自动回收）——
ctx.onMenu(id, handler)          // 清单 file_menu 项的回调。handler({ path, fileIcon })
ctx.onCommand(id, handler)       // 组件 menu 项 / fn_bar 点击 / switch 翻转的回调（01 §4.2/§4.3）。
                                 // handler({ path?, session?: { key }, value?: bool })——按入口给：
                                 // file_menu→path；fn_bar 触发→session（当前会话键，v3）；switch→value（翻转后布尔，v3）
ctx.onPanelOpen(handler)         // 面板激活回调。handler()
ctx.onBroadcast(name, handler)   // 宿主标准组件状态广播（v2.4）。封闭事件集：
                                 // inputpanel / claim（v2.4）+ session（v3：会话标签激活/切换，
                                 // payload { key }；页面未激活不产生）

// —— 会话徽标（v3；owner = 插件 id，多插件互不覆盖）——
ctx.sessions.setBadge({ session, icon, tone })  // 会话列表时间位标记（icon 档位 md）；
                                                // session 与 fn_bar env、pi getSessionId() 同源
ctx.sessions.clearBadge({ session })
```

约定：
- **`fileIcon` 是不透明引用**：插件不解释、只透传（90-3 §3.3）
- **`onMenu` 触发时宿主已拿全路径**，`{ path, fileIcon }` 两个现成字段一起递来，插件不用二次问
- **`data/` 之外的路径写不进去**：`fs.write` 越界 → 报错，不落盘
- **任何注册回调返回后，宿主自动重渲染该插件面板**——插件不需要通知、不需要事件
- **`hostProof` 标准 JS 包禁用**：判定必须在 wasm 内（090-5 L3.3），见 §7；
  违反 → `check` 报错（90-3 §9 U14）
- 动作目标路径不存在 → toast 报错，不抛异常
- 插件逻辑抛异常 → 宿主捕获、toast「插件 <id> 出错」、该插件本次会话禁用（§4）

## 4. 加载时机（启动只承担清单）

```
PF 启动
  └─ 首帧后异步：扫 plugins/*/pf-plugin.toml（纯清单解析，微秒级/个）
      ├─ 校验通过 → 注册右键菜单项 + 状态栏 tab（此时 ctx 未建、data/ 未读）
      └─ 校验失败 → 记日志跳过，不注册

用户点击状态栏 tab            → 懒加载：建 ctx → render → 渲染面板
用户点右键菜单项              → 懒加载同上 → onMenu → 返回后重渲染 → 释放（不驻留）
用户点格子右键菜单项          → onCommand → 返回后重渲染
插件自己写了数据              → 无需通知，下一次 render 自然读到
PF 退出                       → 无需保存（每次写都即时落盘）
```

- **清单启动加载，数据懒加载**：N 个插件不拖启动
- 同一插件的 ctx 全局单例：面板开着时点右键菜单，复用同一 ctx 与同一份内存缓存
- 插件逻辑抛异常：捕获、toast「插件 <id> 出错」、该插件本次会话禁用，**不影响宿主**


## 6. PF 侧责任清单（实现对照）

| 项 | 触点 |
|---|---|
| 扫描 + 清单解析 | `paths::plugins_dir` + 极简 toml 解析（一层扫描） |
| 状态栏 tab 注册 | 状态栏 tab 体系（icon + title，点击切 ContentView） |
| 右键菜单注入 | `tree_menu` File 分支追加「插件」组 |
| ctx 构造 | `script_exec::exec_kind`（isExecutive）、`file_icons`（fileIcon）、`shell_open`、`open_file_tab`、`open_script_terminal` |
| 私有目录 | `plugins/<id>/data/` 创建 + 卸载删除 + `fs.write` 原子写（临时文件 + rename）+ 越界拒绝 |
| 面板渲染 | 01 组件树 → gpui（树解释器：column/row/group/divider/text/icon/button；**不认字段、不 filter、不折算动作**） |
| 回调后重渲染 | `onMenu` / `onCommand` / `onPanelOpen` 返回即刷新该面板 |
| 异常隔离 | catch + toast + 会话级禁用 |
| 宿主证明交付 | `build.rs` 注入常量 + `ctx.hostProof()` 递数据；不验签不解释（§7） |

## 7. 内层 wasm 插件与宿主证明（v2.3）

内层包 = wasm 载体 + 宿主证明校验：宿主交付一份构建期注入的签名材料，插件侧
验签，非指定宿主则拒载。签名只是交付形态，载体本身是加密包。

### 7.1 两种包形态

| | 标准包（公开市场） | 内层包（内部分发） |
|---|---|---|
| 结构 | `pf-plugin.toml` + `main.js` +（可选）`assets/` | `pf-plugin.toml` + `plugin.wasm` +（可选）`assets/` |
| 清单判别 | 无 `wasm` 字段 | `wasm = "plugin.wasm"`（出现即按内层包处理；`forbidden` 的 wasm 仅约束标准包） |
| 逻辑 | QuickJS 同步 `main.js`（§5） | wasm 模块，宿主按内层流程装载 |
| 分发 | 公开市场索引 | 本仓 `inner/` 产出 → 私有渠道；**永不进市场渠道**（U10 禁 `plugin.wasm`） |

### 7.2 宿主证明流

1. **构建期注入**：已签的证明由发布流水线送给宿主 `build.rs`，烙成二进制常量
   （宿主零密码学、不接触签名材料）；无注入构建嵌占位符 + 构建警告。
   签名流程与密钥流转见内部发布文档（不入库）。
2. **运行期交付**：`ctx.hostProof(nonce)` → `{ kid, proof, nonceTag }`（§3）。
   `nonceTag = hex(sha256(proof ‖ 0x00 ‖ nonce))`，宿主交付时现算；
   宿主不验签、不解释。
3. **插件侧判定**：公钥 + `kid` 编译进 wasm（包内不单独放 key 文件）；
   `activate()` 验签 + 复算 `nonceTag`。占位符/伪造/缺失 → 返回错误**拒载**：
   面板不注册、状态栏不出现、设置页给「此插件要求官方 PF」的明确原因（失败不静默）。
   wasm 面 WIT：`get-host-proof` import 与 `init -> result<_, string>` 错误通道；
   宿主钩子未注入 = 占位符 fail-closed；跨语言自检门已建。
   WIT host 提供 `new-draft(prefix,cwd)`——契约 v2.4
   `ctx.newDraft` 的 wasm 面，意图调用（动作队列，无同步返回），宿主建线后经
   on-event broadcast "claim" 回推 `{key,name,cwd}`；宿主→插件广播走既有
   on-event 通道（`kind="broadcast"`，id=事件名，path=负载 JSON 串）。
   WIT v3 面与契约 v3 / pf-hooks.json 同形：
   world 导出 `fn-bar(env) -> string`（功能栏 chrome {icon,tone,tip}）、
   `render-popup() -> string`（弹窗内联树，空串 = null = 自动收窗）、
   `session-row(env) -> string`（会话列表行徽标 {icon,tone}，空串 = 无徽标）——
   返回的都是已算好的 JSON 串，宿主不折算；host 另有 `open-popup(id)`（契约 v3
   act.openPopup 的 wasm 面，意图调用，id 未声明宿主忽略）；on-event 通道含
   `kind="page-active"`（PF 钩子 page_actived，id 空串，path = env JSON
   `{"session":{"key":…}}`）。env 统一 = 宿主口径会话键。徽标/收窗等「无」
   语义用空串表达（JS 侧 "null" 同语义）。宿主侧接线与旧 wasm 包重编
   见 PF 轨后续工单（8tb.2/8tb.4）。
   内层插件 crate 模板待组件接口收口后重建。

### 7.3 隔离纪律与边界

- 公钥、验签逻辑、签名材料全部只在内层区，**永不随市场渠道外发**；`packages/` + 索引 +
  README 等市场面保持零 wasm、零密钥、零签名材料，随时可整体外发。
- 标准包引用 `hostProof` → `check` 报错（90-3 §9 U14）；`plugin.wasm` 出现在标准包 → U10 报错。
- 防护边界与强度评估属内部口径，不在公开文档展开（见内部发布文档）。
