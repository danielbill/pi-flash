# 90-6 插件执行域（plugin-context）

> 状态：**v1 定案（2026-10-29，决策见 §10）**。上位：`90-1-插件设计需求.md`；相关：`90-2-插件清单与贡献规范.md`、
> `90-5-PF插件钩子.md`、`090-5-插件包防盗设计`（验签门）。
> 真源落点：`schema/plugin-contract.json` v4 增量（本文为散文版，定案即进真源）。
> 范围排除：本规范不涉及分发形态、加密、构建链与插件开发效率（另卷议题）。

## 1. 问题陈述

契约现有执行模型只有**同步回调 + 同步渲染**：插件被装载后被动响应宿主。凡越过此
模型的需求——后台任务、异步 IO、第二执行进程——契约没有任何设施，插件只能自建
私有机制补位。自建的代价是结构性的：

1. **通道自建**：两个执行域之间无官方信道，插件被迫以私有文件当信箱。多个写者
   对同一文件读-改-写、无跨进程互斥，丢失更新只能靠启发式猜测补偿；
2. **身份自猜**：执行域不知道"自己是谁"，只能拿运行时环境的内部标识反推；
   宿主内部身份一迁移，绑定即失效，插件被迫引入容错比较（归一化、双口径、兜底链）；
3. **生命周期自管**：起停、清理、与宿主启停的对齐全靠插件自觉——宿主不可见、
   不可管理、不可诊断；
4. **沙箱破戒**：以上三件逼插件越过「唯一能力面 = 宿主注入」的纪律。

这是框架缺口，不是某一方代码的质量问题——凡需要执行域的插件都会踩同一条路。
本规范把它补成宿主托管的一等设施。

## 2. 模型

- 插件贡献分两类面：**呈现面**（既有：panels / fn_bar / popups…）与**执行面**（本规范）。
- 执行面以**实例**运行。实例 =（插件，锚点）二元组；锚点 = scope 的宿主口径标识
  （session scope 下 = 会话键）。
- **身份是宿主义务**：实例可见的锚点在生命周期内不变。宿主内部身份重构（键迁移、
  进程重建）不得改变插件可见锚点；必要时宿主重建实例并以同一锚点实例化、
  补投未达消息。（本条收编 90-5「唯一会话身份」，并取代其验收中的写法归一口径——
  归一存在即身份设计失败。）

## 3. 清单

```toml
[[contributes.service]]
id    = "<kebab-case>"   # 插件内唯一
scope = "session"        # 本版仅 session；global 保留取值位（§8）
entry = "<相对路径>"      # 执行面入口
```

- 清单面新增 → **`manifest_schema` 升 4**（定案）：旧宿主拒装 v4 包、新宿主拒装 v3 包，不降级；存量包（含纯呈现面包）随 v4 迁移 `schema` 键。
- 执行面是全权代码 → 携带门槛沿用 090-5 L3 验签门：非验签包声明本节 → 安装期拒装。
- 宿主校验：`entry` 必须存在；`scope` 取值封闭；未定案的取值位一律拒装。

## 4. 能力接口（载体中立）

呈现面新增（JS 载体 = ctx 注入；wasm 载体 = WIT 导出；两面同加，契约真源一份）：

```js
ctx.service.post(anchor, msg)      // 发往实例；未运行 → 有界排队（按序，溢出返回 false）
ctx.service.onMessage(handler)     // 收实例推送；返回后宿主按既有规则重渲
ctx.service.query(anchor)          // → "running" | "stopped" | "absent"（宿主生命周期事实）
```

执行面入口（实例化时宿主调用一次）：

```js
export function activate(svc) {
  svc.anchor     // 宿主下发的实例锚点（唯一合法身份来源）
  svc.dir        // 执行面专属存储根（§6）
  svc.globalDir  // 宿主解析的全局数据目录：跨实例/跨进程协调的唯一合法位置；
                 // 执行面不得自行解析 home / 环境变量重算
  svc.post(msg)  // 推送至呈现面
  svc.onMessage(h)
  svc.onStop(h)  // 宿主回收实例前恰调用一次；实现须幂等
}
```

**实例化交付**：`activate(svc)` 一次性收到完整交付——锚点、私有存储根、全局目录、
排队消息按序补投；交付之外，执行面不得依赖任何环境推断获得身份或路径。
```

**通道纪律**：负载对宿主不透明、逐字节透传；每方向 FIFO；至多一次投递，
确认语义由插件协议自理；呈现面未装载时到达的消息，按既有懒装载规则装载后投递，
不可达则丢弃并记日志。

## 5. 宿主托管四职责

| 职责 | 内容 | 灭绝的反模式 |
|---|---|---|
| 身份 | 实例化注入锚点；宿主内部迁移 = 对实例发 identity 系统消息 | 自猜身份、容错比较、双口径 |
| 通道 | 既有会话进程 RPC 管道加一路不透明转发；未运行排队 | 私有信箱文件、轮询采样、整文件覆盖竞态 |
| 生命周期 | 随锚点起收；插件禁用/卸载即停实例 | 插件自管起停、宿主不可见不可诊断 |
| 存储 | 呈现面与执行面存储分根，宿主执行越界拒绝 | 多写者共享单文件 |

## 6. 生命周期

| 事件 | 宿主行为 |
|---|---|
| 锚点出现（session scope = 会话进程建立） | 挂载入口，创建实例，注入锚点，补投排队消息 |
| 锚点消失 | `onStop` → 回收实例 → 丢弃未取排队消息 |
| 插件禁用 | 全实例 `onStop` → 回收；存储保留 |
| 插件卸载 | 全实例 `onStop` → 回收 → 整目录删除（既有语义） |
| 实例异常退出 | 宿主存活；`query` 返回 `"stopped"`；呈现面 post 进入排队 |

## 7. 隔离与可观测

- 实例异常不波及宿主（复用既有异常隔离：捕获、记录、状态可查询）。
- 宿主对每个实例记录生命周期事件（创建/停止/原因），纳入统一 log 规范（90-1 需求 6 的宿主侧部分）。

## 8. 边界（本版不做）

- `scope = "global"`：宿主进程内长驻第三方代码，权限模型另立规范；清单保留取值位，宿主遇之即拒装。
- 会话内渲染、渠道语义：不在本规范；执行面消息面仅为其提供传输底座。
- 分发形态、加密、构建链、开发效率：另卷。

## 9. 与既有规范的关系

- `contributes.pi_extensions`（挂载清单语义）由本规范收编升级为 `contributes.service`
  （实例声明语义）。**定案：一步替换**——v4 起 `pi_extensions` 不复存在，声明即拒装；
  现用包随 v4 迁移为 `service`，无兼容双轨。
- 90-5 钩子不受影响：呈现侧钩子照旧；扩展侧身份获取改走实例注入（90-5 §2.1 纪律条已对齐）。

## 10. 定案记录（2026-10-29）

1. **`manifest_schema` 升 4**：`contributes.*` 新增属清单面变化，升档拒装优于静默忽略。
   旧宿主拒装 v4 包；新宿主拒装 v3 包；存量包（含纯呈现面包）随 v4 迁移 `schema` 键。
2. **一步替换**：v4 移除 `contributes.pi_extensions`，由 `contributes.service` 接位，无兼容双轨。
3. **执行面代码形态**沿用现挂载机制（随包、会话进程内全权），090-5 验签门口径不变。

## 11. 验收口径

1. **身份**：宿主内部身份重构前后，实例可见锚点不变；重建实例后排队消息按序补投。
2. **通道**：实例未运行时 post 排队、按序投递；两端以哨兵负载验证宿主零解析。
3. **生命周期**：锚点消失后 `onStop` 恰一次；重复停止幂等；`query` 状态迁移正确。
4. **隔离**：实例崩溃不影响宿主与其余实例。
5. **边界**：任一面越界写入被拒绝；非验签包声明 `contributes.service` 被拒装。
6. **交付**：锚点、私有根、全局目录均由宿主交付且与宿主解析一致；执行面重算
   全局目录（解析 home / 环境变量）视为违例。

> 插件侧如何采用（含迁移）不属于本规范，由各插件施工单自理。
