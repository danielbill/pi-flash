# 90-2 插件清单与贡献规范

> 2026-10-18 与所有者定案。上位需求：`90-1-插件设计需求.md`。
> 战略定位：**首先服务 CLI 侧 pi packages 生态**（PF 做合格客户端），PF 原生
> 插件 = pi package + PF 壳层贡献，一体两读。090「远期储备」状态自本篇起

## 0. 一句话模型

**一份包，两个读者，各读各的节，互不知晓对方存在。**

| 清单里的节 | 唯一读者 | 读取时机 | 用途 |
|---|---|---|---|
| `contributes` + `engines.pf` | PF（pi-flash.exe） | PF 启动（首帧后异步） | 面板/标签页/设置/命令注册表 |
| `pi` 键 | pi sidecar 自己 | 每个 pi 进程 spawn 时 | extensions/skills/prompts/themes |

## 1. 身份与账本

- **身份来自安装上下文，不来自自我声明**——装进 PF 的就是 PF 插件，清单无身份键
- **PF 台账**：`~/.pi-flash/plugins.json`（paths.rs 体系）。source/钉版/identity
  语义与 pi 完全同构：npm 按名、git 按 URL（去 ref）、本地按绝对路径，防双载
- **pi 记账**：安装时若包带 `pi` 节，PF 把来源声明**原样抄**进 pi 的
  `settings.json` packages 数组（`npm:@scope/name@钉版`）——pi 原生发现、原生
  加载、原生装依赖。**PF 永不解析 `pi` 节**（透明透传），pi packages 演化
  PF 零成本跟随
- 纯 pi 包只记 pi 的账；纯 PF 插件只记 PF 的账

## 2. 清单：package.json 即插件清单

```jsonc
{
  "name": "@example/bridge",
  "engines": { "pf": ">=1.0" },                    // 壳层 API 兼容，PF 安装时校验（semver）
  "contributes": {                                  // PF 读；路径必须落包内，安装时校验存在
    "panels": ["./pf/panels/panel.json"]
  },
  "sidecar": "./bin/sidecar",                       // 可选逻辑进程；声明即归宿主管生命周期
  "pi": { "extensions": ["./extensions/*.ts"] }     // pi 读；PF 不解析
}
```

- 零配置优先：约定目录放对位置即可被发现，`contributes` 仅在自定义路径/过滤时写
- sidecar：spawn/心跳/重启/日志（`~/.flash/plugins/<name>/logs/`）归宿主；
  协议版本 = `engines.pf`

## 3. 目录：`pf/` 自留地 + pi 根级约定原样

```
@example+files/                  纯 PF 插件
├── package.json
└── pf/
    ├── panels/  tabs/  settings/  commands/  icons/

@example+bridge/                 混合型
├── package.json
├── pf/                          ← PF 唯一新命名空间，pi 白名单扫描看不见它
│   └── panels/panel.json
├── extensions/                  ← pi 根级约定，pi CLI 零配置照读
└── skills/

@solo/some-pi-package/           纯 pi 包：无 pf/，存量原样，一字不动
```

- **pi 的约定是存量生态**：根级 `extensions/skills/prompts/themes` 不动、不包
  `pi/`，让 pi 零配置照读；`pi` manifest 键仅过滤/自定义路径时需要
- **PF 只圈 `pf/` 一块地**：整包仅引入一个新命名空间
- **物种判定**：有 `pf/` = PF 插件；无 `pf/` = 纯 pi 包（PF 只当 GUI 管理器）
- **报错面各归各主**：`contributes` 坏 → PF 安装时报；`pi` 节坏 → pi spawn 时
  警告；互不连坐（pi 对未知 JSON 键/未知目录零信号）

## 4. 安全三级

| 层级 | 条件 | 信任机制 |
|---|---|---|
| 纯声明式 | 只有 `contributes`，无 sidecar 无 pi 节 | 宿主渲染，零代码执行，装即用 |
| 会话侧 | 有 `pi` 节 | pi 信任模型全权接管（project trust/个人安装） |
| 逻辑进程 | 有 `sidecar` | PF 装时列能力清单（文件/网络/会话 RPC）一次性授权 |

## 5. 面板声明式 schema（v1 第一稿，待评审）

`pf/panels/panel.json`（声明式面板首个验收例）：

```jsonc
{
  "id": "panel",                                // 全名自动冠插件名：bridge.panel
  "title": { "zh": "示例面板", "en": "Example Panel" },
  "icon": "./pf/icons/panel.svg",
  "dock": "panel",
  "body": {
    "type": "column",
    "children": [
      { "type": "text",  "bind": "status", "style": "caption" },
      { "type": "image", "bind": "image_url", "size": 180 },
      { "type": "row",   "children": [
        { "type": "button", "label": { "zh": "刷新" }, "emit": "refresh" },
        { "type": "button", "label": { "zh": "重试" }, "emit": "retry" }
      ]}
    ]
  }
}
```

- **原语集 v1**：布局 `column/row`；显示 `text/image/icon/badge/divider`；交互
  仅 `button`（表单控件归 settings schema）
- **数据流**：sidecar 推 `panel_state` → 宿主更新绑定槽 → 重渲染；
  按钮 `emit` → 宿主 → `panel_event` → sidecar。状态机（等待/超时/过期）
  全在 sidecar，声明里只有「显示什么、绑哪个槽、点了发什么」
- **有意不做**：任意绘制/自由布局/HTML 后门——加原语 = 改宿主 = 走
  `engines.pf` 版本化，约束即安全
- 无 sidecar 的纯声明式面板是静态的

## 6. statusbar 标签策略（2026-10-18 定案）

- **记录宿主**：workspace 管理既有体系（`pi-flash-workspace.json`，
  services/workspace）
- **新装插件 tab 默认排在 statusbar 右侧最末尾**；多个新装按安装顺序
  （plugins.json 台账序）
- **statusbar 至多展示 6 个标签**；超出收进「…」，点开**向上弹窗列表**
- **用户可拖调插件 tab 顺序**，持久化进 workspace；**project 标签固定不可调**
- 卸载即从排序列表摘除；重装按新装处理（追加末尾）
- 作者不拥有排序权：statusbar 是用户领土，声明不参与排序

  `pf-package`（PF 检索标记）
