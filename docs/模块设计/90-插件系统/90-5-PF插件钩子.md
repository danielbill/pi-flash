# 90-5 PF 插件钩子（PF-Hooks）

> 状态：v1（2026-10-28 定案）。真源 = `schema/plugin-contract.json` 的 PF-Hooks 节
> （JSON 是校验口径，本文是散文版；宿主 vendor 同一份做白名单。原单列真源
> `schema/pf-hooks.json` 并入契约，不再单独维护）。
> 适用范围：`contributes.fn_bar` / `contributes.popups` / `contributes.pi_extensions` 的插件。

## 1. 为什么要有 PF-Hooks

pi 的扩展体系只认识**进程内**的东西（session_start / message_end / tool_call…）。
但 PF 是桌面端：它有「当前页、会话列表、功能栏、弹窗」这些 **pi 里不存在的概念**
（一个 pi 进程只服务一个会话，天然没有"当前页"）。

所以凡是这类宿主语义，一律走本表登记的 **PF 钩子**，不允许插件用"猜"的方式反推：
不允许拼 uuid、不允许读会话文件路径、不允许拿 `getSessionFile()` 当身份。

**唯一会话身份 = PF 下发的 `env.session.key`**（宿主口径的会话 id，下文简称 key）。

## 2. 钩子清单

| id | 时机 | 签名 | 返回 | 谁用 |
|---|---|---|---|---|
| `page_actived` | 宿主打开/切换会话页 | `page_actived(ctx, env)` | 无（void） | 需要知道"当前页是哪个会话"的插件 |
| `session_func_bar_render` | 渲染会话标签功能栏 | `session_func_bar_render(ctx, env)` | `{ icon, tone, tip }` | 功能栏入口 icon |
| `session_list_render` | 渲染会话列表每一行 | `session_list_render(ctx, env)` | `null` \| `{ icon, tone }` | 列表徽标 |

`env` 结构统一为 `{ session: { key: string } }`。

### 2.1 `page_actived`

```
page_actived(ctx, { session: { key } }) -> void
```

- **语义**：告诉插件"用户现在看着这个会话"。PF 在打开会话、切换标签页时调用。
- **用途**：把 key 交给插件的**扩展侧**（pi 进程内代码）——pi 进程不知道自己是哪一页，
  没有这个钩子就只能靠 `getSessionId()` / `getSessionFile()` 猜，且首条消息前还是 `undefined`。
- **不负责点亮**：icon 亮不亮是渲染时的一次比较（见 2.2），本钩子只喂 id。
- **纪律**：唯一身份来源 = 宿主下发。扩展侧获取身份的正规通道 = 执行域实例化注入
  （`90-6-插件执行域-plugin-context.md` 的 `svc.anchor`）；执行域落地前的过渡形态，
  才是呈现侧收 key 后经插件私有数据转交。禁止自拼、自猜、再用第二把 id。

### 2.2 `session_func_bar_render`

```
session_func_bar_render(ctx, { session: { key } }) -> { icon, tone, tip }
```

- **语义**：给本会话标签的功能栏返回一颗 icon 的 chrome。
- `icon`：三来源同名规则——宿主内置名 / `assets:<名>` / `assets/` 相对路径。
- `tone`：`accent`（强调）或 `text.faint`（常态灰）。
- `tip`：`{ zh, en }`，悬浮提示。
- **点击**：点击回环到清单 `contributes.fn_bar.command`，宿主再以
  `env = { session: { key } }` 调插件 `onCommand`。
- **缓存**：宿主按会话 + 1s TTL 缓存；`page_actived`、命令回环返回后、弹窗关闭时失效重算。
- **亮灯判据**（插件自己写，宿主不管）：典型形态如
  `key 命中实例持有身份 && 服务健康` → accent，否则 text.faint。

### 2.3 `session_list_render`

```
session_list_render(ctx, { session: { key } }) -> null | { icon, tone }
```

- **语义**：会话列表**每一行**调用一次，返回非 null 就用该 icon 占据**时间位**（时间文字让位）。
- 返回 `null` = 本行无插件徽标，宿主照常画相对时间。
- **多插件**：同一行多个插件都返回时，从右到左、间隔 10px **全部**画出（不裁不并）。
- **这是渲染结果，不是状态**：插件不维护"设置/清除徽标"，行重渲即以最新数据为准。
  （旧的命令式 `ctx.sessions.setBadge/clearBadge` 由本钩子取代。）

## 3. 非钩子的两件事（别混进来）

| 能力 | 归属 | 说明 |
|---|---|---|
| `render_popup(ctx)` | `contributes.popups` 条目 | 弹窗内容渲染，弹窗可见期间由宿主按节奏调用；返回 `null` = 该收窗 |
| `on_command / on_broadcast / on_menu` | 事件回调 | 不是渲染钩子，是宿主 → 插件的消息 |

## 5. 验收口径（测试怎么写）

1. `page_actived`：切页后插件私有数据里的当前页 key 必须等于宿主下发的 key。
   身份稳定性与迁移验收由 `90-6` 的锚点条款接管，**不得依赖任何写法归一**。
2. `session_func_bar_render`：同 key 命中 → accent；不同 key → text.faint；服务未就绪 → text.faint。
3. `session_list_render`：命中行返回 icon，其它行 null；多插件同时命中 → 全部绘制。
4. 三者都**不得**要求插件拼接 id / 读路径 / 依赖 `getSessionFile()`。

> 加钩子 = 本表加一条 + 宿主加胶水 + `hooks_version` 升档；契约 `manifest_schema` 只在
> 清单面变化时升，两者分工不同。
