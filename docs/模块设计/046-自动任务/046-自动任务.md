### 1.5 交互规则汇总

## 2. 开发计划

> 框架对齐 ZCode 自动化(`D:\github\---harness-tools---\ZCode\packages`,下引文件均相对此根)按 PF 单进程现实简化:应用内 timer 泵替代独立 scheduler 进程(desktop/src/scheduler/index.ts)、UI 直出结构化周期全程无 cron 表达式(automationCron.ts 的 scheduleRule 权威思想)、无跨进程 claim 互斥(进程内 running 集合)。存储 SQLite(rusqlite bundled,复用 pf-context domain 已落种子);v1 只做周期任务;Agent 任务每次触发新建会话。

### 2.1 S1 存储(pf-context 种子扩展)

- spec_json 反序列化即领域校验,非法值拒写(对齐 automationCronValidation.ts:40-85 的「写库前拒绝」精神)

### 2.2 S2 定时调度服务 + 任务模块

**架构拍板:「自动任务」仅是用户可见的功能名(§1 文案),内部实现 = 定时调度(共有服务)+ 任务(业务模块)两个正交件——调度只懂时间不懂任务,任务只懂业务不懂轮询:**

**定时调度服务** `crates/app/src/services/scheduler.rs`(共有,不属 046 专属):
- 唯一 timer 20s 一 tick,ticking + tickRequested 两变量合并去重(scheduler/index.ts:60-127 同款——tick 进行中到来的唤醒不丢弃,本轮结束立即补跑);由 `shell/startup/` pumps 拉起
- `ScheduleSource` 注册表 + in-flight 集合;trait 契约:`id / recover(now) / claim(now, in_flight) → Vec<DueJob> / execute(DueJob) → oneshot / settle(job, outcome, now)`
- 启动时逐 source 调 recover(source 自清上个实例残留);作业结算后统一 `cx.notify()`
- **无存储、无业务语义、无 dev-flag**;misfire 宽限等通用判定以纯函数 helper 提供——后续闲时队列等周期类需求同泵注册,不另起 timer

**任务模块** `crates/app/src/tasks/`(046 本体,impl Chat 块接线,实现 ScheduleSource 注册进调度服务;UI 弹窗另落 dialogs/,见 §2.4):
- state(任务/运行状态面)+ store(TaskStore 封装)+ run(执行链)三件
- next_run 计算:chrono Local 本地日历直算,移植 computeScheduleRuleNextRunAt(automationCron.ts:133-220):minute 档从 anchor 推进 k·interval **不对齐墙钟刻度**(11:46 建「每10分」不在 11:50 抢跑);weekly 锚周取周一逐周扫 weekdays;monthly 过滤溢出日(1/31→2月无效);hourly 只对齐 minute
- 锚点语义:创建/编辑周期即重锚 anchor_at=now;仅改名称等其它字段保留原锚(automationService.ts:279-285)
- claim 流程:due = enabled ∧ next_run_at ≤ now → in-flight 则落 skipped run(§1.5 运行中再触发=skip)→ misfire 判定(§2.0)→ 交调度服务派发;settle 重算 next_run_at(按实际派发时刻,automationRepo.ts:987-1038)
- recover(启动扫描):task_runs 中 outcome='running' 残留 → 置 failed(result_json 注明 app_exit 中断);无 CLAIM_STALE 类僵尸回收(单进程无跨进程持有者)
- 状态驱动 UI:调度服务 notify 驱动,列表 spinner/通知点/历史行不自建轮询(§1.5)

### 2.3 S3 执行链

- **agent 任务**(§1.3 Agent 块字段):每次触发经 session/runtime 新建会话——project 用任务所选项目;model =「继承新会话默认」或覆盖;tools 走 034 档位映射;thinking 同 PillMenu::Thinking 清单;投递 prompt(task.desc)。run 落 started + session_path,会话 turn 终态回写 outcome + finished_at。对齐 ZCode dispatchCronRun 每次 createTask(host/index.ts:1016-1145)
- **脚本任务**:services/script_exec 子进程,cwd = 脚本所在目录,**30min 超时强杀**(§1.3 说明行);输出尾 + exit code 写 result_json(§1.4 脚本行 620 弹窗消费)
- **立即运行**:trigger=manual,只写 run 不动 next_run_at/周期/生命周期(ZCode「manual 不污染 cron 节奏」,automationRepo.ts:666-751);运行中再触发被泵 skip
- **模型冻结**:run 派发时一次性固化当时解析的模型进 run 行,回看不重读默认(语义取 fixRunModelSelection,automationRepo.ts:1282-1300)
