# 101-事件总线与完成唤醒

> 状态：**设计稿（2026-11-28，未实现）**——由 zcode 异步执行机制调研
> （[docs/调研/zcode-异步任务执行调研.md](../调研/zcode-异步任务执行调研.md)）驱动，
> 经全仓只读探查（事件泵/调度/退役/子代理账本/wxbot/轮询分布）后成文。
> 定位：PF 从「轮询宿主」转「事件宿主」的地基模块；与 100-管家共享瘦事件协议，
> 与 046-自动任务共享调度泵，与 090-排队护栏共享唤醒通路。
> 本文是异步机制重构的唯一事实源；实现前无需再读调研原文。

## 0. 问题定义

zcode 的判词：**等待属于 runtime 的 promise，不属于模型的时间片**。它把「等待」
从主 agent 时间片里赶出去——终态→通知命令→主动开轮唤醒，PF/pi 目前全靠
sleep 轮询与特例路径。PF 要补的不是 zcode 的对象化 registry（进程哲学不改），
而是进程模型下缺失的三块语义：**终态、迁移、fencing**。

实测后的核心缺口一句话：**宿主级「外部事件→注入会话→唤醒开轮」不存在**——
现只有两条特例：046 定时铸新会话（`tasks/run.rs:97` dispatch）、wxbot 进程内
`pi.sendUserMessage`（pi-flash-plugins 仓 `pf-wxbot/pi/inject.mjs`，特权路径）。

## 2. 设计原则（宪法）

1. **进程哲学不改**：不学 zcode 对象化 RuntimeTaskRegistry/单进程对象图；PF 把任务
   做成进程（崩溃域清晰），补语义不换模型。
2. **不改 vendored pi**：上游项全部转 issue 清单（§5-E），PF 侧做等价缓解。
3. **唤醒收敛为唯一通路**：所有「外部事件→注入→开轮」必经 Wake 入口（复用 090
   护栏），不再出现第二条特权路径；wxbot 是 pi 进程内扩展（插件唯一载体纪律），
   总线只对接其出站信箱，不重写其注入通路。
4. **PF 零业务代码**：总线只搬运瘦事件，不理解事件含义——定制化归消费方
   （046 任务/管家插件），与 100-管家宪法同源。
5. **快是第一卖点**：总线/唤醒全部后台线程 + 过揭幕；新增周期性工作一律并入
   统一泵/总线 tick；禁 UI 线程同步 RPC；改动带 `[perf]` 实测数字进日志。

## 3. 架构

```
事件源（时间/任务终态/外部追加/子进程退出/bot 信箱/…）
   │  推送 channel（source 自带，总线不 poll）
   ▼
┌─ EventBus（services/eventbus/）─────────────────────┐
│ envelope 校验+eventId 幂等 → drain 合批窗(~500ms)    │
│ 同 target 合并 → 一条注入消息                        │
└──────────────┬──────────────────────────────────────┘
               ▼
┌─ Wake（session/pool/wake.rs，唯一通路）──────────────┐
│ gen 比对（过期→降级通知点）→ 按 target 状态分流：     │
│  在池 → send_input 本地队列（090：忙→拒绝回队）       │
│  退役 → open_session 秒开重开 + prompt               │
│  不存在 → 只记台账/通知点，不铸会话                   │
└──────────────────────────────────────────────────────┘
```

### 3.1 EventSource trait

与 `ScheduleSource` 平行的**推送式**契约（事件源自带 channel，无 poll）：

```rust
trait EventSource {
    fn id(&self) -> &str;
    fn subscribe(&mut self, tx: Sender<Envelope>);   // 推送注册
    fn recover(&mut self);                            // 启动残留自清（046 同款）
}
```

调度服务不重写——降级为「时间事件源」反向挂入总线；既有 `spawn_settle`、
watcher 泵、svc 泵逐个改挂。

### 3.2 瘦事件 envelope（采纳 100-管家 §4，wire 唯一格式）

```jsonc
{
  "eventId": "evt_...",          // 幂等键，重放丢弃
  "type": "task.settled",        // 消费方按 type+谓词过滤
  "targetSession": "01a1a...",   // 唤醒对象（None = 仅记录）
  "gen": 7,                      // 目标会话 branch 代际（fencing，§4-C）
  "expiresAt": 0,                // TTL，超时降级不打扰
  "detailRef": "pf://task/run/42" // 想深看时的引用，事件不携带内容
}
```

注入消息文本前缀约定 `[PF 事件|type|eventId]` + detailRef——对齐 pi notice
steering 的 inputSource 语义（PF 无此 RPC 通道，用文本约定替代，陷阱记入
`docs/agents/pi-rpc.md`）。用户 abort 时经 090 `ClearQueue` 一并撤回已入队
事件消息，语义自然成立。

## 4. 分阶段计划

依赖：**A 是根**——不做 A，B 只能再养一套轮询，C 没有投递点可拦。

### A. 事件总线 + 唤醒器（首期，建议首批 bd 卡 `101-A`）

- 新模块 `crates/app/src/services/eventbus/` + `session/pool/wake.rs`
- envelope 的 `gen` 字段本期就位（先恒 0，C 阶段填真值）
- 首批事件源 S1+S2（终态+外部追加），S3–S5 随后逐个迁挂
- 退役联动：有 pending 订阅的会话挂 `has_live_service` 同款豁免闸，
  防「唤醒→30s 又退役→再唤醒」循环
- 验收：cargo build + test 绿；testcase 进 `test/101-*/`（合批窗口、退役重开、
  TTL 丢弃、eventId 幂等、唤醒循环）；唤醒路径 `[perf]` 计时

### B. 跨进程任务视图 TaskRegistry（消费 A）

- 统一台账：runtime 池（running/idle/parked）+ 046 `task_runs` + script 子进程
  + 子代理账本快照 + bot 锁文件探活
- **统一终态映射表**：`ChildStatus` 六态与 `Outcome` 收敛成一张枚举
  （completed/failed/cancelled/killed/stopped/lost，对齐 zcode）；recover 复用
  046 模式（启动扫残留 running→failed）
- 存储：内存快照 + pf-context 落盘（001 domain）；**变迁即发总线**
- UI：任务页加「运行中」段或状态栏聚合（控件全取 ui/kit）；`running_count()`
  顺势接线

### C. fencing——branch generation

- `SessionRuntime` 增 `branch_gen`（与进程 `epoch` 正交：epoch 管进程所有权，
  gen 管树代际）；fork/clone 两口递增（PF 无 rewind，fencing 面比 zcode 小）
- Wake 投递前比对：过期→**降级为通知点不注入**；`queued_inputs` flush 前同比对
  （090 护栏扩展）
- 修掉「child_id 不匹配良性空转」的隐性依赖：settle 不命中时显式判 gen 落台账

### D. 轮询收敛（独立可穿插）

- G6 五处 timer 并入统一泵/总线 tick（语义不变，owner 收敛）；插件弹窗 1s、
  svc 信箱 120ms 优先
- gpui 侧 fs 泵消费端 `try_recv` 轮询（`pumps.rs:88-122`）**带实测数字再动**

### E. pi 上游协同（不在 PF 改 vendor，提 issue 跟踪，不阻塞任何阶段）

| 项 | zcode 范本 | PF 缓解 |
|---|---|---|
| P0 后台 bash + 终态通知轮 | BackgroundTaskTracker（background-tasks.ts:365） | S1/S4 已覆盖「等编译/等脚本」主场景 |
| P2 autoBackgroundMs 前台→后台迁移 | runner.ts:465 commitBackground | 无缓解，等上游 |
| P2 子代理通知合批 | command-queue.ts:185 | A 阶段 drain 窗覆盖 PF 事件侧 |
| P1 子代理 notice 带 leaf generation | branchGeneration | C 阶段是 PF 侧配合面 |

## 5. 风险清单

1. **唤醒循环**：事件→唤醒→空闲→30s 退役→再事件——豁免闸 + TTL 双兜底，
   testcase 必须覆盖。
2. **语境污染**：注入消息被模型当用户插话——前缀约定 + 090 队列（abort 时
   ClearQueue 撤回）。
3. **事件风暴**：外部写入者高频 append——watcher 合批经验 + drain 窗 +
   每会话单飞守卫。
4. **跨实例盲区**：本计划只做「PF 实例内」；跨进程向退役会话投递属 V3 管家
   遥控范畴，明确不在本期。

## 6. 明确不做

- zcode 对象化 RuntimeTaskRegistry / 单进程对象图
- 改 vendored pi 任何文件（全走 §4-E 上游 issue）
- 会话级外部 API（跨进程投递）
- 重写 wxbot 注入通路（它是 pi 进程内扩展，总线只对接出站信箱）
- 046 已定稿的 misfire/接力语义、Settings 模块
