## 工具预设档位

工具胶囊菜单五行（`PillMenu::Tools`）。档位全部落在 spawn 参数上（RPC 面没有
动态换工具的命令），**换档 = kill + respawn + `GetMessages` 整表重读**；运行中
被 `mc_set_tools_preset` 兜底拦截（「运行中不能更换工具预设」）。

| 内部键 | 菜单文案 | spawn 参数 |
|---|---|---|
| `chat-only` | 仅聊天 | `--no-tools` |
| `read-only` | 4 个只读内置工具 | `--tools read,grep,find,ls` |
| `default` | 4 个内置工具 | `--tools read,bash,edit,write` |
| `full` | 全部内置工具（不装任何插件） | `--tools bash,read,edit,write,grep,find,ls` + `-ne` + 个人扩展 + 内置扩展 |
| `custom`（**默认档**） | 自定义 | 不发 `--tools` + `-ne` + 会话插件清单 + 内置扩展 + `full_activate.ts` |

两条设计约束（实测固化，依据见 034 §1.2/§1.3）：

- **`--tools` 是注册级硬 allowlist**：不在名单里的工具连注册都不进（任何
  exposure 都挡，`*`/`all` 无通配），插件工具会被一并挡掉。要插件工具的唯一
  通路 = 不发 `--tools`，由扩展在 `session_start` 调 `setActiveTools`。
- **嘴手一致**（注入 ⊆ 声明）：插件往系统提示词注入的段落与工具声明完全解耦，
  full 档下插件注入可占提示词 58~67% 而模型根本调不到那些工具。所以 full 档走
  「**不装载**」（`-ne`，包一个不装）从源头消灭注入，而不是「装载 + 抑制注入」
  —— pi 的扩展加载顺序里 CLI `-e` 排在包前面，抑制器必然先跑。

## 自定义档（会话级插件清单）

默认档：full 的工具口径 + 本会话选中的插件。清单只属于单个会话，不改动全局
`settings.json`——设置·插件页写 settings，本档写 spawn 参数，两者独立。

### 交互

- **入口**：输入栏工具胶囊右边的「插件」按钮（plug 图标 + `插件(n)`）。
  仅自定义档激活，其余档置灰（置灰 + `open_plugin_picker` 守卫双保险）。
- **面板**（320px，锚定按钮上方，overlay 点外关闭）三层分组：

  ```
  本会话插件清单                          ← 标题 + 「仅本会话生效，不改动设置页的全局插件开关」
  已选中 n
  ── 项目 · 未选中 n
  ── 全局 · 未选中 n
  [取消]  [选择并切换]
  ```

- 多选行 = 14px checkbox + 等宽字体来源 + 小标：项目来源带「项目」；设置页
  disabled 的包照样可勾、带「已禁用」（`-e` 是独立于 settings 资源过滤的显式
  加载路径）。
- **限高 10 行**，超出滚动（滚动位存面板临时字段）；无已配置插件时显示占位文案。
- **临时态**：勾选只改面板临时集合，取消 / 点外 = 丢弃，确认才落地。
- **守卫**：非自定义档不开（提示「插件只能在自定义档勾选」）；会话已有消息不开
  （提示「对话中途无法修改自定义」）——自定义清单只在对话开始前定。
- **确认**：`ext_sources` 写 runtime → 落会话台账（见下）→ 走
  `mc_set_tools_preset("custom")` 既有重绑链路（运行中兜底拦截、整表重读、
  状态栏提示全复用）。
- **胶囊标签**：`自定义(n)`，n = `ext_sources.len()`。切到其它档不清空清单
  （切回来自定义还在）。

### spawn 参数配方

custom 档（`tools_recipe::full_plugin_args`）：

```text
pi --mode rpc --session <file>
  -ne                                   # 精确集：关掉已配置/发现/内置扩展
  -e npm:<选中插件1> …                   # 只加载会话选中的（显式 -e 在 -ne 下仍生效）
  -e builtin:<settings 里开着的内置…>     # -ne 连内置扩展一起关，逐条加回
  -e <full_activate.ts>                 # session_start 里 setActiveTools
```

full 档（`tools_recipe::full_args` + runtime 拼 `--tools`）：

```text
pi --mode rpc --session <file>
  --tools bash,read,edit,write,grep,find,ls
  -ne
  -e <个人扩展…>                         # <agent dir>/extensions/*（发现口径复刻，见 extensions.rs）
  -e builtin:<settings 里开着的内置…>
```

要点：

- **内置扩展清单跟着 settings 走**（`pi_link::config::enabled_builtin_extensions`）：
  默认四个全开（`builtin:mcp` / `builtin:llama.cpp` / `builtin:codemode` /
  `builtin:tool-search`），settings `extensions` 里 `-builtin:x` 关、`builtin:x` 开，
  项目 settings 覆盖用户。不能写死——`-e builtin:<name>` 会**覆盖** settings 里的
  `-builtin:<name>`，写死会把用户关掉的内置扩展强行打开。
- custom **不发 `--tools`**：它是注册级 allowlist，会把插件工具挡在注册之外。
- `-ne` 只关扩展（发现 + 配置 + 内置）；skills / prompts / themes 各有自己的
  开关，不受影响（个人 skills 照常）。

`full_activate.ts`（`assets/`，`include_str!` 编译进二进制）：

```typescript
const EXCLUDE = new Set(["powershell"]); // 对齐 full 档：bash,read,edit,write,grep,find,ls
const FULL = ["bash", "read", "edit", "write", "grep", "find", "ls"];
export default function (pi: ExtensionAPI) {
  pi.on("session_start", () => {
    // full 内置 ∪ pi 自己算出的 active（settings defaultTools + 注册即激活的
    // direct 工具）——不碰 deferred/model-only 的默认非激活态
    const names = new Set<string>([...FULL, ...pi.getActiveTools()]);
    pi.setActiveTools([...names].filter((n) => !EXCLUDE.has(n)));
  });
}
```

激活口径 = **full ∪ `getActiveTools()`**：把 deferred（MCP）/ model-only
（tool_search）的工具拉成直接声明会与普通会话不一致，故只收编 pi 自己已激活的项。

脚本路径解析（`tools_recipe::activate_script_path`）：`PI_FLASH_FULL_ACTIVATE`
覆盖 → dev 工作区 `assets/full_activate.ts` → 内容落地 `~/.pi-flash/full_activate.ts`
（release 包不带 assets 目录）。解析失败时降级：只发 `-ne + -e`，active 回落
defaultTools + 插件工具。

### 持久化（每个对话一份清单）

`~/.pi-flash/session-ext.json`（`pi_link::session_ext`，app 自有文件，不碰 pi
会话文件）：

```json
{ "<会话 key>": ["npm:pi-freeflow", "npm:pi-web-access"] }
```

- key = 会话文件绝对路径（`norm_key` 归一化：斜杠方向 + 盘符大小写；草稿 =
  `draft-N`，草稿不跨重启）。
- 草稿 key 在会话文件落定时由 `on_file_bound` 迁到文件路径；删会话清条目；
  空清单 = 删条目（不落空数组）。
- **只存插件清单，不存档位**：重启回落默认档（自定义），清单按会话恢复。

### 边界与决策

- **0 选中 = 合法态**：`-ne + 内置扩展 + full_activate.ts`（精确空集，全量内置
  工具），不退化回 full。
- **重绑成本**：换档 kill + respawn 一次，无双 spawn；首次选中没装过的 `npm:` 包
  由 pi 现场安装（约 20s），之后缓存命中约 1s。
- **运行中**：开面板被守卫拦、确认被 `mc_set_tools_preset` 兜底拦，均不复绑。
- **已知边界**：custom 档的 `-ne` 会把「发现 / 配置」来源的个人扩展
  （`~/.pi/agent/extensions/*`、settings `extensions` 路径条目）一并关掉且**不
  加回**（full 档会加回个人扩展）；复刻 pi 完整发现规则（含项目 `.pi/extensions`
  的 trust 语义）不在本次范围，需要时另立设计。
- `mc_set_tools_preset` 不感知档名：接收任意 key，custom 与其它档走同一条重绑
  链路。

## @ 项目文件检索引用（对齐 pi-web）

输入框敲 `@` 弹文件补全菜单。**协议上是纯文本**：确认后插入 `@path `，
pi 不做任何展开（模型收到含 `@path` 的文本，自己调 read 工具读文件）——
pi-web / pi TUI 同语义；内容注入只存在于 pi CLI 的 argv 场景（`@file` 首条
prompt 展开成 `<file>` 块），RPC 面不存在。

### 触发与 token（`services/at_file.rs`，正则语义对齐 pi-web extractAtQuery）

- `@` 必须在文本开头或前面是空白字符（邮箱 `foo@bar` 不触发）；`@` 到光标
  之间无空白。左最匹配。
- 引号形态 `@"查询`：查询词可含空格；内部出现 `"` 或换行 = token 失效
  （菜单收起）。
- 以光标（composer cursor 字节偏移）为界，只看光标前文本。

### 数据源（`services/file_index.rs`，对齐 pi-web /api/file-index）

- git 仓库：`git ls-files --cached --others --exclude-standard -z`（尊重
  .gitignore，对齐 TUI 的 fd 行为；LC_ALL=C）；非 git 回退 BFS 遍历
  （深度 ≤ 8、5 万上限、跳隐藏项与 node_modules/target/dist）。
- 硬上限 20 万条（GIT_HARD_CAP）。每 cwd 缓存 TTL 10s、上限 20 份
  （`Chat::at_index`），后台线程构建，构建期间旧清单先顶上。

### 打分与排序（TUI scoreEntry 阶梯）

精确 100 / 前缀 80 / basename 子串 50 / 全路径子串 30 / 子序列 fallback 10，
目录 +10；排序 = 分数 → 路径深度浅优先 → 字母序；截前 20 条。查询含 `/`
时对全相对路径打分——这是目录钻取的机制：确认目录插入 `@dir/`（不闭合），
菜单保持打开，后续查询前缀命中 dir 下所有条目（dir 自身被排除）。

### 交互

- 文件确认闭合 token：`@path `（含空格加引号 `@"path" `），光标在末尾；
  目录确认不闭合（`@dir/`）供继续钻取；引号目录插成闭合 `@"dir/"`、光标
  在闭引号前。只替换 @token，光标后的文本保留。
- 键盘：↑/↓ 循环、Tab/Enter 确认、Esc 只收起（token 保留，pi-web parity）；
  悬停更新高亮。条目渲染 = 目录/文件图标 + 目录前缀暗色 + 文件名亮色 +
  目录尾随 `/`。
- 菜单打开期间每帧 `ensure_at_index` 预热索引（TTL 内幂等）。

## ! 执行 shell 命令（对齐 pi-web）

### 触发

`trimStart` 后以 `!` 开头且无图片附件 → shell 模式：胶囊边框着工具绿 +
提示行「Shell · 输出发给模型」；`!!` = 输出不进模型上下文（「输出仅本地」）。
发送走 `session.send` 同一入口，`send_input` 分流到 rpc `bash`。

### 协议（pi 原生 rpc，pi-web 同款）

```json
{"type": "bash", "command": "ls -la", "excludeFromContext": true}
```

- pi 立即执行（cwd = 会话 cwd；输出 50KB 截断，超限落临时文件
  `fullOutputPath`），结果记成 `role:"bashExecution"` 消息。
- **响应** = `BashResult {output, exitCode, cancelled, truncated, fullOutputPath?}`；
  执行中增量 = `bash_execution_update` 事件（app 就地追加渲染，比 pi-web
  靠会话重载更实时）。
- **进模型时机**：下一次 prompt 时 pi 的 convertToLlm 把非 excluded 的
  bashExecution 折叠成 user 文本（``Ran `cmd` `` + 输出码块）；`!!` 的记录
  会话里有、模型看不到。bash 命令本身不触发模型。
- 中断 = rpc `abort_bash`（Esc / 停止按钮，bash 执行中优先于中止模型流）。
- 会话忙（bash 在飞 / agent 跑动 / 压缩中）时 app 侧拒绝（pi 侧同样拒绝），
  输入保留在输入框可重发。

### 展示与持久化

- 消息模型 `Role::Bash` + `BashInfo`（命令/输出/退出码/取消/截断/excluded/
  running），渲染合成 bash 工具卡（`render_tool_card` 复用）：非零退出码红、
  取消灰、截断附 `fullOutputPath`；excluded 显示名 `bash (local)`；执行中
  加旋转「执行中 · Esc 中止」行。
- 独立消息行，不进轮分组、不计 nav 统计。
- pi 把 bashExecution 写进会话文件（`get_messages` 快照即携带——实测确认，
  无需磁盘并轨）；重启重开会话由快照/磁盘自然恢复。
- 边界：bash-only 的草稿（从未发过 prompt）不落盘（pi 首条 prompt 才写
  会话文件），重启后这部分记录不恢复——pi-web 同限制。
