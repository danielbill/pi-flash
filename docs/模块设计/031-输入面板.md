## full+plugin 会话自定义插件


目标：单个会话独立选择插件（不改动全局 settings.json），与现有"工具预设 = spawn 参数"架构同构（见 `agent_session.rs` 注释：RPC 面没有动态换工具/插件的命令，只能 ride spawn flags）。

### 交互设计（弃用 hover，纯点击）

输入面板工具胶囊菜单（`main.rs` `pill_menu_el`，锚点 `pill_anchor`）末尾追加一行：

```
✓ configured    取自 settings.json 的 defaultTools
  chat-only     仅聊天
  read-only     4 个只读内置工具
  default       4 个内置工具
  full          全部内置工具
▸ full+plugins  全部内置工具 + 自定义插件      ← 新增
```

1. 点击 `full+plugins` 行：关闭主菜单，原锚点弹出**插件选择面板**（同 320px 宽，锚定胶囊上方，复用 overlay 层点外关闭）。
2. 面板内容：
   - 分组头「全局」「项目」（数据源复用 `mc_pkgs_global` / `mc_pkgs_project`，`entry_source()` 即 `-e` 参数字符串）；
   - 多选行（checkbox 勾选态），行渲染参照 `settings/plugins.rs`；
   - **限高 10 行，超出滚动**（`overflow_y_scroll()`，参照 `settings/widgets.rs::sidebar_list()`），滚动态存 picker 临时字段；
   - 底部固定「取消」「选择并切换」两个按钮。
3. 点「选择并切换」→ 写入选择，走 `mc_set_tools_preset("full+plugins")` 同一条路（agent_running 兜底拦截、重绑进程、`GetMessages` 整表重读、状态栏提示全部复用）；点取消/点面板外 → 丢弃临时勾选。
4. 运行中胶囊置灰逻辑不变（`tools_locked`），面板同样只在空闲时可打开。
5. 胶囊标签：`full+plugins(3)`，选中数实时来自 `ext_sources.len()`。
6. 面板文案注明「仅本会话生效，不改动设置页的全局插件开关」——设置·插件页（`settings/plugins.rs`）写 settings.json，本档写 spawn 参数，两者独立。

### spawn 参数配方（已实测，vendored pi 0.87.1）

**实测结论（2026-10-04，探针扩展写 `getActiveTools()/getAllTools()` 落盘）：**

| # | 组合 | 结果 |
|---|---|---|
| A | `-ne -e ext --tools read,grep` | 插件工具**不注册**（`getAllTools()` 都没有） |
| B | `-ne -e ext`（不发 `--tools`） | 全部注册；active = settings defaultTools + 插件工具 |
| C | `-ne -e ext --tools read,grep,<插件工具名>` | 点名则正常 |
| D | 同 A，插件改在 `session_start` 注册 | 仍被过滤 |
| E | 同 A，插件工具 exposure=codemode/deferred | 仍被过滤 |
| F | `-ne -e ext -xt powershell` | `-xt` 只减不加，不提权 |
| G/H | `--tools *` / `--tools all` | 空集，无通配 |
| **I** | `-ne -e ext -e full.ts`（session_start 调 `setActiveTools`） | **✅ active = 7 内置 + 插件工具** |

即：**`--tools` 是注册级硬 allowlist（任何 exposure 都挡），"full 内置"与"插件工具可用"用 CLI flag 互斥**；唯一通路是不发 `--tools` + 扩展侧 `setActiveTools`。

**最终配方（I）：**

```text
pi --mode rpc --session <file>
  -ne                                   # 精确集：关掉全部已配置/发现/内置扩展
  -e npm:<选中插件1> … -e npm:<选中N>    # 只加载会话选中的（显式 -e 在 -ne 下仍加载，cli.md 背书）
  -e builtin:mcp                        # mcp.json 服务器仍需内置 MCP 扩展连接
  -e <app内置 full_activate.ts>         # 见下
```

`full_activate.ts`（app 随包分发，绝对路径传入，路径解析与 `vendor::cli_path()` 同机制）：

```typescript
const EXCLUDE = new Set(["powershell"]); // 对齐 full 档：bash,read,edit,write,grep,find,ls
export default function (pi: ExtensionAPI) {
  pi.on("session_start", () => {
    pi.setActiveTools(pi.getAllTools().map(t => t.name).filter(n => !EXCLUDE.has(n)));
  });
}
```

依据：session_start 时所有扩展 factory 已跑完（I 实测 `getAllTools()` 含插件工具）；`setActiveTools` 的变更由 pi 在下次模型请求前声明给模型（extensions.md）。

### 边界与决策

- **0 选中确认** = 合法：`-ne -e builtin:mcp -e full_activate`（精确空集，仅内置+全量工具）。不退化回 full。
- **持久化**：与现有 preset 一致，重启回落 `configured`；`ext_sources` 不进会话文件（后续如需跨重启，挂会话元数据，另立设计）。
- **设置页 disabled（资源过滤置空）的包**：`-e` 是独立于 settings 的显式加载路径，预期照常加载（待实测 E 确认）。
- **重绑成本**：切换时 kill+respawn 一次（与现有换预设相同），无双 spawn。
- 运行中确认被 `mc_set_tools_preset` 现有兜底拦截，提示语复用「运行中不能更换工具预设」。
