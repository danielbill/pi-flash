## 拖拽移动（Zed project_panel drag_and_drop 移植）

gpui 窗口内 DnD 三件套挂树行（`on_drag` 发起 / `drag_over` 落点高亮 / `on_drop`
提交），payload = `TreeDrag { path, is_dir }`，落点语义与幽灵视图在
`function_panel/file_tree_drag.rs`。

- **落点语义（Zed move_worktree_entry 同款）**：悬停目录行 = 移入该目录；
  悬停文件行 = 移到其父目录；列表空白处 drop = 移到项目根；钉住祖先链上的
  目录行也是合法目标。
- **真实移动判定** `drag_move_target`：原地（拖回所在目录）、进自身子树、
  拖到自己身上 → None（不高亮、drop 静默 no-op）；drop 与高亮同源。
- **悬停自动展开**：折叠目录行悬停 500ms 自动展开（Zed hover_expand 同款），
  目标去重靠 `ws.tree_drag_expand`，离开该行即清。
- **移动提交** `tree_move_commit`（file_actions）：fs::rename（Windows 跨盘
  报错、无复制降级，Zed 同）+ 打开面重映射（tab/缓冲/待聚焦/展开集合，与
  改名提交共用 `remap_moved_entry`）+ 目标链沿途展开 + refresh_git。
  目标重名报错不覆盖。
- **点击语义**：行主动作（展开目录/打开文件）挂
  on_click（mouse-up）——gpui 的 click 与 drag 天然互斥（位移超 2px 进
  drag）。变更列表
  （只看变更）与行内改名态不接拖拽。
- 已知边界：vendored gpui 0.2.2 无 external_drag_payload 一族 API，窗口内
  拖不出去到资源管理器（Zed 有）；Ctrl 复制拖拽（Zed copy 修饰键）未做。

3、unPin：右键菜单「取消固定」（已收藏条目的菜单项即取消固定）；取消最后
一个收藏自动退回文件树视图

视图语义：
- 操作栏 Pin / 只看变更两颗钮 = **视图切换钮**：树视图下显示各自功能
  icon，进入对应视图后 icon 换成目录树（accent 高亮，tooltip 返回目录树）
  ——「点击回目录树」语义
- 根条目按名称字母排序，文件夹和文件一律名称在前，路径淡化显示在后
- 收藏的目录可展开（展开集合与主树共享），子级完整子树；行渲染/右键菜单/
  拖拽/git 徽标/F2 改名全部与文件树一致
- 与【只看变更】互斥（同一树体区域三视图：树/变更/Pin）；行内新建回退树
  模式；空收藏点击 Pin 钮不切换（无空态提示）；视图会话态不持久化，启动
  默认文件树
- 收藏清单 per-project 持久化（workspace.json `__pins`），改名/移动跟随、
  删除清理、切项目换清单

## 文件树状态保存

对齐 Zed：`project_panel` 的展开集合是 **per-worktree 内存态**
（`expanded_dir_ids: HashMap<WorktreeId, Vec<ProjectEntryId>>`，entry id 每次
重建都变，天然不跨会话），切项目不丢、**打开项目默认展开 cwd**（根）。本仓
在此之上加磁盘持久化，存 `~/.pi-flash/workspace.json` 的
`__tree`：

```json
"__tree": {
  "d:i_workspace\pi-flash": { "expanded": ["", "crates", "crates\app"], "pin": true }
}
```

- **展开集合**：存**相对项目根**的路径（`""` = 根）——项目搬迁/盘符大小写
  变化不废，体积小；每项目上限 300 条
- **Pin 视图开关**：关闭前停在 Pin 收藏夹 → 重启按项目恢复该视图（收藏为空
  时无意义，退回文件树）
- 恢复优先级：本次会话内存表（切回来不丢）→ 磁盘 `__tree` → 默认「只展开根」
- 失效 prune：加载时丢弃项目外 / 已删除目录 / 含 `..` 的条目，根恒存在
- 落盘时机：切项目（remount 开头归档旧项目）、保存 UI 状态（关窗/退出）、
  Pin 视图开关；**展开/折叠本身不即时落盘**（高频动作，靠上述时机兜住）

## 文件执行（右键【执行】）

对可执行文件（bat/cmd/ps1/py/js/sh/exe）一键运行。**执行通道复用内置终端**：
解析出命令后新开终端 tab，`Shell::new("cmd.exe", ["/k", "cd /d <文件目录>
&& <命令>"])`——复用 ConPTY/回滚/Ctrl+C/exit banner，交互式脚本天然支持。
不走 pi 侧车。

- **落点**：配方表 + 懒解析函数 = `services/script_exec.rs`（对齐 shell_open
  先例）；菜单动作挂 `function_panel/file_actions.rs`，项文案带解析结果
  （如 `执行 · python 3.12`），解析失败置灰带原因 tooltip。
- **配方表**（静态 const，每行 `扩展名 → 启动配方候选`，加类型=加行）：

  | 扩展 | 配方 | 探测 |
  |---|---|---|
  | exe/com | 直接 spawn | 无 |
  | bat/cmd | `cmd /c <file>`，cwd=文件目录 | 无 |
  | ps1 | `powershell -NoProfile -ExecutionPolicy Bypass -File` | 无（系统必有） |
  | js/mjs/cjs | `pi_link::vendor::node_bin()`（自带 node） | 无 |
  | py | venv → py → PATH python（见下） | 有 |
  | sh | `<git-bash> <file>`（探测见下） | 有 |

  bat/ps1/sh/exe 全部经由 `cmd /k` 包装进 PF 终端 tab，同一执行通道。
  不查系统文件关联。
- **探测链（py / sh 两个，其余类型零探测）**：
  - py：`<cwd>/.venv|venv/Scripts/python.exe` → `C:\Windows\py.exe -3` →
    PATH 逐目录找 `python.exe`
  - sh：PATH 找 `bash.exe`（**排除 System32——那是 WSL 启动器**）→
    `C:\Program Files\Git\bin\bash.exe` → scoop `~\scoop\apps\git\
    current\bin\bash.exe`；全失败菜单项置灰。WSL bash 兜底（需 wslpath
    转路径）留 v2
  - 通用：**只在点击【执行】时懒执行**，正/负结果均会话内缓存（首次数
    毫秒，藏进 ConPTY 的 50~200ms 里）
- **PATH 扫描护栏**：`GetDriveTypeW` 只扫固定磁盘，UNC/可移动/网络盘跳过。
- **陷阱清单**：WindowsApps 假 `python3.exe`（路径含 WindowsApps 即跳过）；
  bat 必须 `cmd /c` 且 cwd=文件目录（`%~dp0` 依赖）；sh 探测认
  `Git\bin\bash.exe`（环境包装器）不认 `usr\bin\bash.exe`（裸 bash），CRLF
  脚本报 `$'\r': command not found` 属脚本自身问题原样回显；`cmd /k` 整串命令的
  空格转义单独进 pi-link 式符合性测试；GUI 型 exe 塞终端会立即“退出”，
  v1 接受，v2 读 PE 头改走 shell_open。
- **不做**：启动期系统扫描、注册表关联兜底（v2 再议）、用户可配置映射 UI
  （Settings 冻结）、WSL bash 兜底（v2）。
