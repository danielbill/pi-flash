# 实现

## 0. 模块与职责分界

- **exe（`services/updater.rs`）**：检查 / 下载 / 校验 / 解压落位到**新目录** /
  启动前交接 / 清理旧版本目录
- **薄壳启动器（`npm/bin/pi-flash.js` + `lib.js`）**：初始安装的下载落位
  （写 `payload/`）+ 启动时选版本最高的完整载荷 + 缺载荷自愈兜底
- **两者共用同一份布局规则**（目录名带 `-<版本>`、`.payload-version` 戳、exe
  在位），因此薄壳不必认识任何"标记/暂存"协议；exe 与薄壳同版本同发布
  （release.sh 三处版本单点同步）

## 1. 落位布局与启动交接

```text
<root>/payload/                安装时的载荷（npm 命令与快捷方式的稳定入口）
<root>/payload-<版本>/          应用内更新解压出的新载荷（版本写在目录名里）
<root>/update.tmp-<pid>/       下载解压中的半截目录（成功后即消失）
```

`<root>` = **exe 所在目录的父目录**（npm 薄壳 = `<pkg>`；绿色解压包 = 解压目录）。

- **完整判据**（唯一，两侧同构）：目录名尾部是 `-<x.y.z>` **且**
  `.payload-version` 戳与之一致 **且** exe 在位。戳在解压完成、目录改名到位、
  **且把新目录里每个文件读过一遍**（下一条）之后最后写 → 「戳在 = 完整且
  成本已付」，半截目录天然落选，不需要任何标记文件
- **安装阶段把成本花完**（`touch_tree`）：落位后、写戳前，把新目录里每个文件
  读一遍（0 字节文件跳过，1~8 线程）。杀软/文件系统对一万多个新文件的首次
  扫描全在安装期付掉，**启动路径一行代码都不加**：点重启、以及以后每次打开
  新版本，都跟平时一样秒开。单个文件失败只跳过（优化，不影响安装正确性）
- **更新 = 解压出一个新目录**（`<载荷目录名剥版本>-<新版本>`）：只写新目录，
  不 rename、不删、不碰任何在用文件
- **启动交接**（`handoff_if_newer`，`main()` 开窗之前）：扫 `<root>`，若有
  版本更高的完整载荷目录 → spawn 它的 exe 并退出。**双击旧目录的 exe 也自动
  进新版**，与启动方式无关（薄壳命令 / 快捷方式 / 绿色包双击都一样）
- **Ready 提示**（新会话页版本号位「下载完成，点击重启更新」）= 新载荷目录
  已就位（= 已安装，只差重启）；点击 = 同一段 spawn 逻辑 + 本进程退出
- **薄壳启动**（`resolvePayload`）：`payload/` 与所有 `payload-<版本>/` 里挑
  版本最高的完整载荷跑（命令行用户直接进程内切换，不经"启动→退出→再启动"）
- **清理**（新版启动后台线程，不阻塞开窗）：删 `<root>` 下**比当前版本旧**的
  版本化载荷目录 + 超过 1 小时未更新的 `update.tmp-*` + 超过 1 小时、**名字带
  版本但没有戳**的载荷目录（落位后写戳前被杀的残留；留 1 小时是免得
  误删另一个实例刚落位、正要写戳的目录）。删目录前先用 `rename`
  当**占用探针**——目录里有进程在用的文件时 Windows rename 必败，失败即跳过，
  绝不删活目录。同一趟还清 `update-swap.log` / `update-staged.json` /
  `payload.old-*`（旧版升级残留）；`payload.stage-<版本>` 除外——它本身是完整载荷，
  走版本规则（更新的拿它交接、更旧的才删）
- **不做**：powershell helper、`update-staged.json` 标记、`payload.stage-*` /
  `payload.old-*`、rename 重试、杀孤儿 sidecar、swap 日志文件、**下载续传**、
  **zip 缓存复用**（被中断就重来：残留按上一条清理规则清掉）

## 2. 检查与下载

- 端点：`api.github.com/repos/danielbill/pi-flash/releases/latest`（tag_name + body）；
  资产 `<mirror|github>/releases/download/v<ver>/pi-flash-<ver>-win32-x64.zip` +
  sidecar `.sha256`（404 回落 `SHA256SUMS`，080 §3.2 同序）
- 纪律：检测 timeout 30s，失败重试 2 次、间隔 10 分钟，最终失败静默回落；
  连接超时 30s / 整体 30min；全程后台线程
- 下载源与 npm 薄壳（080 §3.2-2）同规则同表：直连优先，开传 3s 平均 <128KB/s
  即按序切默认镜像（gh-proxy.com / ghfast.top / ghproxy.net），换源即重试；
  `PI_FLASH_MIRROR` 钉定唯一源、`PI_FLASH_MIRRORS` 追加候选；校验和直连优先
  钉定官方哈希，命中源兜底
- 校验通过才解压（边下边算 SHA-256，单遍）；zip 条目名安全化（拒绝对路径/
  `..`/盘符）；版本比较 x.y.z 逐段数值（`version_gt`，单测覆盖）
- 解压**并行**（原子下标工作窃取，1~8 线程）：Windows 瓶颈是 Defender 对每个
  新建文件的实时扫描；相位 + 百分比让等待显形（`PHASE_DOWNLOAD` / `PHASE_EXTRACT`）
- release body 随下载落 `~/.pi-flash/changelog-cache/<ver>.md`（重启后的
  更新日志页直接读本地；缺失再按 `releases/tags/v<当前>` 现拉一次）

## 6. 已知边界

- **磁盘**：安装目录 `payload/` 永久保留（稳定入口，npm 自愈与快捷方式都指它），
  加上当前版本目录 = 常态两份载荷（≈300MB/份）。更旧的版本化目录由新版启动时
  清掉；`payload/` 本身不动
- **单实例假设**：另一个实例正从某版本目录运行时，清理会因 rename 占用探针
  失败而跳过（不误删活目录）；真删活目录的窗口不存在
- **绿色解压包**：整包双击也能自动更新（`<root>` = 解压目录，旧 exe 交接 +
  新目录并行），代价是解压目录旁边多出 `pi-flash-<版本>/` 与旧目录
- **npm 目录只读**（Program Files prefix 提权安装）：写新目录失败 → 静默回落，
  下次启动再试；不弹错
- **macOS**：Rust 侧校验只认 `pi-flash.exe` 布局；macOS 分发已停（AGENTS.md
  铁律），届时按 `exe_rel()` 对齐
- **off 模式不取消进行中的下载**：开关只影响下一次检查；已开始的下载照常落位
  （重启后生效）

## 7. 端到端复现脚本

`scripts/upd-e2e.sh`（本机 github 不通，故用本地站；
`PI_FLASH_MIRROR` / `PI_FLASH_RELEASES_API` 两个调试口就是为此存在）：

```bash
cargo build && scripts/upd-e2e.sh                  # 19 项断言，退出码 0 = 全绿
scripts/upd-e2e.sh --new-version 0.1.11 --keep     # 指定「新版本」号 / 留现场
```

它怎么造「旧版 → 新版」而**完全不动版本号**（Cargo.toml / Cargo.lock 零改动）：

- **旧版载荷** = 当前源码构建的 exe（真版本 V）+ 真 release 载荷的 node.exe/vendor
  （`cp -al` 硬链接，秒级装配；覆盖 exe 前先 `rm -f` 断链，绝不改到 `dist/`）
- **新版 zip** = `dist/` 里最新的真 release 资产，只把**文件名与版本号**改成 V+1
  （内容仍是真资产）→ 真下载、真 SHA-256、真解压 1.5 万文件；假 `releases/latest` 只说 V+1
- 阶段②点重启前把假 API 的 latest **翻回 V** → 新进程看到「已是最新」→ 断言 state=idle、
  不再重下。因此新版目录里的 exe 其实是 V 版产物，它启动时会打一行
  「版本戳与进程版本不符，跳过启动交接」——**本夹具的预期产物**，不是故障
- 断言面：ready / 新目录（戳 + vendor 完整）/ 旧目录未被碰 / 无 `update.tmp-*` / 更旧版本
  目录被清理 / UI target / 截图 / 重启后新进程落在新目录 / shim 退出 / version 与 state=idle /
  更新日志自动开 / 无重下产物 / 直启旧 exe 交接 / 日志有交接记录
- 隔离与安全：`PI_FLASH_DIR` 独立 app home + `tmp/upd-e2e` 独立安装目录；杀进程只认
  本夹具路径下的实例，**绝不碰用户真实安装**；结束 `trap` 清实例与假源

**无法在本机验的部分**（发版后由所有者/CI 在网络可达环境验）：github.com 直连与镜像
的真实可用性、release profile 构建、npm OIDC 发布链路。
