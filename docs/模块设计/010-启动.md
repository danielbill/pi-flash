# 设计基线（2026-10-17 重设计）：cwd 是会话的属性，不是应用状态

启动永远从**无项目态**出发（`ws.cwd = None`），应用**不捏造**任何当前目录。
此前版本在启动时采纳进程 cwd / exe 目录 / 主目录兜底，衍生出「payload 目录
被当项目注册、删了每次启动又回来」一族 bug（081 交接继承 cwd 污染注册表
是直接导火索）。重设计后：

- **cwd = 最近活动项目 = 最后一次 cwd 切换的项目**（用户定案，极简口径）：
  时刻只有一个来源——`projects.json.last_opened_ms`，由 `register_project`
  在**每次进入项目**时写入。三条切 cwd 的路径全部汇到 `remount_workspace`
  （选择项目/psp 点项目 `switch_project`、打开老会话 `open_session`、文件树
  切 `sync_tree_to_file`），因此「最近打开」≡「最后切换到的 cwd」，不需要
  再聚合会话活动或 mtime。`workspace.json` 的 `__last` 全局键退役。
- **落点优先级**：`PI_FLASH_CWD`（开发覆盖）→ **最近活动项目**（新会话页）→
  无项目态（真首次运行）。
- **不搞「全局最后会话优先」**：恢复对象是「最近项目**里**的最后会话」，不是
  「全局最后会话」。否则刚打开的项目会被别处的旧会话压掉（用户实测：cwd 已
  切到「20观宏知微」，重启却回到 pi-flash）。
- **restore 开关只管会话**（默认 on）：on = 落最近项目并**直接加载该项目自己**
  的最后会话；off = 落同一项目但停在**新会话页**，且不抹该项目的会话记忆
  （`boot_new_session`，下次开 on 仍可加载）。
- **无项目态**只在「真的没有任何项目记录」（首次运行）时出现：零进程、零挂载，
  composer 发送弹「打开项目」先要目录（send 门，文字暂存 `pending_send`，
  选定目录后 `new_session_in` 回填自动发送）。
- **cwd 的合法来源**只剩显式动作：恢复最后会话、切项目/打开项目、
  `PI_FLASH_CWD`（开发覆盖，目录不存在不兜底）。
- 揭幕闸门：有恢复 → 等 pi 附着；无项目态 → `boot_resolved` 直接放行。
- `ws.cwd: Option<PathBuf>`；runtime 的 cwd 保持 `PathBuf`（runtime 恒有
  具体会话目录）；占位 runtime `draft-0` 仅保证 `rt()` 全路径安全，永不 spawn。

### tab 带回放（2026-11 新增，pi-flash-weia）

启动恢复第二条腿：内容区自由 tab（文件/终端）跨重启复原，存档在
`workspace.json` 的 `__tabs`（**单槽全局**：tabs + active + chat，与 `__window`
布局同语义）。

- **单槽全局，不按项目分槽**：内存里 `panel_tabs` 本就是全局态（切项目不
  清带），按项目分槽会存出多份漂移拷贝——关 tab 只清当前项目槽，重启落在
  另一个项目就从那个槽复活（首版实测：同一文件三槽打地鼠，关了又自动开）。
- **回放范围**：文件 tab 重读磁盘（消失条目丢弃）；终端 tab 按 cwd 重生
  （PTY 进程不保活）。Changelog/市场/搜索页属瞬态页，不进存档（重开一键）。
- **回放时机**：`spawn_boot_restore` 里会话恢复**之后**（`switch_to` 会把
  前台拽回 Chat，回放按存档覆盖前台视图）；restore=off 不回放也不覆写存档。
- **落盘时机**：tab 带变更点（开/关/激活/拖位/前台切换，`set_content_view`
  是主要收拢点）+ 关窗 `persist_ui`。内容相同自动跳过写盘。
- **启动期抑制**：`ws.tab_restore_busy` 压住回放/会话恢复中间态的 persist
  （否则空带/半带写穿存档）；存档**先读后回放**，顺序不能反。
- **终端重开要 window**：经 `startup::MAIN_WINDOW` 句柄进 window 上下文
  （automation 同款模式），窗口缺失降级为只恢复文件 tab。
- 上限 [`TABS_SAVE_CAP`] = 32 条（防几十个 conpty 拖慢启动）。旧版
  per-project 嵌套形态读侧不识别，首次落盘自动覆盖迁移。

# 启动阶段：全局态一次性装载

启动阶段应当把后续所有界面要用的全局常量**一次性从硬盘装进内存**，之后渲染只读内存。

## 0. 为什么要有这一层（现状问题）

- 「模型清单」现在只有一份 `Chat.models_by_cwd`，**唯一写入者**是活着的 pi 进程
  的 RPC `get_available_models`（`session/runtime.rs:274` 发、`actions_runtime.rs:77`
  收）。012 是 lazy draft（不 spawn），`ensure_models_requested`（`main.rs:1150`）
  又明确「绝不为选模型 spawn 进程」⇒ 冷启动/换项目时清单为空：模型 pill 回落
  「选择模型」、弹窗「no models match」。
- 「命令清单」同理：`rt.commands` 来自 RPC `get_commands`（`session/runtime.rs:416`），
  每个 runtime 各一份、无内置表 ⇒ 草稿态 `/` 菜单没有命令。
- 磁盘上已有的默认配置（`defaultProvider/defaultModel/defaultThinkingLevel/
  modelThinkingLevels/enabledModels/defaultTools`，`main.rs:556` 读）与会话进程无关，
  **但因为没有清单可解析，作用域算不出来**：`mc_refs()` 也来自清单。
- 其余全局量散在 `reload_settings_panel`（`main.rs:676`，且只在开设置页时再跑）
  与 `switch_project`（`main.rs:1010`，只刷会话/ git /文件树，**不重载任何全局**）；
  `mc_default_tools` 字段甚至没人写（死字段）。

## 1. 装载内容（全部磁盘，一次性）

| 全局量 | 磁盘源 | 备注 |
|---|---|---|
| 默认配置 | pi `settings.json` + `~/.pi-flash/app-settings.json`（§4） | `defaultProvider`/`defaultModel`、`defaultThinkingLevel`、`modelThinkingLevels`、`enabledModels`、`defaultTools`；主题/语言/提示音 |
| 模型清单 | `~/.pi/agent/models.json` + `~/.pi/agent/models-store.json` + pi-flash 缓存 | 见 §2 |
| 插件 | `settings.json packages` + `~/.pi/agent/npm/node_modules/<pkg>` | 声明 + 安装态/版本 |
| skill | `SKILL.md` 目录：项目 `.pi/skills`、`.agents/skills`、`~/.pi/agent/skills`、`~/.agents/skills`、`settings.skills` | 每项带 scope（项目/全局） |
| 思考强度 | `settings.json` | 全局默认 + per-model 记录 |
| 命令 | skill 派生 + pi 内置表 + 扩展命令缓存 | 见 §3 |
| 工具 | `settings.json defaultTools` | 会话预设 `configured` 即由 pi 按它解析 |
| mcp | `mcp.json`（全局 + 项目，项目同名替换全局） | |
| 子代理 | `agents/settings.json` + 档案 md | |

## 2. 模型清单 = 磁盘 ∪ 自建缓存（不 spawn pi 问）

- **磁盘主源**（已核实字段与 `get_available_models` 同形：`id`/`name`/`provider`/`contextWindow`）：
  - `models.json`（用户自定义 provider，**优先**）：`providers → { name, models[] }`
  - `models-store.json`（pi 缓存的远端 provider 目录）：实测 openai 44 / deepseek 2 /
    openrouter 472 / typesafe 1，用户默认模型
    `openrouter/nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free` 带真名
    “NVIDIA: Nemotron 3 Nano Omni (free)” 就在里面
  - 合并规则：按 `provider/id` 去重，保持 provider 出现顺序；任一文件缺失/损坏只少一份
- **app 的 pi 进程带 `-ne`（不加载扩展）**：`pi_link::client` 固定
  `-ne --mode rpc`（扩展隔离，防止宿主扩展崩掉钉版 pi）。因此**包内联 provider
  根本不会进 app 的进程**：`pi-freeflow` 的模型表在 TS 源码里
  （`npm/node_modules/pi-freeflow/src/models.ts`、`src/catalog.ts`），
  `models-store.json` 也没有它 ⇒ 这类 provider 在 app 内不可见（`enabledModels`
  里指向它们的模式会算 stale，属既有行为）。磁盘目录 + 缓存不是"补它的缺口"，
  而是**app 进程答案的等价源 + 新鲜度层**（models.json 手改、pi 刷新 store 后缓存补上）
- **作用域解析**：仍按 pi 语义在清单内解析 `enabledModels`（默认模型命中 → 用它；
  命中不到 → 域内第一个；patterns 解析为空 → 全量回落）；`new_session_default()`、
  模型弹窗、设置页都读这份内存清单
- **进程答复只做覆盖**：`models_by_cwd[cwd]` 有值时优先（保留项目级差异）；无进程时
  回落全局清单。`ensure_models_requested` 的「不 spawn」约定不变

## 3. 命令清单

- 磁盘侧：① skill 派生 `skill:<name>`（带 description，随项目 skills 走）② **pi 内置表**
  —— pi 1.0.0 的 `get_commands` 无内置命令（用 `pi_link::client` 的 `-ne` 进程实测：
  **45 条 = 20 扩展 + 25 skill**；app 侧因为 `-ne` 只会有 25 条 skill ⇒ 内置表为空常量，
  随 `vendor/pi` 升级复核）
- 扩展命令：`-ne` 下 app 的进程不加载扩展 ⇒ 实际收不到（缓存里 commands 恒空，属预期）；
  缓存通道保留，供将来去掉 `-ne` 或多进程答案时自动生效
- 消费：会话有进程且 `rt.commands` 非空 → 用它；否则 = 内存命令清单（项目 skill 派生 + 内置 + 缓存）

## 4. pi-flash 自有目录 `~/.pi-flash/`（不污染 pi）

**原则**：pi-flash 自己写的文件**全部**落在 `~/.pi-flash/`；`~/.pi/agent/` 只留给 pi
自己（`sessions/`、`settings.json`、`models.json`、`models-store.json`、`skills/`、
`npm/`、`auth.json` …）。路径解析单点：`PI_FLASH_DIR` 环境变量优先（开发/测试），
否则 `%USERPROFILE%\.pi-flash`；写前 `create_dir_all`。

| 新路径 | 旧路径（现在） | 内容 | 写入方 |
|---|---|---|---|
| `~/.pi-flash/workspace.json` | `~/.pi/agent/pi-flash-workspace.json` | 工作区记忆：每项目 last_open、dock/窗口布局、`__ui`、`__dock`、语言/提示音兜底键（`__last` 全局键已退役，见上方设计基线） | `services/workspace.rs` |
| `~/.pi-flash/app-settings.json` | `~/.pi/agent/pi-flash-app-settings.json` | 主题 / 语言 / 提示音 / 字体 / 加载时间窗口 / 启动恢复 / 展示思考 | 同上 |
| `~/.pi-flash/session-index.json` | `~/.pi/agent/pi-flash-session-index.json` | 会话摘要指纹索引（tail-seek 缓存） | `pi-link/sessions.rs` |
| `~/.pi-flash/session-recents.json` | `~/.pi/agent/pi-flash-session-recents.json` | 最近活跃会话清单（加载窗口过滤用） | `pi-link/recents.rs` |
| `~/.pi-flash/catalog-cache.json` | （新） | 模型目录 + 扩展命令缓存（§2/§3 的磁盘缺口补位） | `startup` 装载 + runtime 答复回写 |

- **命名**：目录里不再带 `pi-flash-` 前缀（目录本身已经区分）
- **迁移**：首次启动时，新路径不存在且旧路径存在 → 直接 `rename` 过来（原样搬家，不复制不改内容）；
  新路径已存在则忽略旧文件、**不做清理**（避免误删）。`pi-web-session-index.json` 是 pi-web 的，不动
- **禁止**：以后新增任何 pi-flash 文件都不许落 `~/.pi/agent/`

### 4.1 缓存文件 `catalog-cache.json`

- 单文件、**全局一份**（模型目录与命令都与 cwd 无关；项目差异只在 `enabledModels`
  作用域，那是配置，从磁盘读）；以后大了再拆
- 内容：`{ version, fetchedAt, models:[{provider,id,name,contextWindow}], commands:[{name,description}] }`
- 写入：任何 runtime 的 `get_available_models` / `get_commands` 答复到位时。
  **`skill:` 前缀的命令不入缓存**（skill 走磁盘派生，避免把某个项目的 skill 带成全局）
- 读取：启动装载时（§2/§3 的磁盘缺口补位）

## 5. 项目集：加载多少项目，就一次性装多少项目的配置

- 启动项目集 = 「加载时间窗口」（设置·其他，默认 7 天，`workspace.rs:504`）内活跃会话
  所属的项目：`recent_load_paths(window)` → `sessions_for_paths()` → 去重 cwd → 项目分组
- 集合内每个项目装一份**项目上下文**：项目 `settings.json`（enabledModels 覆盖标记、
  packages、defaultTools）+ 项目 `mcp.json` + 项目 skills + 项目子代理档案 + 会话列表
- 切项目：命中已装上下文直接切（零扫盘）；不在集合内的用**同一个装载函数**现算一次并纳入集合
- 打开设置页不再重新扫盘；写盘后只刷新被改的那一项

## 6. 启动时序

1. 读 `~/.pi-flash/app-settings.json`（主题/语言/提示音）；旧 `~/.pi/agent/pi-flash-*.json` 按 §4 一次性搬家
2. 读 pi `settings.json` 默认项（默认模型/思考档/enabledModels/defaultTools）
3. 装模型清单（磁盘 ∪ 缓存）
4. 装插件 / skill / 命令 / mcp / 子代理
5. `spawn_boot_restore`：判定恢复目标（PI_FLASH_CWD 覆盖 → recents 最新
   会话 → 无）→ 有则进入其项目（remount + open_session，进程附着随
   open_session 走）；无则维持无项目态并置 `boot_resolved`
6. 项目集确定后，**后台线程**装集合内各项目的项目上下文（不阻塞首帧）
7. 揭幕（splash 闸门：附着 ‖ boot_resolved ‖ 3s 超时）→ 【012】 或 【030】

## 7. 不变式与消费方

- **不变式**：渲染路径**不得**触发磁盘扫描或 RPC；渲染只读内存。磁盘读只发生在
  启动装载、切项目（未命中集合）、设置页写盘后
- 消费方：012 的模型 pill / 模型弹窗 / `/` 菜单、设置页（模型·技能·子代理·插件·MCP）、
  状态栏，全部读这份内存全局态
- `models_by_cwd`、`rt.commands`、`mc_*` 从「唯一来源」降级为**进程答案覆盖层**

## 8. 退化与维护

- 首次运行（无缓存）：包内联 provider 显示 `provider/id`、扩展命令暂不在 `/` 菜单；
  跑过一次会话写缓存后即补齐
- 路径迁移后首启（§10）：多一次全量扫描（索引重建 + 清单种子），仅此一次，不阻塞揭幕
- 读盘失败（文件缺失/损坏/字段变体）：单项退化，绝不阻塞启动
- 维护点（`vendor/pi` 升级时复核）：`models-store.json` 形状、`models.json` 形状、
  `get_commands` 是否出现内置命令（§3 的空表）、`get_available_models` 字段
- pi-flash 自有文件路径单点集中在 `pi_link`（新增 `paths` 模块）；**新增任何文件都必须落
  `~/.pi-flash/`**（§4），不许再往 `~/.pi/agent/` 写

## 10. 首启与迁移顺序（新路径为空时）

1. 确保 `~/.pi-flash/` 存在；旧 `pi-flash-*.json` 按 §4 逐个 `rename`（新文件已在则跳过）
2. `session-recents.json` 仍为空 → **startup 显式种子**：`sessions::list_sessions(RECENTS_CAPACITY)`
   按 mtime 记录后落盘（原惰性逻辑搬到 startup）
3. `session-index.json` 缺失/为空 → 首次扫描重建（全量 stat 一次，之后走指纹增量）
4. 上述种子完成后才装配项目集（§5）——保证项目集与 psp 列表同源、同顺序
5. 迁移后第一次启动必然多一次全量扫描：允许，且只在迁移那一次发生（§8）


# 启动阶段后 - 延迟加载
PF在启动后，还有一些不关键的全局数据需要加载，这些数据有可能极为庞大，所以放在【延迟加载】环节处理。
该环节要求在切换启动页后执行，不对启动造成额外负担。

延迟加载项目：

- 扩展说明占用token数（需计算）
- skill说明占用token数（需计算）
- 版本更新检查

> **实现（2026-10-09，公式 v3 = v2 + 单会话精确测量）**：静态探针报告「懒注册
> 信号」（挂了 session_start）与实际装载入口后，把全部懒注册包挂进**一个**
> `pi --mode rpc` 进程（bind 即派发 session_start，无需 prompt/模型调用），
> `context_dump.mjs` debounce 后把 `getAllTools()` 全量（含 sourceInfo.source
> = 包源字符串）原子写文件，Rust 轮询读取、按包归属、CJK 感知估算声明——
> 懒注册包（computer-use 58 颗驱动工具、pi-fff 等）由此拿到精确数而非下限
> （实测 computer-use 325 → 31,465）。dump 失败回退静态数。
> 公式 v2：触发点 = `spawn_splash_gate` 揭幕（置
> `booted`）同一帧调 `Chat::spawn_token_probe`。测量本体

> 实测 subagents 5.8k / web-access 3.0k）；③ **指令文本**——会话期才注册的
