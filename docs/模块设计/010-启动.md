# 设计基线：cwd 是会话的属性，不是应用状态

启动永远从**无项目态**出发（`ws.cwd = None`），应用**不捏造**任何当前目录，
不采纳进程 cwd / exe 目录 / 主目录兜底：

- **cwd = 最近活动项目 = 最后一次 cwd 切换的项目**：
  时刻只有一个来源——`projects.json.last_opened_ms`，由 `register_project`
  在**每次进入项目**时写入。三条切 cwd 的路径全部汇到 `remount_workspace`
  （选择项目/psp 点项目 `switch_project`、打开老会话 `open_session`、文件树
  切 `sync_tree_to_file`），因此「最近打开」≡「最后切换到的 cwd」，不需要
  再聚合会话活动或 mtime。`workspace.json` 的 `__last` 全局键已退役（存量脏
  键由 `boot()` 启动清洗摘除，不再写入）。
- **落点优先级**：`PI_FLASH_CWD`（开发覆盖）→ **最近活动项目**（新会话页）→
  无项目态（真首次运行）。
- **不搞「全局最后会话优先」**：恢复对象是「最近项目**里**的最后会话」，不是
  「全局最后会话」。
- **restore 开关只管会话**（默认 on）：on = 落最近项目并**直接加载该项目自己**
  的最后会话；off = 落同一项目但停在**新会话页**，且不抹该项目的会话记忆
  （`boot_new_session`，下次开 on 仍可加载）。
- **无项目态**只在「真的没有任何项目记录」（首次运行）时出现：零进程、零挂载，
  composer 发送弹「打开项目」先要目录（send 门，文字暂存 `pending_send`，
  选定目录后 `new_session_in` 回填自动发送）。
- **cwd 的合法来源**只剩显式动作：恢复最后会话、切项目/打开项目、
  `PI_FLASH_CWD`（开发覆盖，目录不存在不兜底）。
- 揭幕闸门：有恢复 → 等 pi 附着；无项目态 → `boot_resolved` 直接放行。
- `ws.cwd: Option<PathBuf>`；runtime 的 cwd 保持 `PathBuf`（runtime 恒有
  具体会话目录）；占位 runtime `draft-0` 仅保证 `rt()` 全路径安全，永不 spawn。

### tab 带回放

启动恢复第二条腿：内容区自由 tab（文件/终端）跨重启复原，存档在
`workspace.json` 的 `__tabs`（**单槽全局**：tabs + active + chat，与 `__window`
布局同语义）。

- **单槽全局，不按项目分槽**：内存里 `panel_tabs` 本就是全局态（切项目不
  清带），按项目分槽会存出多份漂移拷贝。
- **回放范围**：文件 tab 重读磁盘（消失条目丢弃）；终端 tab 按 cwd 重生
  （PTY 进程不保活）。Changelog/市场/搜索页属瞬态页，不进存档（重开一键）。
- **回放时机**：`spawn_boot_restore` 里会话恢复**之后**（`switch_to` 会把
  前台拽回 Chat，回放按存档覆盖前台视图）；restore=off 不回放也不覆写存档
  （写侧清槽：`clear_tabs_state` 确保关态什么都不恢复）。
- **落盘时机**：tab 带变更点（开/关/激活/拖位/前台切换，`set_content_view`
  是主要收拢点）+ 关窗 `persist_ui`。内容相同自动跳过写盘。
- **启动期抑制**：`ws.tab_restore_busy` 压住回放/会话恢复中间态的 persist
  （否则空带/半带写穿存档）；存档**先读后回放**，顺序不能反；回放结束
  无条件解锁（finally 语义，防锁泄漏静默跳过后续落盘）。
- **终端重开要 window**：经 `startup::MAIN_WINDOW` 句柄进 window 上下文
  （automation 同款模式），窗口缺失降级为只恢复文件 tab。
- 上限 [`TABS_SAVE_CAP`] = 32 条（防几十个 conpty 拖慢启动）。per-project
  嵌套形态的存档读侧不识别，首次落盘自动覆盖迁移。

# 启动阶段：全局态一次性装载

启动阶段把后续所有界面要用的全局常量**一次性从硬盘装进内存**，之后渲染只读内存。

## 0. 为什么要有这一层

新会话页是 lazy draft（不 spawn 进程），而模型清单 / 命令清单过去只能来自
活着的 pi 进程的 RPC 答复 ⇒ 冷启动/换项目时清单为空：模型 pill 回落
「选择模型」、弹窗「no models match」、`/` 菜单没有命令。启动阶段改为从
磁盘装配（`startup::load_globals`，pi-link `catalog` 模块），进程答到之后
只做**覆盖**。

## 1. 装载内容（全部磁盘，一次性）

| 全局量 | 磁盘源 | 备注 |
|---|---|---|
| 默认配置 | pi `settings.json` + `~/.pi-flash/app-settings.json`（§4） | `defaultProvider`/`defaultModel`、`defaultThinkingLevel`、`modelThinkingLevels`、`enabledModels`、`defaultTools`；主题/语言/提示音（app-settings 优先，workspace 记忆 `__lang`/`__sound` 兜底键） |
| 模型清单 | `~/.pi/agent/models.json` + `~/.pi/agent/models-store.json` + `~/.pi-flash/catalog-cache.json` | 见 §2 |
| 插件 | `settings.json packages` | 声明清单（`Globals.packages`） |
| skill | `SKILL.md` 目录：项目 `.pi/skills`、`.agents/skills`、`settings.skills` 额外路径、`~/.pi/agent/skills`、`~/.agents/skills` | 每项带 scope（项目/全局），`pi_link::skills::discover_skills` |
| 思考强度 | `settings.json` | 全局默认 + per-model 记录 |
| 命令 | PF 内置表 + 扩展命令缓存 + skill 派生 | 见 §3 |
| 工具 | `settings.json defaultTools` | 会话预设 `configured` 即由 pi 按它解析 |
| mcp | `mcp.json`（全局 `~/.pi/agent/mcp.json` + 项目 `.pi/mcp.json`，项目同名替换全局） | 不进项目上下文缓存——设置页/勾选菜单随时改盘，消费方一律盘上现读（043） |
| 子代理 | `agents/config.json`（容量事实源）+ 档案 md | 缺失时启动后台补一份（`ensure_module_config`），档案按需读（044） |

## 2. 模型清单 = 磁盘 ∪ 自建缓存（不 spawn pi 问）

- **磁盘主源**（字段与 `get_available_models` 同形：`id`/`name`/`provider`/`contextWindow`，`pi_link::catalog::disk_models`）：
  - `models.json`（用户自定义 provider——042-1 起 PF 私有账本退役，自定义商
    就在这个 pi 的文件里维护，**优先**）：`providers → { name, models[] }`
  - `models-store.json`（pi 缓存的远端 provider 目录，etag/TTL 由 pi 刷）
  - 合并规则：按 `provider/id` 去重，保持 provider 出现顺序；任一文件缺失/损坏只少一份
- **扩展装载归 spawn 参数（工具预设档）管**：full/custom 档发 `-ne` + 显式
  `-e` 精确集（扩展隔离）；default/read-only/chat-only 档不发 `-ne`（加载
  `~/.pi/agent` 扩展与 npm 包，pi-web parity）。因此包内联 provider（如
  `pi-freeflow`，模型表在 TS 源码里）在隔离档进程里不可见——这类 provider
  靠 `catalog-cache.json` 补进清单。磁盘目录 + 缓存是进程答案的等价源 +
  新鲜度层（models.json 手改、pi 刷新 store 后缓存补上）
- **作用域解析**：仍按 pi 语义在清单内解析 `enabledModels`（默认模型命中 → 用它；
  命中不到 → 域内第一个；patterns 解析为空 → 全量回落）；`new_session_default()`、
  模型弹窗、设置页都读这份内存清单
- **进程答复只做覆盖**：`merge_models` 并集、RPC 答案优先（保留项目级差异）；
  首个会话进程答复到达时 `purge_ghosts` 一次性淘汰缓存幽灵（provider 既不在
  实时答复、也不在 models.json 账本 ∪ 静态注册表的条目删掉——
  `catalog_provisional` 期只跑一次，之后多 runtime 答复照旧并集）
- **启动后台 sweep**：揭幕后对已配置 key 的内置商逐个 probe 实拉
  （`spawn_builtin_catalog_sweep`，端点由注册表 dump 携带的 SDK baseUrl/api
  派生——`registry::models_list_target`），并进全局态 + 回写缓存（重启仍在）

## 3. 命令清单

- **PF 内置表**：pi 的 RPC `get_commands` 不返回内置命令（vendor pi
  1.0.0/1.1.0/1.3.0 实测，`vendor/pi` 升级时复核），内置命令由 PF 侧提供：
  `catalog::BUILTIN_COMMANDS` 8 条（compact / auto-compact / reload / name /
  session / mcp / copy / clone），PF 拦截执行（`session/input` 的
  `builtin_slash_dispatch`），不发 prompt——扩展/skill 同名命令让位
- **skill 派生**：`skill:<name>`（带 description）；项目 skill 走
  `ProjectCtx.skill_commands`，全局目录技能进 `Globals.global_skill_commands`
  （无项目态/草稿态 `/` 菜单兜底）
- **扩展命令缓存**：default 档进程答到的扩展命令经 `merge_commands` 并进
  全局清单并回写缓存（`skill:` 前缀不入缓存）；`-ne` 隔离档收不到扩展命令，
  用缓存兜底
- 消费：会话有进程且 `rt.commands` 非空 → 用它；否则 = 内存命令清单
  （内置表 + 缓存 + skill 派生）

## 4. pi-flash 自有目录 `~/.pi-flash/`（不污染 pi）

**原则**：pi-flash 自己写的文件**全部**落在 `~/.pi-flash/`；`~/.pi/agent/` 只留给 pi
自己（`sessions/`、`settings.json`、`models.json`、`models-store.json`、`skills/`、
`npm/`、`auth.json` …）。路径解析单点：`pi_link::paths`；`PI_FLASH_DIR` 环境变量
优先（开发/测试），否则 `%USERPROFILE%\.pi-flash`；写前 `create_dir_all`。

| 文件 | 内容 | 写入方 |
|---|---|---|
| `~/.pi-flash/workspace.json` | 工作区记忆：每项目 last_open（键 = 项目 ws_key）、`__window`/`__ui`/`__dock` 布局、`__tabs` tab 带存档、语言/提示音兜底键（`__last` 全局键已退役，见上方设计基线） | `services/workspace` |
| `~/.pi-flash/app-settings.json` | 主题 / 语言 / 提示音 / 字体 / 加载时间窗口 / 启动恢复 / 展示思考 / 会话显示数 / 自动清理天数 等 | `services/workspace/app_settings.rs` |
| `~/.pi-flash/session-index.json` | 会话摘要指纹索引（tail-seek 缓存） | `pi-link/sessions`（`Scanner::open_persisted`） |
| `~/.pi-flash/session-recents.json` | 最近活跃会话清单（加载窗口过滤用） | `pi-link/recents.rs` |
| `~/.pi-flash/catalog-cache.json` | 模型目录 + 扩展命令缓存（§2/§3 的磁盘缺口补位） | startup 装载 + runtime 答复回写（§4.1） |
| `~/.pi-flash/ext-tokens.json` | 扩展/技能说明 token 数缓存（带 CACHE_VERSION，见「延迟加载」） | `services/token_probe.rs` |

- **命名**：目录里不再带 `pi-flash-` 前缀（目录本身已经区分）
- **迁移**：首次启动时，新路径不存在且旧路径（`~/.pi/agent/pi-flash-<同名>.json`）
  存在 → 直接 `rename` 过来（原样搬家，不复制不改内容）；新路径已存在则忽略
  旧文件、**不做清理**（避免误删）。`pi-web-session-index.json` 是 pi-web 的，不动
- **禁止**：以后新增任何 pi-flash 文件都不许落 `~/.pi/agent/`（路径一律经
  `pi_link::paths` 申请）

### 4.1 缓存文件 `catalog-cache.json`

- 单文件、**全局一份**（模型目录与命令都与 cwd 无关；项目差异只在 `enabledModels`
  作用域，那是配置，从磁盘读）
- 内容：`{ version, fetchedAt, models:[{provider,id,name,contextWindow}], commands:[{name,description}] }`
- 写入：任何 runtime 的 `get_available_models` / `get_commands` 答复到位时、
  设置页手动「获取模型」成功时、启动后台 sweep 实拉到位时（§2）。
  **`skill:` 前缀的命令不入缓存**（skill 走磁盘派生，避免把某个项目的 skill 带成全局）
- 读取：启动装载时（§2/§3 的磁盘缺口补位）；坏文件按空缓存处理

## 5. 项目集：加载多少项目，就一次性装多少项目的配置

- 启动项目集 = 「加载时间窗口」（设置·其他，档位 7/14/30 天，默认 7 天，
  `workspace::load_window_days`）内活跃会话所属的项目：`recent_load_paths(window)`
  → `sessions_for_paths()` → 去重 cwd → 项目分组（`spawn_boot_restore`）；
  置顶会话并入装载清单（pin 的意义就是老会话常驻可见，不挤占尾部预载名额）
- 集合内每个项目装一份**项目上下文**（`startup::load_project` → `ProjectCtx`）：
  项目 `settings.json`（enabledModels 覆盖标记、packages）+ 项目 skills +
  `skill:<name>` 命令
- 切项目：命中已装上下文直接切（零扫盘）；不在集合内的用**同一个装载函数**现算一次并纳入集合
- 打开设置页不再重新扫盘；写盘后只刷新被改的那一项

## 6. 启动时序

1. `main()` 最前：崩溃 hook（panic 落盘）→ 081 更新交接 `handoff_if_newer`
   （安装根下有更高版本完整载荷就 spawn 它并让位）→ 任务栏固定 `win_pin`
   → **`startup::boot()`**（建 `~/.pi-flash/`、旧 `pi-flash-*.json` 按 §4 搬家、
   注册表/工作区记忆清洗、recents 首启种子、042-1 一次性迁移，见 §10）
2. `[perf]` 总开关（`PI_FLASH_PERF=1`）；主题（`PI_FLASH_THEME` 覆盖 →
   app-settings）；语言偏好
3. gpui 启动：内置 JetBrains Mono 字体注册 → 系统字体目录枚举（设置页下拉
   数据源）→ `gpui_component::init` → 键位绑定 → 建窗（首帧画启动页）
4. `Chat::new`：`load_globals()`（§1）→ `reload_model_defaults`（新会话默认档，
   先于第一帧）→ `reload_settings_panel` → 占位 runtime `draft-0` →
   **`spawn_boot_tasks` + `spawn_boot_restore`**（§9）
5. `spawn_boot_tasks`：pf-context 初始化 → 注册/凭据后台线程（pif-secret 入
   PATH、auth.json 标记去路径化、全局 pi shim、agents/config.json 补缺）→
   120ms 泵 / 3s 外部追加观察 / 60s 空闲回收 / 30s recents 对账 / fs watch 泵 /
   syntect 预热 / PF 插件清单扫描 / 定时调度（046，dev-flag 门住注册）
6. `spawn_boot_restore`（后台判定恢复目标）：`PI_FLASH_CWD` 覆盖 → 最近活动
   项目 → 无 → 有则进入其项目（remount + open_session，进程附着随 open_session
   走）；无则维持无项目态并置 `boot_resolved`；随后 tab 带回放 + 会话清单装载
   （窗口过滤 + 项目分组 + 项目上下文预装 + `TAIL_PRELOAD` 尾部预载）
7. 揭幕（splash 闸门：pi 附着 ‖ boot_resolved ‖ 3s 超时，且启动页 ≥500ms）
   → 揭幕帧 `pending_zoom` 补最大化 → 【012】 或 【030】

## 7. 不变式与消费方

- **不变式**：渲染路径**不得**触发磁盘扫描或 RPC；渲染只读内存。磁盘读只发生在
  启动装载、切项目（未命中集合）、设置页写盘后
- 消费方：012 的模型 pill / 模型弹窗 / `/` 菜单、设置页（模型·技能·子代理·插件·MCP）、
  状态栏，全部读这份内存全局态
- `models_by_cwd`、`rt.commands`、`mc_*` 从「唯一来源」降级为**进程答案覆盖层**

## 8. 退化与维护

- 首次运行（无缓存）：包内联 provider 显示 `provider/id`、扩展命令暂不在 `/` 菜单；
  跑过一次会话写缓存后即补齐
- 读盘失败（文件缺失/损坏/字段变体）：单项退化，绝不阻塞启动
- 维护点（`vendor/pi` 升级时复核）：`models-store.json` 形状、`models.json` 形状、
  `get_commands` 是否出现内置命令（§3）、`get_available_models` 字段
- pi-flash 自有文件路径单点集中在 `pi_link::paths`；**新增任何文件都必须落
  `~/.pi-flash/`**（§4），不许再往 `~/.pi/agent/` 写

## 9. 启动职责清单（全部收进 startup）

原则：**启动阶段做的事只在 startup 里有名字**——`main.rs` / `render` / `Chat::new` 不再各自
夹带启动逻辑；清单外的代码不许在启动路径上读盘或发 RPC。

`Chat::new` 只在 runtime 建好后调两个入口：
`startup::spawn_boot_tasks(cx)`（pf-context 初始化 / 注册与凭据后台线程 /
120ms 泵 / 3s 外部追加观察 / 60s 空闲回收 / 30s recents 对账 / fs watch 泵 /
启动页闸门）与 `startup::spawn_boot_restore(cx)`（恢复目标判定 → 进项目 →
tab 带回放 → 会话清单装载 → 项目上下文预装 → 尾部预载）。

启动路径职责全部由 startup 拥有/发起：启动页闸门（`MIN_SPLASH` /
`SPLASH_TIMEOUT`）与揭幕、pending_zoom 最大化、主题/语言/提示音统一应用、
工作区记忆读一次进全局态、pi `settings.json` 默认项装载、全局清单装载 +
项目集（§1/§5）、初始 runtime 决策（恢复 last_open 会话或草稿）、后台泵、
首启种子（`pi-link/recents.rs` 清单为空时按 mtime 扫描种子并落盘）与索引
持久化（`pi-link/sessions` `Scanner::open_persisted`，路径按 §4，种子/落盘
时机由 startup 定义）。

- `scripts/dev.sh`：开发启动脚本（`PI_FLASH_RPC_LOG` 等）；用
  `PI_FLASH_DIR` 指向独立目录即可不碰真实配置。
- `scripts/release.sh`：`启动说明.txt` 的「数据位置」文案：pi 数据
  `~/.pi/agent/`、pi-flash 数据 `~/.pi-flash/`。

## 10. 首启与迁移顺序（新路径为空时）

`startup::boot()`（`main()` 最前面，必须早于任何读盘者——workspace 记忆 /
recents / 会话扫描器都是进程级惰性单例）：

1. 确保 `~/.pi-flash/` 存在；旧 `pi-flash-*.json` 按 §4 逐个 `rename`（新文件已在则跳过）
2. 项目注册表与工作区记忆清洗（幂等）：落在当前安装根内的历史脏条目——
   更新交接不设 cwd 时代写进来的 payload 目录（`projects::purge_app_paths`）、
   脏 `__last` 与载荷目录名下的每项目记忆（`workspace::purge_app_install_memory`）
3. `session-recents.json` 仍为空 → **显式种子**：`sessions::list_sessions(RECENTS_CAPACITY)`
   按 mtime 记录后落盘
4. 042-1 一次性迁移：PF 私有账本（providers.json / pf-auth.json）→ pi 的
   models.json + auth.json 标记条目；旧文件改名 .bak，幂等；失败只记日志
   绝不阻塞启动（下次启动重试）
5. `session-index.json` 缺失/为空 → 首次扫描重建（全量 stat 一次，之后走指纹增量）
6. 上述种子完成后才装配项目集（§5）——保证项目集与 psp 列表同源、同顺序；
   迁移后第一次启动必然多一次全量扫描：允许，且只在迁移那一次发生（§8）
