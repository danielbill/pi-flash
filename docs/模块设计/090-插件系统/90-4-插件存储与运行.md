# 90-4 插件存储与运行

> 清单契约大版本以**插件仓** `schema/plugin-contract.json` 的 `manifest_schema`
> 为准（宿主支持值见 §2）；组件词表与样式 token 见 `90-3-插件UI组件规范.md`。
> 定四件事：**目录、清单、context 能力接口、加载时机**。
>
> 原则一句话：**位置与时机归宿主，内容与格式归插件。**
>
> 执行域：`contributes.service` 声明 + `ctx.service.post/query`（宿主侧实现住
> `crates/app/src/pf_plugin/svc.rs`：状态集、未运行排队、outbox 泵、实例配置
> 同步）。宿主管目录、原子性、卸载清理；插件管自己数据长什么样——**PF 从不
> 解析插件数据**。
>
> **载体优先级**：PF 官方插件**唯一开发载体 = Rust→wasm**（§7 为主干）。
> JS 标准包（§5）冻结为存量兼容面：**新插件、新能力一律不得先落 JS**，开发
> 闭环见 `90-8-插件开发闭环.md`。

## 1. 插件目录（PF 统一）

```
<数据目录>/plugins/<id>/            dev 平铺布局（dir == pkg）
<数据目录>/plugins/<pkg>/<ver>/    市场安装布局（<pkg> = 台账名转写 @scope__name）
  pf-plugin.toml     清单（PF 读，见 §2）
  main.js            JS 标准包逻辑入口（§5）
  plugin.wasm        内层 wasm 包逻辑（§7）
  assets/            图标等静态资源（可选）
  pi/                contributes.pi_extensions 的 pi 扩展文件
  .cache/            cwasm 编译产物缓存（宿主管）
  data/              插件私有数据目录——永远在包层 `<pkg>/data/`（PF 首次加载
                     时创建，插件读写，PF 不解析）
```

- `<数据目录>`：debug = `pi-flash-dev/`，release = `~/.pi-flash/`（`paths.rs` 既有）
- `<id>` = 平铺目录名 = 清单 `id`；市场布局的版本层目录名是版本号，不能当
  身份用（对账走 `pkg_dir` / `pf_plugins::dir_aliases`）
- PF 保证：目录存在、`ctx.dir` 指向包层 `data/`、**卸载时整目录删除**
- **PF 不解析 `data/` 下任何文件**——存储是插件自治领域
- **布局两档，data 只认包层**：版本目录只装**随版本走的东西**（wasm / 入口 /
  assets / `.cache` cwasm / `plugin.log`）；**用户数据永远在
  `plugins/<pkg>/data/`**，无版本维度——`PluginManifest::data_dir()` 是唯一
  派生口（`pkg_dir/data`），不要 `dir.join("data")`。更新换版本目录 data 不动。
  旧版本目录下遗留的 `<ver>/data` 由启动扫描前的 `pf_plugins::migrate_data_dirs`
  一次性 `rename` 到包层（幂等；按台账遍历，**不看清单能否解析**——被本版
  拒载的旧包正是最需要迁的）

## 2. pf-plugin.toml（PF 读的清单）

```toml
schema = 5                        # = 契约大版本（manifest_schema）；高于宿主支持 → 拒装
id = "example"
title = { zh = "示例面板", en = "Example Panel" }
version = "0.1.0"

# 申请进驻（PF 画，不给就什么都不出现）；状态栏入口二选一：
# 状态栏 status_bar 或 topbar 菜单 topbar_menu，不得同时声明
[[contributes.status_bar]]
icon = "assets/icon.svg"          # 状态栏 tab 图标（相对本目录，单色 SVG）
title = { zh = "示例" }

# —— 或（二选一）——
# [[contributes.topbar_menu]]     # topbar「菜单」三横浮层里的条目
# title = { zh = "示例功能", en = "Example" }
# icon = "assets/wx.svg"          # 规则同 status_bar icon

[[contributes.file_menu]]         # 文件右键 → 插件 → 该项
id = "add-pin"
title = { zh = "加入收藏", en = "Add Pin" }
icon = "pin"                      # 宿主内置图标名（90-3 §3.4）

[[contributes.panels]]            # 点击状态栏 tab 打开的面板（dock = panel|tab）
id = "quick"
title = { zh = "示例" }
entry = "main.js"                 # 逻辑入口

# [[contributes.fn_bar]]          # 会话标签功能栏注册槽：每个会话标签一个插件 icon
# command = "bind"                # 点击回环命令（env 带当前 session.key）；chrome 由插件导出 fn_bar(ctx, env) 给

# [[contributes.popups]]          # 非模态弹窗：内容由插件导出 render_popup(ctx) 给
# id = "info"
# title = { zh = "示例弹窗", en = "Example Popup" }
# size = "MD"                     # SM/MD/LG 档位（MD≈500x500，映射归宿主）
# entry = "main.js"

# [[contributes.pi_extensions]]   # 包内 pi 扩展文件（相对包根）；经会话挂载台账
# path = "pi/index.mjs"           # 以 -e 挂进 pi 子进程（§8/§9）

# [[contributes.service]]         # 执行域实例声明（scope 当前仅 "session"）
# id = "main"
# scope = "session"
# entry = "pi/svc.mjs"            # 执行面入口（会话进程内运行）

# [[contributes.sessions]]        # 认领前缀声明（配 ctx.newDraft 建线对账）
# prefix = "示例"
```

校验（清单解析住 `crates/app/src/pf_plugin/manifest/`，与插件仓 `check.mjs`
同读 `schema/plugin-contract.json`）：

- `schema` 必须 = 契约 `manifest_schema`（宿主常量 `SUPPORTED_MANIFEST_SCHEMA`
  = **5**，兼容 3/4）；更高/更低不受支持 → 拒载，进失效包提示（不降级运行）
- `id` kebab-case 且 = 目录名（版本层布局上钻到包层对账）
- `title.zh`、`version` 必填
- `contributes.*` 全可选；无 `wasm`/`bytecode` 的包须至少申请一种进驻面
  （panels/popups/fn_bar/status_bar/topbar_menu/file_menu 任一）——纯库包不装载；
  内层 wasm/字节码包无 contributes 也合法（验签在 wasm 内）
- `icon` 三来源：宿主内置名 / `assets:<名>` / `assets/` 相对路径
- `panels`/`popups` 的 `entry` 必须存在（wasm/字节码包免文件校验）
- **禁用字段**：`layout` / `store` —— 出现即报错（数据归 `ctx.dir` 自管）；
  `api` 等未知键一律即拒；`wasm` 字段仅内层包可用（§7），标准包出现即报错

## 3. context 能力接口（插件拿到的唯一东西）

装载后插件获得 `ctx`，**此外没有任何全局可调**（没有 fs / net / process）。

```js
// —— 提问（同步）——
ctx.isExecutive(path)            // → bool     宿主按后缀/平台判定（script_exec 同表）
ctx.fileIcon(path)               // → 不透明引用，直接放进 button.icon，只透传不解释

// —— 持久化（插件自管，宿主只保证目录与原子性）——
ctx.dir                          // → string   私有目录（data/）绝对路径
ctx.fs.read(name)                // → string   整读；缺失/坏文件 → ""（插件自己兜底）
ctx.fs.write(name, str)          // → void     原子写（临时文件 + rename），只限 ctx.dir 内
ctx.fs.list()                    // → string[] 目录下的文件名

// —— 动作（宿主执行）——
ctx.run(path)                    // 021 执行链，新终端 tab
ctx.edit(path)                   // 编辑器/查看器打开
ctx.revealInExplorer(path)       // 资源管理器定位
ctx.toast(msg)                   // 轻提示
ctx.act.openPopup(id)            // 打开清单 popups 条目（非模态，宿主管定位/随手关）
ctx.act.closePopup(id)           // 关闭

// —— 会话认领（意图调用，无同步返回）——
ctx.newDraft(prefix, cwd)        // 新建插件认领会话；宿主建线后经 broadcast
                                 // "claim" 回推 {key,name,cwd}（ctx.sessions.newDraft 同面）

// —— 执行域（contributes.service 实例通信；宿主侧 svc.rs）——
ctx.service.post(anchorOrKey, msg)   // → bool  投递到执行域实例；未运行 → 宿主
                                     // 排队（溢出 false），实例启动即消费
ctx.service.query(anchorOrKey)       // → "running" | "stopped" | "absent"
                                     // onMessage(payload, meta) 由宿主 outbox 泵投递

// —— 宿主证明（内层 wasm 插件专用，§7）——
ctx.hostProof(nonce)             // → { kid, proof, nonceTag }  官方构建证明；宿主只递数据不判定

// —— 注册（activate 里调，unload 自动回收）——
ctx.onMenu(id, handler)          // 清单 file_menu 项的回调。handler({ path, fileIcon })
ctx.onCommand(id, handler)       // 组件 menu 项 / fn_bar 点击 / switch 翻转的回调（90-3 §4.2/§4.3）。
                                 // handler({ path?, session?: { key }, value?: bool })——按入口给：
                                 // file_menu→path；fn_bar 触发→session（当前会话键）；switch→value（翻转后布尔）
ctx.onPanelOpen(handler)         // 面板激活回调。handler()
ctx.onBroadcast(name, handler)   // 宿主标准组件状态广播。封闭事件集：
                                 // inputpanel / claim / session（会话标签激活/切换，
                                 // payload { key }；页面未激活不产生）

// —— 会话徽标（owner = 插件 id，多插件互不覆盖；JS 面）——
ctx.sessions.setBadge({ session, icon, tone })  // 会话列表时间位标记（icon 档位 md）；
                                                // session 与 fn_bar env、pi getSessionId() 同源
ctx.sessions.clearBadge({ session })
```

约定：

- **`fileIcon` 是不透明引用**：插件不解释、只透传（90-3 §3.3）
- **`onMenu` 触发时宿主已拿全路径**，`{ path, fileIcon }` 两个现成字段一起递来，插件不用二次问
- **`data/` 之外的路径写不进去**：`fs.write` 越界 → 报错，不落盘
- **任何注册回调返回后，宿主自动重渲染该插件面板**——插件不需要通知、不需要事件
- **`hostProof` 标准 JS 包禁用**：判定必须在 wasm 内（插件仓防盗设计 L3.3，
  `docs/插件框架/090-5-插件包防盗设计.md`），见 §7；违反 → `check` 报错
  （90-3 §9 U14）
- 动作目标路径不存在 → toast 报错，不抛异常
- 插件逻辑抛异常 → 宿主捕获、toast「插件 <id> 出错」、该插件本次会话禁用（§4）
- JS 面另有 `openUrl` / `openFolder` / `newSession` / `askPi` 等动作（wasm 面
  未导出，不进 §7 的 host import）

## 4. 加载时机（启动只承担清单）

```
PF 启动
  └─ 首帧后异步：扫 plugins/（台账白名单，纯清单解析，微秒级/个）
      ├─ 校验通过 → 注册右键菜单项 + 状态栏 tab（此时 ctx 未建、data/ 未读）
      └─ 校验失败 → 记日志跳过，不注册（台账启用却拒载的进失效包提示，见 090-10）

用户点击状态栏 tab            → 懒加载：建 ctx → render → 按 dock 形态开面板/页签
用户点右键菜单项              → 懒加载同上 → onMenu → 返回后重渲染 → 释放（不驻留）
用户点格子右键菜单项          → onCommand → 返回后重渲染
插件自己写了数据              → 无需通知，下一次 render 自然读到
PF 退出                       → 无需保存（每次写都即时落盘）
```

- **清单启动加载，数据懒加载**：N 个插件不拖启动
- 同一插件的 ctx 全局单例：面板开着时点右键菜单，复用同一 ctx 与同一份内存缓存
- 插件逻辑抛异常：捕获、toast「插件 <id> 出错」、该插件本次会话禁用，**不影响宿主**

## 5. JS 标准包（存量兼容面）

标准包逻辑入口 = `main.js`（ESM、零 import、唯一能力面 = ctx），宿主以
QuickJS（rquickjs）同步执行，实例固定在 UI 线程、动作类调用入队延后消费；
单次入口调用死线 5s。分发态可为 `plugin.qbc`——由 PF 的 `qjsc`
（`crates/pf-plugin-host/src/bin/qjsc.rs`）从同一份 main.js 编出的 QuickJS
字节码，同一引擎、同一 ctx、同一渲染路径，落盘无明文源码（字节码与 quickjs-ng
版本绑定，换 rquickjs 版本须重编分发包）。入口方法 = `activate(ctx)` /
`render(ctx)` / `unload()`；运行时住 `crates/pf-plugin-host/src/js/`。
**新插件、新能力不得先落 JS**（闭环见 `90-8`）。

## 6. PF 侧责任清单（实现对照）

| 项 | 触点 |
|---|---|
| 扫描 + 清单解析 | `paths::plugins_dir` + 极简 toml 解析（`pf_plugin/manifest/`，台账白名单） |
| 状态栏 tab 注册 | 状态栏 tab 体系（icon + title，点击按 dock 切 dock 面板/内容页签） |
| 右键菜单注入 | `tree_menu` File 分支追加「插件」组 |
| ctx 构造 | `script_exec::exec_kind`（isExecutive）、`file_icons`（fileIcon）、`shell_open`、`open_file_tab`、`open_script_terminal` |
| 私有目录 | `<pkg>/data/` 创建 + 卸载删除 + `fs.write` 原子写（临时文件 + rename）+ 越界拒绝 |
| 面板渲染 | 组件树 → gpui（`pf_plugin/panel/` 树解释器；词表见 90-3 §1，**不认字段、不 filter、不折算动作**） |
| 回调后重渲染 | `onMenu` / `onCommand` / `onPanelOpen` 返回即刷新该面板 |
| 异常隔离 | catch + toast + 会话级禁用 |
| 执行域 | `pf_plugin/svc.rs`：实例配置同步 + outbox 泵（挂 120ms 主泵） |
| 宿主证明交付 | `build.rs` 注入常量 + `ctx.hostProof()` 递数据；不验签不解释（§7） |

## 7. 内层 wasm 插件与宿主证明

内层包 = wasm 载体 + 宿主证明校验：宿主交付一份构建期注入的签名材料，插件侧
验签，非指定宿主则拒载。签名只是交付形态，载体本身是加密包。设计与威胁模型
见**插件仓** `docs/插件框架/090-5-插件包防盗设计.md`（L3 宿主证明）。

### 7.1 两种包形态

| | 标准包（市场分发） | 内层包（内部分发） |
|---|---|---|
| 结构 | `pf-plugin.toml` + `main.js`（或分发态 `plugin.qbc`）+（可选）`assets/` + `pi/` | `pf-plugin.toml` + `plugin.wasm` +（可选）`assets/` |
| 清单判别 | 无 `wasm` 字段 | `wasm = "plugin.wasm"`（出现即按内层包处理；`forbidden` 的 wasm 仅约束标准包） |
| 逻辑 | QuickJS 同步 `main.js`（§5） | wasm 模块，宿主按内层流程装载 |
| 分发 | 签名索引（`90-2` §7） | 插件仓 `inner/` 产出 → 私有渠道；**永不进市场渠道**（U10 禁 `plugin.wasm`） |

### 7.2 宿主证明流

1. **构建期注入**：已签的证明由发布流水线送给宿主 `build.rs`（`PF_BUILD_PROOF`
   / `PF_BUILD_KID`），烙成二进制常量（宿主零密码学、不接触签名材料）；
   无注入构建嵌占位符 `PROOF_PLACEHOLDER` + 构建警告。签名流程与密钥流转见
   插件仓内部文档（不入库）。
2. **运行期交付**：`ctx.hostProof(nonce)` → `{ kid, proof, nonceTag }`（§3）。
   `nonceTag = hex(sha256(proof ‖ 0x00 ‖ nonce))`，宿主交付时现算；
   宿主不验签、不解释。证明材料钩子是进程级（后台验签线程同样取得到）。
3. **插件侧判定**：公钥 + `kid` 编译进 wasm（包内不单独放 key 文件）；
   `load()` 验签 + 复算 `nonceTag`。占位符/伪造/缺失 → 返回错误**拒载**：
   面板不注册、状态栏不出现（失败不静默进 UI，结论只进 stderr 供开发查）。
   WIT 面：`get-host-proof` import 与 `load -> result<_, string>` 错误通道
   （Err = 插件自拒，宿主拒载并透传原因）；宿主钩子未注入 = 占位符
   fail-closed；跨语言自检门 = 插件仓 `npm run inner:selftest`。
4. **WIT 面（`crates/pf-plugin-host/wit/pf-plugin.wit`）**：world 导出
   `load(plugin-ctx) -> result<_, string>` / `unload` / `on-event` / `render`；
   契约钩子导出（`fn-bar(env) -> string` 功能栏 chrome {icon,tone,tip}、
   `render-popup() -> string` 弹窗内联树、`session-row(env) -> string` 会话行
   徽标 {icon,tone}）**不进 world**，由宿主在实例化时能力探测（缺导出 = 功能
   关，旧包不受影响）；返回的都是已算好的 JSON 串，宿主不折算，「无」语义用
   空串/"null" 表达。host import：`measure-text` / `toast` / `open-file` /
   `run-script` / `quick-pins` / `file-icon` / `is-executive` /
   `storage-read|write` / `get-host-proof` / `new-draft` / `svc-post` /
   `svc-query` / `open-popup`（意图调用均入动作队列）。`page_actived` 钩子走
   on-event 通道 `kind="page-active"`（id 空串，path = env JSON
   `{"session":{"key":…}}`）。env 统一 = 宿主口径会话键。`render-popup` 未导出
   时回退 v2 `render` 面。

### 7.3 隔离纪律与边界

- 公钥、验签逻辑、签名材料全部只在内层区，**永不随市场渠道外发**；`packages/` + 索引 +
  README 等市场面保持零 wasm、零密钥、零签名材料，随时可整体外发。
- 标准包引用 `hostProof` → `check` 报错（90-3 §9 U14）；`plugin.wasm` 出现在标准包 → U10 报错。
- 防护边界与强度评估属内部口径，不在公开文档展开（见插件仓内部文档）。

## 8. 宿主协议文件 `pf-runtime.json`

`<pkg>/pf-runtime.json`（包根，与 pf-plugin.toml 同级）——**宿主写、插件只读**的
通用运行许可通道，任何 `contributes.pi_extensions` 插件可用，无插件专属知识：

```json
{ "pf_enabled": true, "pf_seq": 3, "pf_reason": "enable" }
```

- `pf_enabled`：运行许可。ext 泵见 `false` 自我隔离（停渠道、发下线通知、待机
  不自杀）；见 `true` 恢复服务——**无需重启 pi 进程**。
- `pf_seq`：单调递增，供插件识别「许可变更过」而非读盘缓存。
- `pf_reason`：`startup | enable | disable | quit`。
- 写者与时机（唯一写者 = 宿主，`pf_plugin::pf_runtime_write`，原子写 tmp +
  rename）：启动 = `startup`（许可刷新）；挂载成功（attach）= `enable`；
  停用/更新 evict = `disable`；退出扇出 = `quit`。缺文件/缺键 = 许可（兜底安全）。
- 与 `data/` 的关系：`data/` 仍是插件自管区（PF 不解析）；本文件是宿主协议
  面，与插件数据彻底分离。会话身份规范键（`PF_SESSION_KEY` env / 命令 env
  `session.key` / 挂载台账键三通道同源 = `pool.active_key`）见 90-9 §8。

## 9. 挂载台账的版本层自愈

`contributes.pi_extensions` 的绑定通道把**绝对路径**写进会话台账
（`~/.pi-flash/session-ext.json`），而市场安装布局是
`plugins/<pkg>/<version>/pi/index.mjs` —— 路径里带着**版本目录**。插件一升级
（旧版本目录被 prune），台账里那条路径就成了死路径；spawn 把它当 `-e` 传给
pi 时，**pi 加载扩展失败会直接退出整个进程**（`Error: Failed to load
extension … Hint: Start without plugins using "pi -ne"`），于是绑定会话起不来、
ext 无处安身，收发全断。

**规则：台账是「语义引用」，不是路径缓存。** 任何消费台账路径的地方都要先过
`pi_link::session_ext::resolve_sources`：

- 路径在 → 原样用（快路径）；
- 版本层换代 → 在**当前安装包**里按同名相对路径重定位（`<pkg>/<同版本>/…`
  → `<pkg>/<新版本>/…`，平铺 dev 布局保持不变）；
- 包里已找不到该文件 / 包已卸载 → **摘掉条目**（一条死 `-e` 会毒死整批
  `-e`，宁可少挂一条）；非插件包的用户自有绝对路径不替它判生死，原样保留；
- 重复条目（同文件新旧两条、分隔符/盘符大小写不同）→ 去重（`-e` 挂两次 =
  ext 双开、双答）。比较一律走 `session_ext::same_source`。

消费点（改任一都别漏）：`SessionRuntime::new`（读入 + 首次自愈回写）、
`SessionRuntime::spawn`（`ext_sources` 与台账 `-e` 段，自愈后回写）、
`Chat::plugin_attach_pi_exts`（合并前自愈，避免新旧两条并存）、
`Chat::has_live_service`（闲置回收豁免按 `mount_key` 比，抹掉版本段）、
`open_session` 的预热判据（死条目不算「有扩展」，不白起进程）。
