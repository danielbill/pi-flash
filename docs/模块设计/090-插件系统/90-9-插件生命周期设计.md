# 90-9 插件生命周期设计

> 上位：`90-1-插件设计需求.md`。
> 相关：`90-4`（清单/运行）、`90-5`（PF 钩子）、`90-7`（wasm 测试）、`90-8`（开发闭环）；
> 执行域实例的宿主侧实现住 `crates/app/src/pf_plugin/svc.rs`（实例配置/outbox 泵）。
>
> 一句话：**插件侧只有两个接口 `load` / `unload`；宿主侧一条销毁路径（停用）；一切可观测性落 `plugin.log`，不做自动惩罚。**

## 1. 结论速览

| # | 结论 |
|---|---|
| 1 | 插件导出面 = `load(plugin-ctx)` + `unload()`，两个都必需（`unload` 允许空实现） |
| 2 | 没有 `init`：插件的自我初始化发生在 `load` 内，由插件自己完成 |
| 3 | PF → 插件的上下文统一叫 `plugin-ctx`，**常量与变量装在同一个对象里**，每次调用都给完整一份 |
| 4 | 插件 → PF 的呈现申请仍是**清单声明**（不改成运行期交换） |
| 5 | 销毁路径收敛为一条：**停用**（卸载 = 停用 + 删；更新 = 停用 + 覆盖；退出 = 全体停用） |
| 6 | 宿主保留状态机与事件流水，落 `<插件目录>/plugin.log` |
| 7 | 当前边界：不做加载超时强杀、不做自动隔离、不做错误码分类（见 §9） |

## 2. 插件侧接口

| 接口 | 必需 | 语义 |
|---|---|---|
| `load(plugin-ctx)` | 是 | 被 PF 加载。建立自身状态、注册回调、交出运行期动作能力 |
| `unload()` | 是（默认空） | 被 PF 卸载前的最后一次调用：停用 / 卸载 / 更新覆盖 / PF 退出 |

- `unload` 无返回值；best-effort，宿主不等插件确认存盘（JS 载体单次调用死线
  5s；wasm trap 只落日志，关不掉的插件不能卡住宿主）。
- 异常处理：`load` 抛错/失败 → 本次会话禁用该插件 + toast + `plugin.log` 记一条；**不影响宿主**。
- 命名：插件级接口只用 `load`，不用 `init` / `activate`。执行域**实例级**的
  `activate(svc)` / `onStop`（宿主侧 `crates/app/src/pf_plugin/svc.rs`）是另一层，名字不动。

## 3. `plugin-ctx`（PF → 插件）

每次调用都给完整一份，**永远是最新的，插件永远不保存它**。

```json
{
  "plugin":  { "id": "pf-wxbot", "version": "0.2.0", "dataDir": ".../plugins/pf-wxbot/data" },
  "pf":      { "version": "0.6.1", "locale": "zh-CN" },
  "session": { "key": "pf-wxbot-2610302104129" },
  "cwd":     "/path/to/project"
}
```

规则：

- **会话身份只从这里来**（收编 `90-5` 的「唯一会话身份 = 宿主下发」）。无会话时 `session` 为 `null`。
- `dataDir` 恒为包层 `<pkg>/data`（`PluginManifest::data_dir()` 唯一派生口），
  载体运行时的存储目录听它、不听 wasm 文件旁的猜测值。
- 字段**只增不改**：新增字段不构成破坏性变更，旧插件忽略未知字段即可。
- 开关翻值等**输入事件**不是上下文，作为动作参数另传（如 `{"value":true}`）。
- 禁止把可变身份塞进"一次性 ctx 里存着用"——ctx 就是一次性的，状态变了下次调用自然变。

## 4. 插件 → PF（呈现申请）

保持 `90-2`/`90-4` 的**声明式清单**：区域（status_bar / topbar_menu / fn_bar / popups / panels）、图标、标题全部写在 `pf-plugin.toml`。

理由：市场扫描、启动零代码执行都依赖"清单静态可读"。

运行期只保留**动作型**能力（不改区域/图标）：

- `act.openPopup` / `act.closePopup`
- 会话列表徽标（`session_list_render` 钩子返回值 / `ctx.sessions.setBadge`）
- 临时开关（启用位由宿主台账管）

## 5. 宿主状态机

```
Registered ──load──> Loading ──ok──> Active
                        │err            │停用
                        └──> Crashed    ▼
                                     Unloading ──> Disabled
```

- 状态是**宿主事实**，插件不可见（插件可查的只有执行域实例态 `ctx.service.query`）。
- `Disabled` / `Crashed` 可再 `load`：用户手动重新启用是显式意图，宿主不剥夺开闸权。
- 卸载 = 停用（`Disabled`）后删插件目录，无独立状态。
- 每次转移写一条事件（见 §7）。

## 6. 销毁路径（唯一入口 = 停用）

| 场景 | 动作序列 |
|---|---|
| 停用（用户点开关） | 收运行许可（`pf-runtime.json` disable，见 §8）→ 摘会话挂载 → 全体实例 `onStop` → `unload()` → 丢运行时 → 状态 `Disabled` |
| 卸载 | 停用 → 删插件目录（含 `plugin.log`、`.cache/`，被占用残留在下次启动 `sweep_orphans` 清） |
| 更新 | 停用 → 覆盖新版本 → 重载运行态（090-10） |
| PF 退出 | 先收运行许可（quit）→ 全体插件 `unload()`（总预算 1 秒）→ 停 pi 子进程 → 存窗口状态 |
| 会话切换 / 项目切换 | **不触发 `unload`**（会话级收尾归执行域 `onStop`） |

退出顺序固定为：`unload` → 停 pi → 存窗口状态。理由：带 `pi_extensions` 的插件需要在 pi 进程还活着时说完最后一句话。

## 7. `plugin.log`

位置：`<插件目录>/plugin.log`（**每插件一份**；卸载随目录删）。

行式，人可读，含时间与耗时：

```
2026-10-30T21:04:12 load   ok    3120ms   (首次校验+编译)
2026-10-30T21:10:03 load   ok       8ms   (cwasm 缓存命中)
2026-10-30T21:44:51 unload ok       2ms
2026-10-31T09:12:07 load   ERR     45ms   verify failed
```

**成对判定（崩溃识别）**：`load` 与 `unload` 必须成对。启动时读最后一个未闭合的 `load` → 判定上次异常退出 → 追加一条 `[上次异常退出，未执行 unload]`。不需要任何哨兵文件。

- 只记 serving 实例：启动期验签门的实例是即验即弃的另一份，不落本日志
  （否则每次正常启动都留一条永不闭合的 `load`，崩溃判定全数误报）。
- **用户可见性**：日志人可读、可直开排查；宿主不基于日志自动隔离或播报，
  启停开关在市场【已安装】页，由用户自行判断。

## 8. pi 侧扩展（`contributes.pi_extensions`）

- 不归 PF 管生命周期：扩展随 pi 子进程生死，PF 只决定"下次 spawn 时挂什么"。
- 唯一耦合窗口 = PF 退出时那 1 秒 `unload`：插件可经执行域通道与 pi 侧告别；**不提供 ack**。
- **停用不立即杀进程**：宿主写 `<pkg>/pf-runtime.json`（`90-4` §8，唯一写者 =
  宿主），ext 泵见 `pf_enabled=false` **自我隔离**——停渠道、发下线通知、
  待机（不自杀）；恢复许可（`pf_enabled=true`）后原地复活服务，无需重启 pi
  进程。进程内物理摘除落在下次 spawn；忙 → 不动进程，下次 spawn 生效。
- **会话身份规范键**：`pool.active_key` 是唯一规范键——spawn 注入
  `PF_SESSION_KEY` env、命令 env `session.key`、挂载台账键三通道同源。插件
  不得用 pi uuid / getSessionFile（首条消息前 undefined）/ argv 猜身份。
- 版本偏差（更新后 pi 侧仍跑旧码）：**下次 spawn 生效**，更新入口的界面提示可见，不静默。

## 9. 当前边界

- **不做加载超时强杀**：首次装载是秒级 cranelift 编译（缓存命中后毫秒级），
  一刀切阈值会误杀首载；策略等 `plugin.log` 攒够真实分布再议。
- **不做自动隔离**（问题插件下次启动自动关闭）：与「启动不播报」冲突且需要
  解封入口；当前给用户手动启停开关。
- **不做错误码分类**：按事件 + 错误串记录，分类等有样本后再做。

## 10. 现行契约

1. **清单契约**：`manifest_schema` = **5**（宿主常量 `SUPPORTED_MANIFEST_SCHEMA`
   = 5，兼容 3/4；高于支持集拒载并进失效包提示）。
2. **wasm 面**：WIT world 导出 `load(plugin-ctx) -> result<_, string>` /
   `unload` / `on-event` / `render`；`load` 的 ctx = JSON 串（§3）。契约钩子
   （`fn-bar` / `render-popup` / `session-row`）走实例化能力探测，不进 world。
   无 `init`/`activate`，也无回退路径（一刀切，在役包均已改造）。
3. **门禁归属**：`load`/`unload` 的时序与 `plugin.log` 断言进 L2（插件仓
   `npm run test:wasm` + PF `plugin-test` runner，`90-7`）；面板/功能栏/弹窗
   接线走 L3（`pif-ui`，`90-8`）。
