# 90-2 插件清单与贡献规范

> 上位需求：`90-1-插件设计需求.md`。
> 清单与贡献面的机器真源 = **插件仓** `schema/plugin-contract.json`
> （`manifest_schema` 大版本，宿主按它拒装不认识的清单）；本文是散文版，
> 清单字段全量与校验规则见 `90-4-插件存储与运行.md` §2。

## 0. 一句话模型

**PF 读自己的清单，pi 读自己的扩展，两本账分立、互不代读。**

| 面 | 唯一读者 | 载体 |
|---|---|---|
| PF 清单（进驻面/回调/入口） | PF（pi-flash.exe） | 包根 `pf-plugin.toml` |
| pi 扩展（pi 进程内代码） | pi 子进程 | `contributes.pi_extensions` 声明的包内文件，经会话挂载台账以 `-e` 挂进 pi |

## 1. 身份与账本

- **身份来自安装上下文，不来自自我声明**——装进 PF 台账的就是 PF 插件，清单无身份键
- **PF 台账**：`~/.pi-flash/plugins.json`（`paths.rs::plugins_ledger_file`）。
  字段 = name / version / integrity / source / installed_at / disabled，v1
  `source` 恒 `"market"`（市场是唯一安装入口）
- **目录名转写**：台账包名 `@scope/name` 经 `pf_plugins::dir_name` 落盘为
  `@scope__name`；`dir_aliases` 同时认平铺短名（dev 兼容布局），是运行态条目
  ↔ 台账条目对账的唯一桥
- **装载白名单 = 台账**：只有台账登记且未停用的包才装载（启动扫描
  `scan_manifests`），磁盘上的野目录（手拷/卸载残留）一律不装载
- **pi 记账**：`contributes.pi_extensions` 的绑定通道把包内扩展文件的**绝对
  路径**写进会话挂载台账（`~/.pi-flash/session-ext.json`，`pi_link::session_ext`），
  pi spawn 时按 `-e` 挂载；版本层换代的自愈规则见 `90-4` §9

## 2. 清单：pf-plugin.toml 即插件清单

PF 清单 = 包根 `pf-plugin.toml`：`schema` 大版本协商、`id` 与目录名对账、
`contributes.*` 贡献点、可选 `wasm` 内层包声明。字段与校验全量见 `90-4` §2；
宿主解析住 `crates/app/src/pf_plugin/manifest/`（手写极简解析，未知键即拒）。

- 壳层 API 兼容位 = 索引字段 `min_pf`（对应插件清单的 `engines.pf`）：安装/
  更新时按 semver 对当前 PF 版本校验，不满足即挡下并提示升级 PF
- 长驻逻辑进程 = `contributes.service` 执行域实例声明（scope 当前仅 session）：
  宿主管身份/通道/生命周期/存储（宿主侧实现在 `crates/app/src/pf_plugin/svc.rs`）
- 纯 pi 包（无 `pf-plugin.toml`）PF 只当 GUI 管理器：不解析、不装载、只管台账

## 3. 目录：两档布局 + 包层 data

```
plugins/<pkg>/<version>/          市场安装链（<pkg> = @scope__name）
  pf-plugin.toml  main.js | plugin.wasm  assets/  pi/  .cache/
plugins/<id>/                     dev 平铺（link:dev 部署，dir == pkg）
plugins/<pkg>/data/               用户数据：包层，无版本维度
```

- 用户数据永远在包层 `data/`——`PluginManifest::data_dir()` 是唯一派生口
  （`pkg_dir/data`），更新换版本目录 data 不动
- 版本目录只装随版本走的东西（wasm/字节码/入口/assets/`.cache`/`plugin.log`）；
  旧版本目录由 `prune_stale_versions` 清理。布局与迁移细则见 `90-4` §1

## 4. 信任分级

| 载体 | 信任机制 |
|---|---|
| 声明式清单面（纯 `contributes.*`，无逻辑入口） | 宿主渲染，启动零代码执行，装即用 |
| JS 标准包（`main.js` / 分发态字节码 `plugin.qbc`） | QuickJS 沙箱：唯一能力面 = ctx，无 fs/net/process |
| 内层 wasm 包（`wasm = "plugin.wasm"`） | 宿主证明验签（`90-4` §7）：非官方构建拒载 |
| `contributes.pi_extensions` | pi 进程内代码，随 pi 信任模型；契约规定仅官方验签包可携带 |

## 5. 面板：清单声明 + 组件树渲染

面板在 `pf-plugin.toml` `[[contributes.panels]]` 声明（id / title / entry /
dock = panel \| tab）；内容由插件 `render(ctx)`（JS）或 wasm `render` 返回
**已算好的组件树 JSON**，宿主树解释器统一渲染（组件词表与样式 token 见
`90-3-插件UI组件规范.md`，wasm 不另立渲染模型）。

- **数据流**：注册回调（onMenu / onCommand / onPanelOpen）返回后宿主自动重渲
  该插件面板（契约 `rerender_rule`），插件不需要通知、不维护绑定槽
- **有意不做**：任意绘制/自由布局/HTML 后门——加原语 = 改宿主 = 契约
  `manifest_schema` 版本化，约束即安全

## 6. 入口 tab 策略

- statusbar 左段 = 「项目」tab + 各插件 tab（`contributes.status_bar` 声明，
  46px 连体卡与「项目」同形）；停用/被拒载的插件不出 tab
- 点击按清单 `panels[].dock` 解释形态：`tab` 开内容区预览页签，否则开左列
  dock 面板（懒加载链见 `90-4` §4）
- 第二入口 = `contributes.topbar_menu`（topbar「菜单」三横浮层条目，与
  status_bar 二选一，props 同款）
- 当前实现无拖调排序、无数量上限、无「…」收纳；statusbar 是用户领土，
  声明不参与排序

## 7. 市场与分发

- 市场索引 = 私域**签名索引**：ed25519 信封（`pf-market-signed/1`），先验签
  后解析（`pi_link::pf_plugins::verify_signed_index`）；环境变量
  `PI_FLASH_MARKET_INDEX` 未设 = 只用内置索引，零请求
- 分发档：`"npm"`（按 registry 约定解析）| `"url"`（索引自描述 tarball 直链，
  私有渠道/内层 wasm 包用）；`integrity`（SRI sha512）安装时对真实 tarball
  对账，不信任包自带值
- PF 市场页提供检索/安装/更新/启停/卸载与失效包提示
  （`crates/app/src/market/pf_market` + `pf_installed`，更新细则见 090-10）
