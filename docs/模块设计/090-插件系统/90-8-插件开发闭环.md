# 90-8 插件开发闭环（唯一合法开发流程）

> 上位：`90-4`（载体优先级条）、`90-7`（wasm 测试链路）。
> 目的：把「改一行 → 知道好坏」的往返压到秒级，**让人肉验收只发生在最后一次**。
> 插件仓 = `D:\ai_workspace\pi-flash-plugins`（下文 npm 脚本均在其 `package.json`）。

## 0. 一条铁律

**PF 官方插件唯一开发载体 = Rust→wasm。禁止先写 `main.js` 再移植。**

- 加密只能靠 wasm 编译产物（JS 载体无加密能力）。


## 2. 三层门禁（缺一层就不许提交）

| 层 | 覆盖 | 跑一次 | 归属 |
|---|---|---|---|
| **L1 编译 + 契约** | wasm 编译通过（`cargo build -p <slug> --target wasm32-wasip2 --release`）、清单过契约 check（`npm run check`）、WIT 面对齐宿主 `wit/pf-plugin.wit` | 秒级 | 插件仓 |
| **L2 逻辑** | 钩子返回值、动作序列、验签门、状态机、load/unload 时序 | 秒级 | 插件仓 `npm run test:wasm`（`90-7` 瘦协议 + PF 的 `plugin-test` runner） |
| **L3 接线** | 装包 → 台账 → 装载 → 面板出现 → 交互 → 事件回灌 → 停用/卸载 | 十秒级 | **pif-ui 自动化**（`.agents/skills/pi-flash-ui-test/SKILL.md`）驱动隔离实例 |

**提交前 L1+L2+L3 全绿**；任何一层红着提交 = 把往返时间转嫁给用户。

## 3. 开发循环（现行命令）

```
npm run link:dev -- --wasm --pkg <slug>   # inner cargo 产物部署进 PF dev 数据目录
npm run test:wasm                         # L2（全量；另有 test:wasm:<slug> 分插件脚本）
npm run e2e:<slug>                        # L3（PIF 隔离实例，禁抢真实屏幕/鼠标/键盘）
```

- 部署链路 = `scripts/link-dev.mjs --wasm --pkg <slug>`：清单由源清单生成
  （contributes 按段搬运、`entry=` 剥掉）、残留 `main.js` 自动清；部署后顺手
  调 PF 仓的 `pf-precompile` 预编译 cwasm（部署那一次做完，启动恒命中缓存）。
- `load_cached` 按 wasm 内容 sha256 缓存，换文件天然失效、失配自动重编
  （`crates/pf-plugin-host/src/instance.rs`）。
- release 不启用 watch，零输出烟测门禁不变。

## 5. 新增能力的顺序（防止再次双实现）

1. 契约/WIT 先落（插件仓 `schema/plugin-contract.json` + 插件的 `wit/pf-plugin.wit`）；
2. Rust 实现 + L2 用例；
3. 宿主接线 + L3 用例；
4. 清单/文档最后补。

**禁止顺序**：先写 JS 跑通 → 再移植 Rust → 再回头补 WIT。
