# 090-10 插件更新

> 更新 UI 对齐已经稳定的 设置 - 扩展；机制与 `90-4`（存储/运行）、`90-9`（生命周期）衔接。

## 1. 更新 UI

1、PF-market 卡片列表展示插件卡片时，与已安装版本对比：索引版本更高 → 版本号
后标记 ↑、√ 换成 [更新] 按钮。
2、已安装管理页对齐 设置 - 扩展：列表与详情都有升级提示（↑ / 需更新标签）和
相应更新按钮。

## 2. 更新动作

1、停用运行态（evict）：`unload()` + 摘会话挂载清单 + 运行许可收线（`pf-runtime.json` disable）。
2、下载新包体覆盖旧安装（`pf_plugins::install`，integrity 对账后落新版本目录，台账落新版后当场清旧版本目录）。
3、`reload_plugin_by_pkg` 重载运行态（重扫清单、按新清单重建条目），数据不动、无需重启 PF。

## 3. 更新不丢数据

用户数据在 `plugins/<pkg>/data/`（包层，无版本维度，见 `90-4` §1）；更新只换
`<pkg>/<version>/` 版本目录，data 原地不动。历史遗留的 `<ver>/data` 由启动期
`migrate_data_dirs` 一次性迁到包层。

## 4. 不兼容插件的升级提示（契约大版本一刀切后的迁移体验）

台账启用、但清单被本版 PF 拒载（如旧 schema）的包 = 「失效包」，`scan_manifests_full`
收集进市场状态 `stale`，三处提示：
1、揭幕后 toast 一次（2.5s；揭幕前播等于白播）
2、PF 市场页签行下常驻通知行（黄点 WARN + 「N 个已安装插件与本版 PF 不兼容，需更新：…」），
   两个页签都可见，更新/卸载后自动消失——用户不在电脑前错过 toast 靠这行兜底
3、已安装页：行上「需更新」黄标签；详情「状态」= 与本版 PF 不兼容（清单 schema N），请更新
【所有插件】卡片内部不动（已有 ↑ + [更新]）。停用的包不进失效列表（用户主动关的不催）。
市场发新包时 `engines.pf` 钉到最低兼容 PF 版本（索引字段 `min_pf`）：旧 PF 用户点更新被
min_pf 门挡下并提示升级 PF，已装旧包照常运行——因此**先发插件、后发 PF** 供给侧零死窗口。

## 5. 版本目录只认台账

`<pkg>/` 下可能同时存在多个版本目录（更新时旧 cwasm 被 mmap 占住删不掉）。扫描只装载
**台账版本**那一个目录，其余不装载也不算失效；`install()` 在台账落新版后当场清旧版本目录，
启动期 `prune_stale_versions` 补刀（删前若发现旧目录里还有未迁的 `data/` 先救到包层）。
