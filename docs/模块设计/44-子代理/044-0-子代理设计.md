# 044-0 子代理设计（现行定稿）

> 状态：**现行**——子代理模块的产品/宿主侧唯一定稿文档；实现与本文冲突以本文为准（发现即回修本文）。
> 扩展侧机制见 `044-5-subagent管理.md`（含派发/回传/收尾契约）；Settings 页与 Agent 定义见 `044-1`；检索层见 `044-3`；测试口径见 `044-4`。

## 总体设计方向

1. 采取 DSH 的 subagent 框架
2. 提供内置的 subagent
3. 提供完整的设置界面

## 内置的 subagent

1. **通用子代理（id: general-purpose）**
   通用任务执行 agent，和主 agent 没区别。适用场景：完全体的 agent，能力大小只取决于扩展多少。
   - 继承委派 agent 的环境，CWD、注入全局和项目的 AGENTS.md
   - 工具集：默认 full+ 配置；委派 agent 也是 full+ 时继承
   - skills：默认注入全局 + cwd skills

2. **本地探索者（id: explorer）**
   有只读权限的本地资料检索 agent，专门用来查看任务相关的本地文件内容。适用场景：帮委派者做本地资料收集调研总结。
   - 继承委派 Agent 的环境，CWD、注入全局和项目的 AGENTS.md
   - 工具集：read-only
   - skills：默认关闭

3. **摘要机（id: summarizer）**
   无状态的摘要机器人，阅读指定文件或一段内容，按要求总结。适用场景：启用本地模型或云端廉价模型做系统日志摘要等。
   - 不继承环境，no cwd，no AGENTS.md
   - 工具集：read-only
   - skills：默认关闭

## 子代理模块设置

1. **嵌套深度**：默认 1（禁止套娃），可配 1-3
2. **最大并发**：2-5，默认 3（glm 服务器侧只允许 3 个并发）
3. **模块开关**：**默认关**（开发旗标 `dev-flags.json` `"subagents"` / env `PI_FLASH_SUBAGENTS`，非用户设置项；发布包恒关）

传导链：设置页写 `<PF数据目录>/app-settings.json`（`subagent_capacity` / `subagent_max_depth`）→ spawn pi 注入 env（`PI_SUBAGENTS_CAPACITY` / `PI_SUBAGENTS_MAX_DEPTH` 作初值 + `PI_FLASH_APP_SETTINGS` 设置文件绝对路径）→ 扩展**每次委派 execute 前实时重读**设置文件同步 manager。env 是进程级快照会过时，实时重读保证改完即生效、不重启。

## subagent 可设置项目

0. 名称
1. 使用说明：简述该 subagent 用途
2. 定制指令：定制 system prompt，追加在 Pi 系统指令之后
3. 环境注入：可选，是否注入所有 AGENTS.md；注入后获得和主代理一样的环境上下文，默认注入
4. 工具定制：继承 | chat-only | read-only | default | full | full+；full+ 档位为 subagent 选择 pi-ext 和 mcp 服务；默认「继承」主 agent 工具集
5. skills 定制：选择注入的 skills，默认注入系统开启的 skills
6. 最大轮次：max_loop，subagent 最多可自主运行多少轮。50 | 100 | no_limit | custom，custom 由主 agent 指定，默认 100
7. 模型：继承 | 预设，默认继承
8. 工作目录：继承

## 主 Agent 派发任务时设置项

主 agent 通过调用 `agent` 工具派发任务，PF UI 不参与分派，只经 descriptor 观察。调用时可设置：

1. **prompt**（必填）：完整任务陈述。子代理默认看不到主会话上下文（spawn），任务必须自包含；委派者只等结论，不重复自己能委派出去的检索。
2. **profile**：点名子代理身份（内置或自定义），决定其人格/工具档/默认模型/轮次预算；不点名则落系统预设默认子代理（general-purpose），不存在无 profile 的裸分身。
3. **model**：临时模型覆盖，`provider/model` 全名；与 profile 自带 model 同时给时本项优先。
4. **cwd**：子代理工作目录，缺省继承委派者。
5. **label**：任务短标签，展示在 transcript 与子代理面板。
6. **maxloop**：本次任务预估轮次预算，0=不限，省略=100；到预算会收到收尾引导，无视则被截断（max_turns）。
7. **background**：true = 后台交付，立即返回 childId、完成后通知；缺省 = 等待跑完，结果作为普通工具结果返回（caller 模式）。

派发约束（自动生效，无需主 agent 设置）：

- 嵌套深度自动 +1，超过模块 maxDepth 拒绝（DEPTH_LIMIT）
- 并发槽按父会话计数，满则拒绝且不排队（CAPACITY_REACHED）
- 同帧多条委派真并行执行（executionMode: parallel）

派发后的干预：`subagent_send` 追加指令 / `subagent_interrupt` 中断 / `subagent_list` 列出子代理。

## descriptor 字段总表（version 1）

事实源 = 父会话 JSONL 的 `subagent/descriptor` custom entry，**只在相位变迁/终态 `appendEntry`，同 childId 末条覆盖**。运行期 stats/usage 只更新内存 descriptor（`children` 工具实时可读），settle 终态才落盘——逐条 assistant message 重发会把父会话灌到百 MB 级，会话打开全链路 O(文件) 被拖垮；面板运行中行停留在激活快照，「不能统计就不统计」。

| 字段 | 类型 | 落盘时机 |
|---|---|---|
| version | 1 | 创建时 |
| childId | sub-N（N 全局递增，被拒也消耗序号） | 创建时 |
| parentToolCallId | 父 `agent` 工具调用 id（nested 为 `<parent>/<n>`） | 创建时；导航面板按轮归属的钥匙 |
| provider | spawn / fork | 创建时 |
| label | 任务短标签（委派级） | 创建时 |
| profile | 子代理 profile id | 创建时 |
| model | `provider/id`（委派级覆盖或 profile 自带） | 创建时 |
| cwd | 子代理工作目录 | 创建时 |
| depth | 委派深度（父 +1） | 创建时 |
| sessionFile | 子会话 JSONL 绝对路径 | **prepare 返回即回写**（运行中面板行可点开）；settle 再确认 |
| composition | {model, systemPrompt, tools} 快照 | 创建时（resume 还原用） |
| phase | provisioning → active → completed / interrupted / failed | 每次变化重发 |
| stopReason | completed / aborted / error / max_turns（终态才有） | settle |
| errorCode | 稳定分码（max_turns 终态 = MAX_TURNS） | 失败/截断时 |
| usage | {input, output, cacheRead, cacheWrite, total, totalTokens, cost} | 仅内存逐轮累计（`message_end` 求和），settle 终态落盘 |
| stats | {turns, agentMessages, toolCalls} | 仅内存逐轮累计，settle 终态落盘 |
| startedAt / updatedAt | ISO-8601 | 创建 / 每次落盘 |

被拒委派（CAPACITY_REACHED 等）也落一份 `phase:"failed"` descriptor——面板即时红行。

## 子代理错误管理

错误码分两层，只维护自己产生的，不追模型商码表：

- **模块层（准入/控制）**：DEPTH_LIMIT / CAPACITY_REACHED / PROFILE_INVALID / START_REJECTED / ADMISSION_CLOSED / ABORTED / PROVIDER_UNKNOWN / BACKEND_UNSUPPORTED / DUPLICATE_CHILD——稳定码全集，语义归 PF，码表可控
- **运行层（模型商产生）**：429/5xx/超时/断流等不可枚举，一律归一为 PROVIDER_ERROR，原始报错保留在 message 不丢信息

原则：宿主与主 agent 永远拿得到稳定码；分类只区分「我们的 / 模型商的」，后续细分从 message 提取，不动码表。

## 子代理 Max_loop 管理

软限两段式，不硬砍：

1. 预算解析：调用级 maxloop > profile maxTurns > 默认 100；0=不限（不装计数器）
2. 到限先引导：steer 注入收尾指令（禁止新工具调用，立即总结作答），收尾轮也计预算
3. 无视才截断：收尾后仍发 toolCall → abort 硬截断
4. 独立归因：截断后终态标 max_turns（errorCode=MAX_TURNS，非 completed/failed），UI 显「执行异常」类（会话流卡 tooltip 可见分码）
5. usage 口径：面板/卡片的 token 合计 = 子会话**逐轮 `message_end` 内存累计**（ΣtotalTokens），settle 终态落盘同口径——非「末条 assistant message」值

## 子代理会话查看

子会话在 PF 打开为普通会话 tab，**复用对话 view，隐藏输入面板**（只读观察窗）：

- 子代理 live 会话住在父 pi 进程内，tab 是对同一账本文件的观察视图（打开快照 + 空闲态外部追加跟随，~3s 延迟）
- 输入面板一律隐藏：用户输入会生成第二驱动分叉账本、双花 token、抢占模型商并发——子代理由主 agent 独占管理，用户无输入通道
- 变异操作（fork、消息操作栏）随输入面板一并隐藏
- tab 归宿：子会话 = 自由区普通 tab（`PanelTab::Observer`，追加 tab 区末尾，标题=descriptor 任务名，× 可关），固定段第一位永远留给主会话/新会话；观察窗不写 last-open，启动恢复过滤子会话（历史污染防护）

## 主会话中调用 subagent 时的渲染

会话流里用紧凑行，不用详情卡：

> 运行状态 icon（同会话列表条目左侧动画与青红点） 子代理 name 任务名（25 字超长截断） 完成提示（任务完成 | 执行异常 | 派发失败）

注：

1. 完成提示（任务完成 | 执行异常 | 派发失败）使用 faint 样式；执行异常和派发失败用 faint+下划线，hover 弹错误提示 tooltip；tooltip 固定 350px 宽，高度 100-300px，超高滚动条
2. 执行异常包括：max_looped、意外中断、Provider 服务侧异常，及其他异常情况
3. 派发失败包括：PF 侧并发限制、Provider 侧并发限制
4. 运行状态 icon 与会话列表条目左侧动画/青红点统一样式
5. 视觉整齐：子代理名称栏 150px 宽，任务描述 300px 宽；全部左对齐，超长截断；完成提示紧跟任务描述之后左对齐
6. 标记槽固定 15px（spinner 与 7px 状态点同槽），子代理 icon 用 `bot` 16px 主题 accent，「子代理」字样不出现

## subagent 运行状态面板

不设 fn_bar 按钮、不设独立浮层。开启功能后，某轮派发了 subagent，则在导航卡信息中增加第三行：

> `[子代理 icon] · · · · ·`（点数 = 子代理数量，7px 圆点，与第 4 条运行状态 icon 同源）

点色按子代理状态取，唯一例外是运行中：**运行中 = 灰点**（`text_dim`）。background 交付下轮先于子代理收尾，运行点若用 accent 会让已结束的轮看起来仍在活动；灰点表示“后台还在跑、尚无结果”，终态才落色——完成 NOTICE、中断/轮次用尽 WARN、异常 danger。分组数据每秒从 catalog 全量重投影到所有轮，已结束轮的点随结算原地翻色（不追加消息、不新增读盘）。

该行同样超长截断。hover 左弹 400px 扩展菜单（无统计行），菜单行点击打开子会话。
