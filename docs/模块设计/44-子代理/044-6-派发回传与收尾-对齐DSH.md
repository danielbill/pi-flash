## 0. 背景与结论

- 目标原本就是对齐 dsh;`4f44371e` 误照 ZCode(结果里硬命令"end your response"),
  与 dsh 相反 —— dsh 的结果文案是裸句,契约写在**工具描述**里。
- 结论三条:
  1. **派发**:保留 PF 的 `background` 开关(同步/异步双模式是产品差异);background
     分支的结果文案回退为 `started subagent <id>`,异步契约进工具描述。
  2. **回传**:PF 的 custom 消息通道保留,内容结构升级为 dsh 的结算消息三段式
     (摘要分档 + `Its closing message:` + `Structured result:`),正文不截断,
     忙时投递改 `steer`(注入当前轮,不等下一轮)。
  3. **收尾**:父 agent 收尾靠"描述声明 + 运行时通知唤醒",不靠结果文案命令;
     idle → `triggerTurn` 起新一轮,streaming → `steer` 注入当前轮。

## 1. dsh 事实（逐条可核）

### 1.1 如何派发

`packages/subagent/tool-subagent/src/index.ts`

- 工具名 `config.toolName ?? 'subagent'`;**没有 background 参数**,一切派发都
  "立即返回 id"(fire-and-forget 是唯一形态)。
- 描述(模型可见契约):
  - 基础:`providerWording.description`
  - 固定句:`This tool starts an independently managed subagent and immediately returns its id. The runtime notifies you when it finishes.`
  - 可续后端:`The child reports results with 'send_message'; use 'send_message' to steer it while running or continue its conversation after it finishes.`
  - 一次性后端:`The completion notice includes its final answer. This backend does not accept follow-up messages.`
- 参数:`cwd` / `description`(必填,3-5 词展示名)/ `prompt`(必填)/
  `agent_preset` / `provider` / `model` / `reasoning_effort`。
- 输出:`{ kind: 'activation', subagentId }`;`render` 仅
  `` `started subagent ${value.subagentId}` `` —— 裸句,**无任何"结束本轮"指令**。
- `isConcurrencySafe: () => true`;`execute` 需要 `exec.agent`(无父直接抛错)。

### 1.2 如何回传结果

`packages/subagent/subagent/src/continuation-messages.ts:132-175` `createSettlementMessage`:

```
Background subagent <childId> finished and will do no further work unless you send it more.
Its closing message:
<子代理最后一条非空 assistant 文本, 不截断>
Structured result: {…}
<diagnostic>
source: { kind: 'subagent-settled', form: 'notice', summary, senderSessionId }
```

- 摘要按 `stopReason` 分档(`:104-130` `settlementSummary`):
  completed(可续)/ completed(不可续 `It cannot receive follow-up messages.`)/
  aborted(`was stopped before it finished.`)/ max-tokens(`ran out of room before it finished.`)/
  refusal(`declined the task.`)/ error(`failed before it finished.`)/ 未知(`ended abnormally (…)`)。
- 正文选择:`assistant-output.ts` —— 最后一条非空 assistant 消息,否则累计流式文本;
  **不做长度截断**。
- 投递:`manager.ts:1187-1206 notifySettlement` →
  `sendWaking(parent, message, parent.status === 'idle' ? 'queue' : 'steer')`;
  `sendWaking`(`:678-690`)父 resident 时 `deliver + wake`,否则 `steer`/`followup`。
- 形态:父会话里的 **user message**(`role: user`,带 source 元数据),UI 按
  `form: 'notice'` 折叠渲染,`turn-trigger.ts:43` 用 `kind === 'subagent-settled'` 画触发条。

### 1.3 主 agent 如何收尾

dsh 不靠结果文案下命令,靠三条:

1. 工具描述声明 "runtime notifies you when it finishes" —— 模型知道不必等;
2. 结算消息作为 user message **唤醒新一轮**;
3. 父忙时 `steer` 注入当前轮,不打断也不排队;
4. 辅助话术:`list_agents` 描述再强调 `there is no need to keep checking its status.`
   (`packages/subagent/tool-subagent-control/src/list-agents.ts:88-92`)。

## 2. PF 现状与差距

| 维度 | PF 现状 | dsh | 差距 |
|---|---|---|---|
| 派发结果 | `Async subagent launched successfully (started subagent <id>). … Do not poll … end your response`(`4f44371e`) | `started subagent <id>` | 多出指令,与 dsh 不一致 |
| 异步契约 | 写在结果里 | 写在工具描述 | 位置错 |
| `background` 描述 | `Launch asynchronously: … Do not wait or poll.` | 无此参数 | 需 dsh 化措辞 |
| `subagent_list` 描述 | `List this session's child agents …` | 附"无需反复查" | 缺一句 |
| 回传摘要 | 统一"子代理完成/失败" | stopReason 六档 | 不分档 |
| 回传结构 | header + report + 提示截断 | 摘要 + `Its closing message:` + structured + diagnostic | 缺两段 |
| 正文长度 | 截 8000 字 | 不截断 | 需去掉 |
| 忙时投递 | `followUp`(等下一轮) | `steer`(当前轮) | 语义不同 |
| 收尾 | `triggerTurn`(idle) —— 已对 | queue+wake | 一致 |

## 3. 设计（逐字）

### 3.1 工具描述（`tool.ts` · `delegationDescription()`）

在 "The child's final answer is returned as this tool's result." 后插入:

```
This tool starts an independently managed subagent; with 'background: true' it returns
its id immediately and the runtime notifies you when it finishes, and the notice
includes its final answer. The child does not report mid-run; use 'subagent_send' to
steer it while running or continue its conversation after it finishes.
```

`background` 参数描述改为:

```
Return immediately with a child id; the runtime notifies you when it finishes.
```

`label` 参数描述补:"Short (3-5 word) display name for the child."

### 3.2 派发结果（`tool.ts` · `runDelegation()` parent 分支）

```
content: [{ type: "text", text: `started subagent ${activation.childId}` }]
```

(与 dsh `render` 同款;删除 `backgroundLaunchText`,不再输出任何指令。)

### 3.3 结算消息（`completion.ts` · `composeCompletion()`)

摘要(`settlementSummary`)按 `details.stop_reason` / `details.error_code` 分档:

| stop_reason | 行 |
|---|---|
| `completed` | `Background subagent <childId> finished. Its closing message follows.`(可续时追加 `It will do no further work unless you send it more.`) |
| `aborted` | `Background subagent <childId> was stopped before it finished.` |
| `max_turns` | `Background subagent <childId> ran out of turn budget before it finished.` |
| `error` / 其他 | `Background subagent <childId> failed before it finished.` + `(<error_code>)` |

正文(不截断):

```
<摘要行>
Its closing message:
<report>
Structured result: {"childId":…,"stopReason":…,"durationMs":…,"sessionFile":…}
```

- toast 保持中文短句(UI 面向人),不参与模型契约。
- 若正文极大(>128KB):不截断正文,改为附一行
  `The full report is in the child session: <session_file>`(仍不丢内容,错误路径见 §6)。

### 3.4 投递（`index.ts` · `deliverParent()`)

```ts
pi.sendMessage({ customType: COMPLETION_TYPE, content, display: true, details },
  ctx.isIdle() ? { triggerTurn: true } : { deliverAs: "steer" });
```

### 3.5 `subagent_list` 描述（`index.ts`）

```
List this session's child agents with id, phase, label, provider and depth. You will be
notified when a background subagent finishes; there is no need to keep checking its status.
```

## 5. 测试与验收

- L2:`node --test test/*.test.ts` 全绿(现有 146 例 + 新增分档/steer 用例)。
- 人工验收(重启 PF 后,由用户执行):

## 6. 风险与不采用

- **与 044-0 旧契约的冲突**：原 v2 契约是「完成 → 通知卡 → 用户点继续 → `followUp`，不自动触发」。
  本设计按 dsh 与 2026-11-07 实测需求改为完成即自动唤醒（idle `triggerTurn` / 流式 `steer`），
  044-0 该条已标注修订并指向本文——**若产品上要保留用户确认，本条必须先推翻**。
- **不采用** dsh 的"取消 background 开关"：PF 的同步等待是产品能力，且 pi 工具
  结果即回传,删除会改变既有调用语义。
- **不采用** dsh 的 `role: user` + source 元数据:PF 走 `customType` 自定义消息,
  会话内可见且可被 UI 识别;语义等价,不动消息模型。
- 风险:`steer` 注入可能打断模型当前推理措辞(非中断),验收第 3 条覆盖;
  若体验不佳,回退 `followUp` 只改一行。
- 风险:不截断的超长报告会推高上下文;由 compaction 兜底,必要时按 §3.3 附文件路径。
