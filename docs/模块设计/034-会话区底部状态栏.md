模块代码：sessionStatusBar 034

会话内容列最底部一条常驻状态带。pi 扩展通过 `ctx.ui.setStatus(key, text)`
申请信息常驻展示，并且点击信息可打开该扩展的信息面板（如 `usage` 插件走
`/usage`）。

## 0. 承载「扩展状态项」

状态带内部只有一类东西：**状态项**。项可以是纯文本，也可以可点交互。

### 术语

- *状态项*（item）= `{ key, text, action }`，key 由扩展命名（`usage`/`mcp`/…），
  text 是扩展自由文本（可含中文/英文/emoji，扩展自己负责）。
- *动作*（action）= PF 侧动作表把 key 映射出来的结果：
  `RunCommand("/usage")` / `OpenPanel(SettingsMCP)` / `None`。
- *扩展槽* = 状态项横排区（本文主体）；*会话槽* = 左端预留（见 §3.3）。

### 边界（不是什么）

| 不是 | 归谁 |
|---|---|
| 会话内容 / 消息流的一部分 | 032 消息面板（状态带在 composer 之外，不随消息滚动） |
| 上下文用量环与用量详情卡 | 031 composer 右端 + `ctx_tip` 弹层 |
| 左 dock 底部控制条（项目/插件 tab、设置钮） | 018 `status_bar.rs`（另一个东西，勿混名） |
| toast（status 居中 / ext 右上） | `ui/overlay.rs` |
| 排队条数、扩展命令等待行 | 031 状态槽 |

## 1. 设计思路

这是 Pi 老用户的默认需求：扩展的状态行本来就该常驻可见（额度、余额、MCP
服务器数、relay 状态、goal 进度）。

pi 的 `ctx.ui.setStatus` 只保证「有一行文字」，**不保证位置**。pi TUI 把它放在
footer 第三行（`modes/interactive/components/footer.js`：pwd / stats / 扩展状态行，
dim、按 key 字母序、**只显示 text 不显示 key**）。PF 早先照抄到了 composer 上方，
落在消息区领口且把 key 当文字画了出来（`usage deepseek CNY 52.88` 里的 `usage`
是键名）；该落位已按 `EXT_STATUS_ROW_VISIBLE = false` 隐掉，本模块是它的
**设计过的归宿**（迁移见 §8）。

## 4. 内容模型与准入

### 4.1 项来源

唯一数据面 = `Chat.aux.ext_status: Vec<(String, String)>`（`dialogs/ext_ui.rs` 的
`SetStatus` 分支维护，含 ANSI 剥离）。本文只做**读侧派生**：key → action。

- 排序：**key 字母序**（pi footer 同口径），保证同一组项跨会话顺序稳定。
- 同 key 重复写：原地替换 text（不新增项）；`text` 为空/`None` → 摘除该项。
- 去重/合并：不做。扩展要合并自己合并（PF 不替扩展编故事）。

### 4.2 动作表（PF 侧唯一来源，静态 match，渲染期零分配）

| key | 动作 | 语义 | 备注 |
|---|---|---|---|
| `usage` | `RunCommand("/usage")` | 与手打 `/usage` 完全同一条路径 | 见 §5.1 |
| `mcp` | `OpenPanel(SettingsMCP)` | 打开 设置 › MCP（`open_settings(TAB_MCP)`） | 纯 PF 页面，不发命令、不动会话 |
| `mcp-auth` | `None` | 纯文本（登录码/进行中提示） | 登录本身走 `!pi mcp login` |
| 其他（`freeflow`/`goal`/`cline-login`…） | `None` | 纯文本 | 新增动作须改本表并在本文登记 |

> 为什么动作表在 PF 侧：pi 的 RPC `setStatus` 只有 `statusKey` + `statusText`，
> **没有**「可点/点了干什么」的字段。想让它由扩展声明需要改协议（见 §10）。

### 4.3 溢出规则（单行不换行）

可用宽度 = `条宽 − 2×SP6`。超宽时按顺序处理：

1. **先隐藏不可点项**（可点项是功能入口，优先级更高），从最右开始藏；
2. 仍不够 → 对末位项 `text` 中间截断（`…` 保尾部：额度/金额这类关键信息多在
   尾部），并保留 tooltip 出全文；
3. 极端窄（< 3 个项宽）→ 只留第一个可点项 + 其余丢弃，不允许出现「半行省略号
   孤零零挂在右边」；
4. 不做横向滚动、不做「更多」折叠菜单（P3 再议）。

## 5. 交互设计

### 5.1 点击 = 同一条命令路径（不做第二套发送逻辑）

`RunCommand("/usage")` 走 `SessionRuntime::optimistic_send(text, pin, cx)` ——
即 composer 里手打 `/usage` 的**同一个漏斗**，因此等价复现：

- 命令相位（等待行文案「执行扩展命令中…」）与 `disposition: handled` 收场；
- 乐观命令气泡 + 磁盘真相收场（`command_phase_settle_follows_disk_truth` 已有用例）；
- agent 运行中发出 → 排队（pi 侧 flush 语义不变）。

**这是刻意的**：需求是"点了和 `/usage` 一个效果"，不是"点了 PF 自己画一个用量
面板"。`@narumitw/pi-usage` 的 `/usage` 实际是 `ctx.ui.select` 菜单链 → PF 里就是
那串 ext Select 卡，点完与手打一模一样。

### 5.2 可点性判别与视觉

| 状态 | 视觉 | 行为 |
|---|---|---|
| 有 action 且可用 | `cursor_pointer` + hover `bg_hover` + 文字 `text_muted` | 左键点击一次性触发动作 |
| 有 action 但被禁用 | `opacity 0.5`，无 hover、无 pointer | 点击无响应 |
| 无 action | 无 hover、无 pointer，`text_faint` | 纯文本 |

- 点击用 `on_mouse_down(Left)`（与 018 控制条、插件 tab 同款），不用 click
  （gpui click 要 down/up 同点，鼠标微移会丢）。
- 命中区 = 项整块（含 `px 6 / py 2` 内衬），最小高 22。
- 点击后不要求二次确认（命令类本身就是可中断的菜单）。

### 5.3 禁用规则

- 命令类（`RunCommand`）在 `agent_running == true` 时**禁用**，tooltip 说明
  「当前轮次结束后可用」。理由：排队一条命令会让用户以为点了没反应（等待行要等
  上一轮结束才出现），也会污染本轮上下文末尾。
- 面板类（`OpenPanel`）任何时候都可点（纯 UI 跳转，不改会话状态）。
- 整条不渲染时（§3.4）不涉及禁用态。

### 5.4 悬停提示（唯一入口 `ui::tooltip::WithTip`）

| 元素 | 提示内容 | i18n |
|---|---|---|
| 可点项 | 动作名 + 等价命令：`打开用量面板（/usage）` | `footerbar.tip.usage` / `footerbar.tip.mcp` |
| 被禁用项 | `当前轮次结束后可用` | `footerbar.tip.busy` |
| 纯文本项 | 仅在被截断时出全文（`with_tip_text(text)`，动态直排，不过 i18n） | — |
| 显示开关 | `显示扩展状态栏` | `footerbar.tip.toggle` |

- 提示卡样式走 gpui-component 默认盘，不另定制（§5.10）。
- 悬停 350ms 原生手势，不写 hover 状态机；可挂 tip 的元素必须 `.id()`。

### 5.5 明确不做

- 键盘焦点体系（PF 全局无 tab 顺序，硬做要动壳层）；键盘用户走 `/usage` 命令，
  tooltip 里注明等价命令即是替代手段；
- 右键菜单、拖拽排序、双击、长按；
- 点击改扩展内部状态（PF 无此通道）；
- 自动展开面板/悬浮预览（与用量环的 `ctx_tip` 同屏会打架）。

## 6. 数据与生命周期

1. **per-session**：`aux.ext_status` 属于「当前展示会话」。状态带只显示当前活动
   会话的项；切 tab / 切池后按新会话重算，不做跨会话合并、不做"上一次的值兜底"。
2. **清空时机（必须先修的缺口）**：pi 在 `resetExtensionUI()`（换会话 / 重载扩展）
   里 `clearExtensionStatuses()`；PF 目前**切会话不清** `aux.ext_status`（全仓无
   `ext_status.clear()`）。不修就上线 = 上一会话的额度行跟着跑到新会话。
   落点：会话切换/重载入口（`session/nav` 定位对账 + `/reload` 收场）统一清空。
3. **刷新频率**：扩展会秒级刷新（pi-usage 有倒计时 refresh timer）。渲染路径
   **零重算**：动作表静态 match、不排序新分配（键序稳定）、不做字符串格式化；
   `SetStatus` 到达已经 `cx.notify()`，天然一帧一次。
4. **热路径**：纯文本 + flex，无测量循环、无图片/阴影；整条不渲染时零成本
   （开关关闭 = 不建 element，不是 opacity 0）。
5. **快照/自动化**：`automation/snapshot.rs` 增 `session.status_bar`
   （`{enabled, visible, items:[{key,text,action,disabled}]}`）；既有
   `session.ext_status` 原样保留（数据面断言用）。
