模块代码：sessionStatusBar 034

会话内容列最底部一条常驻状态带：承载 pi 扩展 `ctx.ui.setStatus(key, text)`
申请的状态项，"可点项"点击=执行命令，如发送 /usage

## 1. 定义

- **状态项**（item）= `{ key, text, action }`。key 由扩展命名，text 为扩展自由
  文本；action 由 PF 侧动作表把 key 映射出来（`Command(&'static str)` /
  `None`，见 §4.2）。
- **扩展槽** = 状态项横排区（本文主体）；**会话槽** = 左端预留位，当前无
  内容（未启用）。
- 不是会话内容（不随消息滚动）、不是 composer 用量环/`ctx_tip`（031）、不是左
  dock 控制条（018 `status_bar.rs`，勿混名）、不是 toast、不是排队条（031 状态槽）。

## 2. 显示开关

「设置 - 界面」页，紧接「部分操作隐藏」下方一行：标题「显示状态栏」、注释
「设置输入下方状态栏信息是否显示」、**默认开启**。防信息冗余用；关闭只影响
渲染，数据面照旧。

| 项 | 规格 |
|---|---|
| 形态 | 设置页标准行（`set_row`）+ `switch_base`（常规档 SwitchSize::Md） |
| i18n | `settings.show_status_bar` / `settings.show_status_bar_hint` |
| 落盘 | `ui_state().session_status_bar: Option<bool>`，缺省 = 开 |
| 生效 | 状态直切无动画、无 toast（`notify` 重渲 Chat 即按新值决定渲染与否） |

## 内容管理
0、用“|”分隔多条信息
1、状态栏是单行，长度有限，当内容过多时，按照 内容区宽度-20px ，超长截断，禁止折行毁视觉
2、在状态栏右侧，大约对齐Inputpanel发送按钮的位置，添加 [...]icon，点击弹出菜单，200px宽，最小高度200px，
内容是申请常驻状态栏的插件名称，用户点击取消勾选则不再显示

## 3. 位置与几何

### 3.1 位置

inputpanel 正下方，**与内容区（消息列）同宽**，高 30px。放在 `chat-wrap` 底缘
的 **absolute 覆盖层**（最后绘制）——不参与 flex 流，因此**开闭之间 Inputpanel
不动**（胶囊底距永久 = `footer_bar::BAR_H` = 30）。**新会话页（012）不显示。**

垂直几何联动（三处必须一起改，漏一处就会压消息/错位）：

| 量 | 落点 | 现行值 |
|---|---|---|
| 胶囊底距 | `session/input/area/compose.rs` `composer_wrap` | **30**（= `footer_bar::BAR_H`，**永久值**；条是 absolute 覆盖层，开关不改变布局，胶囊永不动） |
| 悬浮让位 | `session/chat_list/mod.rs` `PAD_BOTTOM` | **190**（= `160 + footer_bar::BAR_H`，随条高联动；消息不会压在带子下） |
| 胶囊内部留白 | `session/input/area/mod.rs` 操作栏到下边框 `pb` | **7**（压缩胶囊内部留白；会让实测 `composer_h` −5，033 竖条中心随之 −2.5，预期内） |

### 3.2 尺寸与配色（全取 UI组件规范令牌，禁手搓）

| 项 | 值 | 出处 |
|---|---|---|
| 条高 | 30 | §1 间距体系（2026-11-25 用户上调 28 → 30） |
| 条底 | **会话区背景 75% 不透明（`t.bg` α0.75）**——absolute 覆盖层压在消息列表之上，无底色时滚到带子底下的消息/工具卡会透出来；半透底让底下内容隐约可见又不喧宾。不画上沿线（左邻是 dock tab 栏，横线一拉就对不齐） | — |
| 内容行 | `px 15` + `max_w(chat_content_width())`，**项在列内居中**（右侧已有模型信息，右对齐会成两条贴右竖排文字） | 与消息列/composer 同心（031 同一套 `content_w`） |
| 项间分隔 | `\|` 淡色分隔符（`text_faint`，ui(10)），与两侧项各 `mx 4`（SP2） | §1 |
| 项内 padding（可点项要底） | `px 6 / py 2`，圆角 `R_INLINE` 5 | 命中区放大 |
| 字体 / 字号 | 字体族取**左侧面板字体**（`appearance::panel_font().family`，与 psp 行同源）；字号 = **面板字号 −2**（`ui(10)`） | §2 面板轨 |
| 文字色 | 可点 `text_muted` / 不可点与禁用 `text_faint` | §6 |
| hover 底 | `bg_hover` | §4 / §6 |
| disabled | `opacity 0.5`、去 hover/pointer | §8 |
| 提示 | `ui::tooltip::WithTip`（350ms 原生手势） | §5.10 |

### 3.3 横向分区

```
[        项 | 项 | 项（内容列内居中）        ]
```

- 项在内容列内居中：右侧 composer 已有模型/思考两行信息，
  状态带再右对齐会形成两条贴右的竖排文字。会话槽（`flex_1` 左撑）不启用
  —— 会话态信息仍归 composer 用量环与 022 git 面板，不在此重复。
- **多条信息用 ` | ` 分隔**：淡色分隔符（`text_faint`），
  与两侧项各留 SP2 = 4，项间不再用固定 gap。

### 3.4 显隐（零占位）

整条不渲染（不建 element、不占 BAR_H）的情形：显示开关关；新会话页（调用方
不挂）；非空且未静音的项为空**且**无任何静音键。全部项被静音时**仍出条**
——只剩 `[...]` 管理钮（唯一找回入口，勾选即恢复）。

## 4. 内容模型与准入

### 4.1 数据面

- **数据面**：`SessionRuntime::ext_status: Vec<(String, String)>`（`dialogs/ext_ui`
  的 `SetStatus` 分支写入，含 ANSI 剥离）。**per-runtime 而非 Chat 级**：pi 换会话/
  重载会清扩展状态，池里每个 pi 进程各持一份，放 Chat 上会串味。
- 排序：**key 字母序**（pi footer 同口径）。同 key 重复写原地替换；`text` 空 → 摘除。
- **准入 = 默认全显示 − 用户逐键静音**：扩展状态项全部上屏（Pi 老用户默认
  需求），动作表只决定**可不可点**、不管显示。想藏某一行是个体偏好 →
  `ui_state.ext_status_muted: Vec<String>`（workspace.json 的
  `__ui.ext_status_muted`，如 `["mcp"]`）；数据面照旧收全量，只是渲染跳过。
  写路 `Chat::toggle_ext_status_muted` + `set_ext_status_muted_keys`。

### 4.2 动作表

key → 动作的映射 = `footer_bar::action_of`（静态 match，渲染期零分配）。
**只管"可不可点"**，不管准入：无动作键 = 灰字纯文本、仍上屏。当前只有一个
动作类别：

```rust
enum StatusAction { Command(&'static str) }   // 执行一条斜杠命令
```

| key | 动作 | 上屏 | 说明 |
|---|---|---|---|
| `usage` | `Command("/usage")` | ✅ 可点 | 与手打同一漏斗，见 §5.1 |
| `mcp` / `mcp-auth` / `freeflow` / `goal` / 其他 | — | 默认上屏（灰字纯文本） | 无动作 = 纯文本，不可点（`mcp` 在 composer 功能栏已有 MCP 胶囊做主入口，不做第二入口）；要给某键加动作改 `action_of` + `tip_key_of` + 本节 + 模块注释 |

动作表有单元测试锁语义（`action_table_is_not_admission`：usage 可点、其余键
None 但仍上屏）。

## 4.3 过载处理（内容管理）

0. 多条信息用 `|` 分隔（淡色 `text_faint`，两侧 SP2 = 4）。
1. **单行 + 截断**：可用宽 = 内容区宽度 − 20px（两侧 px10）；项挂
   `min_w_0 + overflow_hidden + whitespace_nowrap + text_ellipsis` —— flex 挤压
   各项、尾部 `…`，**禁止折行**毁状态条；条本体 `overflow_hidden` 兜底。
2. **`[...]` 管理入口**：规范 §5.2 IB_SM 行内 ⋯ 触发钮形制（22 槽 / 圆角
   INLINE / hover bg_hover，kit icon_btn 同款）；**钮中心对齐发送钮中心**
   （right = 31 − 11 = 20，31 = 胶囊边框 1 + 操作栏 px10 + 发送 mr2 + 36/2），
   垂直 `(BAR_H − 22)/2` 居中、不贴 app 底缘（2026-11-25 用户令，原
   贴右缘满条高钅盒已废）。
   图标 = lucide ellipsis（裸三点，全库唯一「更多」），icon::SM 14 / `text_faint`。
   点击弹出菜单：**宽 200px、最小高 200px**，**定位复用 inputpanel 统一
   pill 管线**（`picker_shell::pill_anchor_edges` 唯一落点：钮水平居中、距钮
   5px、半屏定向——状态带贴屏底 → 恒向上弹；tracker 抓钮 bounds 写
   `PillBtns::status_mgr` 槽，开菜单时 `PillBtns::anchor` 写 `dlg.pill_anchor`，
   与 composer 胶囊菜单同源；2026-11-25 用户令：不再 PopupEdges::around
   点击点手搓），内容 = 申请常驻状态栏的插件键清单（当前会话键 ∪ 已静音键，
   字母序），勾选 = 上屏、取消勾选 = 隐藏（写 `ext_status_muted`，菜单保持打开、
   实时生效）；空清单显示 `footerbar.mgr.empty` 文案。
   全部静音时状态带只剩 `[...]`（唯一找回入口）。
   快照不变：`hidden_keys` = 静音键留痕。

## 5. 交互

### 5.1 点击 = 命令路径

`Command("/usage")` 走 `SessionRuntime::send_command`（手打
`/usage` 的同一漏斗）：同一 `Command::Prompt`（命令相位、乐观气泡、磁盘真相
收场全由既有链路接管），区别只是不经输入框、不进 ↑ 历史；发送后走
`optimistic_send`。运行中/压缩中**不发**（按钮侧已置灰，这里兼底——排队一条
命令会让用户以为点了没反应）。不新写发送逻辑，不自己画面板（pi-usage 的
`/usage` 本身是 `ctx.ui.select` 菜单链，PF 里就是那串 ext Select 卡）。

### 5.2 三态

| 状态 | 视觉 | 行为 |
|---|---|---|
| 可点且可用 | `cursor_pointer` + hover `bg_hover` + `text_muted` | 左键触发动作 |
| 可点但禁用（运行中） | `opacity 0.5`、`text_faint`，无 hover/pointer | 无响应 |
| 无动作键 | `text_faint`，无 hover/pointer | 纯文本（可被逐键静音） |

- 点击用 `on_mouse_down(Left)`（与 018 控制条、插件 tab 同款）；命中区 = 项整块
  （含 `px 6 / py 2`），最小高 22；不需要二次确认。

### 5.3 禁用规则

- `Command` 在 `agent_running` 时禁用，tooltip `footerbar.tip.busy`「当前轮次
  结束后可用」（避免排队命令像点了没反应）。

### 5.4 悬停提示（唯一入口 `ui::tooltip::WithTip`）

| 元素 | 提示 | i18n |
|---|---|---|
| 可点项 | `打开用量面板（/usage）` | `footerbar.tip.usage` |
| 禁用项 | `当前轮次结束后可用` | `footerbar.tip.busy` |
| `[...]` 管理钮 | `管理常驻插件` | `footerbar.tip.mgr` |
| 纯文本项 | 仅被截断时出全文 | `with_tip_text`（不过 i18n） |

### 5.5 不做

键盘焦点体系（键盘用户走 `/usage`，tooltip 注明等价命令）；右键菜单、拖拽排序、
双击、长按；点击改扩展内部状态；自动展开面板/悬浮预览（与 `ctx_tip` 打架）。

## 6. 数据与生命周期

1. **per-session**：只显示当前活动会话的项；切 tab / 切池按新会话重算，不跨会话
   合并、不做旧值兜底。
2. **清空**：pi 在 `resetExtensionUI()` 里 `clearExtensionStatuses()`；PF 对应口径 =
   **`spawn_attached` 时清**（新 pi 进程 → 旧 setStatus 快照作废；覆盖 `/reload`
   重绑与空闲回收重建）。切会话不需要额外清——数据随 runtime 走，天然不串味。
3. **零重算**：动作表静态 match、键序稳定、不做格式化；`SetStatus` 到达已
   `cx.notify()`，天然一帧一次。
4. **热路径**：纯文本 + flex，无测量循环/图片/阴影；不渲染时零成本。
5. **快照**：`automation/snapshot` 增 `session.status_bar`
   `{enabled, visible, items:[{key,text,action,disabled}], hidden_keys}`（与渲染
   共用 `action_of`；无动作键 `action: null` 照常进 items）；`session.ext_status`
   保留（数据面）。
