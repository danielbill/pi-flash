模块代码：sessionStatusBar 034

会话内容列最底部一条常驻状态带：把 pi 扩展通过 `ctx.ui.setStatus(key, text)`
申请的那行短状态，搬到**有名字、有位置、有交互契约**的地方，而不是随手塞进
会话领口（旧的 composer 上方那行，已按 `EXT_STATUS_ROW_VISIBLE = false` 隐掉，
见 §7 迁移计划）。

## 0. 一句话定义

- **是什么**：会话区底部（composer 之下、内容列整宽）的 28px chrome 带，
  承载「扩展状态项」；项可以是纯文本，也可以带动作（点击 = 执行某条命令 /
  打开某个面板）。
- **不是什么**：
  | 不是 | 归谁 |
  |---|---|
  | 会话内容 / 消息流的一部分 | 032 消息面板（底部状态带永远在 composer 之外，不随消息滚动） |
  | 上下文用量环与用量详情卡 | 031 composer 右端 + `ctx_tip` 弹层（离输入框最近的地方） |
  | 左 dock 底部控制条（项目/插件 tab、设置钮） | 018 `status_bar.rs`（那一份叫「底部控制状态栏」，与本文不是同一条） |
  | toast（status 居中 / ext 右上） | `ui/overlay.rs` |
  | 排队条数、扩展命令等待行 | 031 状态槽 |
- **术语**：
  - *状态项*（item）= `{ key, text, action }`，key 由扩展命名（`usage`/`mcp`/…），
    text 是扩展自由文本（可含中文/英文/emoji，扩展自己负责）。
  - *动作*（action）= PF 侧动作表把 key 映射出来的结果：
    `RunCommand("/usage")` / `OpenPanel(SettingsMCP)` / `None`。
  - *扩展槽* = 状态项横排区（本文主体）；*会话槽* = 左端预留（见 §2.3）。

## 1. 为什么需要它（事实依据）

1. pi 的 `ctx.ui.setStatus` 只保证「有一行文字」，**不保证位置**。pi TUI 把它
   放在 footer 第三行（`modes/interactive/components/footer.js`：pwd / stats /
   扩展状态行，dim、按 key 字母序、**只显示 text 不显示 key**）。
2. PF 之前在 composer 上方照抄这一行，等于把扩展给「TUI footer」画的东西放进
   **消息区领口**：任何文字在那里都会被读成会话内容，且渲染了 key
   （`usage deepseek CNY 52.88` 里的 `usage` 是键名，pi 自己是不显示的）。
   `docs/UI设计/UI组件规范.md` 里没有这类状态行的任何条目 —— 位置、字号、
   缩进（`px(34)`）都没有出处。
3. 但这类信息本身有价值（额度、余额、MCP 服务器数、relay 状态、goal 进度），
   直接丢弃等于关掉扩展的信息出口。所以需要**一条设计过的落位**：全局 chrome
   语义、单行、低强调、可空、可交互。

## 2. 定位与几何

### 2.1 位置

```
content-col
├─ session-fn-bar（会话 tab 带）
├─ chat-wrap（relative）
│  ├─ 消息列表（可滚动）
│  ├─ composer（悬浮，绝对定位上浮）
│  ├─ subagent 浮层
│  └─ **session-status-bar（本文，chat-wrap 末尾，非 absolute）**
└─ 右列 nav gutter（033）
```

- 挂在 `chat-wrap` flex 末尾：composer 是 0 高 wrapper + 绝对定位胶囊，所以
  状态带自然落在**胶囊下方**、内容列底部，不参与消息区滚动。
- 新会话页（012）同挂一条：draft 会话通常没有扩展状态 → 空则整条不渲染
  （§2.4），视觉上等于不存在。

### 2.2 尺寸与配色（令牌级，禁手搓）

| 项 | 值 | 出处 |
|---|---|---|
| 条高 | 28 | §1 2px 步进 + 4 倍数（≥12 后须 4 的倍数） |
| 条底 | `t.chrome` | 与 topbar / 018 控制条同族：chrome 层 |
| 上沿 | 1px `border_alpha(t, 0x99)` | §5.12 分隔线唯一口径的常驻细线 |
| 内容行 | `w_full` + `max_w(chat_content_width())` 居中 | 与 composer / 消息列同心（031 同一套 `content_w`） |
| 内容行左右内衬 | SP5 = 10 | §1 列表/行水平 padding |
| 项内 gap（图标↔文字，P3 才有图标） | SP2 = 4 | §1 |
| 项间 gap | SP6 = 12 | §1 12 整数档 |
| 项内 padding（仅可点项要底） | `px 6 / py 2` | 命中区放大，视觉维持紧凑 |
| 字号 | `ui(11)`（secondary 档） | §2 面板轨 secondary = 辅助说明 / footer |
| 文字色 | 可点 `t.text_muted`、不可点 `t.text_faint` | §6 占位/最弱文字 |
| hover 底 | `t.bg_hover` + `R_INLINE = 5` | §4/§6（被塞进行里的散件走 5） |
| disabled | `opacity 0.5` + 去 hover | §8 |
| 悬停提示 | `ui::tooltip::WithTip`（350ms 原生手势） | §5.10 |

### 2.3 横向分区

```
[会话槽（预留，本期空）]                  [扩展槽：项 · 项 · 项 →右对齐]
```

- **扩展槽右对齐**：与 composer 右端控件行（模型/思考/发送）同侧，视线落点一致。
- **会话槽本期不接内容**：会话态信息（token 百分比、cwd/分支、运行态）已分别
  在 composer 用量环（031）与 022 git 面板有归属，重复上屏只会制造第二个真相。
  预留区宽度为 0（`flex_1` 左撑），将来定稿再填。
- 两槽之间 `flex_1` 撑开，永不加分隔线。

### 2.4 显隐（三档，全部零占位）

| 条件 | 行为 |
|---|---|
| 无活动会话 / 新会话页且无状态项 | 整条不渲染（不占 28px） |
| 有项但全部为不可点纯文本且 `text` 空 | 等价摘除（pi 的 `setStatus(key, undefined)` 语义） |
| `SESSION_STATUS_BAR_VISIBLE = false`（总开关，P1 落地时给） | 整条不渲染；数据面照旧维护，供快照/自动化断言 |

## 3. 内容模型与准入

### 3.1 项来源

唯一数据面 = `Chat.aux.ext_status: Vec<(String, String)>`（`dialogs/ext_ui.rs`
的 `SetStatus` 分支维护，含 ANSI 剥离）。本文只做**读侧派生**：key → action。

- 排序：**key 字母序**（pi footer 同口径），保证同一组项跨会话顺序稳定。
- 同 key 重复写：原地替换 text（不新增项）；`text` 为空/`None` → 摘除该项。
- 去重/合并：不做。扩展要合并自己合并（PF 不替扩展编故事）。

### 3.2 动作表（PF 侧唯一来源，静态 match，渲染期零分配）

| key | 动作 | 语义 | 备注 |
|---|---|---|---|
| `usage` | `RunCommand("/usage")` | 与手打 `/usage` 完全同一条路径 | 见 §4.1 |
| `mcp` | `OpenPanel(SettingsMCP)` | 打开 设置 › MCP（`open_settings(TAB_MCP)`） | 纯 PF 页面，不发命令、不动会话 |
| `mcp-auth` | `None` | 纯文本（登录码/进行中提示） | 登录本身走 `!pi mcp login`，不做按钮 |
| 其他（`freeflow`/`goal`/`cline-login`…） | `None` | 纯文本 | 新增动作须改本表并在本文登记 |

> 为什么动作表在 PF 侧：pi 的 RPC `setStatus` 只有 `statusKey` + `statusText`，
> **没有**「可点/点了干什么」的字段。想让它由扩展声明，得改协议（未立项，见 §9）。

### 3.3 溢出规则（单行不换行）

可用宽度 = `content_w − 2×SP5`。超宽时按顺序处理：

1. **先隐藏不可点项**（可点项是功能入口，优先级更高），从最右开始藏；
2. 仍不够 → 对末位项 `text` 中间截断（`…` 保尾部：额度/金额这类关键信息多在
   尾部），并保留 tooltip 出全文；
3. 极端窄（< 3 个项宽）→ 只留第一个可点项 + 其余丢弃，不允许出现「半行省略号
   孤零零挂在右边」。
4. 不做横向滚动、不做「更多」折叠菜单（P3 再议）。

## 4. 交互设计

### 4.1 点击 = 同一条命令路径（不做第二套发送逻辑）

`RunCommand("/usage")` 走 `SessionRuntime::optimistic_send(text, pin, cx)` ——
即 composer 里手打 `/usage` 的**同一个漏斗**，因此等价复现：

- 命令相位（等待行文案「执行扩展命令中…」）与 `disposition: handled` 收场；
- 乐观命令气泡 + 磁盘真相收场（`command_phase_settle_follows_disk_truth` 已有用例）；
- agent 运行中发出 → 排队（pi 侧 flush 语义不变）。

**这是刻意的**：用户要的是"点了和 `/usage` 一个效果"，不是"点了 PF 自己画一个
用量面板"。`@narumitw/pi-usage` 的 `/usage` 实际是 `ctx.ui.select` 菜单链
→ PF 里就是那串 ext Select 卡，点完与手打一模一样。

### 4.2 可点性判别与视觉

| 状态 | 视觉 | 行为 |
|---|---|---|
| 有 action 且可用 | `cursor_pointer` + hover `bg_hover` + 文字 `text_muted` | 左键点击一次性触发动作 |
| 有 action 但被禁用 | `opacity 0.5`，无 hover、无 pointer | 点击无响应 |
| 无 action | 无 hover、无 pointer，`text_faint` | 纯文本 |

- 点击用 `on_mouse_down(Left)`（与 018 控制条、插件 tab 同款），不用 click
  （gpui click 要 down/up 同点，鼠标微移会丢）。
- 命中区 = 项整块（含 `px 6 / py 2` 内衬），最小高 22 ≥ 触达下限。
- 点击后不要求二次确认（命令类本身就是可中断的菜单）。

### 4.3 禁用规则

- 命令类（`RunCommand`）在 `agent_running == true` 时**禁用**，tooltip 说明
  「当前轮次结束后可用」。理由：排队一条命令会让用户以为点了没反应（等待行要等
  上一轮结束才出现），也会污染本轮上下文末尾。
- 面板类（`OpenPanel`）任何时候都可点（纯 UI 跳转，不改会话状态）。
- 无活动会话时整条不渲染（§2.4），不涉及禁用态。

### 4.4 悬停提示（唯一入口 `ui::tooltip::WithTip`）

| 元素 | 提示内容 | i18n |
|---|---|---|
| 可点项 | 动作名 + 等价命令：`打开用量面板（/usage）` | `footerbar.tip.usage` / `footerbar.tip.mcp` |
| 被禁用项 | `当前轮次结束后可用` | `footerbar.tip.busy` |
| 纯文本项 | 仅在被截断时出全文（`with_tip_text(text)`，动态直排，不过 i18n） | — |

- 提示卡样式走 gpui-component 默认盘，不另定制（§5.10）。
- 悬停 350ms 原生手势，不写 hover 状态机；状态项必须 `.id()`（`WithTip` 前置要求）。

### 4.5 键盘

**本期不做焦点体系**（PF 全局没有 tab 顺序，硬做要动壳层）。键盘用户继续走
`/usage` 命令；tooltip 里注明等价命令即是这条路径的替代手段。P3 若要补，须先
有壳级 focus 模型，不在本模块范围。

### 4.6 明确不做

- 右键菜单、拖拽排序、双击、长按；
- 点击改扩展内部状态（PF 无此通道）；
- 自动展开面板/悬浮预览（与用量环的 `ctx_tip` 同屏会打架）。

## 5. 数据与生命周期（含现存缺口）

1. **per-session**：`aux.ext_status` 属于「当前展示会话」。状态带只显示当前活动
   会话的项；切 tab / 切池后按新会话重算，不做跨会话合并、不做"上一次的值兜底"。
2. **清空时机（必须先修的缺口）**：pi 在 `resetExtensionUI()`（换会话 / 重载扩展）
   里 `clearExtensionStatuses()`；PF 目前**切会话不清** `aux.ext_status`（全仓无
   `ext_status.clear()`）。不修就上线 = 上一会话的额度行跟着跑到新会话。
   落点：会话切换/重载入口（`session/nav` 定位对账 + `/reload` 收场）统一清空。
3. **刷新频率**：扩展会秒级刷新（pi-usage 有倒计时 refresh timer）。渲染路径
   **零重算**：动作表静态 match、不排序新分配（键序稳定）、不做字符串格式化；
   `SetStatus` 到达已经 `cx.notify()`，天然一帧一次。
4. **热路径**：纯文本 + flex，无测量循环、无图片/阴影；整条不渲染时零成本。
5. **快照/自动化**：`automation/snapshot.rs` 增 `session.status_bar`
   （`{visible, items:[{key,text,action,disabled}]}`）；既有 `session.ext_status`
   原样保留（数据面断言用）。

## 7. 与旧落位的迁移（一条信息只在一个地方渲染）
