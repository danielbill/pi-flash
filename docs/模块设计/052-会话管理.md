PF提供自动清理会话的功能

在其他设置中提供【自动清理会话】选项，最后活动超出 【 - 3天 + 】且非置顶会话， 自动删除。

- 默认值：0天，默认不自动清理；用户可调整，钳制 [0,100]，步长为5
- 0为关闭自动清理，不自动删除
- 置顶会话不删除
- 自动清理不可阻塞主线程，为启动 - 延迟加载中的后排任务
- 设置项放在【提示音】前
- 注释：设置会话停止活动N天后自动删除，0为不自动清理
## 实现落点

- **设置**：`AppSettings.auto_clean_days`（workspace.rs，键名同名，默认 0 = 关闭，
  显式设置后才生效；读入口
  `auto_clean_days()` 统一钳制 [0,100]）。UI 在「其他」页「提示音」前，−/值/+ 步进（步长 5）
  （stepper 已通用化：render/cur/apply 三闭包，会话显示数同款复用），0 显示「关闭」。
- **扫描**：`pi_link::sessions::stale_session_files(root, cutoff)`——只 read_dir+stat
  按 mtime 挑超期候选（最后活动 = mtime，与 recents/加载窗口同口径），不走 Scanner 重解析。
- **删除**：`services/session_clean.rs::spawn_session_auto_clean`，揭幕后触发（与
  token_probe/更新检查同批后排）。trash 移入回收站（项目铁律：删除须进回收站防误删），
  单文件失败只跳过不中断。
- **保护名单**：置顶会话（设计明文）+ 本进程全部 runtime 持有的会话（活跃正被看着，
  后台 runtime 握着 jsonl 句柄，Windows 上回收站搬运也必失败）。
- **收尾**：主线程只做内存状态摘除（pool.sessions/尾窗缓存/psp 各组清单/未读/置顶
  清册/session_ext/recents，与 pool::delete_session 同一清单），然后 refresh_sessions +
  状态栏 toast「已自动清理 {n} 个超期会话（移入回收站）」。per-project last_open 指向
  被清会话时自愈（消费端都有 `.exists()` 过滤），不额外清键。
