# 输入面板

输入面板：输入框；发送（Enter）与停止（ESC）；发送图片、选择模型、选择思考强度、
选择 skill、设置权限、选择工具（档位 + 会话插件清单）、压缩、上下文信息展示，
以及 `@` 项目文件检索引用、`!` 执行 shell 命令。

模块代码：`crates/app/src/session/input/`（`mod.rs` Chat 委托层、`area/` 主输入区
与键路由、`bar/` 控件行、`ctx_tip/` 用量面板、`queue_cards.rs` 排队卡）。

本文范围：「工具档位 + 会话插件清单 + @ 检索 + ! shell」；插件装载机制与
工具声明约束见 041《扩展装载与工具声明》。

## 发送键与排队语义

**只有 Enter 发送，Shift+Enter 永远换行**（不论 agent 在不在跑；任务页嵌入态
Enter/Ctrl+Enter 均不发送，保留换行）。

**缓冲栏三条规则（本节全部语义由此派生）**：

1. **排队**：agent 轮次结束，缓冲信息自动发出（AgentSettled flush）；
2. **缓冲栏有内容时无法继续发送消息**（再按 Enter 只出提示、草稿保留；
   Ctrl+Enter 可立即打断）；
3. **立即 = 中止当前 agent 轮次、重新下达指令**（abort 当前回复半截截断，
   该条立刻作为新一轮 prompt 发出）。

**运行中发送方式（设置-其他「运行中发送方式」，`app-settings.json send_mode`，
`workspace::send_mode_pref`）**：`queue` 排队（**默认**）/ `steer` 插话
（= 打断）。Ctrl+Enter 永远是反向操作（queue 模式 = 本条立即打断；steer
模式 = 显式入队）。

### queue 模式（默认）——PF 本地队列护栏

**仅运行中发送扣 PF 本地队列
`SessionRuntime.queued_inputs`，不进 pi 队列；空闲直接发送（prompt + followUp，
pi 原子判定），不经过缓冲**：

| 环节 | 行为 |
|---|---|
| 入队 | 不上气泡流（**不进 pending_echoes**），以 composer 上方**排队卡**呈现（手柄 + 首行预览 + ↑立即 + 铅笔撤回编辑 + 垃圾桶 + 拖拽重排，`session/input/queue_cards.rs`） |
| flush | 钉死 `AgentSettled`；发 `Prompt{streaming_behavior: None}`——pi 实际在忙会**响亮拒绝**而非静默入队，response 臂放回队首等下一次 settled（`flush_in_flight` 按 id 关联） |
| 入队上限 | **缓冲非空即拒绝再发**（规则 2）：`queue.full` 提示、草稿保留；Ctrl+Enter 转打断（规则 3） |
| 立即 | **打断**（规则 3，`interrupt_deliver`）：abort 当前回复（半截截断）+ clear_queue 撤 pi 残留，该条进打断槽，本轮 aborted 的 AgentSettled 一到即以新 prompt 发出（`interrupt_pending`，槽不渲染卡片——乐观气泡即呈现）。**上屏不钉顶**：退出锚点/垫片切回贴底跟随，消息跟在流后面（发言钉顶只属于空闲普通发送） |
| 撤回编辑 | composer 有草稿则拒绝（`queue.withdraw_conflict`）；否则该条退场、文本+附件回填草稿（ZCode「撤回编辑」parity，非原地改） |
| ESC 中止 | 本地队列**全部退回编辑器**（`restore_queue_to_editor`：文本 `\n\n` 拼接、附件回附件条；`RecallInput` 冒泡），pi 侧滞留由 abort 配对的 `clear_queue` 撤回。`clear_queue` 撤回**分流**：已乐观上屏的插话（用户视角「已发送」）气泡**保留**、文本不回编辑器——它没进模型上下文，快照重读后气泡自然消失，↑ 历史可捞回原文；从未上屏的（仅剩 pif-ui 自动化残留）删气泡 + 回编辑器 |

状态行「已排队 N 条」= 本地队列 + pi 侧镜像（`queue_total` = `queued_inputs` +
`queued_steering` + `queued_followups`；`queue_update` typed 事件，pi 侧镜像
正常恒空，只剩 pif-ui 自动化条目）。排队卡对 `QueuedInput.remote` 条目渲染
手机图标（当前主发送路径不产生远程条目，字段留作排障）。

### steer 模式（= 打断档）

| 状态 | 行为 | 上屏 |
|---|---|---|
| 空闲 | 条目进打断槽，flush 直接开跑 | 乐观气泡立即钉视口顶 |
| 运行中 | **打断**（规则 3）：abort 当前回复 + 该条作为新一轮 prompt | 乐观气泡，等待行衔接新轮 |

pi 的 `prompt + steer` wire 通路保留给 pif-ui 自动化（`session.steer` 现走打断
语义；裸 follow_up 仍直发 pi 队列供协议测试），UI 发送不使用该通路。

### 通用底线（两模式共用）

1. **发成功才清输入**：`Err` 写 status 并保留草稿与附件。
2. **回显去重**：`pending_echoes` 同文队列按位置就地升级；queue 模式入队不产生
   乐观气泡，flush 后回显是气泡唯一来源，去重负担随之消失。
3. **flush 补 040/043 承诺**：消息扣住期间 send_input 的空闲重绑分支不会跑，
   flush 前补做扩展清单/MCP 重绑（`rebind_pending`，`send.rs`）。

## 统一输入菜单（031-2）

Slash/@ 两菜单合并为一个弹层：**搜索栏 + tab 条（技能 `/`、命令 `$`、项目
文件 `@`、会话 `&`、「打开文件」+钮）+ 单列条目区**。代码落点
`session/menu.rs` + `session/menu_views.rs`。

- **弹层壳**：1px accent 描边、圆角 8、阴影；会话区限高 520（任务页嵌入态
  按视口钳）。tab 条复用 topbar `tab_body` 菜单变体：**无圆角 + 填满条高**。
  条高 `STRIP_H` 39 含条下 5px 菜单底色带（`BAND_H`，taffy 的 border 画在
  bounds 内），tab 高 = 39 − 5 = 34 恰填内容区、顶缘与搜索栏接洽；topbar
  连体态的左右 1px 边线与 mb(-1) 在菜单变体里全抹掉；激活 tab 填列表底色，
  条下 5px 菜单底色带。搜索栏与列表同为菜单底色、不画下缘线。
- **字体**：tab 条整条钉**面板字体槽**（挂载点在会话区，ambient 字体 = 会话
  字体槽，用户设其它字体会与搜索框分叉，故显式 `panel_font().family`）；
  搜索框/tab 栏统一面板字体（hint/kbd 的 mono 摘除）。字号 = 面板 −1：
  条目名/目录前缀/tab 文字/搜索框一律 ui(11)（搜索框走
  `TextInput::text_size(11)` 覆盖档，None = 默认阶梯），辅助文案（描述/组头/
  前缀 kbd）ui(10)。
- **触发**：`/` `$` 仅输入开头且其后无空白（整段输入型）；`@` `&` 是光标前
  token（`extract_trigger_query` 参数化同构语法：行首/空白之后，`@"..` 引号
  形态通用）。`!` bash 模式不开 `&`；查询词以 `&` 开头（`&&`）不算。
- **钉住子菜单**：操作栏 + 钮（原图片附件钮）= `ComposerUi.menu_pinned` 钉住
  技能页（无前缀触发，不往输入里插 `/`）：钉住期间整段草稿即查询词（含空白
  = 写正文 → 收起，与 `/`+空白同语义）；显式前缀 / $ @ & 出现即压过钉住；
  Esc/点外清钉（`MenuTrigger.pinned`，`menu_tab_available` 恒真）；on_change
  通知门控补 `menu_pinned`（无触发字符也要刷过滤）。图片附件入口只剩 Ctrl+V
  粘贴。
- **tab 点击 = 改写触发符**：`@`↔`&` 互转、转 `/`/`$` 仅当整段输入型（否则
  tab 置灰不可点，`tr.query` 含空白/引号同禁；`menu_tab_available`：`@`/`&`
  与 File/Session 恒可）。搜索视图里点 tab = 清搜索词落到该子菜单。
- **过滤口径**：技能/命令 = 前缀匹配（技能按剥 `skill:` 前缀名，全名形态
  `/skill:x` 仍通；限 `TAB_LIMIT` 60 条）；文件 = TUI scoreEntry 打分
  （at_filter_cache 记忆化不变，限 `AT_RESULT_LIMIT` 20）；会话 = 标题包含，
  psp 项目清单全量、按修改时间倒序、desc = 项目名。
- **万能搜索**（菜单内搜索栏，`TextInput` flat 档）：非空即独立结果视图，
  四类**仅按名称**子串匹配（文件 = basename，`filter_file_names`），组头
  「类名 · 计数」分组，命中高亮；每类限 `SEARCH_LIMIT` 20。composer 输入一变
  即清搜索词（搜索词只属于菜单内搜索栏会话）。
- **确认只认 Tab / 点击**（Enter 不接受补全；菜单过滤态直接回车 = 字面发送，
  裸 `/命令` 命中内置表仍走 `builtin_slash_dispatch`）：技能·命令 → `/name `
  （token 前有正文时命令置顶、原文跟作参数，不丢字）；文件 → `@path `
  （目录不闭合钻取；引号态触发强制引号形态并吃掉悬在光标处的旧闭引号）；
  会话 → 全路径纯文本（chip 化由 `session_token_for_input` 派生）。Esc：
  技能尾追空格成 chip 形态，其余只收起（token 保留）。
- **「打开文件」+钮**：系统文件选择器（`prompt_for_paths` 多选，仅文件）→
  `@path ` 替换当前触发 token（项目外 = 绝对路径）；菜单已收起则追加到输入
  末尾。
- **焦点**：搜索栏持焦走 focus_arbitrate 白名单（`menu_search_focused`，同
  搜索条输入框模式）；确认/切 tab/收起置 `menu_refocus` 放行 composer 回收。
  搜索栏 ↑/↓/Tab 自弹层根 `on_action` 接管（键位绑定在 "Input" 上下文，
  与胶囊侧同名 handler 同一套 Chat 方法 `menu_move`/`menu_accept_current`）。
- 会话行：图标 `message-square-text` + 标题（固定 400px 宽截断）+ 项目名
  （越界截断）；按时间排序不显示时间。行样式四类一致（图标 + 名 + 描述）。

## 工具预设档位

工具胶囊菜单（`PillMenu::Tools`，渲染 `shell/render/pill.rs`、行定义
`session/menu_rows.rs::tools_preset_rows`）：顶部「计划模式」独立勾选行
（031-1，分隔线与档位隔开）+ 五个档位行。档位全部落在 spawn 参数上（RPC 面
没有动态换工具的命令），**换档 = kill + respawn + `GetMessages` 整表重读**；
运行中被 `mc_set_tools_preset` 兜底拦截（「运行中不能更换工具预设」，
`tools_recipe.rs`）。默认档 = `custom`（full+）。

| 内部键 | 菜单文案 | spawn 参数（`runtime/spawn.rs`） |
|---|---|---|
| `chat-only` | 仅聊天 | `--no-tools`（present_plan 不点名，计划模式在该档不可用） |
| `read-only` | 4 个只读内置工具 | `--tools read,grep,find,ls,present_plan` |
| `default` | 4 个内置工具 | `--tools read,bash,edit,write[,pfctx_manager],present_plan`（pfctx_manager 仅自我调试开关开着才点名） |
| `full` | 全部内置工具，无扩展 | `--tools bash,read,edit,write,grep,find,ls[,agent],present_plan` + `-ne` + 个人扩展 + 内置扩展（agent 仅子代理模块开关开着才点名） |
| `custom`（**默认档**，显示名 full+） | full + 自定义扩展 | 不发 `--tools` + `-ne` + 会话插件清单（源消重后）+ 内置扩展 + `full_activate.ts` |

所有档位统一追加 `--exclude-tools acp_delegate,acp_delegate_wait,
acp_delegate_cancel`（防扩展委派面与 PF 的 `agent` 子代理撞车）。

两条设计约束（依据见 041 §1.2/§1.3）：

- **`--tools` 是注册级硬 allowlist**：不在名单里的工具连注册都不进（任何
  exposure 都挡，`*`/`all` 无通配），插件工具会被一并挡掉。要插件工具的唯一
  通路 = 不发 `--tools`，由扩展在 `session_start` 调 `setActiveTools`。
- **嘴手一致**（注入 ⊆ 声明）：插件往系统提示词注入的段落与工具声明完全解耦，
  full 档走「**不装载**」（`-ne`，包一个不装），而不是「装载 + 抑制注入」。

## 自定义档（会话级插件清单）

默认档（内部键 `custom`，显示名 full+）：full 的工具口径 + 本会话选中的
插件。清单只属于单个会话，不改动全局 `settings.json`——设置·插件页写
settings，本档写 spawn 参数，两者独立。

### 交互（勾选即生效）

- **入口**：工具胶囊右边的「扩展」按钮（plug 图标 + `[n]`，n =
  `ext_sources.len()`，n=0 也显示）。仅 full+ 档激活，其余档置灰（置灰 +
  `open_pi_extension_picker` 守卫双保险，提示「扩展只能在 full+ 档勾选」）。
- **面板**（`session/pi_extension_picker.rs`，420px 宽，锚定按钮 pill_anchor
  半屏定向，overlay 点外关闭）：头 = 「选择扩展」+ 已勾集 token 合计；行 =
  14px checkbox + 等宽字体展示名（去 `npm:`）+「项目」小标 + 右侧说明 token
  数（延迟加载测得才显示）。宇宙 = 全局 → 项目序枚举去重，按展示名排序，
  **已勾置顶**。**限高 10 行**（约 300px），超出滚动（滚动句柄跨帧复用）；
  无已配置插件时显示占位文案。
- **勾选即生效**：无确认按钮——每勾/取消一项当即写 `runtime.ext_sources` +
  落 `~/.pi-flash/session-ext.json`（`write_for_preserving_mounts`：保住
  PF 插件挂载通道写入的路径条目），按钮计数实时变。
- **重绑时机**：统一走 `pending_ext_sources`——下一轮 `send_input` 空闲发送前
  重绑（`--session` 复接不丢消息）；连点 N 项只重绑一次，运行中不掐轮、清单
  在下一轮生效（状态行提示）。档位切换仍走 `mc_set_tools_preset` 的
  kill + respawn 重绑链路。
- **两个宿主**（按 `content_view` 分流）：会话区写 runtime + 台账；046 任务页
  嵌入态写任务表单 `tasks.page.extensions`（随【保存】进任务 spec，派发时按
  它挂载），不碰背后会话。
- **种子**：勾选态只对齐会话数组 `ext_sources`；全局启用集只在会话创建时复制
  成初始清单（`SessionRuntime::new`），菜单不并回全局集（否则取消的勾在重开
  时被全局集顶回去）。
- **0 选中 = 合法态**：`-ne + 内置扩展 + full_activate.ts`（精确空集，全量内置
  工具），不退化回 full。

### spawn 参数配方

custom 档（`tools_recipe::full_plugin_args`）：

```text
pi --mode rpc --session <file>
  -ne                                   # 精确集：关掉已配置/发现/内置扩展
  -e <选中插件1> …                       # npm:x 优先换成 managed 安装路径
  -e builtin:<settings 里开着的内置…>     # -ne 连内置扩展一起关，逐条加回
  -e <full_activate.ts>                 # session_start 里 setActiveTools
```

- **源消重**（`resolve_ext_sources`）：会话清单里的 `npm:x` 在拼装前先换成
  managed 安装路径（`~/.pi/agent/npm/node_modules/<pkg>`，pi 对本地目录全套
  挂载零复制）；直接发 `-e npm:x` 会让 pi 按 temporary scope 又装一份到
  tmp（双份 node_modules + 版本漂移）。未安装/装坏的源原样回退 `npm:x`
  （pi 现场临时安装兜底）。
- **契约 v4**：插件的 `pi/*.mjs` 执行域入口不进 `-e`（再当扩展挂载会让 pi
  整批 `-e` 失败），`full_plugin_args` 与 spawn 的台账段都过滤。
- **tc6 注册过滤**：ext_sources 与台账挂载段 spawn 前过
  `ext_source_allowed`——插件包源须注册在案且未停用（停用/卸载后的残留条目
  失效）；版本换代死路径由 `session_ext::resolve_sources` 自愈回写。
- **会话台账全档位消费**：`session-ext.json` 的路径型挂载条目（PF 插件
  `pi_extensions` 绑定通道写入）**所有档位**统一追加 `-e`（此前只有 custom
  档读，插件 ext 在 full/default 档下挂不上）。

full 档（`tools_recipe::full_args` + runtime 拼 `--tools`）：

```text
pi --mode rpc --session <file>
  --tools bash,read,edit,write,grep,find,ls[,agent][,pfctx_manager],present_plan
  -ne
  -e <个人扩展…>                         # <agent dir>/extensions/*（发现口径复刻，见 extensions.rs）
  -e builtin:<settings 里开着的内置…>
```

要点：

- **内置扩展清单跟着 settings 走**（`pi_link::config::enabled_builtin_extensions`）：
  默认四个全开（`builtin:mcp` / `builtin:llama.cpp` / `builtin:codemode` /
  `builtin:tool-search`），settings `extensions` 里 `-builtin:x` 关、`builtin:x` 开，
  项目 settings 覆盖用户。不能写死——`-e builtin:<name>` 会**覆盖** settings 里的
  `-builtin:<name>`，写死会把用户关掉的内置扩展强行打开。
- custom **不发 `--tools`**：它是注册级 allowlist，会把插件工具挡在注册之外。
- `-ne` 只关扩展（发现 + 配置 + 内置）；skills / prompts / themes 各有自己的
  开关，不受影响（个人 skills 照常）。

`full_activate.ts`（`crates/app/assets/`，`include_str!` 编译进二进制）：

```typescript
const EXCLUDE = new Set(["powershell"]); // 对齐 full 档：bash,read,edit,write,grep,find,ls
const FULL = ["bash", "read", "edit", "write", "grep", "find", "ls"];
export default function (pi: ExtensionAPI) {
  pi.on("session_start", () => {
    // full 内置 ∪ pi 自己算出的 active（settings defaultTools + 注册即激活的
    // direct 工具）——不碰 deferred/model-only 的默认非激活态
    const names = new Set<string>([...FULL, ...pi.getActiveTools()]);
    pi.setActiveTools([...names].filter((n) => !EXCLUDE.has(n)));
  });
}
```

激活口径 = **full ∪ `getActiveTools()`**：把 deferred（MCP）/ model-only
（tool_search）的工具拉成直接声明会与普通会话不一致，故只收编 pi 自己已激活的项。

脚本路径解析（`tools_recipe::activate_script_path`）：`PI_FLASH_FULL_ACTIVATE`
覆盖 → dev 工作区 `crates/app/assets/full_activate.ts` → 内容落地
`~/.pi-flash/full_activate.ts`（release 包不带 assets 目录）。解析失败时
降级：只发 `-ne + -e`，active 回落 defaultTools + 插件工具。

### 持久化（每个对话一份清单）

`~/.pi-flash/session-ext.json`（`pi_link::session_ext`，app 自有文件，不碰 pi
会话文件）：

```json
{ "<会话 key>": ["npm:pi-freeflow", "npm:pi-web-access"] }
```

- key = 会话文件绝对路径（`norm_key` 归一化：斜杠方向 + 盘符大小写；草稿 =
  `draft-N`，草稿不跨重启）。
- 草稿 key 在会话文件落定时由 `on_file_bound` 迁到文件路径；删会话清条目
  （052 会话清理同删）；空清单 = 删条目（不落空数组）。
- 台账是**混合通道**：用户勾选的 scheme 源（`npm:`/`git:`…）+ PF 插件挂载的
  路径条目（面板不显示、不计数，落盘时保住）。
- **只存插件清单，不存档位**：重启回落默认档（custom），清单按会话恢复。

### 边界与决策

- **重绑成本**：换档 kill + respawn 一次，无双 spawn。
- **运行中**：开面板被守卫拦（非 full+ 档）；档位切换被 `mc_set_tools_preset`
  兜底拦；**勾选不拦**——清单下一轮发送前重绑生效。
- **已知边界**：custom 档的 `-ne` 会把「发现 / 配置」来源的个人扩展
  （`~/.pi/agent/extensions/*`、settings `extensions` 路径条目）一并关掉且**不
  加回**（full 档会加回个人扩展）；复刻 pi 完整发现规则（含项目 `.pi/extensions`
  的 trust 语义）需要时另立设计。
- `mc_set_tools_preset` 不感知档名：接收任意 key，custom 与其它档走同一条重绑
  链路。

## @ 项目文件检索引用（对齐 pi-web）

输入框敲 `@` 弹文件补全菜单。**协议上是纯文本**：确认后插入 `@path `，
pi 不做任何展开（模型收到含 `@path` 的文本，自己调 read 工具读文件）——
pi-web / pi TUI 同语义；内容注入只存在于 pi CLI 的 argv 场景（`@file` 首条
prompt 展开成 `<file>` 块），RPC 面不存在。

### 触发与 token（`services/at_file.rs`，正则语义对齐 pi-web extractAtQuery）

- `@` 必须在文本开头或前面是空白字符（邮箱 `foo@bar` 不触发）；`@` 到光标
  之间无空白。左最匹配。
- 引号形态 `@"查询`：查询词可含空格；内部出现 `"` 或换行 = token 失效
  （菜单收起）。token 体按**字符**判空白/引号（字节直转 char 会把 UTF-8
  续字节误判成 NEL/NBSP 空白，掐断中文目录名）。
- 以光标（composer cursor 字节偏移）为界，只看光标前文本。

### 数据源（`services/file_index.rs`，对齐 pi-web /api/file-index）

- git 仓库：`git ls-files --cached --others --exclude-standard -z`（尊重
  .gitignore，对齐 TUI 的 fd 行为；LC_ALL=C）；非 git 回退 BFS 遍历
  （深度 ≤ 8、5 万上限、跳隐藏项与 node_modules/target/dist）。
- 硬上限 20 万条（GIT_HARD_CAP）。每 cwd 缓存一份（`Chat::at_index`），后台
  线程构建，构建期间旧清单先顶上；TTL/项目数读 `app-settings.json` 的
  `at_index_ttl_secs`（默认 60，clamp 1-3600）/ `at_index_max_projects`
  （默认 10，clamp 1-100）。

### 打分与排序（TUI scoreEntry 阶梯）

精确 100 / 前缀 80 / basename 子串 50 / 全路径子串 30 / 子序列 fallback 10，
目录 +10；排序 = 分数 → 路径深度浅优先 → 字母序；截前 20 条（`AT_RESULT_LIMIT`）。
查询含 `/` 时对全相对路径打分——这是目录钻取的机制：确认目录插入 `@dir/`
（不闭合），菜单保持打开，后续查询前缀命中 dir 下所有条目（dir 自身被排除）。

### 交互

- 文件确认闭合 token：`@path `（含空格加引号 `@"path" `），光标在末尾；
  目录确认不闭合（`@dir/`）供继续钻取；引号目录插成闭合 `@"dir/"`、光标
  在闭引号前。只替换 @token，光标后的文本保留。
- 键盘：↑/↓ 循环、Tab 确认（Enter 不接受补全，见统一菜单）、Esc 只收起
  （token 保留，pi-web parity）；悬停更新高亮。条目渲染 = 目录/文件图标 +
  目录前缀暗色 + 文件名亮色 + 目录尾随 `/`。
- 菜单打开期间每帧 `ensure_at_index` 预热索引（TTL 内幂等）。

## ! 执行 shell 命令（对齐 pi-web）

### 触发

`trimStart` 后以 `!` 开头且无图片附件 → shell 模式：控件行左组换成模式提示
「Shell · 输出发给模型」；`!!` = 输出不进模型上下文（「输出仅本地」）。
发送走 `session.send` 同一入口，`send_input` 分流到 rpc `bash`；发送成功进
↑ 历史、清输入。Esc：bash 执行中优先中止 bash（`abort_bash`），其次模型流。

### 协议（pi 原生 rpc，pi-web 同款）

```json
{"type": "bash", "command": "ls -la", "excludeFromContext": true}
```

- pi 立即执行（cwd = 会话 cwd；输出 50KB 截断，超限落临时文件
  `fullOutputPath`），结果记成 `role:"bashExecution"` 消息。
- **响应** = `BashResult {output, exitCode, cancelled, truncated, fullOutputPath?}`；
  执行中增量 = `bash_execution_update` 事件（app 就地追加渲染，比 pi-web
  靠会话重载更实时）。
- **进模型时机**：下一次 prompt 时 pi 的 convertToLlm 把非 excluded 的
  bashExecution 折叠成 user 文本（``Ran `cmd` `` + 输出码块）；`!!` 的记录
  会话里有、模型看不到。bash 命令本身不触发模型。
- 中断 = rpc `abort_bash`（Esc / 停止按钮，bash 执行中优先于中止模型流）。
- 会话忙（bash 在飞 / agent 跑动 / 压缩中）时 app 侧拒绝（pi 侧同样拒绝），
  输入保留在输入框可重发。

### 展示与持久化

- 消息模型 `Role::Bash` + `BashInfo`（命令/输出/退出码/取消/截断/excluded/
  running），渲染合成 bash 工具卡（`render_bash_msg` 复用件）：非零退出码红、
  取消灰、截断附 `fullOutputPath`；excluded 显示名 `bash (local)`；执行中
  加旋转「执行中 · Esc 中止」行。
- 独立消息行，不进轮分组、不计 nav 统计。
- pi 把 bashExecution 写进会话文件（`get_messages` 快照即携带）；重启重开
  会话由快照/磁盘自然恢复。
- 边界：bash-only 的草稿（从未发过 prompt）不落盘（pi 首条 prompt 才写
  会话文件），重启后这部分记录不恢复——pi-web 同限制。
