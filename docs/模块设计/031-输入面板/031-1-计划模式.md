# 031-1 计划模式

> 状态：**已完成**（P0-P5 全部落地，2026-11-10 真机验收全绿）。参照 ZCode
> plan mode：计划态下 agent 只读探索并与用户讨论计划，收尾以 `present_plan`
> 工具呈现计划，用户批准后退出计划态开始实现。

## 1. 功能需求（终版）

- 工具菜单顶部「计划模式」条目（分隔线与下方工具选项隔开）；计划态时
  composer 工具胶囊右侧另有「[notebook-pen] 计划」状态 pill，悬停换 ×、
  点击退出计划模式。
- 计划态下 agent 不得修改文件与系统状态；agent 知道自己在计划模式，应当
  只读探索并与用户讨论工作计划。
- 计划完成后 agent 调用 `present_plan(plan)` 工具，PF 弹出**标准模态卡**
  审批弹窗（`render_ext_dialog` 骨架 1:1）：宽 = 聊天内容区宽、高 94%
  上下居中；标题栏「计划」+ ×；正文 100% 卡宽 markdown；footer 背景 =
  左功能面板（nav）；两钮 300×50 文字居中并排——「批准计划，取消计划
  模式」/「否决 / 取消（Esc）」。present_plan 工具卡对用户隐藏。
- 批准（按钮）→ 退出计划模式，agent 同一轮继续实现。
- 否决 / Esc / 标题 × / 关闭 → 立即中止本轮（Abort+ClearQueue，无收尾
  发言轮），计划模式保持；模型视角收到「用户拒绝或取消了你的计划」。
- 用户的新想法直接在 composer 输入，计划态下 agent 重新计划，零阻断。

## 2. 架构总览

工具在 pi 进程内执行（RPC 模式无宿主审批回调），**闸门必须住在 pi 进程里
= pi 扩展（JS asset）**；PF 插件（Rust→wasm）体系没有 tool_call 拦截位。
本模块走 041 pi 扩展体系，分发机制同 `full_activate.ts`（dev 直读
`crates/app/src/mode/plan_mode.ts`，release 落盘 `~/.pi-flash`，
`PI_FLASH_PLAN_MODE_TS` 可覆盖）。

pi 1.5.0 必需原语（vendor `pi-coding-agent`）：

| 能力 | 原语 |
| --- | --- |
| 执行前拦截 | `pi.on("tool_call")` → `{block, reason}`（handler 出错也 block，fail-safe） |
| 每轮提醒注入 | `pi.on("before_agent_start")` → 返回 `message` 前置本轮上下文 |
| 阻塞等待宿主决定 | 自定义工具 handler 挂起 + race `ctx.signal`（官方 plan-mode 模板同款） |
| 扩展⇄PF 通道 | PF→ext：`prompt "/plan"` 扩展命令（流式中也立即执行）；ext→PF：`ctx.ui.setStatus` fire-and-forget |
| 声明收放 | `pi.getActiveTools()/setActiveTools()`（RPC 命令 handler 内可用） |

```text
┌─ PF (GPUI) ──────────────────────────────────────────────┐
│ 工具菜单「计划模式」/ 状态 pill ──prompt /plan──────┐    │
│ 计划审批弹窗（模态卡：内容区宽×94%，markdown 预览） │    │
│   批准 ──prompt /plan-approve───────────────┐       │    │
│   否决/Esc/× ──Abort + ClearQueue───────────┤       │    │
│   其他想法 ──composer 直接输入──────────────┘       │    │
│ 状态投影 ←──setStatus("pf-plan", JSON)──────────────┼──┘ │
│ 弹窗触发 ←──tool 事件 present_plan(args)───────────┘    │
└──────────────┬───────────────────────────────────────────┘
               │ RPC（现有 wire，零协议改动）
┌──────────────▼───────────────────────────────────────────┐
│ plan_mode.ts（随包 asset 扩展，-e 全档位装载）             │
│  registerCommand("plan")           切换计划状态           │
│  registerTool("present_plan")      handler 挂起等裁决     │
│  tool_call 硬闸                    block edit/write/危险bash│
│  before_agent_start                注入计划模式提醒        │
│  context 钩子                      过滤提醒卡+改写中止反馈  │
│  syncToolExposure()                声明随计划态收放        │
│  sessionManager.appendCustomEntry  持久化+session_start 恢复│
└──────────────────────────────────────────────────────────┘
```

## 3. 设计决策（终版）

1. **扩展是唯一事实源，PF 是投影**：PF 侧点击只发 `/plan`，成功与否以
   扩展 `setStatus("pf-plan")` 广播为准；`session_start` 时扩展广播当前
   状态 → 会话切换/分支/冷恢复零 PF 持久化成本。严禁 PF 本地猜状态后覆盖。
2. **内置工具集恒定，无快照**：计划模式不切换/不快照内置工具集，只靠
   tool_call 闸门把写操作打回；批准 = 仅清除 planEnabled。不碰 PF 的
   `tools_preset` 档位字段（spawn 配方语义不动）。
3. **纯 block，不摘工具**：tool_call 硬闸是唯一执行点（本轮已发出的并行
   tool call 只有它能拦）；被 block 以 error tool result + reason 回给
   模型，模型自行转向只读探索（ZCode 同款 deny 语义）。
4. **计划呈现 = 自定义工具 `present_plan`**（ZCode ExitPlanMode 同款，
   正文在工具参数里，模型无「计划文件」概念）：handler 存下计划正文、
   广播 PF 开弹窗、挂起等待裁决（race abort signal，abort 后 handler
   不悬）；工具结果 = 裁决内容。
5. **弹窗两动作，无输入框**：批准 → `/plan-approve`，resolve
   present_plan 为「已批准」，agent 同一轮继续实现。否决/Esc/× 同一路径
   = PF 侧 `abort_stream`（Abort+ClearQueue 配对，铁律：abort 必清队列）
   → 取消即停；模型视角反馈由扩展 `context` 钩子把中止错误结果改写为
   「用户拒绝或取消了你的计划」。`/plan-reject` 命令保留注册但 PF 不调用。
6. **闸门只拒绝「修改」**：`edit`/`write` 一律 block；`bash` 按破坏性
   黑名单（DESTRUCTIVE_PATTERNS）命中才 block，缺省放行；**其余工具全部
   放行**——压缩/Provider（freeflow）/子代理委派/MCP 等扩展生态不下掉
   （切只读工具集会让 full+ 生态与 free 模型直接不可用）。残留风险：
   bash/python 间接写可漏，edit/write 硬闸是主防线，提醒文案同时约束
   「不得借其他工具绕过」。
7. **`/plan` 防哑弹**：扩展命令若因 `-e` 装载失败未被消费，pi 会把
   `/plan` 当普通消息发给模型（`disposition:"started"` 而非
   `"handled"`）。PF 发送后校验 disposition，未 handled → toast 报错 +
   回滚乐观勾选。
8. **present_plan 注册恒在，模型声明随计划态收放**：`--tools` 白名单是
   注册前提且会无条件激活点名工具（`defaultActive:false` 救不了），故
   注册恒在，声明态由扩展 `syncToolExposure()` 按需收放——session_start
   （恢复对齐）、`/plan` handler（翻转即同步，no-op 也跑 = 自愈）、批准
   路径三处调 `getActiveTools/setActiveTools`（有差才调，避免无谓重建
   系统提示词）。execute 内 guard 兜底：非计划态调用仍被拒。

## 4. 实现地图

**pi 扩展**（随包 asset）：
- `crates/app/src/mode/plan_mode.ts` — 全部扩展逻辑：planEnabled 状态机、
  tool_call 硬闸（DESTRUCTIVE_PATTERNS 黑名单）、before_agent_start 提醒
  （customType `pf-plan-context`，display:false）、context 钩子（过滤提醒
  卡 + `rewriteAbortedPlanResult`）、present_plan 工具、`/plan`
  `/plan-approve` `/plan-reject` 三命令、`persist()`（走
  `ctx.sessionManager.appendCustomEntry`，禁 `pi.appendEntry`——RPC 命令
  handler 里会抛）、`syncToolExposure()`、`broadcast()`（`setStatus(
  "pf-plan", {"v":1,"enabled","pending"})`）。

**PF 侧**：
- `mode/mod.rs` — 扩展落盘/装载：`script_path()`、`mount_args()`（全档位

  CONTEXT_CUSTOM_TYPE / PRESENT_PLAN_TOOL 单一来源。

  handled → 回滚 + toast `plan.ext_unavailable`。

  tool_execution_start → `SessionEvent::PlanPresent`；`pool/runtime_link.rs`
  路由开弹窗（同时刻仅一份挂起；后台会话不弹，切回不重放）。
- `session/messages/` — present_plan 工具卡对用户隐藏（tool.rs）；
  `is_abort_error()` 归一（model.rs / turn render / stream.rs：黄点无红框）；

- `shell/render/focus.rs` — 仲裁白名单加审批弹窗分支（dialog_focus）。
- `session/input/bar/mod.rs` — `plan_marker_button()`（状态 pill，仅
  plan_enabled 渲染，`ComposerUi.plan_marker_hover` 驱动换 ×）；图标

## 5. 风险与陷阱

- **扩展命令 handler 里 `pi.appendEntry` 会抛错**（RPC 模式 runtime
  action 未绑定）——持久化一律走 `ctx.sessionManager.appendCustomEntry`。
- **disposition 校验**是唯一会造成「静默发错消息」的点，必须做（决策 7）。
- **草稿期勾选的同步窗口**：spawn 后 session_start 广播（false）先于
  同步命令的广播（true）到达——`plan_sync_pending` 期间相反广播必须忽略。
- **焦点仲裁是白名单制**（shell/render/focus.rs else-if 链）：新浮层要么
  复用 `dlg.dialog_focus` + 仲裁链加分支，要么走 `DlgUi.dialog` 老枚举
  ——禁自造焦点句柄（不在名单 → Esc 与输入全部失灵）。
- **Abort 打断工具执行时 pi 把整轮标 stopReason=error**（errorMessage
  含 abort）——按 `Msg::is_abort_error` 并入内部中断口径；此为通用修复，
  停止键打断任何工具执行同款受益。
- **MSYS 路径改写**：Git Bash 下 `pif-ui exec --arg text="/plan"` 会被
  改写成 `C:/Program Files/Git/plan`（整条命令静默发给模型）——自动化
  传斜杠文本一律走 `--params-file`。
- 无真实消息前 pi 不落盘会话文件（ENOENT）——冷恢复探针须手工会话文件
  驱动；PF 真实使用中文件必然存在，不受影响。
- `setActiveTools` 每调一次重建系统提示词——`syncToolExposure()` 必须
  有差才调。
- Abort 必配 ClearQueue，否则排队消息在下一轮被冲出来重放。
