## 内置的 subagent

1. **通用子代理（id: general-purpose）**
   通用任务执行 agent，和主 agent 没区别。适用场景：完全体的 agent，能力大小只取决于扩展多少。
   - 继承委派 agent 的环境，CWD、注入全局和项目的 AGENTS.md
   - 工具集：默认 full+ 配置；委派 agent 也是 full+ 时继承
   - skills：默认注入全局 + cwd skills

2. **本地探索者（id: explorer）**
   有只读权限的本地资料检索 agent，专门用来查看任务相关的本地文件内容。适用场景：帮委派者做本地资料收集调研总结。
   - 继承委派 Agent 的环境，CWD、注入全局和项目的 AGENTS.md
   - 工具集：read-only
   - skills：默认关闭

3. **摘要机（id: summarizer）**
   无状态的摘要机器人，阅读指定文件或一段内容，按要求总结。适用场景：启用本地模型或云端廉价模型做系统日志摘要等。
   - 不继承环境，no cwd，no AGENTS.md
   - 工具集：read-only
   - skills：默认关闭

1. **嵌套深度**：恒定 1（禁止套娃；2026-11-07 用户拍板，UI 已移除）
2. **最大并发**：2-10，默认 3（2026-11-07 上限 5→10 用户定稿；glm 服务器侧通常 3-5）

## 主 Agent 派发任务时设置项

主 agent 通过调用 `agent` 工具派发任务，PF UI 不参与分派，只经会话流工具卡观察。调用时可设置：

1. **prompt**（必填）：完整任务陈述。子代理默认看不到主会话上下文（spawn），任务必须自包含；委派者只等结论，不重复自己能委派出去的检索。
2. **profile**：点名子代理身份（内置或自定义），决定其人格/工具档/默认模型/轮次预算；不点名则落系统预设默认子代理（general-purpose），不存在无 profile 的裸分身。
3. **model**：临时模型覆盖，`provider/model` 全名；与 profile 自带 model 同时给时本项优先。
4. **cwd**：子代理工作目录，缺省继承委派者。
5. **label**：任务短标签，展示在 transcript 与子代理面板。
6. **maxloop**：本次任务预估轮次预算，0=不限，省略=100；到预算会收到收尾引导，无视则被截断（max_turns）。
7. **blocking**：缺省（推荐、也是唯一常规形态）= 派发即返回 childId，完成后通知——工具**不占父轮**，用户随时可以对话（对齐 dsh `delivery: 'parent'`）；`blocking: true` 只给需要内联结果的程序化调用方（code-mode 聚合），会把父轮占到子代理跑完。

派发约束（自动生效，无需主 agent 设置）：

- 嵌套深度自动 +1，超过模块 maxDepth 拒绝（DEPTH_LIMIT）
- 并发槽按父会话计数，满则拒绝且不排队（CAPACITY_REACHED）
- 同帧多条委派真并行执行（executionMode: parallel）

派发后的干预：`subagent_send` 追加指令 / `subagent_interrupt` 中断 / `subagent_list` 列出子代理。

## 子代理观测数据面（pi-flash-9eck：主会话自足，descriptor 落盘已删）

2026-11-08 用户定夺：扩展往父会话 JSONL 逐条追加 `subagent/descriptor` 的机制**整体删除**（曾以 ~15 条/秒把父会话灌到 209MB——洪泛根因；其消费面全部可从主会话推导，子会话不回补主会话任何东西）。`SubagentDescriptor` 只留**内存**（`children` 工具实时统计可读），永不写转录。

宿主观测事实源：

| 消费方 | 事实源 |
|---|---|
| blocking 交付（`blocking: true`）：卡片状态/错误/开子会话 | 工具 result details（snake_case：child_id / stop_reason / session_file / error_code / duration_ms / total_tokens） |
| 默认交付：派发即时态 | 派发 result details（child_id / status:"started" / label / session_file） |
| 默认交付：终态 | 父会话 `subagent-completion` custom 消息（onCompleted 落盘，5554fa4a）→ 宿主按 childId 回灌 ToolCall details |
| 被拒委派（CAPACITY_REACHED 等） | `runDelegation` fail 路径 onUpdate 即时上屏（status:"failed" details 落转录卡） |
| 导航第三行点阵 | agent ToolCall 块推导（无 result=灰点运行中，终态按 stop_reason 分色） |

**卡片 details 字段表**（扩展 `tool.ts success()` / completion.ts）：

| 字段 | 来源 |
|---|---|
| child_id | sub-N（N 全局递增，被拒也消耗序号） |
| stop_reason | completed / aborted / error / max_turns（终态才有） |
| error_code | 稳定分码（max_turns 终态 = MAX_TURNS） |
| session_file | 子会话 JSONL 绝对路径——**prepare 返回即存在**，所以 started / running 的 details 就带上（B4，2026-11-08：运行中卡片要能点开观察窗）；settle（caller）与 completion 消息（background）再回写一次终态值 |
| duration_ms / total_tokens / turns 等 | settle 时随 result 回传 |

## 子代理错误管理

错误码分两层，只维护自己产生的，不追模型商码表：

- **模块层（准入/控制）**：DEPTH_LIMIT / CAPACITY_REACHED / PROFILE_INVALID / START_REJECTED / ADMISSION_CLOSED / ABORTED / PROVIDER_UNKNOWN / BACKEND_UNSUPPORTED / DUPLICATE_CHILD——稳定码全集，语义归 PF，码表可控
- **运行层（模型商产生）**：429/5xx/超时/断流等不可枚举，一律归一为 PROVIDER_ERROR，原始报错保留在 message 不丢信息

原则：宿主与主 agent 永远拿得到稳定码；分类只区分「我们的 / 模型商的」，后续细分从 message 提取，不动码表。

## 子代理 Max_loop 管理

软限两段式，不硬砍：

1. 预算解析：调用级 maxloop > profile maxTurns > 默认 100；0=不限（不装计数器）
2. 到限先引导：steer 注入收尾指令（禁止新工具调用，立即总结作答），收尾轮也计预算
3. 无视才截断：收尾后仍发 toolCall → abort 硬截断
4. 独立归因：截断后终态标 max_turns（errorCode=MAX_TURNS，非 completed/failed），UI 显「执行异常」类（会话流卡 tooltip 可见分码）
5. usage 口径：面板/卡片的 token 合计 = 子会话**逐轮 `message_end` 内存累计**（ΣtotalTokens），settle 终态落盘同口径——非「末条 assistant message」值

## 子代理会话查看

子会话在 PF 打开为普通会话 tab，**复用对话 view，隐藏输入面板**（只读观察窗）：

- 子代理 live 会话住在父 pi 进程内，tab 是对同一账本文件的观察视图（打开快照 + 空闲态外部追加跟随，~3s 延迟）
- 输入面板一律隐藏：用户输入会生成第二驱动分叉账本、双花 token、抢占模型商并发——子代理由主 agent 独占管理，用户无输入通道
- 变异操作（fork、消息操作栏）随输入面板一并隐藏
- tab 归宿：子会话 = 自由区普通 tab（`PanelTab::Observer`，追加 tab 区末尾，标题=任务名（主会话反查 args label → profile → prompt 首行），× 可关），固定段第一位永远留给主会话/新会话；观察窗不写 last-open，启动恢复过滤子会话（历史污染防护）

## subagent 运行状态面板

不设 fn_bar 按钮、不设独立浮层。开启功能后，某轮派发了 subagent，则在导航卡信息中增加第三行：

> `[子代理 icon] · · · · ·`（点数 = 子代理数量，7px 圆点，与第 4 条运行状态 icon 同源）

点色按子代理状态取，唯一例外是运行中：**运行中 = 灰点**（`text_dim`）。background 交付下轮先于子代理收尾，运行点若用 accent 会让已结束的轮看起来仍在活动；灰点表示“后台还在跑、尚无结果”，终态才落色——完成 NOTICE、中断/轮次用尽 WARN、异常 danger。分组数据每秒从主会话消息纯内存重投影到所有轮（pi-flash-9eck：descriptor/catalog 已删，零读盘），已结束轮的点随结算原地翻色。

该行同样超长截断。hover 左弹 400px 扩展菜单（无统计行），菜单行点击打开子会话。
