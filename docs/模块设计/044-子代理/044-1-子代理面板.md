# 044-1 Settings-子代理页与 Agent 定义管理（宿主侧）

> 状态：**现行**。实例观测、会话流卡、导航次级弹窗见 `044-0`；扩展侧机制见 `044-5`。
> **开关分两层**：
> 1. **构建门**（开发旗标，默认开）：`dev-flags.json` `"subagents"` 或 env `PI_FLASH_SUBAGENTS`；关 = 发布包排除本模块——不加载扩展 + 隐藏本页 + 隐藏操作栏按钮，同源 `dev_flags::dev_enabled()`。
> 2. **运行时开关**（用户面，本页「全局设置 · 启用模块」行）：写 pf-context hub `Subagents.enabled`。关 = 不挂 `pf-subagents` 扩展 ⇒ `agent` / `subagent_*` 工具压根不注册。工具面是 **spawn 参数**（RPC 无运行时切换），故翻开关要重绑进程：`Chat::apply_subagent_switch` 空闲会话立即重绑（`--session` 复接不丢消息）、运行中的会话由 `rebind_pending` 推迟到下一轮空闲发送。挂载决策唯一入口 `pi_link::subagents::mount_target(host_allows)`，宿主视角 = `subagent_module_active()`（两层相与）。

## 0 概念分层

```
Agent 定义(profile)= 用户资产 = 「类」     ← Settings-子代理页管理
  预制:扩展随包出厂(只读,可复制)
  自定义:用户完全所有(可建/改/删/分享/进项目 git)
子代理实例 = 运行记录 = 「对象」            ← 导航次级弹窗监视(044-0)
  委派产生的运行记录(childId/会话文件/状态/usage)
pf-subagents 扩展 = manager(机制层)        ← 不拥有定义,只消费目录
```

**存放 = 用户资产惯例，非扩展私有数据**：

| 来源 | 路径/载体 | 说明 |
|---|---|---|
| 自定义（全局） | `<PF数据目录>/agents/*.md`（env `PI_SUBAGENTS_PROFILES_DIR` 注入） | 用户完全所有：可建/改/删；名称全局唯一（PF 强制查重）。旧 `~/.pi/agent/agents` **不读取、不迁移** |
| 自定义（项目） | `<cwd>/.pi-flash/agents/*.md` | 与全局并列；同 id 文件占位（迁移残留去重，无显示层语义） |
| 内置 | 扩展代码内常量 | 随 pf-subagents 出厂，只读，可复制 |

**解析顺序（按 key 取 profile）**：`name`（点名句柄）优先——内置 → 全局 → 项目；id 兑底（旧转录/手写文档）——项目 > 全局 > 内置；都无 → `PROFILE_INVALID`。**不存在「自定义覆盖内置」**（同名时内置先中；名称全局唯一由 PF 强制）。

边界：

1. **不做包分发**——PF subagent 是内部组件，不对外发布，无 `pi install` 入口
2. **编辑走 PF 表单**，不让用户直写明文（§1.1）
3. PF 只表单化 v1 字段集（§2）；扩展新增的未知字段**原样透传不碰**（§2.1）

## 1 Settings-子代理页

### 1.1 定位与表单化

**Agent 定义的类型层管理**（观测面板是实例层）。形态与 042 模型管理同构（左列表右编辑）。

**配置项组件化，不让用户直写明文**；配置由 PF **单独管理存储**，不依赖手工改明文 md。

### 1.2 交互稿

```
Settings → 子代理（T 型：顶条全局设置通栏，下方左列表 / 右表单）
┌ 全局设置：启用模块 [✓]   最大并发 [− 3 +] ─────────────────────┐
├ 列表 ─────────────────┐  ┌ 表单详情 ─────────────────┤
│ 内置(随扩展,只读)      │  │ 我的评审员 [自定义]           │
│  ○ 通用子代理   [复制]  │  │ 简介     [代码评审_________] │
│  ○ 本地探索者   [复制]  │  │ 模型+思考 [继承 ▾][auto ▾]   │
│ 自定义            [新建]│  │ 工具     [继承 ▾]（full+:    │
│  ● 我的评审员 [复制][删]│  │           pi-ext/mcp 多选）  │
│  ● broken-scan 损坏    │  │ 技能     [继承 | 自定义]     │
│                        │  │ 环境注入 [✓ 注入所有AGENTS.md]│
│                        │  │ 最大轮次 [5|30|100|不限|指定] │
│                        │  │ 工作目录 [继承 | PF运行目录]  │
│                        │  │ 定制指令 [多行文本________]   │
│                        │  │ ────────────────────────── │
│                        │  │  [放弃] [保存]  ●未保存 Ctrl+S│
└────────────────────────┴────────────────────────────┘
```

- 列表两组：**内置（只读）** / **自定义**；条目展示 `name`（无覆盖 badge——同名被禁止）
- 表单字段：简介 / 模型（下拉，留空继承会话）+ 思考强度（auto = 不覆盖）/ 工具档位（下拉；full+ 另有 pi-ext 与 mcp 多选）/ 技能（继承 | 自定义）/ 环境注入（开关，默认开）/ 最大轮次（五档 seg）/ 工作目录（继承 | PF运行目录）/ 定制指令（多行文本 = 追加式人格）
- 不做：颜色标记、作用域选择、人格二档切换（提示词统一追加语义；schema 的 `systemPrompt` 替换字段保留但 UI 不暴露，见 §2.2）
- 动作：放弃 / 保存（Ctrl+S，未保存黄点）；删除进**回收站**（列表行尾 hover 显影两枚 icon 钮 = 复制/删除，删除仅自定义）
- 内置态：表单只读灰化。复制入口 = **列表行 hover 浮现 [复制]**（内置/自定义通用）：**新建**一个自定义条目（所有参数照抄、名称置「新建子代理」并唯一化（重名退「新建子代理2」…）、id 重摇短 UUID；来源条目保持可见）
- 损坏态：红条错误（解析失败定位）+ [打开文件修复]（源码编辑器，表单化的唯一源码逃生口）+ [删除]；fail-closed 是运行时职责，PF 保证可修

### 1.3 存储

单一事实源 = `<PF数据目录>/agents/*.md` + 项目 `<cwd>/.pi-flash/agents/*.md`；CLI `pi -e`、PF、扩展共享同一目录。Settings 页 = 表单编辑的用户面，读写该目录。

**id = 不可见短 UUID**：纯程序内调用句柄 + 文件名，agent 与用户都看不见、无含义、只需唯一（8 位小写 hex，重摇到未占用）；内置三件同样如此。**名称 = `name` 字段 = 委派点名句柄 + 显示名**：表单「名称」可任意文本（含中文），**全局唯一**（保存查重内置+自定义，撞名报错；复制体自动退「新建子代理2」…）；既有条目 id 恒定、改名不搬文件。委派时模型在 `agent` 工具传名称，运行期名称→id 解析（id 直传仍兑底）。

## 2 字段集 v1（frontmatter）

```yaml
name: 我的评审员              # 点名句柄+显示名;可中文,委派按 name 点名,
                              #   全局唯一;键省略(迁移残留) = 展示回落 id
description: 代码评审          # 列表展示
model: provider/id            # 路由;UI 首项「继承」= 键省略
thinking: medium              # 思考强度;pi ThinkingLevel 七档
                              #   off/minimal/low/medium/high/xhigh/max;
                              #   键省略 = auto = 不覆盖(落 pi 默认档)
tools: inherit                # 工具档位(044-0 六档):inherit(委派者)
                              #    / chat-only / read-only / default / full
                              #    / full+(full+ 可选 pi-ext 与 mcp 服务)
maxTurns: 100                 # 轮次预算:软限(到限 steer 收尾,超限 abort,
                              #    stopReason: max_turns);UI 五档
                              #    5 / 30 / 100 / 不限(写 0) / 指定(键省略 = 主代理
                              #    派发时给 maxloop);默认「指定」
                              #    委派级 maxloop 可覆写(优先级 maxloop > maxTurns >
                              #    config.json maxTurns > 100)
systemPrompt: |               # 替换式人格(优先于追加);走 pi
  你是代码评审员…               #    before_agent_start 的 systemPrompt override
appendSystemPrompt: …         # 追加式(与替换并存,替换优先) = 文档正文
injectAgentsMd: true          # 项目 AGENTS.md 是否注入子代理上下文(默认 true)
cwd: pf-data                  # 工作目录;唯一合法显式值 pf-data = PF 数据目录;
                              #   键省略 = 继承委派者 cwd
skills:                       # 注入的 skills,三态(键存在性是语义):
  - skill-name                #   键省略 = 继承系统开启集
                              #   裸键(下面无条目)= 关闭(内置 explorer/
                              #     summarizer 用它)
                              #   有清单 = 自定义
extensions:                   # full+ 档:挂载的 pi-ext 清单
  - path/to/ext.ts
mcp:                          # full+ 档:允许的 mcp 服务名清单
  - server-name
```

追加/替换语义对齐 pi 官方 SYSTEM.md / APPEND_SYSTEM.md 两档。

schema 已识别（两侧解析 + 非法值 fail-closed）但委派装配未消费：`inheritContextLimit`、`isolation`(worktree)。

### 2.1 未知字段透传

PF 未识别的新字段**原样透传不碰**：解析时把 v1 已知字段之外的键值原序保留（`AgentProfile::unknown`），写回时拼回 frontmatter——用户手写的高级字段不会被表单保存抹掉（`pi-link/agents.rs` ↔ 扩展 `profile.ts` 语义逐字对齐）。

### 2.2 损坏 fail-closed 与保留字段

- 损坏 profile 运行期 fail-closed（`PROFILE_INVALID`），不静默降级；PF 侧保证可修（列表红条 + [打开文件修复]，见 §1.2）
- `systemPrompt`（替换式人格）schema 保留、两侧解析，但 UI 不暴露（提示词框统一追加语义）

## 3 创建入口

- **Settings 页「自定义」组头 [新建] 表单**：手工从零建 / 列表行 hover [复制] 复制内置或自定义
- **对话创建**：让主代理直接写一个 `<PF数据目录>/agents/*.md`（frontmatter 契约即 §2 字段集）

不做包分发/分享入口（内部组件）。

## 4 数据与渲染契约

- 宿主观测**全部来自主会话**（子会话不回补主会话任何东西）：caller 交付看工具 result details，background 交付终态看 `subagent-settled` 条目 / `subagent-completion` custom 消息回灌
- 导航第三行点阵 = 导航缓存字段（与 turns 同一次构建、同一 notify 版本），由内存账本 `SubagentLedger` 投影——重开时从消息投影种子、运行中由事件增量喂，零 IO 轮询（检索层设计见 044-3）
- 不依赖扩展挂件通道（`ctx.ui.setWidget`）——面板数据由主会话消息纯内存推导，与通用扩展挂件无耦合
- 打开子会话 tab 标题 = 主会话反查 args（label → profile → prompt 首行），零读盘

## 5 已知限制

- 无跨会话/项目级范围切换（面板内切换范围）
- 面板内无 send/interrupt（走对话内控制工具 `subagent_send` / `subagent_interrupt`）
- profile 仍是 md 明文 + 表单直写该文件，无中间结构化存储层
