# 083 项目搜索（文件 + 内容）

> 参照：Zed `crates/search` + `crates/project/src/project_search.rs` +
> `crates/project/src/search.rs` + `crates/util/src/paths.rs`（基线 commit
> `4c902c9`）。**Zed 的代码直接抄**，不造自己的轮子：查询/过滤层逐字移植
> （`search/query.rs`）；「搜索文件」弹窗（`Dialog::FileSearch`）已退役，
> 三条入口（Ctrl+L / Ctrl+Shift+F / 文件树钮）统一进本面板。

## 1. 结论：Zed 不建索引（取证）

取证结论：

| 问题 | 取证 | 结论 |
|---|---|---|
| 有倒排/trigram/全文索引吗 | 全仓 grep `tantivy`/`trigram`/`inverted index`/`fts5` 零命中 | 无 |
| spawn ripgrep 吗 | `rg`/`ripgrep` 在 Cargo.toml 与 crates 内零命中 | 无（自己用 `fancy_regex` 行级扫） |
| 内容搜索怎么走 | `project_search.rs`：路径候选 → glob 过滤 → `fs.open_sync` 读盘 → `query.detect()` 找首命中 → 命中的才开 Buffer 全扫 | 纯实时扫 |
| 文件名搜索怎么走 | `file_finder.rs`：`worktree.snapshot().files()` 内存文件树 + `fuzzy_nucleo` 匹配 | 有内存路径树（**非**内容索引，重启重建） |
| 唯一像索引的东西 | `edit_prediction_context/bm25_context.rs`：BM25，**按需构建、不落盘**，只服务编辑预测 | 与用户搜索无关 |

所以「复刻 Zed 的搜索」= 复刻一条**实时扫描流水线** + 一套**结果面板版式**，不是复刻检索索引。

## 2. 逐字抄的部分（`search/query.rs`）

`crates/project/src/search.rs` 与 `crates/util/src/paths.rs` 的 `PathMatcher`
**整体移植**，只做 PF 没有对应类型导致的机械替换：

| Zed | PF | 原因 |
|---|---|---|
| `RelPath` / `RelPathBuf` | `PathBuf`（相对路径） | PF 无 rel_path 层 |
| `PathStyle` | `bool is_posix` | 同上 |
| `BufferSnapshot` + `CharKind`（整缓冲 `search`） | 不移植；扫描层逐行喂 `search_str` | PF 无 Buffer 层；`search_str` 本身就是 Zed 的函数 |

照抄带来的行为：

- 纯文本查询走 `AhoCorasick`；**非 ASCII + 忽略大小写时回退 regex**（Zed 原
  注释：aho-corasick 的 `ascii_case_insensitive` 不支持 unicode）；
- `\c` / `\C` 模式内大小写开关（`case_sensitive_from_pattern`）；
- 整词边界只在贴着「词字符」的一侧补 ``，判据是 `\B` 正则（`WORD_MATCH_TEST`）；
- `RegexBuilder::case_insensitive(!case_sensitive).multi_line(true).crlf(true)`
  —— 故依赖钉 **fancy-regex 0.19**（与 Zed 同版本；0.16 及其 builder 无 `crlf`）；
- `search_str` 的整词判定 = 前后字符是否词字符；
- `match_path` 从全路径向上逐级「先排后收」；
- `replacement_for`：`escaped` 查询字面量替换，真正则模式捕获组展开 + 把
  `\`/`
`/`	` 还原；
- glob 语义 = globset 默认（**`*` 跨分隔符**，Zed 也不设 `literal_separator`），
  这是上游行为，测试按它断言。

## 3. 与 Zed 的结构差异（为什么可以更好）

PF 合并成单阶段：**一次读盘就把「命中行 + 上下文行」一起收齐**（Zed 须两阶段——
精算必须经过 `Buffer`/`MultiBuffer` 快照），行为语义不变：

| Zed 语义 | PF 落点 |
|---|---|
| 路径候选尊重 .gitignore | `git ls-files --cached --others --exclude-standard`（与 @ 检索、文件搜索弹窗同源） |
| Scan Ignored = 连被忽略目录也扫 | `ignore::WalkBuilder` 四源全关 + 跳过 `.git` |
| include/exclude 前置于读盘 | `PathFilters::selected`，逐字移植 `SearchQuery::match_path` 的**向上逐级**判定 |
| 二进制早退（头 1KB） | `analyze_byte_content` + `ByteContent::Binary`（与文件编辑器同判据） |
| CRLF 容忍 | 逐行剥尾 `\r`（`regex` 没有 `fancy_regex` 的 `crlf(true)`） |
| 流式 + 路径序 | 后台按排序后的候选清单串行扫，逐文件回传（天然有序，无需 Zed 的乱序批次缓冲） |
| 上限 5000 文件 / 10000 命中行 | `MAX_FILES` / `MAX_MATCH_LINES`（同值），触顶发 `Limit`，计数后缀 `+` |
| 上下文 2 行、摘录合并 | `CONTEXT_LINES=2`；**相邻命中的重叠窗口并成一块**（Zed 按命中分 excerpt，PF 合并，避免同段代码重复出现） |

单线程串行是刻意取舍：磁盘随机读才是瓶颈（`git ls-files` 十万级文件也是几十毫秒量级）；
并行化留作后续优化。

## 4. 文件名与内容同面板（显示规则）

PF 把文件名与内容两条路并进同一面板，**显示规则照 Zed**：

| 命中情况 | 列表里怎么显示 |
|---|---|
| 内容命中（不管标题是否也命中） | **只显示内容组**（组头 + 摘录行）；标题命中的那份文件栏**不重复出现** |
| **只有标题命中**（内容里没有） | 显示「文件栏」：一条只有组头的条目，右侧标「文件名匹配」，点开文件首行 |

实现：路径命中在扫描前先到（顶部文件栏），内容命中流式到达时
`drop_path_only_for(blocks, rel)` 摘掉同名文件栏（纯函数，单测
`path_only_row_is_dropped_once_content_hits`）。

- 文件名命中：用**同一套查询模式**测相对路径（`CompiledQuery::hits`），命中排在结果区最前的
  独立组里，文件头右侧标「文件名匹配」，`MAX_PATH_HITS = 50` 封顶；点击即开文件首行。
- 内容命中：按路径序分组，文件头显示命中行数，摘录块逐行渲染。

## 6. 结果面板（照 Zed 截图复刻）

Zed 的结果是 `MultiBuffer` + `Block::BufferHeader` + excerpt 头尾控制钮，那套渲染
长在 `editor::Element` + `display_map/block_map.rs` 里，依赖整个编辑器内核。
PF 不复刻编辑器内核，复刻的是**同一套视觉词汇**（用户截图逐条对照）：

```
┌ 文件块（圆角卡片、1px 边框、块间 8px）────────────────────────────┐
│ ▾  AGENTS.md  目录/路径                      4 处   打开文件 Alt+Enter │ ← 组头 h28
│ 13 │   - 环境变量 `PI_FLASH_PI_BIN` …                                │ ← 行 h22
│ 15 │   - UI 验证一律走 pif-ui …       ← 命中区间 accent 22% 洗底      │
│ 16 │                                                                 │
│ ▁▁▁ （同文件另一段摘录：6px 分隔条 + 上边框）                          │
└──────────────────────────────────────────────────────────────────────┘
```

> 版式要点：
> ① 搜索框**不加 border**；② 组头底色 `bg_panel`（`bg_subtle` 是 8 位
> RRGGBBAA，`rgb()` 读会成近黑）；③ 文件块**100% 宽度**（去掉
> 外边距/圆角/边框/块间空隙）；④ 内容区**复用 editor 的渲染轮子**；
> ⑤ **排版照 Zed**：长行折行、行高 1.5、组头 = 2 行（块内 4px 留白）、行号列按
> 字号加宽、命中底色用主题中性 selection 色。

| 元素 | 值 |
|---|---|
| 文件块 | `w_full`、无外边距/圆角/边框（整宽色带，Zed 同观感）、块间靠组头上边框分隔 |
| 代码正文 | 字体族/字号 = `appearance::file_font()`（与 editor 同源）、`line_height 1.5`、`t.bg` 底、**单色正文（不做语法着色）**；**无 hover 变色** |
| 组头（文件操作栏） | **几何逐值照抄 Zed**（`editor.rs:298 FILE_HEADER_HEIGHT=2`、`editor.rs:299 BUFFER_HEADER_PADDING=rems(0.25)=4px`、`element/header.rs:733`）：块高 **= 2 行**（`header_h() = line_h()×2`）、块 `p 4`；内条 `rounded 4`（`rounded_sm`）+ **`border_1`（`t.border`）** + `bg_panel` + `shadow_sm` + `pl 4 pr 8` + `gap 6`；左起「收展钮 28×28 → 文件名（正文族/字号 MEDIUM）→ 目录（同字号 `text_muted`，`gap 2`）」。**间隙来自块内 4px 留白**：块与块之间 8px、条与自己代码行之间 4px、首条与搜索框 5px（`pt 1` + 4） |
| 键帽 | h18、`px 5`、r3、mono ui(10)、`bg_panel` + 1px 边框 + 底部 2px 硬边（`kit::keycap`） |
| 摘录行 | 行高 = `file_font.size × **1.5**`；**长行折行**（`StyledText` 原生换行，行高随内容增长，`min_h` 保底）；字号 **= 正文**、`text_faint` |
| 行号 gutter | **宽度动态算**，逐项照 Zed `Editor::gutter_dimensions`（`editor.rs:12178-12270`）：`digits = 最宽行号位数`（整个结果集取 max，同 `widest_line_number()`）→ `num = digits.max(min_line_number_digits=4) × ch_advance`（字体实测推进宽，非拍脑袋）× → 再 `+ ch_width + ch_width`（Zed 只开行号时的 left/right padding 各 1ch）。数字右对齐、`whitespace_nowrap` |
| 命中高亮 | 命中区间用主题中性 selection 色 **`bg_selected`** 作底色 + 正文 `t.text`（Zed 的命中底色同为中性色，不是 accent 洗底） |
| 上下文行 | 与命中行**同一文字色**（不降透明度） |
| 活跃命中 | **只有左缘 2px accent 竖条，不刷整行底色**（Zed 同；`‹›` 导航滚动到块首） |
| 多段摘录 | 段间 **1px 细线**（`t.border`，不占高度、不刷底色）；块与块之间**无空隙**（靠组头分段） |
| 首块间距 | 结果区 `pt 1` + 文件头块自带 `p 4` = 首条与搜索框 **5px** |
| 收展钮 | Zed `header.rs:747`：**28×28**、`rounded 2px`、悬停底 `element_selected`(= `bg_selected`)、图标 `IconSize::Small`=**14px**（展开 `chevron-down` / 收起 `chevron-right`）；**点它只收展不打开文件**（`stop_propagation`）、**不带 tooltip**。收起 = 该文件内容行不渲染（只留文件头），状态按 `rel` 记，切换时 `ListState::splice` 逼重测高 |
| 组头左侧 | 收展钮 + 文件名 + 目录；无文件类型图标（Zed `ItemSettings::file_icons` 关闭即无） |
| 组头右侧 | 内容命中组**只有名字+目录**；仅文件名命中的文件栏带「文件名匹配」标签。不显示命中计数、不显示「打开文件 Alt+Enter」 |
| 滚动条 | 结果区右缘竖向滚动条（`gpui_component::scroll::Scrollbar`，与 md 预览同款挂法：绝对定位 `top/bottom 4`、`right 4`、宽 8，列表内容已留 18px）。可滚距离 > 0 才挂；PF 全局 `scrollbar_show = Always`，故**常显**不靠悬停 |
| 空态（landing） | 照 `project_search.rs:1049-1092`：居中一列，标题（`LabelSize::Large` = **16px**）+ 副标题（**14px** muted，下留 **8px**）+ 五条「图标 + 文案」行（`ButtonStyle::Subtle`：高 **22px**、`px 4`、`gap 4`、`rounded 4`、悬停 `ghost_element_hover`、图标 `IconSize::Small`=14px）：包含/排除路径、查找并替换、正则匹配、区分大小写、整词匹配——**点行 = 点对应开关**，**不加任何快捷键徽标**。标题随相位变：idle=`Search All Files`、扫描未开始=`Loading project…`、运行中=`Searching…`、完成无结果=`No Results` + 12px 说明句 |
| 打开即聚焦 | 面板打开/快捷键重触发时，`TextInput::focus_soon` 请求在**输入框自己那一帧**兑现（内件建好当帧 `InputState::focus`，光标 blink 同帧启动）——不要用「置 flag、下一帧由面板补推焦点」的写法（光标会晚一两帧） |
| 点击 | 组头 = 打开文件首行；行 = 打开并跳到该行（`pending_jump`） |

列表 = **变高块列表**（`ListState` + `list()`，一个 item = 一个文件块）：一万个
文件时只构建视口内的块，与 md 预览同一套虚拟化机制。

**布局铁律**：结果区外壳 `results_shell` 必须自身
`flex().flex_col()`，列表子件再 `flex_1().min_h_0()`。gpui 的 `div()` 默认是
`Display::Block` 不是 flex 容器——外壳漏掉这两行时列表拿到 0 高，**整片结果区
空白但命中计数照常显示**。
`search/results.rs::tests::real_blocks_render_with_height` 是这条的回归锁：
去掉 `flex_col` 时块连 prepaint 都不会发生，测试直接红。

## 7. 数据流与生命周期

```
TextInput.on_change ──(250ms 防抖)──┐
开关/过滤器/替换动作 ───────────────┴─> Chat::search_start
                                          │ generation += 1（丢陈旧批次）
                                          │ cancel=true（旧循环尽快退出）
                                          ├─ background_spawn(run_search) ──> UnboundedSender<SearchMsg>
                                          └─ cx.spawn(前台泵)  <── 收拢批次（try_recv 排空）
                                                 └─ search_apply → rows(Arc<Vec<Row>>) → cx.notify
```

- **行模型跨帧复用**：`rows: Arc<Vec<Row>>`，追加走 `Arc::make_mut`，换代直接换新 `Arc`；
  渲染帧只克隆 `Arc`（零拷贝）——一万行的结果列表不会每帧深拷贝。
- **查询词镜像**：`SearchUi.query_text`（`on_change` 同步）。结果区空态判定、替换动作都不再读
  输入框实体，渲染路径零实体读。
- **状态住在 `WsUi.search`**（工作区级而非会话级）：切会话不丢，切项目后由 `open_project_search`
  重新发起。
- **tab 单例**：`PanelTab::Search` 在 `panel_tabs` 里至多一个；再按 Ctrl+Shift+F 只切过去并把
  焦点送回查询框（`focus_query` 请求位，渲染帧消费）。

## 8. 焦点（踩点）

搜索条输入框必须进 render 的**逐帧焦点仲裁白名单**（`Chat::search_input_focused`），否则每帧
都会被推回 composer/中性锚点，输入框点进去打不进字——与 040-1 市场搜索框、023 文件编辑器同一条
白名单纪律。`focus_query` 的消费点是「内件已建」才推焦点（`TextInput` 懒建，当帧推 fallback
句柄会造成焦点路径为空）。

## 10. 测试

`cargo test -p app search`（17 项）：查询层（字面量即字面量、AhoCorasick 路径、
非 ASCII 回退 regex、`\c`/`\C`、整词边界、CRLF `$`、`$n` 捕获组替换）、
路径过滤（向上逐级、exclude 压 include、glob 语义与 Zed 一致）、
扫描（行号、CRLF 剥尾、摘录并块/分段）、替换（按行替换、CRLF 保持、换下一处）。
