# 082 - Pi 扩展更新检测与更新

## 背景

pi 的扩展（= pi package，settings.json `packages` 条目）更新频繁，PF 要能**检测**并**更新**它们。

职责对齐：

- **pi 本体升级 = PF 发版的事**（vendored 钉版，bump vendor + VERSION + pi-link 符合性测试，用户经 081 拿新版）。
- **扩展的检测与升级 = pi 生态的内建能力**（`pi update --extensions`）；PF 不自己发明版本判断。
- **PF 只做触发壳**：检测（spawn 探测命令）+ 执行（spawn pi CLI）+ 两处 UI。

## 为什么检测是 Rust 移植而不是 SDK/RPC

| 通道 | 结论 |
|---|---|
| RPC | 协议无任何更新相关方法（`docs/agents/pi-rpc.md` 方法面实测） |
| SDK | pi-web 的 `checkPluginUpdates` 是进程内 SDK，PF（Rust）吃不到 |
| CLI | `pi update` 无 `--check`/dry-run 旗标 |

pi 的 `DefaultPackageManager::checkForAvailableUpdates()`（`core/package-manager.d.ts`）证明**检测与执行是分离的**，但其输入（settings 多层 scope、dedupe、installedPath 解析）由 SDK 私有方法维护。PF 参照 **pi-web `lib/plugin-updates.ts`** 用 Rust 重新实现检测（它同样没用 checkForAvailableUpdates，而是 `npm view` + `git ls-remote` 逐包探测），包清单直接读全局 settings.json 的 `packages`（扩展页 040 已有同源读取）。

## 检测（services/plugin_updates.rs）

对全局 `packages` 逐条，四态（pi-web PluginUpdateState 同名）：

- **unsupported**：npm 钉精确版本（`npm:pkg@1.2.3`）/ git 钉 ref / 本地路径——无法自动检测
- **error**：未安装 / 网络失败 / `PI_OFFLINE=1` / pnpm 等非标准布局读不到实装版本
- **npm 来源**：`<install>/package.json` 实装版本 vs `npm view <spec> version --json` 最新版，semver `gt`（来源带 `^` 范围时取 maxSatisfying）
- **git 来源**：本地 `rev-parse HEAD` vs `ls-remote origin <upstream>`（`GIT_TERMINAL_PROMPT=0`）
- 每包独立线程（`std::thread::scope`），单命令 10s 超时强杀
- 落盘路径复用 `pi_link::skills::package_install_dir`（npm=`~/.pi/agent/npm/node_modules/<pkg>`、git=`~/.pi/agent/git/<host>/<path>`）

**Windows 陷阱**（pi-web node-cli 同款）：PATH 上的 `npm` 是 `npm.cmd`，直接 spawn 被拒（CVE-2024-27980）——定位 `<node 目录>/node_modules/npm/bin/npm-cli.js` 用 PF 自带 node 直跑，找不到退裸 `npm`。

## 执行

复用扩展页 040 的 CLI op 管道（`mc_cli_op` 后台线程 + op 泵收尾刷新）：

- 全部：`node cli.js update --extensions`
- 单包：`node cli.js update --extension <source>`（**注意 `--extension` 与 `--extensions` 解析期互斥**，单给 `--extension` 即扩展目标）
- 完成消息提示「重启会话后生效」（扩展在侧车启动时加载）；op 泵收尾时重跑检测刷新箭头

## UI（两处提示）

1. **新会话页**（`session/new_session.rs`）：选择项目栏下方通知块——分隔线 + 可更新列表（名字 + ↑）+ 标题行右侧【更新全部(n)】。安静原则：检查中不显示、n=0 不渲染。
2. **设置·扩展页**（`settings/plugins.rs`）：
   - 列表加宽 50px（`widgets.rs` 的共享 `LIST_W` 350→400，同时作用模型/技能/MCP 页）
   - 有更新的行标签右侧 ↑
   - 列表 title 行【更新全部(n)】（无可更新不渲染；更新中转圈）
   - 详情 panel 删除 icon 左侧【更新】按钮（更新本包转圈）

## 状态与数据流

```
startup.rs 揭幕后 → Chat::spawn_plugin_updates_check
  → 后台 check_all() → aux.plugin_updates { results, checking }
      ↑ op 泵收尾（装/卸/更后）也重跑
新会话页 notice / 设置页箭头与按钮 ← 只读 aux.plugin_updates
点击更新 → PkgOp::Update(Some|None) → mc_cli_op → op 泵清零 + 刷新 + 重检
```

## 边界（v1）

- 只查**全局** scope（与扩展页 global only 对齐；项目级 `.pi/settings.json` 后续）
- 更新动作不区分 up-to-date/unsupported 包——pi 自己会跳过无可更的包
- `pi update` 默认 target 是 **self（更新 pi 本体）**，PF 永远不裸跑不带旗标的 update（vendored 钉版红线）

## 升级复核

pi CLI 旗标语义以 `package-manager-cli.js` 的 `parsePackageCommand` 为准；vendor bump 时复核 `--extensions`/`--extension` 互斥关系与默认 target（现为 self）。
