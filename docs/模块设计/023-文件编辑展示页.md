## 编辑器底座

**不语义自研，简化对齐 zed。** 文本缓冲区/光标/undo/IME 不自己写，
用 gpui-component 0.2.0（已在依赖；构建在 Zed 的 gpui 框架上的组件库，
当前 app 只用了它的 Scrollbar）Input 的 **CodeEditor 模式**：

- 多行编辑 + 行号 + tree-sitter 语法高亮（Zed 同款高亮技术）+ tab 设置
- 内置搜索弹层：搜索 + 替换，行为对齐 zed buffer search（Ctrl+F）
- 我们做的是**对齐工作**：键位、编辑行为、外观对齐 zed editor；
  砍掉 LSP、多光标、补全、悬浮文档等高级功能
- 高亮语言仅 9 种（rust/ts/js/go/json/html/markdown/zig），
  其余语言纯色显示，可接受

## 实施补记

1. **文件树点击一律进 fileView**；diff 入口收敛在 git 面板（022）。
2. **编辑器配色映射**：`appearance::sync_gpui_tokens` 补映射
   `highlight_theme`（编辑器 gutter/当前行/背景专用 token，默认停暗色盘
   ——浅色主题黑 gutter 即此）；编辑器面色覆写为应用主题 token，
   语法配色用组件内置明/暗盘。
3. **高亮语言裁剪**：vendored gpui-component 剔除 `tree-sitter-sequel`
   （cc ~1.2.1 钉版与 gpui 的 embed-resource 冲突）与 `tree-sitter-ruby`
   （parser.c 在 MSVC 下编不过）；其余 ~30 语言随
   `tree-sitter-languages` feature 启用。workspace `exclude` 补登
   两个 vendored 包（重解析时的归属检查）。
4. **注入语言高亮缓存**：`<style>`→css、
   `<script>`→javascript 的注入高亮做解析成品缓存 +
   查询按请求行裁剪（逐可见行整块 parse + 全量 query 在 118KB HTML
   上每帧 ≈8s）。计量/复核见 050 §二 与 `docs/agents/gpui.md`。
5. **html/htm 并入代码类处理器**：`HtmlKind` 删除，html/htm
   与 xml/vue 同用一个 CodeKind（ts "html"）；「浏览器项打头」差异由
   路径判据 `editor::kind::browser_openable` 决定，由
   编辑器右键菜单与文件树菜单共用（两处扩展名规则不再各写一份）。
   html 编辑器右键菜单仍首位「在浏览器中打开」。

## 默认约定（有异议再改）

- 保存 Ctrl+S；未保存修改 tab 显示脏标记圆点；关闭脏标签弹确认
- 外部改动检测（notify 已在依赖）：缓冲区无未保存修改 → 自动重载；
  有修改 → tab 标记冲突，等用户确认重载（Zed 行为）。**监听面 = cwd 递归
  watch + cwd 外打开文件按所在目录单挂非递归 watch**（Zed 为 workspace
  外文件建 single-file worktree 同款）。重载用 `reload_value`——
  保留阅读位置/光标（Zed 的外部 reload 保留 anchor；set_value 是程序化
  赋值语义，会把光标扔到文末、滚动归零）；markdown 预览同理不因块数变化
  跳回顶部，且**有未保存修改时预览渲染缓冲区**（Zed preview 读 buffer，
  不是磁盘文件）
- 二进制/超大文件（>10MB）提示不打开
- 面包屑 = 项目根相对路径段，可点击逐级导航（对齐 zed）；**工作区外文件
  退化为绝对路径，Windows 盘符前缀与根合为一段（`D:\` 一个 crumb，
  不再是 `D:` + `\` 两段）**——分段与累积路径由
  `content::breadcrumb_segments` 单一实现，渲染与自动化快照共用
- **自动回行（soft wrap）全程开启**：md 预览靠块内容段 `min_w(0)` 拿到
  确定宽度自然折行（zed markdown 同款 `min_w_0`）；源码编辑走
  vendored gpui-component 的 `soft_wrap(true)`（增量折行，未折行时仍是
  等高行快路径）

## 搜索面板

- **token 映射**：`sync_gpui_tokens` 按应用 token 映射 gpui-component 的
  `popover/popover_foreground/secondary_*`（popover 留给 tooltip/菜单；
  popover 相对 bg_panel 混 4% text 抬升——`mix_rgb(a,b,wa)` 的 wa 是
  **a** 的权重，主色放第二参）。
- **样式对齐 zed**：搜索条全宽平贴、背景
  = `editor_background()`（与上方面包屑操作栏同色，非浮卡）；搜索/替换
  输入框 Medium（32px），面板按钮 small；全部按钮加本地化 tooltip
  （区分大小写/切换替换/上下个匹配含快捷键/关闭），文案在组件
  `locales/ui.yml`，locale 随 `i18n::set_lang` 同步（繁体走组件 zh-HK
  桶）；启动时无条件 `set_lang(load_lang_pref().unwrap_or(0))`。
- **结构归位（搜索框是操作栏的一部分）**：面板不挂在编辑器 TextInput
  顶部（vendor `text_input.rs` 摘掉 `.children(search_panel)`，升级重放
  时勿漏），由 app 操作栏 `file_nav_bar` 作为第二行渲染
  （`InputState::search_panel_element()` 返回面板 Entity 元素 +
  `search_panel_open()` 控制占位）——面包屑行与搜索行同块同底色，× 与
  右侧图标列同缘，Esc 收起整行。`file_nav_bar` 为此增 `cx` 参数。
- **折叠态搜索高亮**：wysiwyg 折叠 `**` 等语法字符后，搜索/高亮 quad
  需 doc→vis 换算 + 行首游标 vis 累加（vendor element.rs，升级重放清单
  同 024 的 element.rs 项）。
- **Ctrl+F / Ctrl+H 分职**：action `SearchReplace` 绑 Ctrl+H（出搜索+
  替换两行；Ctrl+F 只出搜索行，重复按键按新意图归位）；替换行对齐
  zed——placeholder「替换为…」、Replace/Replace All 为 ghost 图标钮
  （上游 replace-all.svg 资产 + vendor IconName::ReplaceAll）；Esc 整体
  收起。
- **焦点**：app 的帧级焦点仲裁（render 每帧回收焦点给 composer）不认识
  搜索面板的输入框——它不是编辑器本体的 focus_handle。vendor 补丁：
  `SearchPanel::inputs_focused` + `InputState::search_panel_focused`
  （均在 `input/search.rs`，升级重放）；`Chat::file_editor_focus` 把
  面板持焦视同编辑器持焦。
- **图标资产**：SearchPanel 的 Aa/替换/‹/›/× 用 gpui-component 的
  `IconName`（`icons/*.svg`），上游 crate 不带 assets，宿主 app 的
  `Assets` 需补嵌 4 枚 lucide 图标（case-sensitive/replace/
  chevron-left/close，源：上游 crates/assets/assets/icons，jsdelivr 可达
  时随升级对账）。
- **编辑区右键菜单**：编辑块（复制/粘贴/剪切/全选，派发 Input 动作前先
  归位焦点）+ 文件动作块（浏览器 html/预览 md 源码态/资源管理器/终端
  所在目录 + 改名/删除回收站），样式与文件树菜单同套（menu_card/
  menu_item/menu_sep，状态槽 `Chat::editor_menu` 渲染挂 psp_overlays
  同层，右键触发在 fv-editor 容器）。vendor：编辑器内置 MouseContext
  菜单（英文 PopupMenu）摘除——Right 降级为「无选区移动光标」，宿主
  接管右键（升级重放清单：state.rs Right 分支）。自动化验证入口
  `file.context_menu`（置状态槽，与真右键同路）。
- **自动化**：`input.focus` 增 `editor` 目标（Ctrl+F 类「焦点在编辑器才

## FileTypeHandler 注册表架构

文件类型决策收口为 `editor/kind.rs` 的 **FileKind 注册表**：按后缀名注册
handler，未注册一律走默认文本 kind（TextKind）。调用点（打开路由/编辑器
配置/主体渲染/工具栏/右键菜单）零 if-else——新增文件类型 = 声明 kind 静态
量 + 注册表登记一行，框架不动。

- **handler 职责**：`editor_config`（tree-sitter 语言/软换行/025 图片粘
  贴钩子；None=无编辑器类型如图片）、`render_body`（主体渲染算法）、
  `toolbar`（默认仅搜索；仅 md 追加 eye）、`menu_file_actions`（右键菜
  单文件动作块，含分隔线；md 源码态带预览项）、
  `supports_view_mode`（双态门控，file.view_mode op 对非双态类型静默成功）
- **kind 清单**：TextKind（默认；ts "text" 纯色）/ CodeKind{语言}（txt 与
  code 是两个 kind；html/htm/xml/vue 共用 ts "html" 的那个）/
  MarkdownKind（双态，默认源码态）/ ImageKind{格式}（img() 查看器，
  无编辑器）。csv 未注册走 default
  （将来表格视图 = 纯增量注册，不再碰框架）
- **不进 kind 的路径判据**：`browser_openable`（html/htm）——「在浏览器中
  打开」只由一个判据决定，编辑器右键菜单与文件树菜单（021）共用，不再
  为它单开一个 kind
- **共享基建不管类型**（对一切已打开 tab 统一生效）：文本缓冲/脏位/自动
  保存/外部改动检测/冲突横幅/搜索面板/面包屑/焦点仲裁
- **调用点收口**：open_file_tab html 特例、file_editor_body 三分
  支、file_nav_bar eye 特例、ensure_file_editor 扩展名特判、ts_language
  表、psp_overlays 菜单 html/md 特判 → 均向 handler 询问；
  fv-*/edm-* 元素 id 与自动化 op/快照契约原样保留（file.view_mode
  的门控只影响「对非 md 文件显式调 op 后 md_source 字段不再被改写」这一
  无测试依赖的差异）

### html 打开行为

html/htm **不开系统浏览器，直接开源码 tab**（tree-sitter html 高亮、
可编辑、共享自动保存/外部改动全套基建）。「在浏览器中打开」为 html
右键菜单首位文件动作（MenuAction::Browser，与文件树菜单 021 同款）。
无 OpenRoute 路由旁路钩子——注册表当下没有需要旁路的类型，将来要用
再加。
