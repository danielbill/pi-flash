会话区（及所有 gpui List）的滚动手感与滚动性能设计。v61 落地，bead pi-flash-52q。

模块代码：vendor/gpui/src/elements/list.rs（手感层）、text_system/line_layout.rs（排版缓存层）、session/chat_list.rs（钉顶状态机，见 032）

## 背景：pi-web 对照结论

pi-web **没有自己写滚动物理**——"减速缓停"是 Chrome 合成器原生
ScrollAnimator（每格滚轮触发 ~250ms 缓出曲线动画）。pi-web 自做的是围绕
它的配套：scroll anchoring、分页懒加载（50 条/页）、`scroll-behavior:
smooth` 程序化滚动。

gpui 0.2.2 原生行为：滚轮 delta **直接**加到滚动位（一格一跳、零动画），
且 LineLayoutCache 只有**两帧滑动窗口**——滚出视口的条目 shaped 布局两帧
即被清除，滚动中每条重进视口 = 整块重新排版。内容一多即卡，即此二因。

## 一、滚动手感层：指数减速平滑滚轮

位置：`elements/list.rs`，`SmoothScroll` + `begin_smooth_scroll` /
`advance_smooth`。

- **路径分流**（List::paint 滚轮 handler）：非 precise delta（notched
  滚轮，Windows 上全部滚轮事件）走动画；precise delta（触摸板，macOS
  trackpad）保持原生直滚（OS 自带惯性）。
- **动画模型（v61-2 重写，Zed `gestures.rs` fling 同源）**：轨迹是时间的
  **闭式函数**——`position(t) = 起点 + 距离 × 缓出样条(t/时长)`，样条即
  AOSP `OverScroller.SplineOverScroller` 的 SPLINE_POSITION（Zed Apache-2.0
  转录，100 等分采样 + 线性插值）。与帧节奏**完全解耦**：掉帧、帧间隔抖动
  都不产生轨迹误差；时长有限、t=1 精确归零，无渐近爬行尾。
  旧指数逼近法（v61~v61-1，`τ` 时间常数）两因「不丝滑、总有点卡」：
  起步速度 ∝ 剩余距离 → 每格滚轮首帧只走 ~13%（发闷）；收尾每帧亚像素
  爬行百来 ms（150% DPI 下肉眼可见的顿挫）——已废弃。
- **分段重启（Chrome ScrollAnimator 同款）**：滚轮事件只把本次像素量
  **累计进绝对像素 target**，并从当前实际位置**重启轨迹段**滑向新 target，
  时长 = 剩余距离 / 巡航速度（钳上下限）——连续快滚保持巡航速度，停手后
  一段定长减速精确停住。每帧在 `List::prepaint`（prepaint_items 之前，本帧
  即按推进后位置绘制）由 `advance_smooth` 闭式求值推进。
- **语义零分叉**：推进复用 `StateInner::scroll()` 全语义——钳制、贴底胶水
  （Bottom 对齐 logical=None）转换、scroll handler 触发、cx.notify，与原生
  直滚完全一致。上层（钉顶/垫片/at_bottom）无感知。
- **程序化定位取消动画**：`scroll_to` / `scroll_to_reveal_item` /
  `set_offset_from_scrollbar` / `reset` 置 `smooth = None`。
- **帧驱动**：动画未结束时 prepaint 里 `window.request_animation_frame()`
  自续；事件派发期只 `window.refresh()` 起步。Windows present 为
  `Present(0)`（与 Zed 一致，无垂直同步），平滑靠「轨迹按时间戳闭式求值
  + DWM 合成节拍取最新帧」实现，重绘耗时须压在合成间隔内（性能层三缓存
  即为此）。

### 参数（list.rs 顶部，调手感只动这里）

| 常量 | 值 | 含义 |
|---|---|---|
| SMOOTH_CRUISE_PX_PER_SEC | 1400 | 轨迹段平均速度：时长 = 剩余距离/此值；越大快滚越快 |
| SMOOTH_MIN_DURATION_SECS | 0.18 | 单段时长下限：单格滚轮（~100px）保持完整减速曲线，不按 1400px/s 算出 70ms 急促段 |
| SMOOTH_MAX_DURATION_SECS | 0.7 | 单段时长上限：长滑行不无限拖尾 |
| SMOOTH_WHEEL_LINE_PX | 33 | 平滑路径行高换算：33px × 系统 3 行/格 ≈ 100px/格，对齐 Chrome（通用路径 20px/行 = 60px/格） |

手感调参：滑行不够长 → MIN/MAX 时长 ↑；跟手变肉 → CRUISE ↑ 或 MIN ↓；
单格距离 → SMOOTH_WHEEL_LINE_PX。

### 陷阱（勿当 bug 修）

- `request_animation_frame` 内部 `current_view()` 带 paint/prepaint 断言，
  **事件派发期调用会 panic**——事件期只能 `refresh()`。
- 滚轮 handler 必须传**本次事件**的像素量（非 paint 期累计值）：target 是
  绝对位，动画中多事件各自累加；paint 捕获的 scroll_top 只在动画起步用一次。
- 宽度变化帧条目高度全部失效（sum height ≈ 0），按它钳 target 会误跳——
  advance 跳过宽度变化帧。
- 复用 scroll() 推进 = 每帧触发 scroll handler（is_scrolled=true）→
  ChatList 滚轮退役锚点语义自动保持。

### 与钉顶状态机的配合（chat_list.rs）

钉顶期滚轮 → 动画首帧 scroll → handler 退役锚点（request_detach）→ 下一帧
渲染 take_frame_sync 卸垫片 → scroll_max 骤降 → target 重新钳到新上限 →
「内容整块下落」从瞬跳变**平滑滑落**。内容短于视口时 scroll_max=0 无法动画，
维持原生瞬跳（贴底胶水语义，不变）。

## 二、性能层：三缓存

### 1. LineLayoutCache 存档层（text_system/line_layout.rs）

- 问题：两帧滑动窗口 → 滚动重进条目 = 数百行重新 shape（大 markdown 轮块
  单帧 5-30ms）。最新 Zed 也是两帧设计（编辑器靠自有 wrap map 不受害）。
- 方案：新增 `archive: ArchiveCache`（48MB 字节预算、插入序驱逐）。
  `finish_frame` 把掉出两帧窗口的布局**沉降**入档而非丢弃；查找路径
  current → previous → archive 三级回退，命中搬回 current（预算内重新沉降
  时自然刷新插入位，近似 LRU）。
- 字节估算 16B/字符 + 512B 常数；重复沉降覆盖不重复记账，order 陈旧 key
  驱逐时跳过（total_bytes 在查找搬回时已扣减，无下溢）。

### 2. markdown 解析缓存（app/markdown.rs `cached_blocks`）

- 问题：List 每帧对可见条目重建元素树，pulldown-cmark 每帧白打（大消息
  数百 µs～ms）。
- 方案：key =（FNV-1a 8 字节块哈希, 源文长度, html 标志），命中后**全等
  校验**防碰撞；线程局部 VecDeque 128 项 LRU，值 Rc<Vec<MdBlock>> 渲染期
  零拷贝。流式末条每 delta 一变 → 命不中也只是队头轮换，不影响他条命中。
- 只缓存解析（src+html 决定），不缓存渲染（streaming/theme/字体每帧可变）。

### 3. 图片解码缓存（app/session/messages.rs `decode_image_cached`）

- 问题：base64 图每帧重走解码 + `Image::from_bytes` 内容哈希（几百 KB =
  ms 级）。
- 方案：key =（哈希, 长度, ImageFormat），64 项 LRU；**Err 同样入缓存**
  （坏数据不反复重试）；`Image.bytes` 公开字段保住 MAX_IMAGE_BYTES 校验。

## 四、调参指南（肉眼验收口径）

- 滑行不够长 → SMOOTH_MIN/MAX_DURATION_SECS ↑
- 快滚不够快 → SMOOTH_CRUISE_PX_PER_SEC ↑
- 跟手变肉 → SMOOTH_MIN_DURATION_SECS ↓（单格响应更脆）
- 单格距离 → SMOOTH_WHEEL_LINE_PX（33 ≈ Chrome 100px/格）
