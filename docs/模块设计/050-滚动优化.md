# 050 滚动优化

会话区（及所有 gpui List / 编辑器）的滚动手感与滚动性能设计。

模块代码：`vendor/gpui/src/elements/list.rs`（List 滚轮路径）、
`vendor/gpui/src/text_system/line_layout.rs`（排版缓存层）、
`session/chat_list/`（钉顶状态机，见 032）、`vendor/gpui-component/src/input/`
（文件编辑器路径）。

## 零、滚轮：原生直滚（Zed parity，勿再加动画）

Zed 全仓没有滚轮平滑动画：编辑器滚轮收到 delta 后直接改 scroll 位置，gpui 的
`List` / `div().overflow_scroll()` 同样把 delta 直加到滚动位。**「丝滑」来自
帧时间 ≤ 一帧（一帧预算 16.7ms），不是缓动。**

滚轮不做动画：动画与 Zed 行为不一致，而且在 debug 构建下（每帧 50ms+）无论
怎么调参都不丝滑——动画只是把掉帧摊开。手感问题请改帧时间，不要再往滚轮上
加动画。手感/帧时间一律以 `target/release/pi-flash.exe` 判（release 才是 Zed
那一档），dev 构建只用于迭代。

## 一、性能层：三缓存

### 1. LineLayoutCache 存档层（vendor/gpui/src/text_system/line_layout.rs）

- 问题：两帧滑动窗口 → 滚动重进条目 = 数百行重新 shape（大 markdown 轮块
  单帧 5-30ms）。
- 机制：`ArchiveCache`（48MB 字节预算、插入序驱逐）。`finish_frame` 把掉出
  两帧窗口的布局**沉降**入档而非丢弃；查找路径 current → previous → archive
  三级回退，命中搬回 current（预算内重新沉降时自然刷新插入位，近似 LRU）。
- 字节估算 16B/字符 + 512B 常数；重复沉降覆盖不重复记账，order 陈旧 key
  驱逐时跳过（total_bytes 在查找搬回时已扣减，无下溢）。

### 2. markdown 解析缓存（editor/markdown/cache.rs `cached_blocks`）

- 问题：List 每帧对可见条目重建元素树，pulldown-cmark 每帧白打（大消息
  数百 µs～ms 级）。
- 机制：key =（FNV-1a 8 字节块哈希, 源文长度, html 标志），命中后**全等
  校验**防碰撞；线程局部 VecDeque 128 项 LRU + 32MB 源文字节预算（超预算
  从头驱逐），值 Rc<Vec<MdBlock>> 渲染期零拷贝。
- **流式解析门**（`STREAM_PARSE_GATE`）：流式末条源文每 delta 一变 → LRU
  恒 miss → 每帧全量重解析 O(已流式字数)。门内（150ms）源文是上一棵树的
  前缀增长（append-only 流式）时直接复用上一棵解析树——显示滞后 ≤150ms
  （与 spinner/t-s 徽章刷新粒度一致）；非前缀（换块/截断）立即重解析并
  换门内容：交替流式块退化为原行为，只慢不错。
- 只缓存解析（src+html 决定），不缓存渲染（streaming/theme/字体每帧可变）。

### 3. 图片解码缓存（session/messages/images.rs `decode_image_cached`）

- 问题：base64 图每帧重走解码 + `Image::from_bytes` 内容哈希（几百 KB =
  ms 级）。
- 机制：key =（哈希, 长度, ImageFormat），64 项 LRU + 128MB 字节预算（源串
  + 解码后字节合计；条目数上限只防碎片）；**Err 同样入缓存**（坏数据不反复
  重试）；`Image.bytes` 公开字段保住 MAX_IMAGE_BYTES（10MB）校验。

## 二、编辑器路径（大文件）的每帧成本

`vendor/gpui-component` 的 CodeEditor 每帧只建可视行，其中三处为闭式实现
（**未折行**时行高恒定；fileView 编辑器默认 `soft_wrap(true)`，一旦有行被折
即自动落回线性可见区间路径）：

- `calculate_visible_range`：可见首行 = `(-scroll_top)/行高`（Zed PositionMap
  同款闭式），不再从第 0 行累加行高；
- `layout_cursor`：光标/选区 y = 行号 × 行高，不再从第 0 行扫到光标；
- `scroll_to` / `offset_to_display_point` / `display_point_to_offset`：同款闭式；
- 行高吸附整设备像素（`snap_line_height`）：非整倍显示缩放下 1.5× 字号的
  小数行高会让滚轮步进落在小数设备像素上、整屏亚像素抖动发虚；吸附后所有行
  的 y 都落在整设备像素（request_layout/prepaint/paint 三处用同一份纯函数）；
- 打开大文件：`text` 语言不再建 tree-sitter parser（Zed：无语言 = 无语法树）、
  不软换行时不再逐行 materialize 行文本；
- 全文灌入（打开/watcher 重载）走 `set_value` 专用 reset 路径：不再进
  「utf16 全文统计 → replace_text_in_range → InputEdit」编辑管线（4.6MB
  双程字符迭代 ≈48ms），直接换 Rope + `text_wrapper.reset`（单行保留原
  管线：mask/validate 是单行特性）。TextWrapper 重建零物化：
  `LineItem.line: Rope` → `len`、行迭代用 `RopeSlice::lines(LF)` 流式、
  `wrapped_lines` 收成 `SmallVec<[Range;1]>`（不软换行恰 1 段零分配）；
  Change 脏比较用 Rope==String 零分配比较（原 value().to_string() 每次
  编辑全文物化）；目录树点已开文件只切 tab 不重读（外部改动由 watcher
  disk_sig 兜底）；
- composer 每帧 `state.value()` 全文物化改 Rope==String 零分配比较
  （composer_input.rs，同脏比较套路）。
- 代码语言大文件的语法树全量重建（`SyntaxHighlighter::new` 的 Query
  编译 + 首次全文 parse）转后台线程，完成后整树换入 + 重绘（Zed reparse
  同款：主线程只留增量小 parse）。阈值 `BG_PARSE_MIN_TEXT_LEN` 256KB，
  之下的文件维持同步（数 ms 与增量同级）；在飞期间不重复 spawn，完成时
  比对文本（ropey eq）没变才换入，变了作废并以下一帧文本重发；语言切换
  /全文 reset 递增纪元（`bg_parse_epoch`）作废旧成果。`text` 语言维持
  完全不建树。
- HTML/XML 的**注入语言高亮**（`<style>`→css、`<script>`→javascript）不再
  逐行整块 parse：`handle_injection` 的解析成品按 (语言, 注入节点范围) 缓存
  （宿主文本变一次才重做，`update()` 换文本时整表清空），每次查询再用
  `set_byte_range` 裁到该请求行在注入内容里的字节段。病根是
  `highlight_lines` 逐可见行调 `styles()`，而原实现每次调用都整块
  `parser.parse` + 整树全量 query——118KB 设计稿 HTML（32KB `<style>`）
  每帧 ≈8s，UI 线程被占死（连 `file.open` 复用分支都要 9s 才返回）。
  代码：`vendor/gpui-component/src/highlighter/highlighter.rs`
  （复核点与"为什么只能 pif-ui 实测"见 `docs/agents/gpui.md`）。

性能预算（release 构建实测口径）：逐页翻帧时间 ≈12ms 均 / 20ms 峰（≈80fps，
深浅页同量级，O(滚动深度) 已消除）；4.6MB/80k 行 txt 打开 0.6s(release)；
`set_value` 首开/重载 ~25ms、脏比较 ~1ms；目录树切回已开文件 0（复用不重读）；
118KB 注入高亮 HTML 开文件后 `app.info` ~0.18s；utf16↔offset 换算 O(log N)
（ropey 树内，打字路径无 O(偏移) 问题）。
