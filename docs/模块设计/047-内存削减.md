# 047 - 内存削减

> 上位：AGENTS.md 铁律「快是第一卖点」；来源：2026-11-12 全仓内存审计（多路静态审计 + 行级复核）。
> **量级数字均为静态估算，未经运行时实测**——落地时以 §4 度量口径的前后实测为准。

## 0. 背景与目标

审计结论：PF 内存基线良好——四大图片缓存全部预算化（合计封顶 ~256MB）、消息/文件树/搜索三列表全虚拟化、流式三层节流、空闲 600s 退役、尾窗 2MB 封顶、图标编译期嵌入不占运行时堆。

剩余削减空间集中在两类：

1. **无界路径**：事件通道无界 + wire 事件携带大 Value 死重；叶链修复全史 Value 驻留；`count_message_entries` 整文件 read；`system_msgs` 无限追加；pfctx/Scanner/model_price 等缓存无上限；node 侧车无堆上限。
2. **双份持有 / 无淘汰**：编辑器 `content: String` 与 InputState Rope 同内容双份；`file_cache` 无 tab 数上限；终端 tab 数无上限且隐藏 tab 不释放。

目标：消除无界路径、给常驻结构加上限、给进程加护栏。**不改变行为语义**（消息完整显示、pi-web parity、并发监控卖点均不动摇）；所有改动不引入热路径同步重活。

## 2. 设计原则

1. **缓存必预算化**：条数上限 + 字节预算双保险，范式照抄 §1.1（推荐样板 `editor/markdown/cache.rs:16`）。
2. **事件 move 不 clone**：Value 子树所有权化，解析路径任何 `v.clone()` 都要有存在理由。
3. **后台读必有界**：全量读文件必须走前缀/尾窗/字节门（先例 `read_tail_messages` 2MB 封顶）。
4. **上限放软不放硬**：soft cap 超限放行并留痕，不硬拒用户操作（脏 tab、活跃会话永不逐出）。
5. 铁律对齐：热路径改动带 `[mem]`/`[perf]` 实测数字（§4）。

## 3. 开发计划

里程碑总览：**P0 快改批**（7 项，低风险，半天级）→ **P1 协议层**（6 项，收益最大，pi-link 测试护驾）→ **P2 进程与资源上限**（3 项，含 UX）→ **P3 实验项**（独立分支带实测）。每项独立 commit；开工先 `bd prime` 对齐协议，逐票推进。

- 验收：二进制体积 + 启动时间（对齐「快是第一卖点」验收口径）；编译时间上涨可接受范围内拍板。

## 4. 度量与验收

1. **`[mem]` stderr 周期打点**：debug 构建每 30s 打 working set（对齐 `[perf]` 计时先例，实施时看现有打点怎么取数）；发版零输出纪律同 dev-flags。
2. **洪泛会话 fixture**：`tmp/` 下生成脚本（不入库）——50MB 级 JSONL：交替 `type:message` 条目 + 数 MB 单行 tool 输出 + 错链/环形样本。
3. **对比口径**：pif-ui 自动化同一脚本（启动 → open_session(洪泛会话) → snapshot → 流式注入 → 全局搜索一次）前后各跑 3 次取 working set 峰值/稳态；P0 多数项影响的是瞬时峰值而非稳态，按项标注口径。
4. 每项 commit 描述带前后数字；`cargo test` 全绿才提交。

## 5. 暂不做清单（含理由）

| 项 | 理由 |
|---|---|
| 事件 delta 合并 | pump 30ms 批窗已够，合并语义复杂无必要 |
| undo 字节预算 | 需动 vendored gpui-component `history.rs`，触发罕见（10MB 文件 replace-all） |
| 编辑器 String/Rope 单源化 | 需动 vendored InputState 契约，成本高；P2-2 的 tab cap 已封总量 |
| `models_by_cwd`/`project_ctx`/`tree_memory` 切项目对账 | 总量 <10MB，不值得引入失效复杂度 |
| 终端 scrollback 可调设置 | 动 app_settings + 设置页，收益存疑；cap 16 已封总量 |
| sessions/search 16MB 整读改 seek 分段 | 峰值 16MB 可控、顺序处理读完即弃 |
| model_price 兜底取任意陈旧条目（`:347`） | 正确性 bug 非内存项，另行小修 |
| `get_messages` 大响应行（全会话单行 Value） | pi 侧行为，P1-1/P1-2 已削 app 侧峰值；根治需 pi 侧分页，超出本模块 |
