# 047 - 内存削减

> 上位：AGENTS.md 铁律「快是第一卖点」。本文是**现行内存设计说明**：源起一次
> 全仓内存审计，其所列无界路径与无上限常驻结构均已落地为现行机制（§1.2/§3）。

## 0. 背景与目标

PF 内存基线：四大图片缓存全部预算化（合计封顶 ~256MB）、消息/文件树/搜索三列
表全虚拟化、流式三层节流、空闲 600s 退役、尾窗 2MB 封顶、图标编译期嵌入不占
运行时堆。审计发现的削减空间——无界路径（事件通道/整文件读/无限追加/无上限
缓存）与双份持有/无淘汰（编辑器双份、file_cache、终端 tab）——已按 §2 原则
全部处置。不变量：**不改变行为语义**（消息完整显示、pi-web parity、并发监控
卖点均不动摇）；热路径不引入同步重活。

## 2. 设计原则

1. **缓存必预算化**：条数上限 + 字节预算双保险，范式照抄 §1.1（推荐样板
   `editor/markdown/cache.rs` 的 LRU+字节预算）。
2. **事件 move 不 clone**：Value 子树所有权化，解析路径任何 `v.clone()` 都要有存在理由。
3. **后台读必有界**：全量读文件必须走前缀/尾窗/字节门（先例 `read_tail_messages` 2MB 封顶）。
4. **上限放软不放硬**：soft cap 超限放行并留痕，不硬拒用户操作（脏 tab、活跃会话永不逐出）。
5. 铁律对齐：热路径改动带 `[perf]` 实测数字（§4）。

## 3. 上限与预算补充说明

§1.2 总表各行的关键取舍：

- `count_message_entries`：needle 是 compact JSON 片段，JSONL 每行一个完整
  JSON，needle 不跨行——逐行扫描与整文件扫描严格等价；字节级上界、假阳性容忍
  的函数头语义保留（假阳性代价 = 一次全量叶链重读）。
- 扩展阻塞件保护窗对齐通用空闲退役阈值（600s）：保护窗是「parked toast + 侧栏橙点
  召回用户」的注意窗；超过一个空闲周期未兑现 = 泵死扩展或用户已放弃，事件随
  runtime drop 丢失（pi 侧 pendingExtensionRequests 语义本就不保证送达）。
  任务会话跳过保护窗：无输入通道，阻塞件永远无人兑现。单测
  在 `session/runtime/ext_queue_ttl_tests.rs`（闸本体在 `session/recycle.rs`）。
- `read_leaf_messages` 的 `LEAF_REPAIR_MAX` 保持 `usize::MAX`（长度竞赛语义：
  修复链必须长于截断的 RPC 快照才能赢）。
- reader 白名单遗漏 = 功能静默失效，新增 WireEvent 消费点须同步
  `wire_event_allowed`（pi-link 单测钉住）。
- 编辑器逐出顺序以 tabs 域有序列表为准（`file_cache` 是 HashMap 无序）；
  `TABS_SAVE_CAP=32` 恢复带独立不受影响。
- 终端隐藏 tab 不释放 PTY/线程是有意设计（并发监控卖点），cap 只顶进程数。

## 4. 度量

- **`[perf]` 打点**：`PI_FLASH_PERF=1` 门控输出——app 启动阶段与每帧渲染分段
  计时（`main.rs`）；pf-context 的 `settings.load` / `settings.flush` µs 进
  pfctx.log。
- `[mem]` 周期 working-set 打点未实施；洪泛会话 fixture 未沉淀为入库用例。

## 5. 已知边界

| 边界 | 理由 |
|---|---|
| 事件 delta 合并不做 | pump 30ms 批窗已防主线程冻结，合并语义复杂无必要 |
| undo 无字节预算 | 需动 vendored gpui-component `history.rs`，触发罕见（10MB 文件 replace-all） |
| 编辑器 `content: String` 与 Rope 双份 | 需动 vendored InputState 契约，成本高；tab soft cap 64 已封总量 |
| `models_by_cwd`/`project_ctx`/`tree_memory` 无切项目对账 | 总量 <10MB，不值得引入失效复杂度 |
| 终端 scrollback 固定 8000 行 | 可调需动 app_settings + 设置页；总量已被 tab cap 16 封住 |
| sessions/search 16MB 整读 | 顺序处理读完即弃，峰值可控 |
| 无 mimalloc 全局分配器 | 需独立分支 + 同负载实测对比 |
| release profile 未配 lto/strip | 需启动/体积实测权衡 |
| model_price 网络失败兜底取任意陈旧条目 | 正确性 bug，非内存项（`resolve` 兜底 `values().next()` 可能取到陈旧价） |
| `get_messages` 大响应行（全会话单行 Value） | pi 侧行为；根治需 pi 侧分页，超出本模块 |
