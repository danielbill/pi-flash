# 042-1 模型管理（现状设计）

目标：**pi 的文件是唯一真相源**——`~/.pi/agent/auth.json`（凭据）+ `~/.pi/agent/models.json`（provider/模型）。写这两个文件的语义照抄 pi-web（含 proper-lockfile 同款锁协议与 `chmod 0600`）。

## 1 两条铁律

1. **用户自己写的内容不看、不改、不删**——`models.json` 与 `auth.json` 里非 PF 标记的内容一律只读。
2. **PF 保存的 apikey 只进系统钥匙库**，盘上永不落明文；pi 通过 `!command` 在请求时取回。

## 2 凭据模型

PF 写入 `auth.json` 的条目：

```json
{ "deepseek": { "type": "api_key", "key": "!pf-secret get deepseek" } }
```

- 标记判据：`type == "api_key"` 且 `key` 以 `!` 前缀 + 含 `pf-secret`。**标记 = 来源判据**（人工不可能手写该命令形态）：有标记 = PF 创建的条目。
- 秘密只存钥匙库（条目名 `env_var_name(provider)`）；pi `AuthStorage.read()` 走 `resolveConfigValue` 的 `!` 分支取回；命令失败 = 该商未配置。
- 换 key 后需**重开会话**生效（pi 的 `commandResultCache` 进程级）。

| 动作 | 规则 |
|---|---|
| 保存 key | 钥匙库写入 + 读回校验 → 锁内写 `auth.json` 标记条目 → 失败回滚钥匙库。目标条目非 PF 标记时先弹覆盖确认 |
| 移除 | 只删 PF 标记条目 + 钥匙库条目；非标记条目不碰。oauth 归 pi，一律不动 |
| 预填掩码 | 标记条目从钥匙库解出掩码；明文条目展示掩码。只读 |

## 3 模型列表管理（2026-11-01 定稿）

**列表 = 展示层，models.json = 用户勾选。**二者分离：

| | 模型列表（罗列）来源 | models.json 写入 |
|---|---|---|
| 内置 Provider | pi 自带注册表（`registry-cache.json` 静态 `models[]`，**无需 apikey**）∪ 进程答案 / models-store 目录 | **零写入**——pi 静态注册表即持久态；勾选只写 `enabledModels` patterns（pi `settings.json`，available 门） |
| 自定义 Provider | 骨架常驻 models.json；模型**完整定义**（自动拉取 / 手填 / 手调参数）存 PF 侧 **`~/.pi-flash/custom-provider.json`**（清单仓）；列表 = 仓内全部条目 | 勾选 on → 仓里的定义**原样复制**进 `models[]`（缺 api/baseUrl 由骨架补齐）；off → 只删 models.json 投影，**定义留仓**（off/on 往返不丢参数）；`models[]` 空则骨架保留 |

- 罗列单点：`settings/models.rs::provider_models_for_list`（账本 ∪ 目录 ∪ registry 静态 ∪ 清单仓，按 id 去重）。静态/仓**不进** `catalog_for`/`Globals.models`（picker 非虚拟化，性能铁律）。已配置凭据的内置商经 `catalog_with_ledger` 并入静态——否则其模型不在 `mc_refs`、勾选链静默丢弃。
- 清单仓写入点（`services/custom_models_store.rs`）：探测 Ok（**只补缺不覆盖手调**）/ 模型详情保存（恒写仓；已勾选的同步 models.json）/ 手填 +模型（显式创建 = 勾选，仓 + models.json 双写）/ 模型详情【移除】（仓 + models.json 同删）/ 删商（整条目删）/ 改名（键搬家）。**不是 051 账本复活**：pi 仍只读 models.json，仓不参与注册、不注入、不碰凭据。
- 勾选双写：`mc_toggle_model` = enabledModels patterns + 自定义商物化/移除投影（内置商不物化）。
- 侧栏成员资格：内置商 = 有凭据（移除凭据即出列，models.json 覆盖条目不构成成员）；自定义商 = models.json 有条目。
- 内置商「获取模型/刷新」钮：**隐藏不删**（`Chat::BUILTIN_FETCH_UI = false`）；`mc_probe_start` 只做保存 key 后的连通检查，不落目录。
- 探测端点单源 = registry dump 的 SDK baseUrl/api（`registry::models_list_target`）；探测链见 `pi-link/probe.rs` 三模块（①api type 判定 ②连通 ③拉目录，**不得写死任何厂商/模型名**）。

## 4 热路径约束

- 启动不做钥匙库 / `auth.json` 写入；registry dump、sweep 均在揭幕后后台执行。
- 写 `auth.json` / `models.json` / 清单仓只在用户动作或后台回写时发生；渲染路径只读内存镜像（`CfgUi.mj_probe_cache`）。

## 5 测试钉子（pi-link 符合性）

1. 临时 HOME 写一条 `!cmd` 凭据 → pi 判「已配置」（`pi auth check --json` ready）；helper 缺失 → not ready。
2. `ReadOnlyAuthStorage` 不执行 `!command`（元数据读取不触发 shell）。
3. 锁协议：PF 写入与 pi 并发写不互相覆盖（OAuth 轮换场景）。
4. `models.json` 不可读时保存被拒（不覆盖）。

## 6 已知不满足项（明示，不当 bug）

- 跨机 / 远程使用 pi-web 时，PF 管理的商显示「未配置」（钥匙库与 helper 不在场）。
- helper 随安装目录走：auth.json 指向的 helper 不存在时该商失效。
- 会话进程在自定义商创建/修改**之前** spawn 的，models.json 的变更（新商 / 勾选 / key）要**重开会话**才生效（pi 每会话装载一次）。

## 7 受保护改造（**不改**）

只允许换数据源（`mj_doc()` / `mj_write()` = models.json），不改布局 / 交互 / 字段语义：

1. 自定义 Provider 详情页（`mj_provider_editor`）。
2. 模型详情页（`mj_model_modal_overlay`，500×500 弹窗）。
3. 自动填参（`mj_catalog_fill` → `pi_link::openrouter`）：数据源 OpenRouter；填参**只进表单**（`mj_fill_entry`），名称/价格在【保存】时补进模型落盘。

`input` 只允许 `text` / `image`（pi `MODEL_INPUT_MODALITIES` 仅此两项；多写会让整份 models.json schema 校验失败）。

### 7.1 填参检索键：家族名 id → 版本名检索

官方 /models 的 id 常是**家族名**（`deepseek-flash`），版本信息只在 name（`DeepSeek-V4.1-Flash`）。OpenRouter 对家族名常只有「-latest」别名聚合条目（参数失真），版本名才有具体型号：

| 目录条目 | ctx | maxTokens |
|---|---|---|
| `~deepseek/deepseek-flash-latest`（别名） | 1048576 | **943718** |
| `deepseek/deepseek-v4.1-flash`（具体） | 1048576 | **393216** |

铁律：**只换查询键，不换字段值**。`model_ref::query_candidates(id, name)` 产出 `[官方 id, slug(name)]`，`openrouter::resolve_many` 具体型号优先于别名；落盘 id/name 恒为官方列表值。账本匹配（点列表行开详情）先精确 id，兜底只认 **id**（唯一才认，name 绝不参与——账本 name 是显示字符串，曾因此串行）。
