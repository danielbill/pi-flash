## 2 不变量（两条铁律）

1. **用户自己定义的明文不看、不改、不删**——`models.json` 与 `auth.json` 里非 PF 标记的内容一律只读。
2. **PF 保存的 apikey 只进系统钥匙库**，盘上永不出现明文；pi 通过 `!command` 在请求时取回。

推论：PF 只写/只删**带自己标记**的条目（§3.1）。

## 3 凭据模型

### 3.1 标记与形态

PF 写入的条目：

```json
{ "deepseek": { "type": "api_key", "key": "!pf-secret get deepseek" } }
```

- 标记判据：`type == "api_key"` 且 `key` 以 `!pf-secret get ` 开头。
- 秘密只存在钥匙库（条目名沿用 `env_var_name(provider)`）。
- 依据：pi `AuthStorage.read()` 对 api_key 的 key 走 `resolveConfigValue`，`!` 前缀即“执行命令取 stdout 作为 key”；命令失败 = 该商未配置（不会把命令串当 key 发出）。
- helper：`pf-secret` 独立小二进制随安装分发，形如 `!<install-dir>/pf-secret.exe get <provider>`（Windows 走 Git Bash `bash -c`，路径用正斜杠 + 单引号）。
- 换 key 后**需重开会话生效**（pi 的 `commandResultCache` 是进程级），与既有 env 注入语义一致。

### 3.2 写 / 删 / 展示

| 动作 | 规则 |
|---|---|
| 保存 key | ① 钥匙库写入 + 读回校验 → ② 锁内写 `auth.json` 条目 → ③ 失败回滚钥匙库。目标条目**非 PF 标记**时先弹确认“该商已有你手写的凭据，覆盖？” |
| 移除 / 断开连接 | 只删 PF 标记条目（类型+标记双守卫）+ 删钥匙库条目。非标记条目：不删、不报错，提示由用户自行维护 |
| 详情页预填掩码 | 非标记明文条目 → 展示该值掩码；PF 标记条目 → 从钥匙库解出掩码。只读 |
| 失效校验 | 启动/打开设置页时校验：标记条目指向的 helper 存在、钥匙库条目在。对不上给明确文案，不静默 |

OAuth（订阅）条目归 pi，PF 永不写。

### 3.3 迁移器（可选、非承重）

历史 PF 账本 → 钥匙库 + 标记条目。允许慢/允许失败/可重复跑；每条改写后自校验（`pi auth check --provider X --json` 必须 ready），失败即回滚该条。不跑也一切正常。

## 4 模型/provider 模型

- 自定义 provider/模型全部写 `models.json`：**整份草稿保存**，文件存在但读不出来 → 拒写（pi-web `ModelsConfigReadError` 同款守卫）。
- 模型清单来源收敛为：pi 进程答案（`get_available_models`）优先，冷启动回落到磁盘（`models-store.json` + `models.json`）——不再有 registry dump / 静态目录保底。
- 白名单 `enabledModels` 语义保留（写 pi `settings.json`），对齐 pi-web `enabled-models`。
- 移除 `app-settings.json` 的 `removed_providers` 墓碑：移除 = 删凭据 + 从 `models.json` 删该商。

## 5 热路径约束

- 启动不做任何钥匙库/`auth.json` 写入；迁移器后台低优先级。
- 写 `auth.json` / `models.json` 只在用户动作时发生（保存/移除/新增 provider）。

## 6 测试钉子（pi-link 符合性）

1. 临时 HOME 写一条 `!cmd` 凭据 → pi 判“已配置”（`pi auth check --json` ready）；helper 缺失 → not ready。
2. `ReadOnlyAuthStorage` 不执行 `!command`（元数据读取不触发 shell）。
3. 锁协议：PF 写入与 pi 并发写不互相覆盖（OAuth 轮换场景）。
4. `models.json` 不可读时保存被拒（不覆盖）。

## 7 已知不满足项（明示，不当 bug）

- 跨机 / 容器 / 远程使用 pi-web 时，PF 管理的商显示“未配置”（钥匙库与 helper 不在场）。提供显式动作【导出明文 auth.json】兜底，默认不导出。
- helper 生命周期与安装耦合：auth.json 指向的 helper 不存在时该商失效；由 §3.2 失效校验兜底提示。

## 8 三处受保护改造（**不改**）

只允许换数据源（`mj_doc()` / `mj_write()`：`providers.json` → `models.json`），不改布局 / 交互 / 字段语义：

1. 自定义 Provider 详情页（`custom_models.rs::mj_provider_editor`）：头行 name+【移除】、API Key 段、Base URL、API 下拉、操作栏[测速][保存][+模型]、高级设置、可用模型区。
2. 模型详情页（`mj_model_modal_overlay`）：500×500 弹窗，ID / 上下文 / 最大输出 / 能力(text·image) / 推理，[自动填参][测试][保存][移除]。
3. 自动填参（`mj_catalog_fill` → `pi_link::openrouter::resolve`）：数据源 = OpenRouter（单模型直查 + 全量兜底），替代 models.dev；覆盖 `contextWindow` / `maxTokens` / `input(text,image)` / `reasoning` / `name`，`cost` 只填空。
