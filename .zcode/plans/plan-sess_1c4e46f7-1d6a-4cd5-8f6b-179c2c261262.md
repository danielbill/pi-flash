# pi-flash 架构重构计划(v4:框架 + 极速启动 + 外观体系)

## 总纲

以 docs/模块设计(005-032)为规格:框架层抄 zed、会话列表抄 ZCode、对话层以 pi-web 为行为规格、外观体系按 006/007(架构 zed、数据 pi-web)、通用基座 gpui-component。把 main.rs 6161 行/Chat 128 字段/render 3260 行拆到新模块树,按 zed 机制重做启动链路。**本轮搭框架;各功能模块细节等用户详细要求后逐模块细化。**

## startup 设计(写入契约)

启动清单四层(pi-web 核实):恢复层(主题/语言/布局/上次workspace/每项目上次会话,同步一次读)/会话列表层(索引化扫描)/会话内容+运行时层(磁盘直读渲染,pi 单次 spawn,新会话懒 spawn)/后台杂项(git/模型/信任)。

状态机(startup.rs):Restore(一次读 app_settings.json+状态文件,<5ms)→FirstFrame(按恢复 bounds 开窗,壳骨架+欢迎页,零 IO,<50ms)→BackgroundFill 并行(会话列表 group 目录定位+tail-seek+指纹索引;pi 单次 spawn 带 --session/newSession 懒到首条 prompt;文件树后台+子目录懒加载;git 后台;设置分层)→SessionReady(最后会话磁盘直读渲染,pi ready 后 RPC 对账)→页面流转 welcome→(空|新建→newSession;有上次→sessionView)。

预算:首帧<50ms;会话列表<150ms;上次对话上屏<300ms(与 node 无关);pi 就绪<1s 不阻塞。

现状瓶颈(实测,全修):Chat::new 全同步阻塞首帧;list_sessions 72MB 全量读×2;git 同步双子进程;node 双 spawn;workspace-memory 读 4 次;settings 面板数据启动全量装载;窗口尺寸硬编码;记忆文件非原子写。

## 外观体系(006/007,写入契约)

- 主题架构换 zed 式:ThemeRegistry+主题族+ActiveTheme(真身,非 shim),内置 7 套——浅色 mist/rose(pi-web 令牌转换)+One Light/nord light/ayu light(拷 zed 主题 JSON);深色 One Dark/nord dark;现有 default/dark 退出;PI_FLASH_THEME 调试覆盖保留。
- syntax 衔接:zed 主题 syntax 色→syntect 色彩方案映射(markdown.rs/syntect 保留,006 定案不引 zed markdown)。
- icon theme 架构用 zed(注册表/文件图标集解析),内置内容用 pi-web 图标(assets/icons 迁入)。
- 字体三档:session font(≈zed UI font)/panel font/markdown preview font+字号,gpui 字体栈全局生效。
- 配置三层分界:pi settings.json(模型/凭证/工具,归 pi)/ app_settings.json(主题/图标/字体,~/.pi/agent/ 下,原子写,启动一次读)/ 运行时状态文件(窗口 bounds/dock/面板状态/每项目上次会话,原子写+500ms 防抖)。
- 外观设置 UI:设置面板 general 扩为外观 tab(主题/图标/字体选择器最小版),细节后置。
- 007 多语言:沿用 i18n.rs 现行模式(pi-web parity),新模块字符串走 tr() 收口,列入守护。
- 主题切换时重跑 gpui-component token 映射。
