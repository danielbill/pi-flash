# 会话池重构:每会话常驻 SessionRuntime(pi-web 多开模型对齐)

## 模型纠正(写入契约,替换"单进程+停靠"的旧理解)

pi-web 的会话 = 常驻运行时注册表(`__piSessions`):每个会话独立 pi 进程/模型/思考级/工具集/草稿,几十个并发,空闲才回收;切换 = 用户注意力转移(UI 换订阅),**不存在挂起**;侧栏转圈 = 并发运行监控面板。pi-flash 旧实现(单进程,切换杀进程)是根本性错误,本轮重做。

## 架构

**SessionRuntime(新实体,session/runtime.rs)= 一个会话的全部状态:**
- 运行时:AgentSession(进程+epoch)、cwd、file(Option,草稿为 None)、key(文件路径或 "draft-N")
- 消息:messages、list(ListState)、collapsed、phase_waiting、stream_started、agent_running、status
- 会话态:state、stats、branch_tree、active_user_entry_ids、pending_rename、commands、available_models
- **inputPanel(031)全套独立**:input 草稿、pending_images、history/history_ix、thinking_override、tools_preset(→ spawn 参数)、模型选择(state 内含,经 set_model RPC 活改)
- 自有事件泵(consume_events 按本 runtime epoch 守卫)+ 自有 title 泵(auto_title 迁入,用本会话模型)
- **EventEmitter<SessionEvent>**:Changed / RunningChanged / FileCreated(AgentEnd 后文件落盘)/ ExtUi(请求)——Chat 订阅做壳级副作用

**Chat = 壳 + 池 + 注意力指针:**
- runtimes: HashMap<key, Entity<SessionRuntime>>、active_key
- 切换 = 改 active_key + 草稿 flush/load(旧 runtime.input ← chat.input;新 → chat.input)+ cx.notify——**零进程操作、零 IO,毫秒级**
- on_event reducer 及 send/steer/follow_up/abort/refresh_state/fork/auto_title 全部迁入 runtime;Chat 保留壳动作(open/new/delete/switch)
- 侧栏转圈:render 遍历 runtimes 读 agent_running(几十个实体读取/帧,可忽略)
- 状态栏/声音/git 刷新:list 订阅事件,is_active(key) 才做 UI 副作用;FileCreated 任何来源都 refresh_sessions
- ext_dialog:仅 active 会话的弹;停靠会话的请求在 runtime 内排队(G+ 做角标提示)

**打开/新建/删除:**
- open_session(path):池中有 → 直接切换(秒回,含全部消息);无 → **先建 runtime + 磁盘尾窗直读上屏,进程 spawn 丢 background_spawn**(UI 不等 node);复用 session_tail_cache
- new_session(cwd):草稿 runtime,**懒 spawn**(首条 prompt 才拉进程,pi-web parity)
- delete_session:abort + 移除 runtime;若是 active 则按 cwd 开新草稿
- tools_preset 变更:该会话带 --session 重绑进程(--tools/--exclude-tools/--no-tools/--no-builtin-tools 参数化);模型/思考走活改 RPC

**启动(§4 更新):** last_open → runtime + 尾窗直读,spawn 后台;列表/预加载照旧。

**空闲回收:** 后台每 60s 扫一遍——非 active 且 !agent_running 且 10 分钟无活动 → 只杀进程、**消息保留**(重开秒出,下次 prompt 带 --session 重拉)。

## 已知偏差(记录进契约)
- 工具集活改:pi-web 走 SDK setActiveToolsByName;RPC 无此命令 → spawn 参数 + 重绑(状态无损)
- 停靠会话的阻塞 ext 请求:排队不弹窗(G+ 角标)
- sa_runs(子代理测试)仍挂 Chat(设置面板触发,G+ 归位)

## 实施步(每步 build+test 绿)
1. session/runtime.rs:字段+实体+泵+reducer+ingest/assistant_slot/notify_list 迁入(编译驱动,Chat 字段先保留影子,逐步删)
2. Chat 池化:runtimes/active_key、open/new/delete/switch 重写、input mirror flush/load、侧栏转圈遍历
3. inputPanel 每会话化:草稿/附件/history/thinking/preset 随 runtime;preset→spawn 参数
4. 启动路径:后台 spawn + 懒草稿;空闲回收定时器
5. 全量回归(dev.sh 实测:两项目各一会话并发跑、切换即时、双转圈、停靠会话完成不丢)
6. 契约更新(模型纠正+偏差)+ 提交
