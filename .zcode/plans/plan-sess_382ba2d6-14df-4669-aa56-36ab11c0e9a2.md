## 1. 设计原则(抄 pi-web 的骨架,用 Zed 的实体模式实现)

pi-web 三层结构的 Rust 对应:
- React 组件 ↔ GPUI `Entity<T> + Render`(Zed 同款)
- props 向下 ↔ 父持 `Entity<T>` 句柄,`child.update(cx, |c| c.set_xxx(...))`
- callbacks 向上 ↔ 子 `cx.emit(Event)`,父 `cx.subscribe`(替代现在的 weak.update 散弹)
- lib 服务层 ↔ 无 UI 的纯函数/服务模块

铁律(写进 ARCHITECTURE.md + 守护脚本):
- 单文件 ≤1500 行;render 函数 ≤300 行
- **禁止** `on_key_down` 手写字符匹配当输入框用(这正是改名框 IME 坏掉的病根),所有文本输入必须走 `TextInput`
- 视图组件不直接碰 PiSession RPC(pi-web: ChatInput/MessageView 无网络请求)

## 4. TextInput 组件设计(修死这类 bug)

HTML `<input>` 原生带 IME/焦点/光标,pi-web 全靠它,30+ 输入点零成本;GPUI 没有,所以造一个等价物,全 app 唯一入口:

```rust
pub struct TextInput {
    focus: FocusHandle,           // 每实例独立(废除 5 输入点共享 dialog_focus)
    value: String,
    marked: Option<Range>,        // IME 组合段(utf16,从 Chat 现有实现泛化)
    placeholder/masked/single_line/max_len,
    on_change/on_submit/on_escape: 回调(闭包持 WeakEntity 父),
}
impl Focusable; impl EntityInputHandler for TextInput  // 现 Chat 的 IME 合同平移
pub struct TextInputElement{..}  // paint 阶段 window.handle_input 注册
// render: track_focus + click 聚焦(focus_on_click)+ 手绘闪烁光标(仅聚焦时)
```
替换全部 9 站点:改名框、扩展 input/editor 对话框、设置 API-key(带 mask)、插件安装、子代理并发数(数字校验)、**补建 session 搜索行(现在是空壳)**、**补建模型过滤框(现在是静态文本)**;主编辑器迁为 Composer 基座(保留已验证的多行/菜单逻辑,IME 合同改用 TextInput 内部同一实现)。光标闪烁:单个全局 blink 泵广播,只 notify 聚焦中的实例。

## 5. 通信规约(替代 88 个 weak.update 散弹)

- 父→子:方法调用 `composer.update(cx, |c| c.set_draft(...))`
